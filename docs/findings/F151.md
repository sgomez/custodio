### Seed (NoCloud) and channel
`ssh` and `ssh-keygen` are not in the dev container, so the channel is the **serial console**, which needs no change to the product or to the container. (An SSH channel would need `openssh-client` in `harness/Containerfile`: a person's rebuild; not needed.)
Seed, `cloud-localds seed.img user-data meta-data` → `ISO 9660 CD-ROM filesystem data 'cidata'`; the guest read it (`cloud-init status` → `status: done`, hostname `f151`, the password below worked):
```
user-data:  #cloud-config
            chpasswd: {expire: false, users: [{name: ubuntu, password: custodio-throwaway-test, type: text}]}
            ssh_pwauth: false
meta-data:  instance-id: f151-1 / local-hostname: f151
```
`custodio-throwaway-test` is a throwaway test credential for a VM that exists for one test and is never reachable from a network (user networking, no port forward); no key or reusable secret is involved.
`genisoimage` is the unused fallback (`-volid cidata -joliet -rock`).

How a script drives it: QEMU serves the serial on `-serial unix:serial.sock,server,nowait`; the script connects, sends `\n`, and waits (with a timeout, not a sleep) for `f151 login: `, sends `ubuntu` and the password, waits for `$ `,
then `PS1='<<P>> '; stty -echo`. Each command is sent as `CMD; echo "__RC=$?__"` and the script reads until the regex `__RC=\d+__` (the echo of the typed line is off, and the sentinel holds `$?` unexpanded, so it only matches real output). Output is the text before the sentinel, the exit code is the digits.
The guest's shell prints OSC `ESC ]3008;...ESC \` sequences and `ESC[?2004h`; strip `\x1b\][^\x1b\x07]*(\x1b\\|\x07)?` and `\x1b\[[0-9;?]*[a-zA-Z]` first. A new connection to the socket after a login still has the logged-in shell (the script must accept both the login prompt and `$ `). Boot to login prompt took under 30 s with KVM. All of this ran with the product not installed. **verified**

### QEMU command line (the one that booted every run below)
```
swtpm socket --tpm2 --tpmstate dir=$STATE --ctrl type=unixio,path=$PWD/swtpm.sock --daemon --pid file=$PWD/swtpm.pid --log file=$PWD/swtpm.log
qemu-system-x86_64 -machine q35,accel=kvm -cpu host -smp 2 -m 2048 -display none \
  -drive if=pflash,format=raw,readonly=on,file=/usr/share/OVMF/OVMF_CODE_4M.fd \
  -drive if=pflash,format=raw,file=vars.fd \
  -drive file=disk.qcow2,if=virtio,format=qcow2 -drive file=seed.img,if=virtio,format=raw,readonly=on \
  -netdev user,id=n0 -device virtio-net-pci,netdev=n0 \
  -chardev socket,id=chrtpm,path=$PWD/swtpm.sock -tpmdev emulator,id=tpm0,chardev=chrtpm -device tpm-crb,tpmdev=tpm0 \
  -serial unix:$PWD/serial.sock,server,nowait -monitor none -daemonize -pidfile $PWD/qemu.pid
```
`vars.fd` is a copy of `OVMF_VARS_4M.fd`; `disk.qcow2` is `qemu-img create -f qcow2 -b <image> -F qcow2 disk.qcow2 10G` (the verified image stays untouched). Firmware: `OVMF_CODE_4M.fd` with `OVMF_VARS_4M.fd`, **not** the `.secboot`, `.ms` or `.snakeoil` variants in `/usr/share/OVMF`.
Secure Boot is off in the guest: `/sys/firmware/efi/efivars/SecureBoot-8be4df61-...` does not exist (no keys enrolled). `-nographic` cannot be combined with `-daemonize`. `swtpm` exits by itself when QEMU disconnects (no `swtpm` left after each `poweroff`), so the harness starts it right before QEMU and does not kill it.
A `swtpm` started without a QEMU (my first start failed on `-nographic`) stays idle forever, and `kill`, `kill -9` and `os.kill` on it all returned `Permission denied` in this container's tool sandbox (same uid; it has `NoNewPrivs`, `Seccomp: 2`): start `swtpm` only together with QEMU, and never in a step that can fail between the two. **verified** (that process, `swtpm` 32088, was still alive when this was written; it goes away with the container).
