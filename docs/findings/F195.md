## F195: what the library tells about a failed import (2026-11-15)

Run in the dev container: `p12-keystore` 0.4.1 `Pkcs12Archive::from_pkcs12` through `custodiod::import::parse_p12`
(the code of 05d1add), OpenSSL 3.5.7 fixtures from `crates/custodiod/tests/fixtures/gen.sh` (section `# F195 begin`).

**Conclusion (verified).**
- A MAC is present when the outer `PFX` has `macData` (`archive.rs:73`, `if let Some(mac_data) = pfx.mac_data`). The MAC is checked
  first, before any bag is read; a mismatch is `MAC tag mismatch`. So (a) is decidable from the file: `macData` present and verify fails.
- Safe contents and key bags are encrypted by every real exporter (OpenSSL, NSS, Firefox). With a wrong password the library fails on
  the MAC (or on decryption without a MAC) before it sees a single bag. **A MAC-bearing file that is unusable (no key, no certificate)
  with a wrong password is indistinguishable from a good file with a wrong password**: both give `MAC tag mismatch`. SPEC Design 4's
  "(b) with any password" cannot hold for those cells by any rule over the bytes and the library's result.
- Without a MAC, only a file whose bags are plain `Data` shows its defect with a wrong password (`nokey-nomac`); a shrouded key
  gives `PKCS#5 decryption failed`, the same as a good file (`good-nomac`, `nocert-nomac`): that is (c), as SPEC says.
- Not PKCS#12: DER parse error whatever the password, so (b) (BER fallback in `from_ber` also fails).

| file | right password | wrong password |
|---|---|---|
| `p256.p12`, `rsa2048-nss.p12` (good, MAC; DER, NSS BER) | ok | `MAC tag mismatch` |
| `good-nomac.p12` | ok | `PKCS#5 decryption failed` |
| `nokey.p12` (MAC, certificate in encrypted safe) | `NoPrivateKey` | `MAC tag mismatch` |
| `nokey-nomac.p12` (plain cert safe) | `NoPrivateKey` | `NoPrivateKey` |
| `nocert.p12` (MAC, shrouded key) | `NoCertificate` | `MAC tag mismatch` |
| `nocert-nomac.p12` | `NoCertificate` | `PKCS#5 decryption failed` |
| `notp12.bin` | `unexpected ASN.1 DER tag` | same |

Not done: the two-keys files (no tool here writes two key bags into one file except NSS, which exports one certificate per file;
a MAC-less one needs a generator written for it). The MAC case follows from the same code path as `nokey.p12`.
