## F180

Classifying the state directory (SPEC Design 7; closes the open question "Classifying the state directory").
Machine: the dev container (Debian 13, systemd 257.13, kernel 7.0, uid 1000).

**Verified** (command run here, or the systemd 257 `systemd.exec(5)` text read):

- The chain needs no tool. `/proc/self/mountinfo` gives, per mount, `major:minor`, mount point, fstype; `/sys/dev/block/<maj:min>`
  is a symlink to the device's sysfs directory. A partition has a `partition` file and its parent directory is the disk;
  a physical disk has a `device` link and no `dm/` or `md/`; a device-mapper device has `dm/uuid` and `slaves/` (symlinks to
  its members). Run: `readlink -f /sys/dev/block/259:4` ends `.../nvme/nvme1/nvme1n1/nvme1n1p1`; `ls <that>/partition` exists,
  `ls <that>/../device` exists, no `dm`, no `md`. `cat /sys/block/dm-0/dm/uuid` is `LVM-Mc0k...`; `ls /sys/block/dm-0/slaves`
  is `nvme0n1p2`. `findmnt -no FSTYPE,MAJ:MIN -T /dev/shm` is `tmpfs 0:55`.
- dm-crypt is recognised by the dm uuid prefix `CRYPT-` (cryptsetup writes `CRYPT-LUKS2-<uuid>-<name>` or `CRYPT-PLAIN-...`);
  LVM volumes carry `LVM-`. The prefix is read from `dm/uuid`; the dm name is not used (a user can name any device "crypt").
- Dev container record (not asserted by any test, CI has other storage): `/work` mount `259:4`, ext4, partition of
  `nvme1n1`, no dm, so *not encrypted*; `/dev/shm` is tmpfs, `0:55`, so *unknown*. The device number is the `major:minor`
  field, never the source string (a runner may show `/dev/root`).
- Sandbox of `data/custodio.service`, from `systemd.exec(5)` 257: `ProtectSystem=strict` makes the tree read-only except
  `/dev`, `/proc`, `/sys`, which stay as they are; `ProtectKernelTunables=yes` makes `/sys` and `/proc/sys` read-only (not
  hidden) and hides `/proc/kallsyms`, `/proc/kcore`; `PrivateDevices=yes` replaces `/dev` only; `ProcSubset=pid` hides what is
  not process information in `/proc`, and `/proc/self/mountinfo` is process information; `ProtectProc=invisible` hides other
  processes only; `PrivateUsers=identity` maps uids to themselves, sysfs files are `0444` and the directories `0755`;
  `DynamicUser=yes` only changes the uid. So the reads are allowed. These were not run under the real unit (no systemd
  unit can be started here); an unreadable file would give *unknown*, never *encrypted*.
- DynamicUser state: systemd makes `/var/lib/private/custodio` and a bind mount (or symlink) at `/var/lib/custodio`. The
  mount entry of the bind has root `/var/lib/private/custodio` and mount point `/var/lib/custodio`, with the backing
  filesystem's device number; the classifier takes the longest mount point that is a path prefix of the canonical state
  directory, the last entry for equal points, and uses its device number. A symlink is resolved first (`canonicalize`).

**Verdicts** (the rule: *encrypted* only when every path from the filesystem to the physical devices goes through a `CRYPT-`
device; *not encrypted* only for a chain fully read that ends at physical devices with no dm-crypt; everything else *unknown*):

| Case | Verdict | Why |
|---|---|---|
| plain partition (ext4, xfs, f2fs, ...) | not encrypted | partition, disk with `device`, no dm |
| LUKS (`CRYPT-`) on a partition | encrypted | dm uuid |
| LVM on LUKS | encrypted | `LVM-` over members that are all encrypted |
| LUKS on LVM | encrypted | the top device is `CRYPT-` (nothing beneath is read) |
| LVM without crypt | not encrypted | `LVM-` over physical members |
| LVM over a mix of crypt and plain | unknown | not all members agree |
| dm-integrity (not `CRYPT-`, not `LVM-`) | unknown | other dm types are not classified; integrity under crypt is *encrypted* (top is crypt) |
| RAID (md), no crypt | unknown | md is not dm-crypt |
| RAID over crypt (all members encrypted) | encrypted | every leg is encrypted |
| crypt over RAID | encrypted | top is `CRYPT-` |
| btrfs (several devices or one) | unknown | anonymous device `0:N`; members are not mapped from the mount |
| ZFS | unknown | fstype `zfs`, anonymous device (**inferred**: no ZFS here) |
| fscrypt | unknown | a directory with `FS_ENCRYPT_FL` (`FS_IOC_GETFLAGS`) on a chain that is not encrypted; **inferred**: no fscrypt volume here |
| NFS / CIFS / FUSE, overlay, tmpfs | unknown | fstype not on the block list |
| loop, zram, nbd, anything without a `device` link | unknown | not physical |
| unreadable file, missing `slaves`, cycle, depth over 16, no covering mount | unknown | any read error |

The block list of filesystems: ext2, ext3, ext4, xfs, f2fs, jfs, vfat, exfat. `CRYPT-` on a device that is not in the chain is
ignored. A failing `FS_IOC_GETFLAGS` on an otherwise *not encrypted* chain gives *unknown*.
