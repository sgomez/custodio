## F190

How `custodio doctor` check 5 (a persistent journal, SPEC Design 2, open question 3) reads journald's effective storage as an
ordinary user, with no `journalctl`, no D-Bus, no root. Machine: the dev container (Debian 13, uid 1000, systemd 257.13), `podman`
4+ with network. Sources: systemd v257, v259, v260, v262 (read by a subagent from GitHub), `man journald.conf`/`systemd-journald`,
and runs of the real `systemd-journald` inside the five target images.

**Conclusion.** Doctor reads only files and one `stat`. The effective `Storage=` is the last valid assignment in the main file and
its drop-ins; the dir `/var/log/journal` decides only `auto` (and an unset value whose compiled-in default is `auto`).
`/run/log/journal` is never used. The `Decision: ` line at the end is what F203 implements.

**Probe (step 1).** `podman` pulls and runs the target images here:
`podman pull docker.io/library/{debian:13,ubuntu:26.04,fedora:44,almalinux:10,archlinux:latest}` all succeed; then
`podman run --rm -v probe.sh:/p.sh:ro <image> sh /p.sh` (installs `systemd` if missing, prints versions, files, `ls`, `dpkg -L`/`rpm -q`/
`pacman -Ql`; for Storage tests it starts `/usr/lib/systemd/systemd-journald` in the container and sends `SIGUSR1`, which is what
`journalctl --flush` does). So the targets below are **verified** for the package contents and for journald's behaviour with a set
machine-id. A container is not a booted system: what an installer or first boot adds is **inferred**.

### Files and precedence
- **Verified** (`systemd-analyze cat-config --root=<fixture> systemd/journald.conf` as uid 1000, and journald runs): the **main file**
  is the first that exists of `/etc/systemd/journald.conf`, `/run/systemd/journald.conf`, `/usr/local/lib/systemd/journald.conf`,
  `/usr/lib/systemd/journald.conf`; the others are not merged (`/etc` = `none` over `/usr/lib` = `persistent` gave "not persistent").
  Source: `conf-parser.c` `config_parse_many_files`, "First read the first found main config file" then `break` (**verified** by reading).
- **Verified:** drop-ins are `*.conf` in `<dir>/systemd/journald.conf.d/` for `/etc`, `/run`, `/usr/local/lib`, `/usr/lib` (not `/lib`).
  A name present in several dirs is read from the first dir in that order (cat-config printed only the `/etc` copy of `a.conf`; journald
  run: `/etc/x.conf`=volatile masks `/usr/lib/x.conf`=persistent). The remaining files sort by name across all dirs and are applied
  after the main file: fixture `a.conf` (`/etc`), `b.conf` (`/usr/lib`), `c.conf` (`/run`), `z.conf` (`/usr/local/lib`) printed in that
  order; `/etc/.../a.conf`=volatile then `/usr/lib/.../b.conf`=persistent gave persistent. A drop-in beats the main file.
- **Verified by journald runs** (Debian 257), with `Storage=persistent` unless noted: key before any section, `[Other]` section,
  and `storage=` (lower-case key) have no effect; `Storage=Persistent`, `"persistent"` and `persistent # c` log
  `Failed to parse Storage=..., ignoring: Invalid argument` and have no effect; ` Storage = persistent ` (spaces) works; a repeated key:
  last valid wins; `Storage=persistent` then `Storage=` then `Storage=bogus` stays persistent (the empty and the invalid value are
  warnings; the earlier value is kept). Source (**read**): `DEFINE_CONFIG_PARSE_ENUM(config_parse_storage, ...)` returns an error on
  an unknown string, without writing the field; `storage_table` is `auto, volatile, persistent, none`.
- **Inferred** (read in `conf-parser.c` `parse_line`, not run): a line ending in `\` is joined with the next one; `#` and `;` start
  comment lines; a repeated section header is fine.
- `cat-config` shows only which files are read and in what order; every "which value wins" claim above comes from the journald runs and
  the parser source, not from `cat-config`.

### `Storage=` on disk (journald 257 runs, machine-id set; `var` = `/var/log/journal`)
| Config | var before flush | after `SIGUSR1` flush (done on every boot by `systemd-journal-flush.service`) |
|---|---|---|
| `auto` | absent | `var` still absent; data only in `/run/log/journal/<id>` (**verified**) |
| `auto` | present | `var/<machine-id>/` created and used (**verified**) |
| `persistent` | absent | `var` and `var/<id>` created (**verified**) |
| `volatile` | present | `var` stays empty, only `/run/log/journal/<id>` (**verified**) |
| `none` | either | nothing in `/run/log/journal` nor `var`; data dropped (**verified**) |
Source (**read**, v257 `journald-server.c` `server_system_journal_open`): `persistent` does `mkdir_parents` + `mkdir`; `auto` only
creates `var/<id>` "but not the prefix", so **`auto` never creates `/var/log/journal`**. `tmpfiles.d/systemd.conf` has only `z`/`a+` lines
(mode, owner, ACL, no creation), `journal-nocow.conf` only `h` (attribute); **verified**: on `almalinux:10`, `systemd-tmpfiles --create`
leaves `/var/log/journal` absent. Container artifact (**verified**, cause **inferred**): with an empty `/etc/machine-id` journald
stores `system.journal` directly in `/var/log/journal` and creates it even for `auto` (Alma 257); doctor sees booted systems, which have an id.

**`/run/log/journal`**: it exists on every boot for `auto`, `persistent` and `volatile` (journald writes there before the flush) and stays
after the flush (**verified**: present in every row except `none`). Its presence proves nothing, its absence only suggests `none`.
F203 must not read it. A "volatile override" is not a directory: it is `Storage=volatile` in a file, in practice
`/run/systemd/journald.conf.d/*.conf`, handled by the precedence above.

### systemd 257 and later
- **Read** (v262 `NEWS`, "CHANGES WITH 259"): "The default storage mode for the journal is now 'persistent'. Previously ... 'auto' ...
  The default can be changed with -Djournal-storage-default=" (values `persistent`, `auto`, `volatile`, `none`). The shipped
  `journald.conf` shows the compiled default: `#Storage={{ JOURNAL_STORAGE_DEFAULT }}` in v259 (**verified** below on each target).
- **Read** v258+: config code moved to `journald-config.c`, same search path (`config_parse_standard_file_with_dropins`), reload
  re-parses it; in the initrd `persistent`/`auto` become `volatile` (irrelevant to doctor). No NEWS entry from 258 to 262 about the
  search path, `Storage=` values or `/var/log/journal` creation; tmpfiles `systemd.conf.in` has the same `z` lines in v262 and
  `var.conf.in` has no journal line. NEWS of 258 itself was searched only through the v262 file (**inferred** for 258);
  v262.2 itself was not fetched, v262 was.
- **Verified** on `ubuntu:26.04` (259.9), `fedora:44` (259.10) and `archlinux` (262.1), no config, no `/var/log/journal`, machine-id set:
  after a flush `/var/log/journal/<id>` exists. So on 259+ a missing directory with an unset `Storage=` is persistent.

### Default install per target (`/etc/systemd/journald.conf` or `/usr/lib/...` as listed)
- `debian13` **verified**: systemd 257.13-1~deb13u1; `/etc/systemd/journald.conf` has `#Storage=auto`; drop-in
  `/usr/lib/systemd/journald.conf.d/syslog.conf` (`ForwardToSyslog=yes` only). `/var/log/journal` is not in the package list
  (`dpkg -S` finds none): `systemd.postinst` line 73 `mkdir -p "$DPKG_ROOT/var/log/journal"`; exists after install, `2755 root:systemd-journal`.
- `ubuntu2604` **verified**: 259.9-0ubuntu0.1; `#Storage=persistent`; same `syslog.conf` drop-in; `systemd.postinst` line 71 `mkdir -p`
  creates the dir; persistent even without it (above).
- `fedora44` **verified**: 259.10-1.fc44; only `/usr/lib/systemd/journald.conf` (rpm lists `/etc/systemd/journald.conf` as ghost `cng`),
  `#Storage=persistent`, no drop-in. Dir: `%ghost` plus a scriptlet `[ -w /var ] && mkdir -p /var/log/journal` ("only on initial
  installation"); exists after install.
- `alma10` **verified** in the image, boot **inferred**: 257-23.el10_2.2.alma.1; `/usr/lib/systemd/journald.conf` with `#Storage=auto`
  and an active empty `Audit=`; no drop-in. `/var/log/journal` is `%ghost` and no scriptlet creates it, so it **does not exist** after
  install: `auto` means volatile. The fix applies by default here (an installer could create it; not checked).
- `arch` **verified**: 262.1-1; `/etc/systemd/journald.conf` with `#Storage=persistent`, no drop-in; `pacman -Ql` lists
  `/var/log/journal/` (package creates it, `2755 root:root` in the container). Persistent by default.
So the targets differ in who creates the directory: package file or maintainer script (Arch, Debian, Ubuntu, Fedora; visible in a
container), none (Alma). journald itself creates it only for `persistent`, at the first flush on a booted system.

### What an ordinary user can read
Verified as uid 1000: config files `0644 root`; `/var/log` `0755`; `/var/log/journal` `2755 root:systemd-journal` (Arch `root:root`) so `stat`
works; `system.journal` is `0640` and is never needed. Doctor needs `stat`/`read` only, no `read_dir` of `/var/log/journal`. Any path
read may still fail with `EACCES` (verified: `stat`/`ls` of a `0000` directory give "Permission denied").

### Documented fixes (all need root; doctor only prints them)
| State | Fix (quoted) |
|---|---|
| `auto`/unset on 257, dir absent | `systemd-journald(8)`: "it is sufficient to create the directory, and ensure it has the correct access modes and ownership": `mkdir -p /var/log/journal` and `systemd-tmpfiles --create --prefix /var/log/journal` (**verified** gives `2755 root:systemd-journal`); then `journalctl --flush` or reboot. Or a drop-in `/etc/systemd/journald.conf.d/50-persistent.conf` with `[Journal]` `Storage=persistent` and a restart of `systemd-journald` (config is read at start; **inferred** for reload) |
| `volatile` | `journald.conf(5)`: "volatile ... stored only in memory, i.e. below the /run/log/journal hierarchy": remove or change `Storage=volatile` in the file doctor names (file:line of the winning assignment); a file under `/usr/lib` is overridden by a same-named file in `/etc` ("or a copy of it placed in /etc/ if the original file is shipped in /usr/", the header of the shipped file) |
| `none` | "none turns off all storage, all log data received will be dropped": same edit; nothing is logged at all, the audit entries are lost even in the current boot |

### States (what doctor answers)
Let S = last valid `Storage=` (or unset), D = `stat("/var/log/journal")`. Unset takes the compiled default from the first line
`#Storage=<value>` (exact, `auto|persistent|volatile|none`) of the **main file**; the shipped file shows it (**verified**, five
targets). A stale copy in `/etc` can only be older, so it can say `auto` where the binary persists: a false "not persistent" with a harmless fix.
| S | D | Answer |
|---|---|---|
| `persistent` | any | persistent (journald creates the dir at the first flush) |
| `auto` | directory | persistent |
| `auto` | ENOENT | not persistent, fix 1 |
| `auto` | other error, or not a directory | could not check (stat failed / `/var/log/journal` is not a directory) |
| `volatile` | any | not persistent, fix 2 (even if the dir exists: `var` stays empty, **verified**) |
| `none` | any | not persistent, fix 3 |
| unset, comment `persistent` | any | persistent |
| unset, comment `auto` | as `auto` | as `auto` |
| unset, comment `volatile`/`none` | any | not persistent, fix 2/3 |
| unset, no main file or no such comment | any | could not check (the default is `auto` on 257 and `persistent` on 259+; a missing file does not say which) |
| any `Storage=` with an invalid value or a `\`-ended line in `[Journal]` | any | could not check: journald ignores it (**verified**) but doctor does not guess the intent |
| unreadable file or directory (`EACCES`, `EIO`, `ELOOP`, `ENOTDIR`, any error but `ENOENT`), file over 1 MiB, non-UTF-8 | any | could not check |
Combinations: `volatile` + dir, `none` + dir (contradict: dir is ignored); `persistent` + no dir (not a contradiction); a `/run`
drop-in overriding an `/etc` one with a later name (S is the later). Read errors in a drop-in directory that is absent (`ENOENT`) are skipped.
The answer describes the configuration that applies at the next journald start: doctor cannot tell, without asking journald, whether
a recent edit was loaded.

Decision: Doctor reads, with `stat`, `read_dir` of the four `<dir>/systemd/journald.conf.d` and file reads only (never `journalctl`, D-Bus,
varlink or polkit, never `/run/log/journal`): the main file = first existing of `/etc/systemd/journald.conf`, `/run/systemd/journald.conf`,
`/usr/local/lib/systemd/journald.conf`, `/usr/lib/systemd/journald.conf`; drop-ins `*.conf` from `journald.conf.d` under `/etc`, `/run`,
`/usr/local/lib`, `/usr/lib` (a name in several dirs comes from the first), sorted by file name bytes, applied after the main file; in each file only
`[Journal]` lines, key exactly `Storage`, value trimmed and exactly `auto|persistent|volatile|none`, the last valid assignment wins; unset takes the
first line `#Storage=<v>` of the main file; then S × `stat(/var/log/journal)` as in the state table (persistent: `persistent`, `auto`+directory, default `persistent`; not persistent: `volatile`, `none`, `auto`+ENOENT, each with its fix and the file:line that set it); a missing file or directory (`ENOENT`) is skipped and a missing main file with `Storage=` unset is "could not check"; "could not check" also for every error but `ENOENT` (EACCES, EIO, ELOOP, ENOTDIR, a size over 1 MiB, non-UTF-8), an invalid or empty `Storage=` value, a `\`-ended line, `/var/log/journal` that is not a directory, and an unset value with no `#Storage=` line.
