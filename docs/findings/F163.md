### State directory owner in a VM (attempt 10)
- Command: `just e2e-vm-cases lacking 'upgrade-kinds-*'` with a temporary line in `e2e/upgrade.sh` that printed `systemctl --version` and `stat -c '%u:%g %a %n'` of the state directory and its children, as root in the guest, after the upgrade.
- Result: `systemd 259 (259.9-0ubuntu0.1)`; `/var/lib/custodio -> /var/lib/private/custodio`; `65534:65534 700 /var/lib/private/custodio`, `65534:65534 700 .../1001`, `65534:65534 700 .../4711`; unit `User=custodio DynamicUser=yes`.
- Conclusion: seen from the guest's root namespace this is the real on-disk owner (65534), not a mapping of the test. The service accepts it (its owner check passes: it signs before and after the upgrade) and the mode is 0700 as `StateDirectoryMode=` asks. SPEC.md has no requirement on the numeric on-disk owner of the state (only the 0700/0600 modes and the decision in `docs/decisions.md` that the owner must be the service). In the containers (M4) the owner is the `custodio` account. So the VM run pins 65534; a person may want to confirm that a state owned by `nobody` on a systemd 259 host is intended.
