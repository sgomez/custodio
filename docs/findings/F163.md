## F163

Probe in a real `lacking` guest (`vm.sh start lacking`, Ubuntu 26.04, tpm2-tools 5.7, 2026-11-08). The `tpm2-tools` come from `apt-get update` + install in the guest (as `run.sh` does).

- Route A works: `tpm2_clear` from the guest on `/dev/tpmrm0` exits 0 with the empty lockout auth, also in `lacking`. The `lacking` `Commands` list (107 commands) still has `TPM2_CC_Clear`, `TPM2_CC_PCR_Extend`, `TPM2_CC_PCR_Read` and `TPM2_CC_PolicyPCR`. **verified**
- The owner primary of the fixed template (`tpm2_createprimary -C o -G ecc256:null:aes128cfb`) changes after the clear: read with `tpm2_readpublic` (`name:` line); the primary made before differs. The `-c` output of `createprimary` itself prints only `name-alg`; the name is taken from `readpublic`. **verified (name before: 000b9cc6…0ee56c1f0b; the one after differs)**
- `systemd-creds encrypt --with-key=tpm2` works after the clear in `lacking` (the SRK is rebuilt), and decrypting a credential made before the clear fails with `TPM key integrity check failed. Key most likely does not belong to this TPM.` **verified**
- PCRs through `/dev/tpmrm0`: `tpm2_pcrextend 7:sha256=<h> 0:sha256=<h>` exits 0 and both PCRs change. A PolicyPCR object bound to PCR 0 and 7 unseals before; after extending PCR 7 alone the unseal fails (`a policy check failed`, 0x99D). PCR 0 alone was not tried separately (both are in the policy; the second PCR is shown by its changed value). **verified**
- After `vm.sh cycle` the PCRs are **equal to the first reading** (before any extend: PCR0 `0x0101271704CC…3F8E`, PCR7 `0x127C18EBA230…6FA1`; after the cycle the same values). OVMF measurements are deterministic here, and the swtpm state kept does not keep the extension (PCRs are reset by the power cycle). **verified in `lacking` and in `full`** (`full`: `vm.sh start full`, `tpm2_pcrread sha256:0,7` → PCR0 `0x0101271704CC…3F8E`, PCR7 `0x127C18EBA230…6FA1`; after `tpm2_pcrextend` both change; after `vm.sh cycle` the first values return)

Commands (root in the guest, `/dev/tpmrm0`; output line that proves each):
- `tpm2_pcrextend 7:sha256=<h> 0:sha256=<h>` → exit 0; `tpm2_pcrread sha256:0,7` then shows `0 : 0x841BE8D0…16C3`, `7 : 0x709725BA…576D`. The case extends PCR 7 and PCR 0 (not 11).
- `tpm2_createprimary -C o -G ecc256:null:aes128cfb -c p.ctx` then `tpm2_readpublic -c p.ctx` → `name: 000b9cc6…`; the same pair after `tpm2_clear` → a different `name:`.
- `tpm2_clear` → exit 0 (empty lockout auth).
- Policy/unseal pair: `tpm2_startauthsession -S s.ctx; tpm2_policypcr -S s.ctx -l sha256:0,7 -L p.dig; tpm2_create -C prim.ctx -L p.dig -i secret -c obj.ctx` then `tpm2_unseal -c obj.ctx -p session:s.ctx` → prints the secret before; after extending PCR 7 → `a policy check failed` (0x99D).
