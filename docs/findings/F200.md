## F200

Ubuntu 26.04 VM guest, 2026-11-16. Versions: polkit 127-2ubuntu1.1, fprintd 1.94.5-4, libfprint 1:1.95.1+tod1-0ubuntu2, libpam-fprintd 1.94.5-4.

Conclusions (all **verified** by `just e2e-vm-cases full 'vm-fingerprint-*'`, 12 cases `run`):

- **Archive**: `apt-get install -y --no-install-recommends fprintd libpam-fprintd pkexec` works in the guest; `pkexec` is its own package, absent from the image.
- **Virtual driver**: `FP_VIRTUAL_DEVICE` is in the libfprint library (`grep -q FP_VIRTUAL_DEVICE` on the file from `dpkg -L libfprint-2-2*`). The drop-in of `acceptance-6-fingerprint.md`
  gives `Device at /net/reactivated/Fprint/Device/0`.
- **Socket**: `/run/fpvirt/sock` exists only while a client holds the device (during `fprintd-enroll`), not after `fprintd-list`; the stage case checks it during the enrolment.
  `SCAN <id>` on it is accepted; five scans of one id enrol a finger.
- **`pkexec` cannot be the client**: under `su -lP` it answers `No session for cookie` (its in-process agent). The cases use `pkttyagent --process $$ --notify-fd 1 --fallback`
  with `pkcheck --action-id org.freedesktop.policykit.exec --process $$ -u` (`e2e/vm/fingerprint-check.sh`).
  With it: finger match approves; unenrolled finger gives `Failed to match fingerprint` then `Password:`; no touch gives `Verification timed out` (after 10 s) then `Password:`.
- **The text agent does not ask again after a wrong password** (`AUTHENTICATION FAILED`), so the polkit cases type the right password once; the wrong-then-right order is kept for `sudo` only,
  which refused a wrong password and accepted the right one with the harness rule out of the way.
- **Typing too early**: a password typed before the reader turns the echo off is flushed, so the pty driver waits for ECHO off.
- **fprintd reports `no-match` on a timeout too**: the timeout case forbids `scan`/`matched`; the scan tells it from the unenrolled case.
- **Admin rule**: the polkit rules file must sort before `49-ubuntu-admin.rules` (ours is `49-e2e-fingerprint.rules`, `e` < `u`).
- **Signing**: the signing process is the polkit subject, so `pkttyagent --process` runs for that very pid (a fifo holds the `exec pkcs11-tool` until the agent is registered).
  The key is imported before `/etc/pam.d/polkit-1` is set aside (the harness agent approves the import). The journal field of the key is `CUSTODIO_KEY_ID`.
- **Fallbacks** (module file moved, daemon stopped and masked, drop-in removed, enrolled finger deleted) each go straight to the password; each is restored and fprintd is
  `unit=active device=listed` again before the next case.

Evidence: the judge `e2e/vm/fingerprint.py` accepted every case of the run (`scripts/test-e2e-vm-fingerprint.sh` holds the fixtures of that shape); the step took 53 s.
