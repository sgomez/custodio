# F200 — what the first VM runs showed (Ubuntu 26.04 guest, 2026-11-16)

Conclusions from `just e2e-vm-cases full 'vm-fingerprint-*'` (debugging runs; log lines in `target/e2e/vm.full.log`).

- Archive: `apt-get install -y --no-install-recommends fprintd libpam-fprintd pkexec` works in the guest. `pkexec` is its own package (absent from the image). Versions: polkit
  `127-2ubuntu1.1`, fprintd `1.94.5-4`, libfprint `1:1.95.1+tod1-0ubuntu2`, libpam-fprintd `1.94.5-4`.
- The virtual driver is present (`FP_VIRTUAL_DEVICE` in the library); the drop-in of `docs/findings/acceptance-6-fingerprint.md` gives `Device at /net/reactivated/Fprint/Device/0`.
  The socket `/run/fpvirt/sock` exists only while a client holds the device (during `fprintd-enroll`), not after `fprintd-list`; the stage case checks it during the enrolment.
- Enrolment (5 scans of one id) and `custodio fingerprint enable` work; the judge's `stage` accepts the record.
- `pkexec` as a test user: the agent shows `Swipe your right index finger...`, a `SCAN` of the unenrolled id gives `Failed to match fingerprint` then `Password:`; no touch gives
  `Verification timed out` then `Password:` (the 10 s bound holds). `sudo` asked a wrong password, refused it and accepted the right one (the harness rule was out of the way).
- OPEN, blocks the polkit cases: with both `setpriv` and `su -lP` (a logind session) the helper answers `No session for cookie` after a finger match or a right password, so the
  authentication never completes. A wrong password gives `pam_authenticate failed` and the text agent does not ask again (`AUTHENTICATION FAILED`), so the judge's
  "wrong password refused, then the right one" order cannot hold for pkexec; only for sudo. Next: try `pkcheck --process $$` with `pkttyagent --process $$` from one shell, and
  read the polkit journal at debug level; also check whether the harness's test agent (run.sh) is registered for the same subject.
