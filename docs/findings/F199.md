## F199

**Verified** (commands run in the base images): packages, module paths and the PAM client per family.

Probed by installing the packages in the bare base image of each family (`podman run`, 2026-11-16):

- Debian trixie and Ubuntu 26.04: `fprintd libpam-fprintd` put `pam_fprintd.so` in `/usr/lib/x86_64-linux-gnu/security/`; the `pam-auth-update` profile
  `/usr/share/pam-configs/fprintd` exists but `grep -c pam_fprintd /etc/pam.d/common-auth` is 0 after the install, so no Containerfile change is needed (the
  evaluator's note 1 does not apply). D-Bus service file: `/usr/share/dbus-1/system-services/net.reactivated.Fprint.service`.
- Fedora 44 and Alma 10: `fprintd fprintd-pam` put the module in `/usr/lib64/security/`; `authselect current` says profile `local` (no features) in both,
  so `authselect apply-changes` has a profile to apply. `which` is not installed; the guest uses `command -v`. The SELinux tools are `libselinux-utils`
  (`matchpathcon`) and `policycoreutils` (`restorecon`).
- Arch: `fprintd` alone has the module (`/usr/lib/security/pam_fprintd.so`) and the D-Bus service file.
- PAM client: Python `ctypes` on `libpam.so.0` (`e2e/fingerprint-pam.py`); every image has python3. It reads `/proc/self/maps` after `pam_authenticate`
  and reports whether `pam_fprintd.so` is mapped: with the override ignored, the vendor file does not load it.
