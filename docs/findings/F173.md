## F173

`deb-systemd-invoke restart` does not start a static unit that is not running, so the last step of a deb upgrade of a running service cannot use it. **Verified** (Debian 13 `/usr/bin/deb-systemd-invoke`, lines 114-141, and the e2e upgrade case).

The script runs `systemctl is-enabled` (a static unit is not `enabled*`) and `is-active`; with `restart`, `!installed && !active` prints
`<unit> is a disabled or a static unit not running, not starting it.` and skips the unit. `custodio.service` is static and the postinst has just stopped it (systemd refuses to start the socket while the service is active), so the service stayed down after the upgrade; `e2e/upgrade.sh` caught it (service not active after `dpkg -i`).

Decision: the final restart is `systemctl restart custodio.service`, run only after postinst asks `/usr/sbin/policy-rc.d custodio.service restart` itself (exit 0 or 104, or no `policy-rc.d`, allows; the stock container one exits 101, `docs/findings/F48.md`). The stop and the socket start stay on `deb-systemd-invoke`.
