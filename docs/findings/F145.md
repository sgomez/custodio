## F145

Commands of the M4 manual acceptance steps, run in the dev container (2026-11-06, tpm2-tools as installed there, swtpm through `scripts/with-swtpm.sh`).

- **Record check (verified).** `scripts/tpm-record-check.sh STATE KEY_ID` reads a record with `python3 -I e2e/tpmdup.py scan`, makes the service's parent (`tpm2_createprimary -C o -G ecc256:aes128cfb -a 'fixedtpm|fixedparent|sensitivedataorigin|userwithauth|noda|restricted|decrypt'`),
  `tpm2_load`s the areas, `tpm2_readpublic` and `tpm2_duplicate` under a policy session on `TPM2_CC_Duplicate`. On a key made on the swtpm with no policy it prints `authPolicy: empty` and
  `tpm2_duplicate: failed with TPM_RC_POLICY_FAIL (...0x99D...)`, exit 0. On a key made duplicable (policy on `TPM2_CC_Duplicate`, no fixed attributes) it prints `authPolicy: NOT empty` and
  `tpm2_duplicate: succeeded`, exit 1 (so the session is right: the same invocation duplicates when the policy allows it). A record with the last byte of the private area altered fails in `tpm2_load`, exit 1.
- **PCR 7 substitute (verified on the swtpm).** `tpm2_pcrread sha256:7` before and after `tpm2_pcrextend 7:sha256=<64 hex>` differ; the same extend on PCR 8 leaves PCR 7 as it was. The extension lasts until the TPM is
  reset (a reboot), so it is not a lasting change of a machine. On a hardware TPM it was not run.
- **`fwupd` (unverified here).** `fwupdmgr` is not installed in the container. The page uses `fwupdmgr refresh`, `fwupdmgr get-updates`, `fwupdmgr update`; the `dbx` device is named
  "UEFI Secure Boot Forbidden Signature Database" by fwupd (from its documentation, not run). The person reads PCR 7 before and after; if equal, the step says the event proved nothing.
- **Plaintext check (verified).** `printf '%s\n' test-password | scripts/check-no-plaintext.sh COPY k.p12` on a `cp -a` copy of a fixture state directory: exit 0 in 0.06 s; with the `.p12` copied into the copy: exit 1 and the file
  named on stdout; wrong password: exit 3 and a message.
- **`custodio list` (verified, source).** `crates/custodio-cli/src/list.rs` prints `  kind: <kind>` and no sentence about a weaker key; SPEC acceptance 14 says `custodio list` says it. The page states this and leaves the decision to the approver.
