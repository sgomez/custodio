## F139

Injected TPM and credential failures in the debian13 guest (2026-11-06, systemd 257, mode swtpm, the packaged service). All **verified** by a run of `just e2e-cases debian13 'tpmfail-*'`.

- **Stopping the credential service.** `systemctl stop systemd-creds.socket 'systemd-creds@*.service'` is enough: `custodio import` then fails with `com.rfirma.Custodio1.Error.CredentialsUnavailable`
  and the entry has `CUSTODIO_CAUSE=credentials_unavailable`. `/run/systemd/io.systemd.Credentials` is still listed afterwards (`srw-rw-rw-` root, old timestamp): the socket file stays, so the
  connection is refused, not "missing". `systemctl start systemd-creds.socket` brings it back (new timestamp) and the same import succeeds. No runtime mask was needed; nothing under `/usr`
  or `/lib` is touched.
- **Stale socket.** A socket file made with `bind` and closed (no listener, mode 0666, under `$TPM_DIR`, which the drop-in's `BindReadOnlyPaths=` shows to the unit) is *refused*:
  the TSS logs `Failed to connect to .../stale.sock`, `Cannot connect to swtpm TPM socket`. Result: D-Bus `TpmFailed`, cause **`tpm_device`** (`open.rs`: `EsysSession::open` failing is
  `OpenError::Failed(TpmError::OpenFailed)`). A missing path is "no TPM" and imports as `encrypted-host`.
- **TPM error.** A stub (`e2e/tpmfail-stub.py fail-capability`) in front of the real swtpm that answers `TPM2_GetCapability` with `TPM_RC_FAILURE` (0x101) makes the import fail with
  `TpmFailed`, cause **`tpm_error`** (the TSS logs `Esys_GetCapability ... ErrorCode (0x00000101)` four times: ESYS retries). The stub must proxy `<path>.ctrl` to swtpm and
  `shutdown()` its upstream sockets on exit: with a plain `close()` swtpm kept a control client that was gone and every later `tpm2_getcap` hung (found when `tpm_observe` blocked).
- **TPM lacking RSA, in swtpm mode.** The `tpm-filter` program is mounted only in mode `lacking` (`scripts/test-e2e-tpm-host.sh` checks that), so `tpmfail-stub.py lack-rsa` does the same for
  RSA: `TestParms` of an RSA key answers `TPM_RC_TYPE` on parameter 1 and `GetCapability(ALGS)` leaves RSA out. The import then fails with `CredentialsUnavailable` /
  `credentials_unavailable` (the choice is `encrypted-tpm`, whose credential cannot be made in the container, `docs/findings/F134.md`), with the credential socket up or down.
- **The CLI has no text of its own for these two errors**: it prints `custodio: the service answered with an unknown error (com.rfirma.Custodio1.Error.TpmFailed)` and exits 1
  (`crates/custodio-cli/src/failure.rs`, `Unknown`). The name is in the output, which is what the cases judge; a CLI message is not part of this feature.
- **Time.** A polkit-authorised call takes about 5 s in the guest: a failing import 5-6 s, a successful import or a delete about 5 s more; the drop-in rewrite and service restart are under 1 s.
  The step takes 61 s with 10 `su -l` sessions (the deletes of the keys the step imported run at once in one session at the end).
