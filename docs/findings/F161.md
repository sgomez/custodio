## F161

- The `lacking` profile `e2e/vm/lacking-rsa.json` now has `Commands` = F152's default minus `0x159` (`TPM2_RSA_Decrypt`) **and** `0x15d` (`TPM2_Sign`). In a real `lacking` guest (`vm.sh start lacking`, Ubuntu guest, systemd 259.9, tpm2-tools 5.7, 2026-11-08) the combination keeps everything the project needs, and P-256 lacks `Sign`. **verified**
- `--user` credentials with `--with-key=tpm2` fail in `full` mode too (`Selected key not available in --uid= scoped mode, refusing.`): it is systemd 259's rule, not the profile. `--user` with `--with-key=auto` or `host` works in `lacking`. The probe uses those. **verified**
- No persistent SRK exists in the guest (`0x81000001` → `0x18b`); systemd uses a transient one, so "SRK still ECC" is shown by the working root credential plus the ECC parent, not by a handle. **verified**
- The P-256 expectation stays `encrypted-tpm` in `lacking`; no fallback to `tpm` is needed.
