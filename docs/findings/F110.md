## F110

SPEC open question "How the service uses `systemd-creds` without root": from the service's uid and unit,
which scope and call of `systemd-creds` / Varlink `io.systemd.Credentials` work, is TPM binding available, does
"TPM-bound" mean TPM alone or host plus TPM, how to bind to no PCR, how plaintext avoids a temp file, which errors
mean "credential service unavailable" / "cannot decrypt". Run 2026-11-03 in the six e2e containers (F109 images,
started as `e2e/run.sh` does: `podman run -d --privileged --cgroupns=host --tmpfs /run --tmpfs /run/lock --tmpfs
/tmp`, rootless, vfs; `strace`, `swtpm`, `swtpm-tools`, `tpm2-tools` added at run time) and the dev container
(systemd 257.13, uid 1000, no PID 1 systemd, no `strace`, `swtpm` 0.7.1, `tpm2-tools` 5.7, no `/dev/tpm*`). The
probe is a real unit: shipped `data/custodio.service` minus `Type=dbus`/`BusName=`/`After=`/`Requires=`, plus
`Type=oneshot`, F109's `DeviceAllow=/dev/tpmrm0 rw`, `BindPaths=-/dev/tpmrm0`, `SupplementaryGroups=tss`, a shell
`ExecStart=`; static `custodio` user (`systemd-sysusers`: uid 988/992/992/995/997/968 on debian13, ubuntu2404,
ubuntu2604, fedora44, alma10, arch), full sandbox (`PrivateUsers`, `PrivateTmp`, `ProtectSystem=strict`,
`RestrictAddressFamilies=AF_UNIX`, `SystemCallFilter`, no capabilities). Verified unless marked *inferred*.

### Which scope and call work from the service's uid

In the probe unit, five `--user` targets (same lines, byte counts differ):

| call | result |
|---|---|
| `--user encrypt --with-key=host` / `host+tpm2` / `auto`, then `--user decrypt` | rc=0, equal; id `55b9ed1d38594d43a8319d2ebb332ac6` (host, scoped) for all (no TPM in reach) |
| `--user encrypt --with-key=tpm2` / `null` | rc=1 `Selected key not available in --uid= scoped mode, refusing.` |
| no `--user`; Varlink `scope=system`; `scope=user uid=0` | rc=1 `io.systemd.InteractiveAuthenticationRequired` |
| Varlink `Encrypt` / `Decrypt` `scope=user` | `{"blob":"..."}` / `{"data":"<base64>"}` |

- **`user` scope, own uid, no polkit**: CLI `systemd-creds --user encrypt|decrypt --name=NAME - -` or Varlink
  `Encrypt {"name","text"|"data","scope":"user"}` → `{"blob"}`, `Decrypt {"name","blob","scope":"user"}` →
  `{"data"}`: the same daemon call.
- **`system` scope or another uid needs polkit** (`io.systemd.credentials.encrypt`/`.decrypt`, `auth_admin_keep`,
  `pkaction -a ... -v` on debian13): never used (no cached authorization, no polkit rule for the service). With no
  bus (dev container) it is `io.systemd.System {"errno":2}`.
- **The non-root CLI always uses Varlink**; with no socket: `Failed to connect to io.systemd.Credentials: No such
  file or directory`. It never reads `/var/lib/systemd/credential.secret`.
- **Bound to uid (verified), user name (source: `NoSuchUser`) and machine-id (*inferred*).** uid 65534 decrypting
  the service's credential: `Bad credential format.` / `io.systemd.Credentials.BadFormat`; asking for another
  uid's scope goes to polkit.
- **Host secret unreadable by the service** (`-r-------- root root 4112`, `Permission denied`); the root daemon
  (`systemd-creds@.service`) reads it and mixes it in: after replacing it, decrypt fails (`Failed to decrypt:
  io.systemd.System`; Varlink `{"errno":2}` on 257, `ENOENT` on 259/262); after restoring, works.
- **ubuntu2404 (255):** non-root `--with-key=host`/`host+tpm2` → `Failed to determine local credential host secret:
  Permission denied`; `--with-key=tpm2 --tpm2-pcrs= --tpm2-device=swtpm:path=...` **works** as uid 992 (`setpriv`,
  outside the sandbox). Only TPM-alone without root; nothing without a TPM.

### Key used: TPM alone or host plus TPM, and where the TPM is opened

Varlink has **no key choice before v259 and no TPM choice ever**: `vl_method_encrypt` passes `_CRED_AUTO_SCOPED`
(user) or `_CRED_AUTO` (creds.c v257:1219, v258:1288; v259:1371 reads `withKey`). `auto` = host plus TPM when the
root daemon finds a usable TPM, else host; scoped is never TPM-only (creds-util.c v258:1010). The daemon opens the
TPM; device and PCR mask are its command-line globals (creds.c v259:62, :984); `SYSTEMD_TPM2_DEVICE` only from its
own environment.

- **No TPM reaches that daemon here, so a TPM-bound Varlink credential was not produced (*inferred*, F147).**
  debian13 with `SYSTEMD_LOG_LEVEL=debug` on `systemd-creds@.service`: `System lacks TPM2 support or running in a
  container, not attempting to use TPM2.`; `/sys/class/tpmrm` empty, `systemd-detect-virt -c` → `podman`.
  `tpm2_support()` skips the TPM in a container without `/sys/class/tpmrm` (tpm2-util.c v255:7324, v258:7770); no
  override. `swtpm` (F108 route 2) is a socket, not a kernel device.
- **`withKey` (v259+) is a trap in `user` scope** (ubuntu2604): `withKey=host` → id
  `5a1c6a86df9d4096b1d5a65e0862f19a` (**not scoped**) that the service cannot decrypt (`scope=user` → `BadScope`,
  `scope=system` → polkit); `withKey=null` **succeeds** (id `058469daf6f54324800549da0f8ea2fb`, no encryption);
  `host+tpm2` is not a value (`host_tpm2`; in the container `ENOTRECOVERABLE`). So: never send `withKey`, refuse the
  null id.
- **What "TPM-bound" means** (root CLI, which opens the TPM itself, `--tpm2-device=swtpm:path=<sock>`, from
  `just with-swtpm` or `scripts/with-swtpm.sh`; expectations written first; all decrypt with nothing changed):

  | made with | host secret replaced (expected / observed) | new `swtpm` state (expected / observed) |
  |---|---|---|
  | `tpm2` | **ok** / ok | **fail** / `Esys_Load ... Received TPM Error` |
  | `host+tpm2` | **fail** / `Decryption failed (incorrect key?)` | **fail** / `Esys_Load ...` |
  | `host` | fail / `Decryption failed` | ok / `MARKER` |

  Same on the dev container and all six (arch `Esys_Load.c:314`, others `:324`). `tpm2` is **TPM alone**;
  `host+tpm2` and `auto` with a TPM are **host plus TPM**; `user` scope adds the uid (name and machine-id
  *inferred*). The service's `auto_scoped` is host plus TPM, or host alone.
- **ubuntu2404**: TPM alone as the service uid, rc=0 both ways; anyone who can open the TPM can decrypt it.

### No PCR, explicitly

`systemd-creds encrypt --with-key=tpm2` (root, explicit device, six targets); `pcr_mask` read with `od` of
`base64 -d` at **byte 48** of the header (16-byte id, four `le32`, 12-byte IV padded to 8, `le64 pcr_mask`;
creds-util.c v258:645-672; for a non-TPM id those bytes are IV):

| targets | systemd | default | `--tpm2-pcrs=` (empty) | `--tpm2-pcrs=7` |
|---|---|---|---|---|
| debian13, ubuntu2404, alma10 | 257, 255, 257 | `8000000000000000` (PCR 7; warns `none of the selected PCRs are valid`) | `0000000000000000` | `8000000000000000` |
| ubuntu2604, fedora44, arch | 259, 259, 262 | `0000000000000000` | `0000000000000000` | `8000000000000000` |

**Empty `--tpm2-pcrs=` is the explicit "no PCR", accepted by all six**; `host+tpm2` same mask, same offset. **The
service cannot pass it**: the daemon runs `ExecStart=-systemd-creds` with no argument, so on 255-257 a present TPM
makes `auto` use PCR 7 (`TPM2_PCR_MASK_DEFAULT`, creds.c v257:1032-1033), on 258+ empty (v258:1101-1102); both
*inferred from the source*. Hence: after each `Encrypt` the service reads the header back and **refuses to store a
credential whose mask is not 0, or whose id is the null id**. F147 runs it on hardware.

### Plaintext without a temporary file

`strace -f -qq -s 300 -e trace=execve,openat,creat,connect,write,send,sendto,sendmsg` of `systemd-creds --user
encrypt|decrypt --name=k - -` as the service uid (`setpriv`; `@system-service` refuses `ptrace`), five `--user`
targets: marker in no argv; no file opened for write; two `connect()` to `/run/systemd/io.systemd.Credentials`;
plaintext in via `sendto(3, "{\"method\":\"io.systemd.Credentials.Encrypt\", ...")` (base64 `data`), out via
`write(1, "F110-STRACE-MARKER-1610", 23)`; marker (raw or base64) in `/tmp /var/tmp /var/lib /run /root`: none. The
probe unit's own `grep -rIl --binary-files=text MARKER /tmp /var/tmp /var/lib/custodio /run`: no match, all six.
`ProtectProc=invisible` hides other processes' `/proc`. Remaining exposures: the pipe or socket, and the root
daemon's memory (SPEC threat model). Direct Varlink needs no child or pipe; the reply's `data` is plaintext:
zeroize. `SYSTEMD_LOG_LEVEL=debug` prints `"data":"<sensitive data>"`.

### Errors

Service uid, `--user`/Varlink, debian13, ubuntu2604, fedora44, alma10, arch (two forms: 257 / 259-262):

| case | CLI (rc=1) | Varlink | class |
|---|---|---|---|
| socket missing / stopped | `Failed to connect to io.systemd.Credentials: No such file or directory` | `Failed to open '/run/systemd/io.systemd.Credentials': ...` | **unavailable** |
| ubuntu2404 | `unrecognized option '--user'` | no socket | **unavailable** |
| encrypt, no key (secret on tmpfs, no TPM) | `Failed to encrypt: io.systemd.System` | `io.systemd.System {"errno":2}` | **unavailable** |
| needs polkit | `InteractiveAuthenticationRequired` | same | **unavailable** (not called) |
| TPM unusable at encrypt (259 `withKey=tpm2`) | - | `{"errno":131,"errnoName":"ENOTRECOVERABLE"}` | **unavailable** |
| corrupt, garbage, empty, other uid | `Bad credential format.` | `BadFormat {}` | **cannot decrypt** |
| wrong `--name` | `Name in credential doesn't match expectations.` | `NameMismatch` | **cannot decrypt** |
| blob not base64 | - | `org.varlink.service.InvalidParameter {"parameter":"blob"}` | caller bug |
| host secret changed | `Failed to decrypt: io.systemd.System` | `{"errno":2}` / `ENOENT` | **cannot decrypt** |
| TPM state replaced (root CLI) | `Esys_Load ... Received TPM Error` | not shown; 259+ `KeyBelongsToOtherTPM` etc. | **cannot decrypt** (*inferred*) |
| `withKey=host` blob, `scope=user` | - | `BadScope` | **cannot decrypt** |

The CLI loses the error name; the service should speak Varlink itself and read it (`varlinkctl` is only a test tool).
**Indistinguishable**: on 257 `io.systemd.System {"errno":2}` is "no key" at `Encrypt` and "host secret changed" at
`Decrypt`; at `Decrypt` "TPM unusable / cleared / locked out" vs "key wrong". Conservative mapping: connect failure
or any `Encrypt` error but a caller bug is **unavailable**; any `Decrypt` error is **cannot decrypt**, as a TPM blob
that does not load (SPEC section 3); no signature either way.

### Dev container (no systemd as PID 1), uid 1000

- Unprivileged `systemd-creds --user encrypt --name=k - -` (any `--with-key`, even with
  `SYSTEMD_CREDENTIAL_SECRET`) → `Failed to connect ...`: needs the daemon. `unshare -Urm bash -c 'mount -t tmpfs t
  /var/lib/systemd; systemd-creds encrypt --with-key=host ...'` works (userns root takes the direct path).
- **`--user` and Varlink, real daemon, no root:** `unshare -m --map-root-user --map-users=auto --map-groups=auto`
  (uids 1-998 via `newuidmap`, `/etc/subuid`); inside: `mount -t tmpfs t /run/systemd`; `mount --bind <dir on a real
  filesystem> /var/lib/systemd` (tmpfs gives `no encryption key available`); `systemd-socket-activate -a
  --fdname=varlink -l /run/systemd/io.systemd.Credentials systemd-creds &` (**`--fdname=varlink`**, else `list`
  runs and the client gets `Connection reset by peer`); `chmod 0666` the socket; clients `setpriv --reuid=42
  --regid=42 --clear-groups systemd-creds --user ...` (uid 42 `_apt` resolves; unknown uid: `No such
  user.`). Results match the targets: `host`/`host+tpm2`/`auto` rc=0 (id `55b9ed1d...`), `tpm2`/`null` refused,
  system scope `{"errno":2}`, other uid `BadFormat`, `NameMismatch`, secret replaced `{"errno":2}`, socket removed
  `Failed to connect`, introspect lists `Encrypt`/`Decrypt`. Every error row but the TPM ones.
- **TPM-bound, `swtpm`:** `just with-swtpm unshare -m --map-root-user bash -c 'mount --bind <real dir>
  /var/lib/systemd; systemd-creds encrypt --with-key=tpm2|host+tpm2 --tpm2-device="$TPM2TOOLS_TCTI" ...'`: the "Key
  used" and PCR tables came from here first (a second `with-swtpm` call is the "new TPM").
- **Only on `just e2e-cases`/F147 (kernel TPM):** a Varlink `Encrypt` with the TPM, and its mask. The rest can be
  integration tests with the real `systemd-creds` and `swtpm`, no fake.

Decision: debian13: scope `user` (own uid, no polkit), call the Varlink interface directly (`Encrypt`/`Decrypt` with `name`, `data`, `scope":"user"`, no `withKey`; plain `systemd-creds --user ... - -` is the same call), key `auto` is the daemon's (host+uid, plus the TPM when it finds one); no per-call no-PCR argument exists (`--tpm2-pcrs=` is the daemon's), so the service reads the mask back at byte 48 and refuses a nonzero mask or the null id; Encrypt error or connect failure → credential service unavailable, any Decrypt error → cannot decrypt.
Decision: ubuntu2404: no `--user`, no Varlink; the service can only run `systemd-creds encrypt|decrypt --with-key=tpm2 --tpm2-pcrs= --tpm2-device=<device> - -` itself (TPM alone, non-root, `--tpm2-pcrs=` = no PCR, stdin/stdout); no host-bound form without root; CLI exit 1 text: `Failed to determine local credential host secret` and a missing TPM → credential service unavailable, `Esys_Load` / `Decryption failed` / `Bad credential format` → cannot decrypt.
Decision: ubuntu2604: scope `user`, Varlink `Encrypt`/`Decrypt` directly, never `withKey` (user scope + `withKey` gives an unscoped or null credential); the default mask is empty in 259 (verified with the root CLI, source for Varlink) and the service reads the mask back at byte 48 and refuses nonzero or the null id; Encrypt error or connect failure → credential service unavailable, any Decrypt error (`BadFormat`, `NameMismatch`, `BadScope`, `io.systemd.System`, the TPM names) → cannot decrypt.
Decision: fedora44: as ubuntu2604 (systemd 259.10): scope `user`, Varlink directly, no `withKey`, read-back refusing nonzero mask or null id; Encrypt error or connect failure → credential service unavailable, any Decrypt error → cannot decrypt.
Decision: alma10: as debian13 (systemd 257): scope `user`, Varlink directly, no `withKey` (not in 257); no per-call no-PCR argument, read-back of the mask at byte 48 refusing nonzero or the null id; Encrypt error or connect failure → credential service unavailable, any Decrypt error → cannot decrypt.
Decision: arch: as ubuntu2604 (systemd 262.1): scope `user`, Varlink directly, no `withKey`, default mask empty (source), read-back refusing nonzero mask or the null id (the header ids differ in 262: `d4062dfb...` TPM, `1414258818...` host+TPM, so the id test is a list per version, not a constant); Encrypt error or connect failure → credential service unavailable, any Decrypt error → cannot decrypt.
Deviation: debian13 (systemd 257, `auto` binds to PCR 7 on a machine with a usable TPM and the caller cannot change it; the encrypted fallback is unavailable there when a TPM is present, host+uid-bound otherwise)
Deviation: alma10 (systemd 257, the same)
Deviation: ubuntu2404 (systemd 255: no `--user`, no Varlink, no host-bound credential without root; only a TPM-alone credential, no uid binding, and nothing on a machine without a TPM)
