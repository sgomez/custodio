## F201

Double fingerprint prompt, SPEC open question 5. Run on 2026-11-16 in the ubuntu2604 VM (`e2e/vm/vm.sh start full`, Ubuntu 26.04.1 LTS) with libfprint's virtual sensor of F200 (`FP_VIRTUAL_DEVICE`,
drop-in and enrolled finger as in `e2e/vm/fingerprint.sh`), the text agent `pkttyagent` with `pkcheck` (`e2e/vm/fingerprint-check.sh`, driven by `fingerprint-pty.py`) as user `fpuser`.
Versions (`dpkg-query -W`): polkitd 127-2ubuntu1.1, fprintd 1.94.5-4, libfprint-2-2 1:1.95.1+tod1-0ubuntu2, libpam-fprintd 1.94.5-4, libpam-modules 1.7.0-5ubuntu3.2, custodio 0.8.0-1 (the packaged deb).
The driver was a throwaway script outside the repository: per configuration it runs the three cases below, counts `VerifyStart` in `busctl --system monitor net.reactivated.Fprint` and takes the times from the driver's events.

Conclusions:

- **verified**: `pam-auth-update --enable fprintd` puts into `/etc/pam.d/common-auth` the line `auth [success=2 default=ignore] pam_fprintd.so max-tries=1 timeout=10 # debug`; it was absent after the install of
  `fprintd libpam-fprintd`. `/usr/lib/pam.d/polkit-1` has `@include common-auth` and the image has no `/etc/pam.d/polkit-1`, so the switch alone gives polkit one finger prompt (A).
- **verified**: with the switch and Custodio's file (B) a matching finger gives one prompt and approves; a wrong finger or no touch gives **two** finger prompts, then the password. No touch takes 20 s instead of 10 s.
- **verified**: with the switch and an Omarchy-style file (C) a matching finger is still one prompt; a wrong finger gives **four** prompts (three of the file's line, whose default is `max-tries=3`, then one of `common-auth`),
  no touch takes **40 s** (30 s default timeout of the file's line, then 10 s). The password still approves at the end in B and C.
- **verified**: the file `/etc/pam.d/polkit-1` is read in preference to `/usr/lib/pam.d/polkit-1`, and `common-auth` is reached after the file's own fingerprint line failed: the count of verifications differs from A and D (B wrong 2, C wrong 4, A wrong 1, D wrong 1).
- **verified**: the double prompt costs time only; the fallback to the password and the approval work in every cell, and a matching finger never prompts twice (`success=done` / `sufficient` stop the stack).
- **inferred**: Omarchy prepending its `auth sufficient pam_fprintd.so` to Custodio's file (two `pam_fprintd` lines in one file) is a third combination, not run; it would add the same extra prompts as C. Omarchy's behaviour
  is from `docs/reports/polkit-fingerprint.md` (it prepends to an existing file, or writes a `pam_unix`-only file when there is none, which cannot double the prompt). C is that file adapted to Ubuntu: the `pam_fprintd.so` line plus
  `@include common-auth`, because Ubuntu has no `system-auth`; it is the relevant case since it is what an Omarchy file does where polkit's stack includes `common-auth`.

Table (prompts = finger prompts shown; verifications = `VerifyStart`; time = whole authentication; every cell approved after the password where one was asked):

| configuration | matching finger | wrong finger | no touch |
|---|---|---|---|
| A switch only | 1 prompt, 1 verif., 0.1 s | 1, 1, then password, 0.2 s | 1, 1, password after 10.1 s |
| B switch + Custodio file | 1, 1, 0.1 s | **2**, **2**, password, 0.2 s | **2**, **2**, password after 20.1 s |
| C switch + Omarchy-style file | 1, 1, 0.1 s | **4**, **4**, password after 10.1 s (4th prompt untouched) | **2**, 2, password after 40.2 s (30 s + 10 s) |
| D Custodio file only | 1, 1, 0.1 s | 1, 1, password, 0.1 s | 1, 1, password after 10.1 s |

Evidence (lines of the run). B was reached as real use does: `custodio fingerprint enable` first (D, exit 0, `Wrote /etc/pam.d/polkit-1.`), then `pam-auth-update --enable fprintd`:

```
-- pam (B): auth     [success=done default=ignore] pam_fprintd.so max-tries=1 timeout=10 | auth include /usr/lib/pam.d/polkit-1 | ...
-- common-auth: auth	[success=2 default=ignore]	pam_fprintd.so max-tries=1 timeout=10 # debug
RESULT Bnotouch rc=0 approved=yes VerifyStart=2 total=20.2s
  events: 0.0 start;0.1 prompt-finger;10.1 prompt-finger;10.1 nomatch;20.1 prompt-password;20.1 typed-right;20.1 nomatch;20.2 approved
  agent: Info: Swipe your right index finger across the fingerprint reader / Info: Verification timed out / (again) / Password:
-- pam (C): auth    sufficient    pam_fprintd.so | @include common-auth | @include common-account | @include common-session
RESULT Cwrong VerifyStart=4 total=10.2s     RESULT Cnotouch VerifyStart=2 total=40.2s
```

Decision: `custodio doctor` flags the combination as a warning (it costs time, it does not lock anyone out) when, reading files only (no root, no prompt), `/etc/pam.d/polkit-1` has an uncommented `auth` line with `pam_fprintd.so`
and `/etc/pam.d/common-auth` has an uncommented `pam_fprintd` line (the polkit stack includes it, directly or through `/usr/lib/pam.d/polkit-1`); the fix is `sudo custodio fingerprint disable` when the file is Custodio's
(the global switch already gives polkit a finger, as in A), or, for a file that is not Custodio's, removing its `pam_fprintd.so` line or `sudo pam-auth-update --disable fprintd`; `enable`'s refusal (when `pam_fprintd` is in `common-auth`) stays as it is.
