## F147

M4 acceptance 13 (`docs/manual-acceptance.md` section 20) on a hardware TPM, run by a person on 2026-11-07, driven by a
local script that logged every command (not shipped). Verified unless marked inferred.

Machine: desktop with an AMD firmware TPM (`TPM2_PT_MANUFACTURER` `0x414D4400` "AMD", `TPM2_PT_FIRMWARE_VERSION_1`
`0x30039`), driver `tpm_crb` (`MSFT0101:00`), Secure Boot disabled, firmware in Setup Mode, UEFI capsules not enabled.
Ubuntu 26.04.1, kernel 7.0.0-42-generic, systemd 259.9, polkit 127, tpm2-tools 5.7, fwupd 2.1.1, Firefox 159.0.1 (the
Mozilla team `.deb`, not the snap), LibreOffice 26.2.6.3. `TPM2TOOLS_TCTI` default. Packages: `custodio 0.1.0-1` from
`target/packages` of milestone/m4, upgraded to `0.1.1~rc.1-1` (`just package version=0.1.1-rc.1` at c07d02f).

### Differences from the page

- Firefox on Ubuntu does not load the module through p11-kit: without registration it sent no certificate
  (`s_server`: `peer did not return a certificate`, Firefox `SSL_ERROR_RX_CERTIFICATE_REQUIRED_ALERT`).
  `modutil -force -dbdir sql:<profile> -add custodio -libfile /usr/lib/custodio/libcustodio_pkcs11.so` per profile
  fixes it (as M01-acceptance found for the Mozilla `.deb`); section 11's "no manual registration" is Fedora's.
- Firefox asks twice per key: two TLS handshakes, two `Sign` calls, a polkit dialog for each (no cached
  authorization, as the spec requires). For `p256` the second ended `denied` every time with polkit's
  `FAILED to authenticate` (dialog dismissed); the page loaded on the first.
- LibreOffice: one dialog per signature; `MOZILLA_CERTIFICATE_FOLDER` pointed at the NSS database of section 6.
