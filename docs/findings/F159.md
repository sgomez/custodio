## F159

The unpacked `swtpm` 0.10.2 (the four forky `.deb` files of F152, `dpkg-deb -x` into a new directory, not installed), run by hand in the dev container, 2026-11-08, user `dev`.

Conclusion:
- Unpacked with `dpkg-deb -x` it runs only with **both** library directories on `LD_LIBRARY_PATH`: `usr/lib/x86_64-linux-gnu/swtpm` (for `libswtpm_libtpms.so.0`) and `usr/lib/x86_64-linux-gnu` (for `libtpms.so.0`). With only the second: `symbol lookup error: undefined symbol: g_mainloop_terminate` (the 0.7.1 `libswtpm_libtpms` from the system is found first). **verified**
- The profile `e2e/vm/lacking-rsa.json` (default `Algorithms` as `--print-info 0x08` prints them, `Commands` of F152 without `0x159`) is accepted at `PTM_INIT`: `swtpm_ioctl --unix c.sock -i` → exit 0. **verified**
- A restart on the same state directory **with** `--profile` fails at `PTM_INIT` (`TPM result from PTM_INIT: 0x9`, exit 1); a restart on that state **without** `--profile` succeeds (exit 0). The profile is kept in the state, so a power cycle starts `swtpm` without it. **verified**
- `swtpm_ioctl` takes the socket as `--unix <path>` (`-i` init, `-s` shutdown); `-s` ends the daemon. **verified**

Evidence (`x` is the unpacked tree, `P=$PWD/x/usr/lib/x86_64-linux-gnu`, `export LD_LIBRARY_PATH=$P/swtpm:$P`):
```
$ x/usr/bin/swtpm socket --tpm2 --profile file=e2e/vm/lacking-rsa.json --tpmstate dir=st --ctrl type=unixio,path=c.sock --daemon --pid file=p.pid --terminate
$ x/usr/bin/swtpm_ioctl --unix c.sock -i; echo $?                  0
(same command again on st, with --profile)  swtpm_ioctl -i  →     TPM result from PTM_INIT: 0x9   (exit 1)
(same command again on st, without --profile)  swtpm_ioctl -i →    exit 0
```
