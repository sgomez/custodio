# F174 — The peer label parser, with its fuzz target

## Scope
Builds a pure function in custodiod (a new module next to `snap_socket`, public so the integration
test and the fuzz crate reach it) that takes the `SO_PEERSEC` bytes and the snap the socket is for
and returns accept or a refusal reason. Accept means exactly `snap.firefox.firefox (enforce)`: the
one profile F171 decided (`docs/findings/F171.md`, Decision lines: only the browser app; the
geckodriver app, the four hooks and every other snap are refused), then ` (enforce)`, and nothing else.
The kernel appends a trailing NUL to some `SO_PEERSEC` values; whether one final NUL is tolerated is
the builder's call, decided by what the kernel returns (a step checks it) and recorded in a test.
Any other NUL, anywhere, is refused. The reasons are a closed enum with a stable display text, one
per refusal class (empty, embedded NUL, SELinux context "not a snap label", stacked, child profile,
complain or unconfined mode, another snap or app, extra text, not UTF-8 or other malformed bytes).
An SELinux context is recognised without being parsed as a snap label.

Left for other features: reading `SO_PEERSEC`, `SO_PEERCRED` and `SO_PEERPIDFD` from a connection,
the per-connection peer check, the test label source, and refusing before any method (F175, which
proves the peer-level half of acceptance 2: missing pidfd, missing label, root included). The parser
is not called from the service yet.

Mutation: `just mutants-diff F174` runs in `verify`; the parser is small, so the table tests must
kill every mutant in it (no new mutant sets are built here).

Cost of the new tests (estimates from `app_id` and the other integration tests):
- `crates/custodiod/tests/peer_label.rs`: pure unit-level cases, parallel with the other integration
  tests, well under 1 s once built. No sleeps, no I/O.
- Fuzz target `peer_label`: one more entry in `fuzz-smoke` (2000 runs, fixed seed), about 1 to 2 s plus
  an incremental build of the fuzz crate (the other nine targets already take that today). It runs
  in sequence with the other targets as `fuzz-smoke` already does. `fuzz-build` and `lint-fuzz` pick
  it up by scanning `fuzz/Cargo.toml`; no recipe change beyond the expected list.
- No e2e case, no script test: nothing here depends on the distribution.

Environment: nightly and cargo-fuzz are in the dev container (the other targets build with them); the
step that runs `just fuzz-build`, `just lint-fuzz` and `just fuzz-smoke` shows it. Each is one
command and is well inside one session.

## Evidence
- Accepts `snap.firefox.firefox (enforce)` for the firefox socket → `cargo test -p custodiod --test peer_label --locked` (accept case) → returns accept.
- Accepts only that one profile of the snap: `snap.firefox.geckodriver (enforce)`, `snap.firefox.hook.install (enforce)` → same test → refused as another app of the snap, per F171's decision.
- Another snap (`snap.chromium.chromium (enforce)`, `snap.firefoxx.firefox`, a prefix or suffix of the right name, case changes) → same test → refused as another snap.
- Stacked (`snap.firefox.firefox//&unconfined (enforce)`, any `//&`) → same test → refused as stacked.
- Child profile (`snap.firefox.firefox//child (enforce)`) → same test → refused as child profile, a different reason from stacked.
- Complain and unconfined (`snap.firefox.firefox (complain)`, `unconfined`, `snap.firefox.firefox (unconfined)`, a missing mode, `(enforce)` in another case or with other spacing) → same test → each refused with its reason.
- Extra text (leading or trailing space, newline, a second label, text after `(enforce)`) → same test → refused as extra text.
- Embedded NUL (at the start, in the middle, before the mode, two trailing NULs) and empty input → same test → refused with their own reasons; the trailing-NUL rule fixed by the second step is asserted both ways.
- SELinux context (`unconfined_u:unconfined_r:unconfined_t:s0`, with `-s0:c0.c1023`, `system_u:system_r:...`) → same test → refused as "not a snap label", asserted to be a different reason from "another snap"; and a context that contains `snap.firefox.firefox (enforce)` as a substring is refused.
- Non-UTF-8 and over-long input → same test → refused without panic and without unbounded text in the reason.
- Parser fuzzed, and the fuzz target can fail without a crash → `just fuzz-build && just lint-fuzz && just fuzz-smoke` → all targets build and run, and `peer_label` is in the expected list; the target asserts that accept implies the input is exactly the accepted label (with the permitted trailing NUL), so a lenient parser fails it. Negative control: `just fuzz-smoke "peer_label_missing"` fails with "missing or did not run" (run once by the builder, not added as a test).
- Tests can fail (no weak mutants) → `just mutants-diff F174` → no surviving mutant in the new module.
- Nothing else regressed → `just quick` → green.
