# F40 — Cross-check that the caller's pidfd and pid name the same process

## Scope
F39 already built the cross-check (`check_pidfd_info`, called as `check_pidfd_info(&info, caller.pid)?`
in `caller_from`, `crates/custodiod/src/credentials.rs`; it reads the `Pid:` line of
`/proc/self/fdinfo/<fd>`). `docs/findings.md` M1.2 cites the kernel source showing that this read works
under `ProtectProc=invisible`/`ProcSubset=pid`/`PrivateUsers=yes`, so the first branch of the feature
applies: the cross-check stays, `data/custodio.service` is not loosened, and no `docs/decisions.md` entry
is written. This feature does not re-implement it. It proves the points F39 tested only in part.

Already in F39 and not counted as new: `sign_refused_with_pidfd_of_another_process` (`tests/audit.rs`,
constant checks through `refused_for_process_fd`), `pidfd_of_another_process_is_refused`,
`process_fd_that_is_not_a_pidfd_is_refused` (a `/dev/null` fd: fdinfo without a `Pid:` line, which is the
unreadable-fdinfo evidence) and the pure parser test in `credentials/tests.rs`, the missing-`ProcessFD`
journal wire test, and `tests/fd_leak.rs` for the success path.

New here:
- mismatch refused *exactly like* missing `ProcessFD`: the two cases are compared with each other (D-Bus
  error name and message, `asked()`, the whole journal entry), not each against constants;
- the exited-and-reaped form gets evidence at both levels; the journal wire test uses a mismatching pidfd;
- fd-leak coverage of the mismatch and reaped paths;
- the unit and the threshold are unchanged, and a check fails if either is loosened, including by a
  duplicate setting line;
- every new test is shown to fail without the cross-check call.

Not tested, stated honestly: the dev container cannot mount a `hidepid=invisible,subset=pid` `/proc`
(`mount -t proc` fails with "Mount too revealing" because other mounts cover `/proc` paths) and has no
systemd as PID 1, so **the cross-check is not exercised under the unit's hardened `/proc` view by any
`verify` command**. Its evidence for that is the cited kernel source in M1.2 plus the unit-settings check
below, which pins the settings M1.2 was written for. A systemd-run case in the e2e guest is possible
future work but is outside this feature; a dev-container change would be BLOCKED.md, not a step.

Mismatch forms (all `CredentialsError::Missing`). `ProcessID` in each case is the test process's own
pid (`std::process::id()`) unless stated:
1. pidfd of another live process (the test's parent), `ProcessID` = own pid;
2. pidfd of a child that has exited **and been reaped** (`wait()` before the read): fdinfo shows
   `Pid: -1`; `ProcessID` = that child's old pid (so the result does not depend on `-1` simply differing
   from own pid: also covered by a case with `ProcessID` = own pid);
3. unreadable fdinfo: the existing `/dev/null` test. A `ProcessFD` naming a closed fd number is dropped:
   it cannot be built under `#![forbid(unsafe_code)]` (a zbus `Fd` needs `BorrowedFd::borrow_raw`, and an
   `OwnedFd` in the map stays open).

A zombie (exited, not reaped) still shows its real pid and is **accepted**. One unit test records this as
current behaviour; refusing it would need `PIDFD_GET_INFO` or `/proc` access, and a later stricter feature
may change the test.

Size: five steps. Left for other features: passing the pidfd to polkit, the security label,
`PIDFD_GET_INFO`.

## Steps
- [x] Unit tests in `credentials/tests.rs`: reaped child's pidfd with `ProcessID` = child's old pid →
      `Missing`; same with `ProcessID` = own pid → `Missing`; zombie child's pidfd with `ProcessID` = child
      pid → `Ok` (current behaviour, commented as such).
- [x] Integration tests in `tests/audit.rs`, using a shared helper that runs a Sign with a given
      `ProcessFD` edit and returns the D-Bus error (name and message), `asked()` and the entry: (a)
      `mismatch_is_refused_identically_to_missing_process_fd`: parent's pidfd (`ProcessID` = own pid)
      versus no `ProcessFD` (`ProcessID` = own pid), same fixture type → equal error name, equal message,
      both `asked()` empty, entries equal as a whole (`Entry` equality or all accessors, timestamp
      excluded); (b) the same comparison with a reaped child's pidfd, `ProcessID` = own pid; (c)
      `mismatching_pidfd_reaches_the_journal_as_authorization_unavailable`, a copy of the missing-`ProcessFD`
      wire test using the parent's pidfd: one datagram with `CUSTODIO_OUTCOME=authorization_unavailable`,
      then a nonblocking `recv` shows no second datagram.
- [x] Extend `tests/fd_leak.rs` with the mismatch (parent's pidfd) and reaped-child paths: `/proc/self/fd`
      count equal before and after. It runs under `just test` (`cargo test --workspace`), not
      `test-integration`.
- [x] Add `unit-hardening` to `system-gates` in `justfile` (so `just check` runs it) calling
      `scripts/check-unit-hardening.sh`: asserts `data/custodio.service` has `ProtectProc=invisible`,
      `ProcSubset=pid` and `PrivateUsers=yes`, **each exactly once**, and that the
      `security-score threshold="10"` default, read from the `justfile` line, is 10 (and fails if it cannot
      parse it). Add `scripts/test-check-unit-hardening.sh`, wired into `shell-scripts-test`, with fixtures:
      the real files pass; `ProtectProc=default`, `ProcSubset=all`, `PrivateUsers=no`, each line missing, a
      duplicate `ProtectProc=default` appended after the real line (also for `ProcSubset` and
      `PrivateUsers`), and a justfile with `threshold="11"` each fail.
- [x] Remove the `check_pidfd_info(&info, caller.pid)?` call at `credentials.rs` by hand (cargo-mutants
      does not delete statements, so no mutant covers it), run the new tests and `tests/audit.rs`, and
      record in PROGRESS.md the exact list of tests that fail; every new test from steps 1–3 that exercises
      a mismatch must be on it. Restore the call. Then run `just check`, `just test-integration` and
      `just mutants`.
