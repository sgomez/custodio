# F206 — Checkpoint: the command line, the defects of 0.8.0, the fingerprint command, doctor and completions

## Scope
Almost nothing is built. This feature runs the suites of its `verify` on the work of F189–F205 and fixes whatever fails, at
its cause, under the earlier checkpoints' rules: no `#[ignore]`, no lowered threshold, no `#[allow]` without a justification, no
recipe turned into a no-op, no guard loosened, no case changed except where the case is wrong, no skip added without a stated
and evidenced reason, no edit of `budgets.tsv`. The `verify` is
`just check && just api-contract && just fuzz-smoke && just memory-safety && just e2e && just package-gates && just coverage-gate`;
the loop runs it whole, a builder session never does. No new test, script, case or e2e target is added (no new cost). A fix may add
a regression test at the cheapest level that catches its cause and says what it costs in `PROGRESS.md`.

**Left to F209, not proven here:** the VM suite (`just e2e-vm full|lacking`), so the `vm-fingerprint-*` group of F200 and
SPEC acceptance 18 and 19 are not run in this feature. Acceptance 20-and-later prose items are a person's.

**What the checkpoint proves, and where** (each earlier feature's own tests already ran at its cheap level; this is the first run
of the expensive ones on the work of F189–F205):
- `just check`: lint, every unit and integration test (the help, output-rules, cert text, list view, import split, storage stability,
  fingerprint, doctor and completions test binaries), system gates, and `package-gate-test`, `shell-scripts-test` and `test-scripts`
  (among them `test-check-packages-pam.sh`, `test-check-packages-completions.sh`, `test-check-parity.sh`, `test-e2e-fingerprint.sh`,
  `test-e2e-doctor.sh`, `test-check-fixture-seams.sh`). Completion tests drive real bash, zsh and fish (F192/F205). A red test is run alone first.
- `just api-contract` (the F196 storage addition, F195 import errors). `just fuzz-smoke`: its default list must equal the fuzz targets
  that exist (18 today: `cargo fuzz list` on each fuzz crate; `cli_args`, `cert_fields`, `pam_file`, `journald_conf` are the new ones of M7);
  a target the list lacks is added to it.
- `just memory-safety` (Miri, ASan, fuzz build, `lint-fuzz`) on the code of F193–F205 (help, escaping, doctor, journald and PAM
  parsers, `__key-ids`).
- `just e2e` with `E2E_TPM` unset: alma10, arch, debian13, fedora44, ubuntu2604 with `swtpm`, and debian13 also with `none`: six
  records. New in this milestone and first run together here: the seven `fingerprint-*` and eleven `doctor-*` ids of `e2e/cases.list`
  and the per-target ones (`fingerprint-pam-auth-update` on debian13/ubuntu2604; `fingerprint-selinux-label`, `fingerprint-authselect`
  on fedora44/alma10). F199 requires none of them skipped on any target (acceptance 17). Every case id owed is accounted for exactly once.
  Old `target/e2e/` records of other targets are removed before counting.
- `just package-gates` (package, parity, glibc ceiling, snap base fit, package lint): the real packages hold no PAM file and no script
  naming `/etc/pam.d` (acceptance 5, F198's check on real packages), the three completion files at the F191 locations and the two
  zsh parity exceptions (acceptance 12, package part), and the install notice. A lint list entry only with a reason and only for a finding that is not a defect.
- `just coverage-gate` (`coverage`, then `crap`) at unchanged thresholds over the code of F189–F205.

**Environment, checked while writing this contract (2026-11-16, dev container):** `podman info` exit 0; the five target directories
exist under `e2e/targets/`; `target/e2e/` holds records of an earlier run for the five targets (old); `e2e/cases.list` has 7
`fingerprint-*` and 11 `doctor-*` ids; zsh 5.9, fish 4.0.2 and bash-completion are present (F205). If podman, the network or an image
is gone, that is `BLOCKED.md`, not a reason to skip a target or case. If podman lost its pause process,
`timeout 120 podman system migrate` is the known remedy.

**Time and budgets** (`budgets.tsv`, set by a person; the builder compares and never edits):
- `just check`: ~10–15 min cold; skipped on an unchanged tree through `target/check-ok` (`CHECK_FORCE=1` forces it).
- `just e2e`: six records at once, wall = the slowest, which is debian13 (row 800 s; alma10 540, fedora44 570, arch 480, ubuntu2604 530).
  M7 added about 18 cases to every target: doctor group 18 s and fingerprint group measured per target in F199/F204 (`doctor-*` 18–74 s
  wall alone, mostly image and setup shared with the run). The builder compares each record's wall time with its row; a target over its row is a
  `BLOCKED.md` request with the measured time after the other steps are done; no case is removed or skipped to fit.
- `just package-gates`: the lifecycle scripts have their own rows (`script *` 120 s, others up to 250 s); `test-check-packages-completions.sh`
  (~1 s) and the other new script tests sit under the 120 s default. A script over its row is reported the same way.
- `just coverage-gate`: run as `just coverage` then `just crap`, one per command, `timeout 1700`; the builder records both times.
- Limits: a command runs at most 30 min and a session 45 min. `just e2e`, `just memory-safety`, `just package-gates` and each coverage half get a
  command of their own with `timeout 1700`. No step runs the whole `verify`. A failure fixed here may take more than one session; a step
  stays ticked only if its evidence passed on the final tree.

## Steps
- [x] Baseline, host side: `just check` (a red script test is run alone first), `just api-contract`, `just fuzz-smoke`. Fix each failure at its cause,
      one commit per fix. Compare the `fuzz-smoke` default list with `cargo fuzz list` of every fuzz crate.
- [x] `timeout 1700 just memory-safety`; fix every finding at its cause (a Miri or ASan report on M7 code is a defect, not a list entry).
- [x] Container end-to-end: environment checks above; clear old records; `timeout 1700 just e2e` once (six records at once); fix every failing case,
      set-up or accounting error at its cause; note the six results, the `fingerprint-*` and `doctor-*` ids run per target, and wall times against `budgets.tsv` in `PROGRESS.md`.
- [x] `timeout 1700 just package-gates`; fix every finding. Note lifecycle script times against their rows.
- [x] `timeout 1700 just coverage`, then `timeout 1700 just crap` (each its own command); fix every finding with a test of the behaviour, not by lowering a threshold.
- [x] Final: after the last fix, rerun what ran before it (one per command), from a `target/e2e/` cleared of old records; recount the Evidence records;
      run `just quick` once. `BLOCKED.md` for budget rows only after every other step is ticked, with the measured times.
