# F135 — End-to-end cases: no plaintext key in the state directory

## Scope
New cases `noplain-*` for SPEC acceptance 3: after each import of an RSA 2048 and of a P-256 `.p12`, `scripts/check-no-plaintext.sh`
(F127; password on stdin) run on the service's real state directory in the debian13 container finds none of the encodings of that
key, and no file in the directory holds an unencrypted private key. The cases run in all three modes (`swtpm`, `none`, `lacking`),
because the stored form differs by mode. The script itself, its encodings and its negative controls are F127's (`no_plaintext`
integration target and `scripts/check_no_plaintext.py`); they are not re-proven here, only run against the real service.

- **Kinds reached.** `swtpm`: `tpm` for both keys. `none`: `encrypted-host`. `lacking`: `tpm` (the F131 filter; the deviation in
  `SPEC_DEVIATIONS.md` for F134 says no container can give `encrypted-tpm`). So `encrypted-tpm` is **not** exercised end to end:
  it is covered by F127's `no_plaintext` test under every kind. The builder extends the F134 deviation entry (and the amendment
  here) to F135, with the finding it already cites (`docs/findings/F134.md`), and the evaluator approves it. The cases read
  `ListKeys` for their own two keys and expect the mode's kind exactly (a wrong kind fails the case, so the run is not vacuous);
  they do not judge the kind otherwise (F133/F134 do).
- **Cases** (each reported exactly once, all `run` in every mode, none skipped; "report as skipped in a mode they do not apply to"
  holds vacuously and is deliberate): `noplain-rsa` (the script on the state directory right after the RSA import: exit 0),
  `noplain-ec` (the same after the P-256 import, the RSA key still stored), `noplain-no-key-file` (no file under the state directory is
  an unencrypted private key: no PEM `PRIVATE KEY` header other than `ENCRYPTED PRIVATE KEY`, and no file that `openssl pkey` /
  `openssl rsa` / `openssl ec` read as a key without a password, DER or PEM; the files that exist are listed in the run log).
  Each check runs after its own import, before any later step touches the state. The builder may add one; every id matches `noplain-*`.
- **Placement.** Ids in `e2e/targets/debian13/cases.list` (outcome depends on TPM/kind), not in `e2e/cases.list`, none in `skip.list`;
  `check-cases.sh` rejects a `noplain-*` skip in any mode (the F134 pattern); `select.sh` gets a group `noplain` (today they would fall
  to `user`), run after the `sign` step with keys of its own, deleted at the end, so counts and state seen by other steps are unchanged.
- **Where the script runs.** `scripts/` is not mounted in the container (only `e2e/`, docs and a source file). Step 1 decides how the
  script reaches the guest (a read-only mount in `e2e/run.sh`, or a copy under `e2e/` that a host test shows is identical) and
  confirms `openssl` and `python3` in the image. The script is run unchanged; its exit code 0 is the pass, 1/3 fail the case.
- **Negative controls** (host-side, in `scripts/test-e2e-noplain.sh`, no container): the no-key-file judgement rejects a directory
  with a planted unencrypted PKCS#8 PEM, a PKCS#1 PEM, a DER key and a `.p12` read without password, and accepts one that holds only
  an `ENCRYPTED PRIVATE KEY` and opaque files; the judgement rejects a kind that is not the mode's (an `encrypted-tpm` under `swtpm`, a
  `tpm` under `none`). One guest control per run: the script is run on a **copy** of the state directory with the key's PKCS#8 DER
  planted and must exit 1 naming the file (never the live directory, never left behind), showing the script works in the container.
- **Not here.** Signing (F134), kinds in the CLI/journal (F133, F138), duplication (F136), PCR (F137), the F127 encodings' own
  controls. Full `just e2e`, other targets and package gates are proven at the checkpoint.
- **Environment.** swtpm 0.7.1 and all three modes already run in this container for debian13 (`docs/findings/F131.md`, F134 runs).
  Step 1 confirms with one run of the first case in `lacking`.
- **Cost.** Host test `scripts/test-e2e-noplain.sh`: under 5 s (planted-file cases run in parallel; script default budget 60 s),
  in the justfile script-test list, parallel with the others. Guest: two imports (as alice with the test agent, ~2–4 s each, as F134),
  three runs of the script (each about ten `openssl`/`python3` calls over a state directory of a few files: estimated 1–3 s) plus the
  planted-copy control and the no-key-file scan: about 10–20 s per mode on top of shared setup; it adds no new container. The
  checks are independent of each other and run at once (background jobs joined with `wait`), but the two script runs follow their own
  imports. Waits are on the agent's `registered` line, no fixed `sleep`. Each `just e2e-cases debian13 'noplain-*'` run is
  estimated 1.5–3 min (shared setup dominates; F134's was 50–70 s); the three `verify` runs are separate commands. The full debian13
  `swtpm` run (budget 430 s, measured 360 s) grows by the same 10–20 s; if the measured full run passes the budget the builder asks in
  BLOCKED.md. No `budgets.tsv` change expected.
- Size: five steps, one session each at most.

## Evidence
- After each import under each kind, none of the encodings of the key are in the state directory → `noplain-rsa`, `noplain-ec`
  (`just e2e-cases debian13 'noplain-*'` in `swtpm`, `E2E_TPM=none`, `E2E_TPM=lacking`) → `scripts/check-no-plaintext.sh` exits 0 on the
  real state directory with the key's own `.p12` and password, run after that import; the case log names the kind found.
- The run is not vacuous: the script detects a leak in the container → the planted-copy guest control (inside the same cases) → exit 1
  naming the planted file; the live state directory is untouched (listing before and after equal).
- The kinds are the ones the mode gives, so "each kind" is what was run → the kind check in each case, and the host test feeding the
  judgement a wrong kind → accepted only for `tpm`/`tpm` (`swtpm`, `lacking`) and `encrypted-host`/`encrypted-host` (`none`).
- `encrypted-tpm` → not run end to end (deviation, extended to F135) → F127's `cargo test -p custodiod --test no_plaintext` covers it; part of `just quick`.
- No unencrypted key file exists → `noplain-no-key-file` → no file in the state directory is a readable private key without a password
  or carries a non-encrypted `PRIVATE KEY` header; host test rejects each planted form above and accepts the encrypted-only directory.
- Run in all three modes, none skipped → `scripts/test-e2e-noplain.sh` (host) and the three `verify` commands → ids in the debian13 list
  and not in `e2e/cases.list` or `skip.list`; a `noplain-*` skip is rejected in each mode; each `just e2e-cases` exit 0 with the
  listed cases `run`.
- State left as found → the cases' deletes → both keys absent from `ListKeys` afterwards; later steps in the same run still pass (full run at the checkpoint).
- `just quick` green and the `verify` command → exit 0.
