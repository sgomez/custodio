# F133 — End-to-end cases: TPM kind on import, list and journal

## Scope
New cases `tpm-kind-*` for SPEC acceptance 1: with `swtpm`, an RSA 2048 and a P-256 `.p12` imported with `custodio import`
get kind TPM, and the kind shows in the import result (the CLI's output), in the API's list (`ListKeys`, which returns the
kind per key) and in `custodio list`, and the import journal entry names the kind (`CUSTODIO_STORAGE_KIND`). Cases, one per
requirement and key type where the outcome can differ: `tpm-kind-import-rsa`, `tpm-kind-import-ec` (import output),
`tpm-kind-api-list`, `tpm-kind-cli-list` (both key types in one case each), `tpm-kind-journal` (the import entry of each key).
The builder may add a case; every case id matches `tpm-kind-*` and is reported exactly once.

- **Placement.** The feature text says `e2e/cases.list`; SPEC ("End-to-end scope") and the session rules put a case whose
  outcome depends only on the TPM or the key kind on debian13, and `verify` runs debian13 only. So the ids go in
  `e2e/targets/debian13/cases.list`, not in the every-target list. Running them on five distributions would test nothing
  the debian13 run does not (the kind is chosen by the service and the TPM, not by the distribution).
- **Skipped where they do not apply.** They run only with `E2E_TPM=swtpm`. In `none` (debian13 runs it, `tpm-none` marker) and
  `lacking` the guest reports each as `skipped` through `case_skip`, with a reason naming the mode, and the ids are on
  `e2e/targets/debian13/skip.list`. (Kinds under `none` and `lacking` are proven by later features, not here.) No other
  target lists them, so none reports them.
- **Own imports.** The shared setup imports `rsa1`/`ec1` and discards the output, and other cases count agent requests and
  journal windows. So these cases import their own two keys (an RSA 2048 and a P-256 `.p12`, made by the existing fixture
  generator or equivalent; the test asserts the key size and curve of the fixtures), as alice in one session with the test
  agent approving, in a separate agent state directory like `import-user.sh`, and delete them afterwards, so the state, the
  agent counts and the audit counts the other steps read are unchanged. They run before the steps that read those counts
  or after them without disturbing them; the builder picks the place and `select.sh` gets a group for `tpm-kind-*`
  (today `tpm-*` maps to the group reported at the end of the guest, which does not fit).
- **Reuse, not repeat.** The refusal/approval of import by polkit (F92), the generic journal fields of every operation (F94),
  and the CLI's wording about weaker kinds (F-earlier unit tests) are proven elsewhere; here only that the kind is TPM. The
  no-plaintext, duplication and PCR checks and signing under each kind are other features (F134 and later).
- **Environment.** `swtpm 0.7.1` and the TPM modes already work in the debian13 container (`docs/findings/F131.md`, `just e2e-cases
  debian13 pkcs11-tool-approve-rsa` ran in all three modes at F131). The builder confirms by running the first case before
  writing the rest. The journal is read inside the container with `journalctl` as root, as `journal-check.sh` does.
- **Cost.** Host-side self-tests (the judging functions on good and bad evidence, `scripts/test-e2e-*.sh` style, no container):
  well under 5 s, run in parallel with the other script tests. In the container: 2 imports and 2 deletes through polkit, a
  `ListKeys` call, `custodio list` and one `journalctl` query, estimated 10–20 s on top of the debian13 setup (the shared
  setup is the cost of `just e2e-cases`, about 2–3 minutes; the whole debian13 `swtpm` run is 360 s, budget 430 s in `budgets.tsv`). The cases add
  no new container and no wait on a fixed `sleep`: the agent is awaited on its `registered` line as `import-user.sh` does. The
  cases are in the debian13 list only; the `none` run only reports skips (no extra time). No budget change is needed; if the
  measured debian13 `swtpm` time passes 430 s the builder asks in BLOCKED.md.
- Proven at the checkpoint, not here: the full `just e2e` in both modes (F132 passed; the next checkpoint reruns it).

## Evidence
- Import result names TPM for both types → `tpm-kind-import-rsa`, `tpm-kind-import-ec` (`just e2e-cases debian13 'tpm-kind-*'`)
  → the CLI output of each import says `Storage: tpm` and neither says `weaker`; the fixture check shows the first key is
  RSA with a 2048-bit modulus and the second is EC on P-256, from `openssl`, not from the file name.
- API list → `tpm-kind-api-list` → a `ListKeys` call as alice returns both new ids, each with its key type (`rsa`/`ec` as
  docs/api.md names them) and kind `tpm`; no other kind appears for these ids.
- `custodio list` → `tpm-kind-cli-list` → the line of each new id shows kind `tpm` (exact column/word, not `encrypted-tpm`).
- Journal → `tpm-kind-journal` → in the journal window of the two imports there is exactly one `import` entry per key, outcome
  success, `CUSTODIO_KEY_ID` the key's id, `CUSTODIO_STORAGE_KIND=tpm`; and no entry for them has another kind.
- Cases listed and skipped by mode → `scripts/test-e2e-tpm-kind.sh` (host, new) and `E2E_TPM=none just e2e-cases debian13
  'tpm-kind-*'` once → ids are in the debian13 list and its skip list; in `none` every `tpm-kind-*` is reported `skipped` and
  the accounting (`check-cases.sh`) passes; in `swtpm` each is reported `run` exactly once.
- No skip under `swtpm` → `scripts/test-e2e-tpm-kind.sh` (host) → `check-cases.sh` takes the skip list per target, so a `tpm-kind-*`
  case reported `skipped` in a `swtpm` run would pass the accounting; the run (the guest, or the accounting made mode-aware) must
  fail on it, and the host test feeds it an `swtpm` output with such a skip and expects a rejection. Control: the same output
  under `none` is accepted.
- State left as found → the same cases → both keys are deleted at the end (`ListKeys` lacks them), and the request count of
  `$WORK/agent` and the audit totals the later steps check are unchanged (those steps still pass in the same run).
- Negative controls, each must fail: (1) the judging functions on a list whose kind is `encrypted-tpm`, on one with kind
  `encrypted-host`, and on a journal entry without `CUSTODIO_STORAGE_KIND` or with another kind (host test, no container);
  (2) one run of the case with the drop-in pointing at no TPM (`E2E_TPM=none` with the skip bypassed in a throwaway copy) shows
  the case fails with `encrypted-host`, then the copy is discarded; (3) a fixture swapped for a 3072-bit key is rejected by the
  fixture check.
- `just quick` green and the `verify` command → exit 0.
