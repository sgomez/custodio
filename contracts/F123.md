# F123 — `custodio import` and `custodio list` show the storage kind

## Scope
The `custodio` CLI prints the storage kind (SPEC section 7, "CLI"). F119 already carries the kind on the bus and in
`custodio-client::Kind`; `crates/custodio-cli/src/bus.rs` reads it and drops it today.

- **Import.** The `Importer` seam returns the key type and the kind (a `custodio_client::Kind`, parsed from the wire string;
  the CLI defines no kind type of its own and does not depend on `custodiod`). The import message names the kind. For
  `tpm` it says only that the key is in the TPM and cannot be copied. For `encrypted-host` it says plainly that the key is
  weaker than a TPM key and why: this machine has no TPM, so the key is a file encrypted with the host key, which root and
  anyone with a copy of `/var/lib` can use. For `encrypted-tpm` it says the same (weaker) and why: the TPM lacks a
  capability the key type needs, so the key is a file encrypted with a key bound to this TPM, which root can use while the
  machine runs. For a kind the client does not know (`Kind::Unknown`) it prints the kind's text, escaped for the terminal
  like every other service text, and says the CLI does not know what it protects against; it does not claim "weaker" or
  "stronger". The "delete the original file" reminder stays and still appears only after the service accepted the import.
- **The reason is derived from the kind alone.** The import result carries no list of missing capabilities, and changing the
  API is not part of this feature. So for `encrypted-tpm` the text says the TPM lacks something the key needs and points
  to `docs/api.md` ("TPM capabilities") for what a key type needs; it does not invent a capability name and does not
  suggest the journal says which item is missing (the journal records only the kind). This is the narrowest reading of "the TPM lacks the named capability" that the existing API
  supports; if the evaluator reads it as requiring the item name on the wire, that needs a new feature (API change) and
  the builder must write `BLOCKED.md` rather than guess.
- **List.** Each block of `custodio list` gets a `kind:` line with the kind's wire string (escaped), next to `type:`. A weaker
  kind is not repeated with the long explanation there; `kind:` plus the wire string is enough, and an unknown kind is
  shown as its escaped text.
- **PKCS#11, daemon, API, docs/api.md, journal:** unchanged. Left to the checkpoints: a real `custodio` run against a real
  service (e2e).

## Evidence
- Import says the kind, TPM → `storage_kind::import_tpm` → output names `tpm`, says the key stays in the TPM, contains
  neither "weaker" nor a reason line; the delete reminder follows.
- Import, no TPM → `storage_kind::import_encrypted_host` → output names `encrypted-host`, says the key is weaker, says the
  reason is that the machine has no TPM, and who can copy the file (root, anyone with a copy of `/var/lib`).
- Import, TPM lacks a capability → `storage_kind::import_encrypted_tpm` → output names `encrypted-tpm`, says weaker, says
  the reason is that the TPM lacks a capability the key needs (not "no TPM"), says root can use it while the machine
  runs, and points to the capabilities section of `docs/api.md` (no claim that the journal names the missing item). The two weaker texts differ from each other
  (`storage_kind::weaker_reasons_differ`, which fails if a mutant swaps them).
- Unknown kind → `storage_kind::import_unknown_kind` → prints the escaped text (a control character in it is escaped,
  not raw), says the kind is not known to this CLI, and says neither "weaker" nor "in the TPM".
- Both key types → each import test is parameterised over RSA 2048 and ECC P-256 and the output keeps the key type.
- Reminder only after success → `storage_kind::failed_import_prints_no_kind` → a failing `Importer` gives no kind text and
  no reminder.
- List shows the kind of each key → `storage_kind::list_shows_each_kind` → three keys of three kinds plus one unknown, in
  one reply; each block has the `kind:` line with that key's own wire string (pairing id to kind, so swapped kinds fail).
- List escapes → `storage_kind::list_escapes_kind` → a kind with an escape character prints as `\x1b`, no raw control byte.
- The CLI uses only `custodio-client` → `! cargo tree -p custodio-cli -e normal --locked | grep -q custodiod` succeeds and
  `storage_kind` imports `Kind` from `custodio_client` (the test file compiles only if the seam uses that type).
- Existing behaviour kept → the existing `custodio-cli` unit tests and `exit`, `man` targets pass under `just quick`.
- Whole feature → `just quick && cargo test -p custodio-cli --test storage_kind --locked` green.
