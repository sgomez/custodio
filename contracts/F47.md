# F47 — End-to-end target Arch

## Scope
Built here:
- Target `arch`: `e2e/targets/arch/` with `Containerfile` (from `docker.io/library/archlinux:latest`; the verify greps `archlinux`),
  `skip.list`, `install.sh`, `probe.sh`, `package.pattern` (`custodio-*.pkg.tar.zst`). The package is the Arch package of F36/F58, mounted
  read-only and installed with `pacman -U` on the mounted file (never copied, never in the image). Dependencies come from the sync
  databases, so the Containerfile refreshes them with a full upgrade (`pacman -Syu --noconfirm`, never `-Sy` alone: that is the unsupported partial
  upgrade on an image built earlier). `install.sh` runs `pacman -U` and, only if it must refresh databases again, does so as a full
  upgrade too; the findings record why. The shared guest of F45 runs `e2e/cases.list` (including `journal-catalog`), each case run or on `skip.list`. A new target is
  a new directory; a shared script changes only where it is wrong for Arch (small, keeps debian13, ubuntu2604, fedora44 and alma10
  passing, named in `PROGRESS.md`).
- `scripts/test-e2e-host.sh` learns the `arch*` family; `target_problems` (which finds the package list only on `apt|apt-get|dnf ... install`
  lines) is extended to read the `pacman -S...` lines too, so each control fails with its own message and not for "no package list found"
  (polkit package `polkit`, as for fedora/alma; installs with `pacman -U "$1"`;
  `pacman -S` of the file or copying files rejected) with a control fixture per rule that must be rejected.
- Bus daemon and journald default, recorded from the booted container. Checked while writing this contract (dev container, network
  available): `podman pull docker.io/library/archlinux:latest` succeeds; in the base image `dbus 1.16.2`, **`dbus-broker 37`**,
  `dbus-broker-units` and `dbus-units` are already installed (pacman -Q), and `pacman -Si dbus-broker-units` shows `dbus-units` provided by a
  package depending on `dbus-broker`. So Arch's default is expected to be `dbus-broker`, NOT `dbus-daemon`: the row "Arch | 128 | 1.16.2 / 37"
  of `docs/findings.md` section 3 reads as if `dbus-daemon` 1.16.2 ran, and is corrected if the booted container confirms it (as is the
  "inferred" note at `docs/findings.md:99-100`, and the Arch row of the table in "M1.2 Caller detail" near `:382`). If the boot shows
  `dbus-daemon` instead, that is a finding: the check and section 3 are amended to match; the image is never made to fit the expected value. The builder must not force `dbus` or `dbus-broker` in the image beyond what the base image has and `polkit` pulls in.
- Tool availability (checked now with `pacman -Si` after `pacman -Sy`, core/extra): `polkit` 128, `dbus-broker` 37, `opensc` 0.27.1,
  `pkcs11-provider` 1.3.0, `nss` 3.132 (certutil, modutil), `python-gobject` 3.58.1 (and `python-dbus` 1.5.1; `agent.py` uses Gio since F46),
  `p11-kit`, `openssl`, `procps-ng`, `util-linux`, `systemd` 262.1 all have a candidate. The builder re-checks in the image; a real gap
  becomes a `skip.list` entry with a reason, and a tool that is available is not skipped.
- Environment limits to settle while building: pacman's download sandbox and Landlock may fail in a rootless user namespace (like
  `apt` did, F45 findings): the fix goes in the Arch image only (for example `DisableSandbox` in the image's `pacman.conf` or `--disable-sandbox`), scoped to
  that image, never in the package or in `install.sh`'s behaviour on a real system; the findings record the error seen. systemd 262 in the
  image and the dev container's nested podman options are those of F45 (`docs/findings.md`); the real run uses the same options.
- Journald's default on Arch (effective `Storage=`, whether `/var/log/journal` exists in the image and after boot, commands used) recorded
  in `docs/findings.md`. Nothing in the package changes journald (SPEC section 6).

Not here: the upgrade, removal, reinstall and `pre_install` behaviours of pacman (F58, F48, F49), the Omarchy acceptance, CI wiring,
`docs/install.md`.

Size: about five steps; no split needed.

## Steps
- [ ] Write the failing tests first in `scripts/test-e2e-host.sh`: the `arch*` family rules (including reading `pacman -S...` package lists)
      and a control fixture for each, each asserting its own message, and the accepted variant returning empty (`polkitd`
      instead of `polkit`; `pacman -U` missing or replaced by copying files; a forced bus-daemon package other than the base image's),
      an accepted variant; include `arch` in the stub-engine run, the expected "available targets" line and the shellcheck list. Run it red.
- [ ] Create `e2e/targets/arch/` and settle tool availability and pacman-in-userns by building the image. The image holds no package and
      no bus daemon beyond the distribution default.
- [ ] Run `just e2e arch` until it passes: each failure is a target defect, a small shared-script fix that is wrong for Arch (others
      stay green), or a real gap (skip-list entry with reason). Investigate before skipping.
- [ ] Write the findings, heading `### End-to-end target Arch`: tool sources per tool, the skip list with the `pacman -Si`/`-Ss` output
      that shows each absent tool (or "empty"), the observed bus daemon, its process and version, polkit version, the correction of section 3
      (row and the "inferred" note) if needed, journald default with the commands. Update docs that list the targets.
- [ ] Real run, required: `just e2e arch`, then `just e2e` (all five targets). Paste exit status, per-case results and
      `target/e2e/arch.record` into `PROGRESS.md`; run `verify`. If it cannot run, write a finding and `BLOCKED.md`; do not fall back
      to the stub test.

## Evidence
- Target exists and runs like the others → `scripts/test-e2e-host.sh` (in `test-scripts`, stub engine) and `verify`'s greps (`archlinux`
  in the Containerfile, `skip.list` exists) → adding `arch` to the stub-engine list and the "available targets" line is enough: the existing F45/F46 stub assertions already prove
  build, privileged run, read-only package mount and shared guest for every target; no Arch-specific stub assertions.
- `pacman -U` installs the `.pkg.tar.zst`; image has no package; real polkit and the distribution's bus daemon → the arch rules of
  `test-e2e-host.sh` with their rejected control fixtures (wrong polkit name, no `pacman -U`, forced bus daemon) → accepted (empty problems) for the real
  directory, rejected for each control with that control's own message.
- The default bus daemon is recorded → REQUIRED real run: `target/e2e/arch.record` holds `bus-daemon=`, version, polkit version, target;
  the expected `bus-daemon=dbus-broker` is asserted with `grep -qx` and pasted in `PROGRESS.md`; `probe.sh` reports the broker's own
  process as for fedora44 (the bus names `dbus-broker-launch`). Section 3 of `docs/findings.md` agrees with the record
  (`grep -n 'Arch' docs/findings.md` shows no `dbus-daemon` claim for Arch unless the record says so; this covers section 3 and the
  "M1.2 Caller detail" table; the findings say both were corrected). If the record shows `dbus-daemon`, the `grep -qx` expectation is amended instead.
- The suite runs on Arch → REQUIRED real `just e2e arch` → exit 0, "e2e: passed: arch", every case of `cases.list` reported run or on
  `skip.list`; `just e2e` (all) exits 0 for debian13, ubuntu2604, fedora44, alma10, arch.
- Gaps are skip-list entries with reasons → `scripts/test-e2e-skips.sh` and `e2e/check-cases.sh` (F45) validate format and accounting; a
  missing tool without an entry fails the run; the findings list the tools next to `pacman` output; a skip of an available tool is a defect.
- Bus daemon and journald default recorded → `grep -n '^### End-to-end target Arch' docs/findings.md`; `Storage=` and `/var/log/journal`
  outputs and commands sit under it, and it says the result comes from the minimal base image. `journal-catalog` and the audit-entry cases
  pass on that default (real run).
- No partial upgrade, sandbox fix scoped → `grep -n 'pacman -Sy' e2e/targets/arch/*` shows only `-Syu`; any sandbox option appears only in
  the Containerfile/image config, not in `install.sh` → confirmed by grep and recorded in the findings.
- Shellcheck and syntax → `just check` and `bash -n e2e/*.sh` → pass.
