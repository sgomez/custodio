# F156 — Drop the ubuntu2404 end-to-end target; docs/install.md states the systemd 257 floor and libtss2-rc0t64

## Scope
Design 5, tests and docs. Built here:
- `e2e/targets/ubuntu2404` is deleted. With it go what exists only for it: the `refusal-only` marker mechanism (the branches in `e2e/run.sh`, `e2e/guest.sh`),
  `e2e/refusal.sh`, `refusal-lib.sh`, `refusal-selftest.sh`, `refusal-static.sh` and their self-tests (`scripts/test-e2e-refusal.sh`, the refusal-only parts of
  `test-e2e-host.sh`, `-host-oldpath.sh`, `-lifecycle.sh`, `-m3.sh`, `-select-host.sh`, `-targets.sh`), the `ubuntu2404` entry of the matrix in `.github/workflows/e2e.yml`
  (and its "On 24.04" comment), and the ubuntu2404 lines of the `justfile` and `scripts/test-check-budgets.sh` fixtures only if they refer to the target. A step first lists every
  reference (`grep -rIn ubuntu2404 e2e scripts .github justfile docs/*.md packaging`, excluding `docs/milestones`, `docs/findings`, `contracts`, `CHANGELOG.md`) and
  decides each as "only for the target" (delete) or "tests something else" (keep).
- **Kept:** the bus check (`packaging/bus-check.sh`, its per-format copies, `scripts/test-bus-check.sh` and `scripts/lib/bus-fixtures.sh`, whose `ubuntu2404` os-release fixture is
  a fake-OS input that proves the check looks at the capability, not the name); the glibc ceiling (`packaging/glibc-ceiling.txt`, `test-glibc-ceiling.sh`). The bus-check message text
  is not changed (its pointer to docs/install.md still resolves: the ProcessFD section stays).
- `budgets.tsv` is not edited (its `ubuntu2404` row is left for a person). `scripts/test-check-budgets.sh` uses its own fixture and stays unless it reads the real row.
- `docs/manual-acceptance.md` section 14 and `scripts/test-docs-manual.sh` point at the install.md section that is removed: they are adjusted to the remaining content (the
  section is dropped or marked as no longer applicable, and the test follows; no test checks wording of the new text, only that what it names exists).
- `docs/install.md`: "Supported systems" drops the Ubuntu 24.04 entry and says every package requires systemd 257 or later and that older systems (Ubuntu 24.04 among them) are not
  supported and refused by the package manager; the section "Ubuntu 24.04: switching to dbus-broker" and its anchor links go; the "TPM2 Software Stack" `.deb` line lists `libtss2-rc0t64`
  and the text says why (systemd loads it by `dlopen`; an install without recommends otherwise lacks it); the `systemd (>= 255)` deb line and the "Ubuntu 24.04 has 255" sentence become 257.
- `scripts/test-docs-install.sh`: drops the ubuntu2404 heading and the "precondition"/Ubuntu 24.04 section checks; derives the systemd bound from `packaging/nfpm.yaml` and checks the
  document's stated floor and every `.deb` dependency (`libtss2-rc0t64` included, via `scripts/lib/tss_names.py` / `package_expected.py` `TSS_DLOPEN`) against it; keeps the install-command check
  over the remaining `e2e/targets/*/install.sh` (so the Debian/Ubuntu 26.04/Fedora/Alma/Arch steps are the ones run). Each new claim gets a negative control on a broken copy.
- Left to other features/checkpoints: the VM harness, SPEC wording, the package gates and `just e2e` (checkpoint features). No real `just e2e` run is needed here: removing a target removes a run.
- Size: about five steps, no split. Costs: no new suite. `test-docs-install.sh` gains about five controls, each one `grep`/`awk` pass over a 200-line file (milliseconds; total stays well under the 120 s script
  budget, runs in parallel with the other script tests). The removed ubuntu2404 e2e run (120 s budget) and `test-e2e-refusal.sh` make the loop cheaper. The `budgets.tsv` row stays for a person.
- Environment: nothing beyond the repository is needed (no container engine, no network); `python3` with `yaml` is already used by `tss_names.py`.
