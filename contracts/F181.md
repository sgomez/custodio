# F181 — Browser files: strict parsers, profile discovery and their fuzz targets

## Scope
Builds, in `custodio-cli`, the read-only half of SPEC Design 3 ("Native browsers", "Safety" for the lock,
"Browsers that already see Custodio through p11-kit"), as library code the registration command will call. The rules are
the `Decision:` lines of `docs/findings/F172.md`; where they leave a choice, the more conservative one holds.
- **Parsers**, strict and read-only, over bytes, returning an error that names the file and never panicking, never
  reading outside the file it is given: `profiles.ini` and `installs.ini` (the `[ProfileN]`, `[InstallHASH]` and `[General]`
  sections as F172 describes them), and `pkcs11.txt` (module entries: `library=` and `name=`, other lines such as
  `parameters=` and `NSS=` kept as they are, an unknown or malformed shape an error, not a guess). An input has a size
  bound; an oversized one is an error.
- **Discovery**, over a home directory and an environment passed in (so a fixture home stands in for the real one; nothing
  reads `$HOME` inside the parsers): the profiles of Firefox (all channels, both roots, every root that exists),
  Thunderbird, LibreWolf, Floorp and Waterfox, from the data table of F172 (shipped as data in the crate, not as
  scattered conditions), and of the Firefox snap when `~/snap/firefox/common/.mozilla/firefox/` holds a `profiles.ini`
  listing a profile. Each profile is reported with its browser, root, path (deduplicated by real path) and **lock
  state**, by the F172 rule (stale `lock` symlink to a dead local pid is free; live local pid, foreign address,
  unparseable target or a `.parentlock` held by another process is held; mere presence proves nothing). Discovery
  only reads: it takes the `.parentlock` probe lock and releases it, it creates nothing.
- **p11-kit rule**: where `/etc/crypto-policies/back-ends/nss.config` (path injectable) has the line
  `library=p11-kit-proxy.so`, every native profile is marked *skipped* with the reason; the snap profile never is.
- **Fuzz targets** `profile_index` and `nss_modules` in a new `crates/custodio-cli/fuzz` workspace, joined to
  `just fuzz-build` (found by its glob), `just lint-fuzz` and `just fuzz-smoke` (the `expected` list gains both names).
- **Left for other features**: the registration command, its flags, `modutil`, the snap copy, removal, the report, the
  man page and the README (their features); the e2e on real browsers. Whether `modutil` is installed is not checked here.
  The SPEC's "exits non-zero" for a held profile belongs to the command; here the lock state is data.
- No split is needed: five steps.

**Costs.** `browser_files` and `register_discover` are ordinary integration tests over fixture homes in temp dirs and
a held `fcntl` lock taken in-process or by a child `sleep`-free helper (the test binary re-run, waiting on a pipe, not a
timer): estimated under 3 s each, parallel with the other integration tests (similar: `storage_kind`). The two fuzz
targets add two 2000-run smoke runs (about 2 s each) and a first build of a new fuzz workspace (estimated 60–90 s
cold, of the same order as the existing two fuzz crates; incremental afterwards); `fuzz-build`, `lint-fuzz` and
`fuzz-smoke` run each workspace in turn as they do now, which this feature does not change. No e2e case; no script
test. No budget in `budgets.tsv` covers these (they are not scripts or e2e); if `fuzz-smoke` becomes noticeably slower
the builder reports the measured time in PROGRESS.md.
Environment check (run now): `rustc +nightly`, `cargo fuzz` and `modutil` are already what `fuzz-build` and F172 use;
the builder runs `just fuzz-build` once in step 4 to show the new workspace builds before relying on it.

## Steps
- [ ] Parsers for `profiles.ini`, `installs.ini` and `pkcs11.txt`, tests first in `tests/browser_files.rs`: the F172
      fixtures (absolute and relative profiles, `[InstallHASH]` default, entry with `parameters=`/`NSS=`) and each
      malformed shape, with errors naming the file.
- [ ] Lock state by the F172 rule, tests first with the fixtures of its lock table (absent, stale local, live local,
      foreign host, unparseable, `.parentlock` held by a live process, `.parentlock` present but free).
- [ ] Discovery over a fixture home: the data table, both Firefox roots, legacy-and-XDG both present, Thunderbird,
      derivatives, the snap, dedupe, and the p11-kit rule, in `tests/register_discover.rs`.
- [ ] The fuzz workspace with `profile_index` and `nss_modules`; add both to `fuzz-smoke`'s expected list and
      `lint-fuzz`; run `just fuzz-build`, `just lint-fuzz`, `just fuzz-smoke`.
- [ ] `just quick`; a `docs/findings/F172.md` correction only if a fixture disproves a Decision there (as a new
      finding note, not a rewrite); PROGRESS.md entry.

## Evidence
- Parses `profiles.ini`/`installs.ini`: absolute and relative profiles, install `Default=` not repeated →
  `browser_files::profiles_ini_lists_relative_absolute_and_install_default` → exactly the F172 fixture's two paths,
  each once (negative control: a profile listed twice by `Default=` and `[ProfileN]` is deduped).
- Strict, error names the file, never a panic → `browser_files::malformed_index_is_an_error_naming_the_file` (table:
  entry without `Path`, section header unclosed, NUL byte, non-UTF-8, duplicate key, oversize, empty) → each `Err`
  whose text contains the file name; `browser_files::pkcs11_txt_malformed_is_an_error` likewise.
- `pkcs11.txt` entries → `browser_files::pkcs11_txt_reads_library_and_name_and_keeps_other_lines` → library and name
  of every entry incl. the internal module; an entry with `parameters=`/`NSS=` retained; a missing file is a distinct
  "absent" result, not an error.
- Read-only → `browser_files::parsing_and_discovery_change_nothing` → a fixture tree's file list, bytes and mtimes are
  identical afterwards (and no file was created).
- Lock state → `browser_files::lock_state_follows_the_rule`, one case per row of F172's lock table, with the naive
  "lock exists" rule failing two of them → free, free, held, held, held (by a child holding `fcntl`), free.
- Native browsers listed, with lock → `register_discover::lists_every_browser_root_and_channel` (Firefox legacy only, XDG
  only, both, Thunderbird both roots, LibreWolf with and without `~/.librewolf/profiles.ini`, Floorp, Waterfox, an
  excluded browser's directory such as `~/.zen` absent from the result) → the expected set of (browser, path, lock).
- Snap → `register_discover::the_snap_profile_is_listed_only_with_a_profile` → listed with `profiles.ini`; not
  listed with `~/snap/firefox` present but no profile; not listed when absent.
- p11-kit → `register_discover::p11_kit_system_skips_native_profiles_but_not_the_snap` → with a `nss.config` line
  `library=p11-kit-proxy.so`: all native profiles carry a skipped reason naming p11-kit, the snap's none; with no file, or
  a file without that line (including a commented one and `library=p11-kit-proxy.so.1`), nothing is skipped.
- Fuzz targets → `just fuzz-build && just lint-fuzz && just fuzz-smoke` → both targets build, lint clean, run 2000
  seeded iterations without a crash, and `fuzz-smoke` fails when one is dropped from the list (`just fuzz-smoke "<old list>
  profile_index nss_modules"` with a target removed is the existing negative control of that recipe; run it once for
  `nss_modules`).
- Whole feature → `just quick` and the `verify` of features.json → green.
