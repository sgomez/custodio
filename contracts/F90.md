# F90 — Checkpoint: the clients

## Scope
Nothing new is built. This feature runs the full suites on the service API and the clients (module, CLI `import`,
`list`, `delete`, the `pkttyagent` helper of F89) and fixes whatever fails. It runs the whole `verify`:
`just check && just api-contract && just e2e && just package-gates`.

What the checkpoint proves, and where:
- `just check` covers lint (including `deps-check`: neither `custodio-cli` nor `custodio-pkcs11` reaches `custodiod`, in
  every dependency kind), every unit and integration test of the workspace (the `custodio-it` suites for import, list,
  delete, agent, ownership), the system gates and the script tests (package-gate and install-script tests).
- `just api-contract` covers acceptance 12 (client document against the live service, error type and policy file).
- `just e2e` runs every case of `e2e/cases.list` on every target (alma10, arch, debian13, fedora44, ubuntu2404,
  ubuntu2604). Its accounting fails on a missing, unknown or duplicated case. These are the M0–M2 cases (acceptance 13).
- `just package-gates` covers package, parity, glibc ceiling and package lint on the .deb, .rpm and Arch package.
- Not proven here: the new two-account ownership cases (F91), the CLI cases `list`/`delete`/`pkttyagent` in the
  containers and the manual steps. Those belong to F91 and later features; the CLI behaviour is proven by the
  integration tests F86–F89 that `just check` runs.

One item F89 left for this feature: the CLI runs `setpriv --pdeathsig=KILL -- pkttyagent ...` (see `docs/findings.md`,
"F89: which agent answers"), so each package must declare the packages that provide `setpriv` (util-linux) and
`pkttyagent` (the polkit package that ships it on that distribution) as runtime dependencies. This is fixed here
because the package gates and `e2e` are where a wrong dependency list shows.

Environment (commands run in the dev container, 2026-11-02): `podman info` succeeds (podman at `/usr/bin/podman`);
`nfpm`, `rpm`, `bsdtar`, `zstd`, `lintian`, `dpkg`, `cargo-deny`, `pkttyagent` and `setpriv` are present. `rpmlint` and
`namcap` are not on the host, so `package-lint` uses its container path (as the script documents). The e2e and
lint containers need the network to pull images the first time; if an image cannot be pulled, that is a `BLOCKED.md`
question (a person's run), not a reason to skip a target.

## Steps
- [ ] Baseline: run `just check` and `just api-contract`; fix every failure at its cause (no gate weakened, no test
      ignored). Record each fix in the commit.
- [ ] Package runtime dependencies: add the packages providing `setpriv` and `pkttyagent` to the deb, rpm and Arch
      dependency lists in `packaging/nfpm.yaml`, with each name checked against the target distribution's package
      database (in the target's container); extend the package tests that pin the dependency lists so they fail when
      one of these is removed.
- [ ] Run `just e2e-cases` for one target (debian13) with a cheap case first to confirm the shared setup works with
      the new CLI binary and dependencies; fix what fails.
- [ ] Run `just e2e` (every target); fix every failing case or accounting error at its cause. A case may be changed
      only if it is wrong, never to make it pass; skips only as already listed in each target's `skip.list`.
- [ ] Run `just package-gates`; fix every finding, adding to `packaging/lint/*.txt` only with a reason per entry and
      only for findings that are not defects.
- [ ] Run the whole `verify` once, in order, from a clean tree, and note the result in `PROGRESS.md`.
