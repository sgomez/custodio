# F117 — Choose the storage kind at import, and fail closed

## Scope
Built in `custodiod`. Today `import::store_parsed` always encrypts through the credential service (the interim wiring
F116 recorded). This feature replaces it with the choice of SPEC section 2, after polkit approves and the `.p12` is
decoded (M3's order, unchanged):

- **The decision** is one pure function from the F112 classification of the key's type (`tpm::assess` for the RSA 2048 or
  P-256 key type) to a choice or a refusal: `Ready` → TPM; `Lacks(_)` → encrypted, TPM-bound; `Absent` → encrypted,
  host-bound; `Error(_)` → refusal. Nothing else chooses a weaker kind. A mechanism the TPM cannot serve is already
  one of the `Lacks` items (F111/F112), so it takes the `Lacks` branch; this feature adds no list of its own.
- **Acting on the choice, failing closed.** TPM: `tpm::import::import_pkcs8` and `Protected::from_imported`. Encrypted:
  `creds::seal`, and the binding the credential's header names must agree with the chosen kind (TPM-bound kind needs
  `Binding::Tpm`, host-bound needs `Binding::Host`); a disagreement is a failure, never a re-labelling and never a
  different kind. Any error after the choice (TPM import error of any code, including one that looks like a lack, a
  `seal` error of any kind, a store error) fails the import and is not retried under another kind. Classification
  `Error` (device present but unopenable, TPM error, unusable owner hierarchy) fails the import before any key is
  protected.
- **Nothing is stored and nothing is left** on every failure: no record, no `.tmp-` file, no object left loaded in the
  TPM (the import flushes; the test checks it after a faulted import). The plaintext key (`ParsedP12.key`), the password
  and the `.p12` are dropped as soon as the protected form exists (before the store write), and also on every failure path.
- **Errors.** Import failures from the TPM and from the credential service get documented D-Bus error names under the
  compatibility rule (names only added): one for "the TPM failed or cannot be used" and one for "the credential
  service is unavailable or refused". Added to `custodio-client`, `ServiceError` (fixed messages, no input, no response
  codes) and the `## Errors` list of `docs/api.md`, so `just api-contract` stays green. The builder picks the names.
  Explaining them for readers, and the kind values in the API, stay in F119.
- **Journal.** One entry per failed import, as today (outcome `StorageFailure`, key type set, since the key was decoded);
  `Stored` for a success. A failure is never recorded as success and never produces two entries. Naming the cause and the
  kind in the entry is F120; this feature does not change `audit/`.
- **Wiring.** The service gets a `TpmAccess` next to its credentials access point: the production `main` passes the
  F112 implementation that opens only `/dev/tpmrm0`; tests pass `swtpm` or faulty ones. No environment variable or
  configuration of the shipped unit can substitute it (F108's test-only seam stays as decided).
- **Files.** The decision and the protection step live in new file(s) under `crates/custodiod/src/import/` (or
  similar), each under 5000 tokens, and every new or changed non-test file that holds them joins the `mutants` recipe's
  `--file` list (`src/import.rs` is not on it today; add it, or move the code, so the mutants run covers the changed lines).
- **Left to other features.** The kind in the import result, the list and the client (F119); the kind and the causes in
  the journal and `docs/audit.md` (F120); signing a TPM key (F118: until then a TPM record still answers `Internal`
  on sign, as F116 left it); the CLI wording (F119/later); the purge (F121); end-to-end cases on all targets (checkpoints
  F132/F146 and the e2e features).
- **Size.** About five steps; no split proposed.

Environment check: F112/F115/F116 tests already run `swtpm` (0.7.1, started by the tests as `tpm_import` does) and the
real `systemd-creds` in the `custodio-dev` container; this feature needs nothing beyond them. The builder confirms with
`cargo test -p custodiod --test tpm_access --locked` before relying on the fixtures.

## Steps
- [ ] The pure decision: a function from `Classification` to choice-or-refusal, with unit tests over every variant
      (`Ready`, `Lacks` with one and several items including a mechanism item, `Absent`, each `Error` kind).
- [ ] The protection step for each choice, with the binding-agreement check and the drop of the plaintext, in the new
      file(s); `store_parsed` calls it; the new error variants map to fixed outcomes (`StorageFailure`) and to the new
      D-Bus names. Tests first, per failure.
- [ ] Wire `TpmAccess` into `Custodio` and `main`; add the error names to `custodio-client`, `ServiceError` and
      `docs/api.md`; `just api-contract` green.
- [ ] The integration target `storage_choice` (rows below), including the negative controls.
- [ ] Add the files to the `mutants` recipe; run `just quick` and `just mutants-diff F117` until 0 missed; hand off.

## Evidence
- Kind per reason (success paths), through the real import path on the private bus with fake polkit →
  `storage_choice::{ready_gives_tpm, lacks_gives_encrypted_tpm, absent_gives_encrypted_host}` for both RSA 2048 and P-256 →
  `swtpm` (ready), a lacking `swtpm` (e.g. no SHA-256 or a refused scheme, as `tpm_access` builds it) and no device
  (`NoDevice` access point) give, read back from the store, kinds TPM, encrypted TPM-bound and encrypted host-bound; the
  TPM record holds a blob and the encrypted records hold a credential whose header binding matches the kind.
- A mechanism the TPM cannot serve takes the `Lacks` branch (F111, F112) →
  `storage_choice::unserved_mechanism_gives_encrypted_tpm` with a TPM that refuses the scheme/command of one mechanism
  of the key type (the F112 `Lacks.flips`-style filter) → kind encrypted TPM-bound, not TPM and not a failure.
- Each other failure fails closed, one test per injected reason, for each key type →
  `storage_choice::fails_closed::{device_unopenable, tpm_error_in_query, owner_hierarchy_unusable, tpm_error_during_import,
  import_refused_with_lack_like_code, credentials_down_with_no_tpm, credentials_down_with_lacking_tpm,
  credentials_cannot_encrypt, binding_disagrees_with_kind_tpm, binding_disagrees_with_kind_host}` → the call returns the
  documented error name (the TPM one or the credential-service one, as the reason says), the store listing is empty and
  the owner area holds no file at all (no `.tmp-`), and a later import of the same id with working parts succeeds
  (nothing half-stored). The "TPM ready then import faults" and "import refused with a lack-like code" cases assert
  that no encrypted record appeared (the no-fall-through rule), and the credentials double records that `encrypt` was
  never called on those paths.
- Nothing left in the TPM after a failed or successful import → `storage_choice::tpm_is_clean_after_faulted_import` →
  the `swtpm` has no transient object loaded afterwards (`tpm2_getcap handles-transient` empty, or the F113 helper).
- One journal entry per failed import → in each `fails_closed` test, the in-memory sink holds exactly one entry,
  operation import, outcome `StorageFailure`, the right key type; on success exactly one `Stored`. Not two, not none.
- Order unchanged: polkit first, then decode, then the choice → `storage_choice::tpm_untouched_when_polkit_denies` and
  `..._when_p12_is_wrong` → a TPM double that counts `open` calls shows zero calls; credentials `encrypt` zero calls.
- The plaintext is dropped as soon as the key is stored, and on failure paths → a unit test that the protection step
  takes the key by value and that the key is no longer reachable after (type-level: the signature consumes
  `ParsedP12`), plus `storage_choice::no_plaintext_in_store_after_any_outcome` over all outcomes above: no PKCS#8 of the
  sentinel fixtures (`p256-sentinel.p12`, `rsa2048-sentinel.p12`) in the owner area, and the existing `Debug`/redaction
  tests still pass. No claim is made about freed memory beyond the `secrecy`/`zeroize` types.
- The choice joins the `mutants` recipe, and a mutant that falls back on the wrong condition is killed →
  `just mutants-diff F117` → 0 missed (the table of every classification variant and each `fails_closed` row exist to kill
  mutants that map `Error`→fallback, `Lacks`→TPM, `Absent`→TPM-bound, or drop the binding check).
- Negative controls (a test that can fail) → `storage_choice::controls`: (a) a `Lacks` TPM and an `Error` TPM give
  different results, so the `Error` rows would fail if `Error` fell back; (b) a record planted in the store before a failing
  import is seen by the emptiness helper, so "empty store" is not vacuous; (c) a credentials double returning a host
  header for a TPM-bound request is accepted by a deliberately wrong test-only chooser stub, shown caught by the
  binding-agreement test.
- New error names are documented and in the client → `just api-contract` → green; it fails if `docs/api.md` lacks one
  (checked once by removing a line, not committed).
- Unit tests, lints, size gate → `just quick` → green.
