# F36 — Build the .deb, .rpm and Arch package with nfpm from one file list

## Scope
Replace `cargo deb` with nfpm. `just package` builds the release binaries and then one `.deb`, one `.rpm`
and one `.pkg.tar.zst` (x86_64) in `target/packages`, from a single nfpm configuration.

Built here:
- `packaging/nfpm.yaml`: the one file list (source, destination, mode, owner of every installed file;
  everything under `/usr`, nothing in `/etc` or `/var`) and the common metadata. Per-format
  `overrides:` hold only metadata, dependency names and `polkit >= 124` where the format can say it.
- The service moves to `/usr/lib/custodio/custodiod` in all three formats (open question "Arch and
  `/usr/libexec`", option (a)); `data/custodio.service` and `data/com.rfirma.Custodio1.service` are updated.
  No second unit or activation file.
- Per-format lifecycle script files under `packaging/deb/`, `packaging/rpm/`, `packaging/arch/`. Until
  F43/F44 each only does what the M1 `data/debian/postinst` does (sysusers, daemon-reload, reload the bus).
- `scripts/check-packages.sh`: the package build gate (every package exists exactly once; every path of
  the list is in each package with the listed mode and owner). `just package` runs it.
- Versions: Debian revision, RPM release and Arch pkgrel derived from the workspace version; `just package`
  takes a version override (`just package version=0.1.1`) so a test can build N+1 from the same tree.
  Recorded in `docs/decisions.md`.
- Supply chain: nfpm pinned in `mise.toml` (checksum where mise supports it) and installed in
  `harness/Containerfile`. `cargo-deb`, `[package.metadata.deb]`, `data/debian` and every `cargo deb`
  use leave the repository, mise.toml, the dev image and CI.
- `shell_scripts` in the justfile covers the maintainer scripts whatever their file names.

Left for other features: the parity check, glibc ceiling and package linters (other M2 gates), real
lifecycle behaviour (F43, F44), e2e (later features). Dependency lists name the libraries the binaries
link, taken from `readelf -d`/`ldd` on the release binaries; no automatic computation.

Fits in six steps; no split needed.

## Steps
- [ ] Add `scripts/check-packages.sh` and its test first (fixtures: a good set, a missing package, a
      file missing from one package); then `nfpm` pinned in `mise.toml` and `harness/Containerfile`.
- [ ] Move the service path to `/usr/lib/custodio/custodiod` in the unit and the D-Bus activation file.
- [ ] Write `packaging/nfpm.yaml` with the single file list and per-format overrides (dependencies,
      polkit >= 124 where expressible), plus the three sets of lifecycle script files.
- [ ] Rewrite the `package` recipe: release build, version derivation and override, nfpm for each of
      the three formats into `target/packages` (cleaned first), then the gate script.
- [ ] Remove cargo-deb: `[package.metadata.deb]`, `data/debian`, mise.toml, Containerfile, CI, docs.
      Update `shell_scripts` and add the lint test.
- [ ] Record the version scheme (and the libexec move) in `docs/decisions.md`; run the `verify` command
      and the evidence below.

## Evidence
- One .deb, one .rpm, one .pkg.tar.zst in target/packages → `just package && ls target/packages` and the
  three `test $(ls … | wc -l) -eq 1` lines of `verify` → exit 0, each count is 1; also a rerun after a
  version override leaves still exactly one of each (the directory is cleaned).
- Built from a single nfpm configuration listing every file once → `test $(ls packaging/nfpm*.y*ml | wc -l)
  -eq 1` and a check in `scripts/check-packages.sh` that no destination appears twice in the `contents`
  list → exit 0; a fixture with a duplicate destination makes it fail.
- Every file of the list is in every package, with the listed mode and owner → `scripts/check-packages.sh`
  reads the list with `yq`/`nfpm`-independent parsing and compares with `dpkg-deb -c`, `rpm -qp --dump`
  (or `bsdtar -tvf` for Arch) → exit 0; the test `scripts/test-check-packages.sh` removes a file from a
  rebuilt package (and, separately, a package) and expects a non-zero exit naming it.
- The ten files are installed (service, CLI, PKCS#11 module, unit, sysusers, D-Bus policy and activation,
  polkit action, p11-kit module, journal catalog) → the same check against an explicit expected list of
  ten destinations written in the test, so an incomplete nfpm.yaml fails too.
- All under /usr, nothing in /etc or /var → test lists each package's paths and fails on any path not
  starting with `/usr/` (config files such as `/etc` and `/var` entries, including `config|noreplace` types) →
  exit 0; fixture with `/etc/x` fails.
- Service at /usr/lib/custodio/custodiod in all three formats; one unit and one activation file →
  `grep -q '^ExecStart=/usr/lib/custodio/custodiod' data/custodio.service`, same for `Exec=` in the
  activation file; `! grep -rqs '/usr/libexec' data` (from `verify`); package listing shows the binary at
  that path, mode 0755, and no `/usr/libexec` path; `ls data/*.service` still shows exactly the two files.
  `just system-gates` still passes with the new path.
- Overrides hold only metadata, dependency names and polkit >= 124 → test parses the nfpm config and
  fails if any override has `contents`, `scripts` other than script paths, or any key outside an allowed
  list (`depends`, `recommends`, `provides`, `conflicts`, `replaces`, `scripts`, `deb`/`rpm`/`archlinux`
  metadata keys such as `release`, `pkgrel`, `section`).
- polkitd on .deb; polkit on .rpm and Arch → `dpkg-deb -f … Depends`, `rpm -qpR`, `bsdtar -xOf … .PKGINFO`
  checked by the gate script: .deb has `polkitd` and not bare `polkit`; .rpm and Arch have `polkit`, not `polkitd`.
- polkit >= 124 where expressible → same queries show `polkitd (>= 124)` on the .deb and `polkit >= 124` on
  the .rpm and Arch; an unversioned dependency fails the check. Also systemd, the system bus
  (`dbus`/`dbus-broker` alternative as the format allows) and p11-kit are present in each.
- Every shared library the binaries link is a dependency → the gate script runs `readelf -d` on the three
  ELF files taken from the package, maps each NEEDED soname to a package declared per format (table in
  the script) and fails if a soname that is not provided by libc/libgcc is not covered; a test with a fake
  NEEDED entry not in the table fails.
- Own lifecycle script files per format that do only what the M1 postinst does → the packages contain the
  scripts (`dpkg-deb -e`, `rpm -qp --scripts`, `.INSTALL` in Arch) and each runs sysusers, daemon-reload and
  `reload dbus` and nothing else; the three source files are distinct paths, and a stubbed-tools run of each
  records exactly those three calls (`scripts/test-package-scripts.sh`, not the F43/F44 `just test-scripts`).
- The recipe fails if any package is missing or a file is missing → `just package` with `nfpm` format
  skipped via a stub PATH wrapper (test in `scripts/test-check-packages.sh`) exits non-zero; see above.
- Versions derived from the workspace version, with override → `just package` yields
  `custodio_0.1.0-1_amd64.deb`, `custodio-0.1.0-1.x86_64.rpm`, `custodio-0.1.0-1-x86_64.pkg.tar.zst`
  (names as nfpm renders them; asserted by the script from `Cargo.toml`'s version);
  `just package version=0.1.1` yields 0.1.1 in the metadata of all three (`dpkg-deb -f Version`,
  `rpm -qp --qf '%{VERSION}-%{RELEASE}'`, `.PKGINFO pkgver`), and the workspace `Cargo.toml` is unchanged
  (`git diff --exit-code Cargo.toml Cargo.lock`). Entry in `docs/decisions.md`: `grep -q` for the title.
- nfpm pinned with checksum where supported → `grep -E '^nfpm *=' mise.toml` shows an exact version;
  `mise.lock` (or the `checksum` field) holds a checksum if mise supports it, otherwise the reason is in the
  step's commit; `grep -q nfpm harness/Containerfile` with the same version.
- cargo-deb gone → the three `! grep` lines of `verify`, plus `! grep -rqs 'cargo-deb\|cargo deb' mise.toml
  harness/Containerfile .github justfile`, `test ! -e data/debian`, and `cargo metadata` still resolves.
- `shell_scripts` covers the maintainer scripts whatever their names → the packaging scripts are named
  without `.sh` (`postinst`, `%post`-style names) so the test is real: `just shell-scripts-list | grep`
  contains each of them (the recipe prints `{{shell_scripts}}`); a temporary tracked script with a shell
  shebang and no `.sh` suffix and a shellcheck error makes `just lint` fail, and removing it makes it pass.
- Whole tree stays green → `just check` exit 0 (includes `scripts/check-files.sh` size limit on the new
  files, and the new tests added to `check`).
