# F36 — Build the .deb, .rpm and Arch package with nfpm from one file list

## Scope
Replace `cargo deb` with nfpm. `just package` builds the release binaries and then one `.deb`, one `.rpm`
and one `.pkg.tar.zst` (x86_64) in `target/packages`, from a single nfpm configuration.

Built here:
- `packaging/nfpm.yaml`: the one file list (source, destination, mode, owner of every installed file;
  everything under `/usr`, nothing in `/etc` or `/var`) and the common metadata. Per-format
  `overrides:` hold only metadata, dependency names and `polkit >= 124` where the format can say it.
- The service moves to `/usr/lib/custodio/custodiod` in all three formats (open question "Arch and
  `/usr/libexec`", option (a)). Only `ExecStart` in `data/custodio.service` changes. The D-Bus activation file
  `data/com.rfirma.Custodio1.service` needs **no** change: it keeps `Exec=/bin/false` and
  `SystemdService=custodio.service` on purpose, so `dbus-daemon` can only start the service through the
  hardened unit, never the binary directly. That is recorded in `docs/decisions.md` (a later session might
  "fix" the `/bin/false`). One unit, one activation file.
- Lifecycle script files, one set per format, with names that differ per format and no `.sh` suffix:
  - deb: `packaging/deb/postinst` only (no preinst, prerm, postrm). It keeps the M1 guard
    `[ "$1" = configure ]` around the three actions.
  - rpm: `packaging/rpm/post` only (nfpm `postinstall`, rendered as `%post`; no pre, preun, postun).
  - Arch: `packaging/arch/post_install` and `packaging/arch/post_upgrade` (nfpm `postinstall` and
    `postupgrade`, rendered as the functions `post_install` and `post_upgrade` of `.INSTALL`; M1's postinst also
    ran on upgrade, so both exist). No other function.
  Until F43/F44 each does only what `data/debian/postinst` does: `systemd-sysusers custodio.conf`,
  `systemctl daemon-reload`, `systemctl reload dbus`, each with `|| true`.
- `scripts/check-packages.sh`: the build gate run by `just package` on the real packages.
- `scripts/test-check-packages.sh`, `scripts/test-package-scripts.sh`, `scripts/test-shell-scripts.sh`: tests
  of the gate, of the lifecycle scripts and of `shell_scripts`. Recipes, all part of `check`:
  `package-gate-test` (runs the first two) and `shell-scripts-test` (the third). `check` stays fast and does
  not need `target/packages` nor a release build: the tests build their own small fixture packages with nfpm
  (a throwaway `nfpm` config in a temp dir, using a copied system ELF for the binaries, and the real
  `packaging/` scripts and unit file). `just package` runs `scripts/check-packages.sh` against the real
  packages; it does not run the fixture tests.
- Version scheme (below) and `docs/decisions.md` entries.
- Supply chain: nfpm and the checking tools installed in the dev image, CI and (nfpm) pinned in `mise.toml`.
  `cargo-deb`, `[package.metadata.deb]`, `data/debian` and every `cargo deb` use leave the repository,
  mise.toml, the dev image and CI. `target/debian` references move to `target/packages` (`e2e/run.sh`,
  `docs/manual-acceptance.md`, the `justfile` comments).
- `shell_scripts` in the justfile covers the maintainer scripts whatever their file names.

Version scheme (decision recorded in `docs/decisions.md`): source of truth is `[workspace.package] version`
in `Cargo.toml`, `X.Y.Z` or `X.Y.Z-pre`. The packaging revision is always `1` in all three formats (Debian
revision `-1`, RPM release `1`, Arch pkgrel `1`): the tree is the source, so there is no packaging-only rebuild
to number; bumping the workspace version is the only way to get a new package. A pre-release is passed to
nfpm as `version` plus `prerelease`, so each format uses its own pre-release sorting and not a plain `-`:
`0.2.0-rc.1` becomes deb `0.2.0~rc.1-1`, rpm version `0.2.0~rc.1` release `1`, Arch pkgver `0.2.0_rc.1`
pkgrel `1` (Arch forbids `-` in pkgver). Step 1 confirms with nfpm what it renders; if nfpm renders differently,
the scheme recorded is what nfpm renders, provided a pre-release sorts below its release in deb and rpm and
the Arch pkgver has no `-`. `just package version=X.Y.Z[-pre]` overrides the version without touching
`Cargo.toml` or `Cargo.lock`.

Left for other features: the parity check, glibc ceiling and package linters (other M2 gates), real lifecycle
behaviour (F43, F44), the e2e contents (it only needs the new path). Dependency lists name the libraries the
binaries link, read from `readelf -d`; no automatic computation.

Larger than five steps (eight, each small); a split is not needed.

## Steps
- [ ] Tooling. Install in `harness/Containerfile`: `nfpm` (pinned release tarball with its sha256 checked),
      `rpm`, `libarchive-tools` (bsdtar), `zstd`, `python3-yaml` (apt); `dpkg-deb` and `readelf` are already
      there. Pin `nfpm` in `mise.toml` (the aqua backend verifies the checksum; the checksum is recorded in
      `mise.lock` if the repo uses one, otherwise the reason is in the commit). Add a CI job `just package` in
      `.github/workflows/ci.yml` that installs the same tools (apt for rpm, libarchive-tools, zstd, python3-yaml;
      nfpm from the pinned release with a checksum) and runs the package recipes; the existing CI step that runs
      `just lint system-gates` also runs the two new test recipes. Run nfpm once on a throwaway config to record in
      `docs/findings.md` the file names it gives the three packages and how it renders `prerelease` for each,
      and check the dependency strings below against distro metadata (`apt-cache`, Fedora/Arch package pages).
- [ ] Tests first, `scripts/test-check-packages.sh` + fixtures + `scripts/check-packages.sh`: good set, missing
      package, file missing from one package, wrong mode, duplicate destination, path outside `/usr`, wrong
      dependency, fake NEEDED, missing tool. Recipes `package-gate-test` and `shell-scripts-test` added to
      `check`.
- [ ] Move `ExecStart` to `/usr/lib/custodio/custodiod`; leave the activation file as is.
- [ ] `packaging/nfpm.yaml` with the single file list, per-format overrides, and the lifecycle script files;
      `scripts/test-package-scripts.sh`.
- [ ] `package` recipe: release build, version derivation and override, `target/packages` cleaned first, nfpm
      for each of the three formats, then `scripts/check-packages.sh`. Update `e2e/run.sh`,
      `docs/manual-acceptance.md` and the recipe comment for `target/packages`.
- [ ] Remove cargo-deb: `[package.metadata.deb]` (and its comment), `data/debian`, `mise.toml`,

- [ ] `shell_scripts` rewritten to cover scripts by shebang; `scripts/test-shell-scripts.sh`.
- [ ] `docs/decisions.md` entries (version scheme; libexec move and why the activation file keeps
      `Exec=/bin/false`); run `verify` and the evidence below.

## Evidence
- Tools are installed and a missing one fails, not skips → `harness/Containerfile` contains `nfpm`, `rpm`,
  `libarchive-tools`, `zstd`, `python3-yaml` and `.github/workflows/ci.yml` installs the same (`grep -q` for each);
  `grep -E '^nfpm *=' mise.toml` shows an exact version equal to the one in the Containerfile and CI. The test
  in `scripts/test-check-packages.sh` runs `scripts/check-packages.sh` and the test's own nfpm step with a PATH
  that lacks, in turn, each of `nfpm`, `dpkg-deb`, `rpm`, `bsdtar`, `readelf` and `python3`, and expects exit
  status non-zero and a message naming the tool (never 0, never a skip).
- One .deb, one .rpm, one .pkg.tar.zst in target/packages → `just package && ls target/packages` and the three
  `test $(ls … | wc -l) -eq 1` lines of `verify` → exit 0, each count is 1; after `just package version=0.1.1`
  and again `just package` the directory still has exactly one of each (it is cleaned).
- Built from a single nfpm configuration listing every file once → `test $(ls packaging/nfpm*.y*ml | wc -l) -eq 1`;
  `scripts/check-packages.sh` fails if a destination appears twice in `contents`, and the test's fixture with a
  duplicate destination makes it fail.
- Every file of the list is in every package, with its mode and owner → `scripts/check-packages.sh` reads
  `packaging/nfpm.yaml` with `python3 -I` + `yaml` and compares with `dpkg-deb -c`, `rpm -qp --dump`, and
  `bsdtar -tvf` (Arch) → exit 0 on the real packages. `scripts/test-check-packages.sh`, on fixture packages built
  with nfpm, removes one file from one package (each format in turn), removes one whole package, and changes a
  mode: each gives non-zero exit and a message with the path and the format.
- The ten files are installed (service, CLI, PKCS#11 module, systemd unit, sysusers, D-Bus policy and
  activation, polkit action, p11-kit module, journal catalog) → the gate also compares against an explicit
  list of those destinations written in the gate (not read from nfpm.yaml); a fixture whose nfpm.yaml omits one
  fails.
- All under /usr, nothing in /etc or /var → the gate lists every path of each package (including dirs and
  config-typed entries) and fails on any not starting with `/usr/`; a fixture with `/etc/x` fails, one with a
  `config|noreplace` entry fails, and `/var` likewise.
- Service at /usr/lib/custodio/custodiod in all three formats; one unit and one activation file →
  `grep -qx 'ExecStart=/usr/lib/custodio/custodiod' data/custodio.service`; `! grep -rqs '/usr/libexec' data`
  (from `verify`); the gate extracts the unit from each package, takes its `ExecStart` and checks that this path
  is in the package as a regular file with mode 0755, and that no `/usr/libexec` path exists in the package;
  `test $(ls data/*.service | wc -l) -eq 2` and `ls data/*.service` names the unit and the activation file only.
  `just system-gates` still passes (its `unit-verify` stubs `ExecStart`).
- The activation file is untouched in its dangerous part → `grep -qx 'Exec=/bin/false' data/com.rfirma.Custodio1.service`
  and `grep -qx 'SystemdService=custodio.service' data/com.rfirma.Custodio1.service`; the gate checks that the
  packaged activation file has the same two lines; `git diff --stat` for the feature shows no change to that file
  and `ExecStart` as the only changed line of `data/custodio.service`. The decision entry exists
  (`grep -q 'Exec=/bin/false' docs/decisions.md`).
- Overrides hold only metadata, dependency names and polkit >= 124 → a test parses `packaging/nfpm.yaml` and
  fails if any `overrides.<fmt>` contains `contents`, or any key outside the allow-list (`depends`, `provides`,
  `conflicts`, `replaces`, `recommends`, `scripts`, and the format's metadata block `deb`/`rpm`/`apk`/
  `archlinux`); `scripts` there may only be file paths; a fixture with `contents` in an override fails.
- Dependencies by name and exact declaration, checked in the package metadata (`dpkg-deb -f … Depends`,
  `rpm -qpR`, `bsdtar -xOf … .PKGINFO`), comparing with whitespace normalised:

  | | .deb | .rpm | Arch |
  |---|---|---|---|
  | polkit | `polkitd (>= 124)` | `polkit >= 124` | `polkit>=124` |
  | systemd | `systemd` | `systemd` | `systemd` |
  | system bus | `dbus-system-bus` | `dbus-daemon` | `dbus` |
  | p11-kit | `p11-kit` | `p11-kit` | `p11-kit` |

  The .deb has `polkitd` and no bare `polkit` entry; the .rpm and Arch have `polkit` and no `polkitd`. An
  unversioned polkit dependency fails (fixture). The system-bus names were chosen to be provided by both dbus
  implementations (dbus-daemon and dbus-broker); step 1 verifies them against distro metadata and records the
  result in `docs/findings.md`. If one is not provided by both, the implementer writes `BLOCKED.md` rather than
  weakening the check.
- Every shared library the binaries link is a dependency → the gate runs `readelf -d` on the three ELF files
  extracted from each package and maps every `NEEDED` soname to a package name per format, from a table in the
  script, e.g. `libc.so.6`, `libm.so.6`, `libdl.so.2`, `libpthread.so.0`, `librt.so.1` → `libc6` / `glibc` /
  `glibc`; `libgcc_s.so.1` → `libgcc-s1` / `libgcc` / `gcc-libs`; any other soname the real binaries link is added
  in step 4. Each mapped name must be in the package's dependency list. The only exemption is the dynamic loader
  (`ld-linux-x86-64.so.2`, the `PT_INTERP` of the binary): it is not a library the code links by choice and the
  glibc package that ships it is already required through `libc.so.6`. Fixtures: (a) removing `libgcc-s1` from the
  .deb `Depends` fails (no libc/libgcc exemption), same for `glibc` in the rpm and `gcc-libs` in Arch; (b) a
  binary whose `NEEDED` has a soname not in the table (the fixture copies a system ELF and edits `libc.so.6` to
  `libq.so.6` in place) fails and names the soname.
- Own lifecycle script files per format that do only what the M1 postinst does → the packages contain the scripts
  (`dpkg-deb -e`, `rpm -qp --scripts` / `--qf '%{POSTIN}…'`, `.INSTALL` of Arch) and the gate checks the exact
  set per format: deb has `postinst` and none of `preinst`, `prerm`, `postrm`; rpm has a post scriptlet and
  none of pre, preun, postun, pretrans, posttrans; Arch `.INSTALL` defines `post_install` and `post_upgrade` and
  no other function. The four source files are distinct paths. `scripts/test-package-scripts.sh` extracts the
  scripts from the fixture packages, runs each with `systemd-sysusers`, `systemctl` placed as recording stubs on
  PATH (deb: `postinst configure`, also `postinst abort-upgrade` which must record nothing; rpm: `post 1` and
  `post 2`; Arch: source `.INSTALL`, call `post_install` then `post_upgrade`), and asserts the recorded calls are
  exactly `systemd-sysusers custodio.conf`, `systemctl daemon-reload`, `systemctl reload dbus` in this order and
  nothing else; stubs that fail must not make the scripts fail (`|| true`). It is part of `check` through
  `package-gate-test`, distinct from the F43/F44 `just test-scripts`.
- The recipe fails if any package is missing or a file is missing → `scripts/check-packages.sh` exits non-zero in
  the fixtures above; additionally the test runs the `package` recipe's final step (the gate on a directory) with
  one of the three files deleted, for each format, and expects non-zero. `just package` runs the gate last, so its
  failure fails the recipe.
- Versions → per the scheme in Scope: `just package` yields packages whose metadata match `Cargo.toml`'s version
  (`dpkg-deb -f … Version` = `0.1.0-1`; `rpm -qp --qf '%{VERSION}-%{RELEASE}'` = `0.1.0-1`; `.PKGINFO` `pkgver = 0.1.0-1`,
  where Arch's pkgver-pkgrel is `0.1.0-1`); the file names are found by glob (`custodio_*.deb`,
  `custodio-*.x86_64.rpm`, `custodio-*-x86_64.pkg.tar.zst`) and the exact names nfpm gives are the ones recorded

  `0.2.0-rc.1` and checks the metadata: deb `0.2.0~rc.1-1`, rpm `0.2.0~rc.1` / `1`, Arch `0.2.0_rc.1-1`, and that
