# F173 — The Firefox snap socket: tmpfiles.d directory, socket unit, and the service taking it

## Scope
Builds, for the `firefox` snap only: the shipped `tmpfiles.d` entry and socket unit (every package
format), the `PrivateUsers=` change F170 decided, custodiod taking the passed socket by name next
to the bus with the directory check, and the two gates. Left for other features: the peer label
parser (F174), the per-connection peer check, the p2p handshake and any method (F175; here a
connection is accepted and closed, nothing is read or answered), the module's client, journal
fields, limits. Acceptance 1 and 8 are proven here; 15 is proven for the exposure score (the
test-label half is F175). That the directory and socket exist on a real install under a VM is case
17, a later feature. The package gates, lifecycle and parity tests and `just e2e` on other targets
run at the checkpoint; this feature only edits the lists they read (step 7).

Fixed by earlier work: `docs/findings/F170.md` Decisions (`PrivateUsers=identity`, systemd 257 floor,
exposure stays 0.7, measured today with the current unit: `0.7 SAFE`; Debian 13 ships systemd 257).
The socket's name tells custodiod which snap it is for, so the code derives `/run/snap.<snap>/` from
the name and nothing else (SPEC Design 1). The builder picks the unit and descriptor names; the
service unit is the one activated (`Service=custodio.service` if the socket's name differs).

Environment: `systemd-analyze security --offline`, `systemd-tmpfiles --root` and the debian13
container are available (existing gates and `scripts/test-relabel.sh` use them). Unit-test fixtures use
real directories: `/usr` (root, 0755) is the accepted case, `/tmp` (root, sticky, world-writable)
and a tempdir owned by the test user are refused, and a symlink to `/usr` is refused. No privilege
is needed. The tests cannot create a root-owned directory of another mode, so group- and
other-writable root-owned cases use the check function over real metadata where it is injectable
without a mock of the filesystem (builder's call) or `/tmp` and a chmod'ed tempdir.

Known tension the builder resolves, within the limits here: `scripts/test-relabel.sh` forbids
packaging scripts that call `systemd-tmpfiles`, and the unit "is never enabled" in the maintainer
scripts today. The socket needs its directory before it starts and needs to be started on install
and stopped before the service on removal (a socket left running restarts a stopped service).
Whatever the scripts do must keep install tolerant of a missing live systemd, and `test-relabel.sh`
is amended only as narrowly as needed with its own negative control kept.

Cost of the new tests (estimates from similar ones):
- `crates/custodiod/tests/snap_socket_dir.rs`, plus unit tests of the descriptor-name logic: parallel
  with the other integration tests, under 3 s once built (tempdirs, one in-process socket, the
  existing private-bus harness for "bus unaffected"). No sleeps; waits are on the connection.
- `scripts/check-snap-sockets.sh` ~0.2 s (greps); `scripts/test-check-snap-sockets.sh` ~3 s of fixture
  copies and runs of the gate. It joins `test-scripts` and runs in parallel with the other script
  tests (`test-check-unit-hardening.sh` takes 2 s now); within the 120 s `script *` budget.
- One e2e case (step 8) in `e2e/targets/debian13/cases.list` only (SPEC end-to-end scope, the
  unit is the same on every distribution and the parity of the files is a gate). It reuses the guest
  the run already has: about 5 s added to a debian13 run (budget 800 s), waited on conditions
  (`systemctl is-active`, the connection's EOF), never `sleep`.
- `just system-gates` gains the new script, about 1 s. `just mutants-diff F173` is run by `verify`.

Fits in about eight steps over two sessions; no split proposed.

## Steps
- [ ] Failing tests first: `crates/custodiod/tests/snap_socket_dir.rs` and unit tests of the socket
      selection (which passed descriptors are the snap sockets), then the code below to pass them.
- [ ] Descriptor handling in custodiod: take the passed sockets by systemd name alongside the bus
      (`LISTEN_PID` must be the process, `LISTEN_FDS` count, names); only a descriptor named for a
      known snap socket is used, an unnamed, unknown or surplus one is closed and ignored. The snap
      is read from the name; no unsafe code (`forbid(unsafe_code)` stays).
- [ ] Directory check before serving: the directory of the socket is opened without following a
      symlink, is a directory, is owned by root and has no group or other write bit. Otherwise
      the socket is not served and a line naming the socket and the reason goes to the journal (the
      process's stderr is the journal under systemd); the connection backlog is left unserved; the
      bus connection starts and serves as usual.
- [ ] Serving: accept connections on the checked socket, close each at once; read and write nothing.
      A failed accept does not end the service.
- [ ] Units and files: add `data/` files for the tmpfiles entry (`/run/snap.firefox/`, root, `0755`, the
      only snap) and the socket unit (listens on `/run/snap.firefox/custodio.sock` and no other,
      reachable by any uid, named descriptor, activates custodio.service, installs into
      `sockets.target`); the service unit gets `PrivateUsers=identity` and no `RuntimeDirectory=`;
      nothing else in it loosens. Both files are listed for every format in `packaging/nfpm.yaml`
      without a `packager:` restriction. The exposure score of the service stays at or below 0.7.
- [ ] Gates, test first: `scripts/check-snap-sockets.sh` (in `just system-gates`) and its test with
      negative controls; `scripts/check-unit-hardening.sh` and its test updated to the new
      `PrivateUsers=` value (`yes`, `no` and a missing line now fail; every other check unchanged);
      a score ceiling of 0.7 that fails on a unit scoring above it.
- [ ] Packaging scripts and expected-file lists: the files in `e2e/lifecycle-lib.sh`,
      `scripts/package_expected.py` and any parity/lint list; the maintainer scripts of the four
      formats start/enable the socket on install, restart it with the service on upgrade, and stop
      it before the service on stop/removal/purge. `scripts/test-relabel.sh` amended as in Scope.
      Checked here with the script tests that cover those files (`test-relabel`, the static script
      tests), not with the package gates.
- [ ] One debian13 e2e case (name per `e2e/check-cases.sh` conventions) and its line in
      `e2e/targets/debian13/cases.list`; run `just e2e debian13` once at the end after `just quick`
      and `just system-gates`, plus `just mutants-diff F173`.

## Evidence
- Packages ship the tmpfiles entry in every format → `scripts/check-snap-sockets.sh` (run by
  `just system-gates`) → passes on the shipped files: the entry is exactly one line
  `/run/snap.firefox/` with type `d`, mode `0755`, user `root`, group `root`, no other path; both
  files appear in `packaging/nfpm.yaml` for all of deb, rpm and archlinux.
- Socket unit listens only on `/run/snap.firefox/custodio.sock` and activates custodio.service →
  same gate → passes on the shipped unit: exactly one `ListenStream=` with that path, a single
  `Accept=no`, the named descriptor, no other `Listen*=`, and the service it starts is custodio.service.
- Never `RuntimeDirectory=` → same gate checks `data/custodio.service` and the socket unit for
  `RuntimeDirectory=` and `RuntimeDirectoryPreserve=`; fails on either.
- "Exactly the Firefox ones", negative controls → `scripts/test-check-snap-sockets.sh` → each fixture
  makes the gate fail with a message: a second snap (a second tmpfiles line or a second
  `ListenStream=`), mode `0775`, `RuntimeDirectory=` in the service, plus owner not root and a
  socket path outside the directory; the unmodified files pass.
- Unit takes F170's uid route, hardening check updated, nothing else loosened →
  `scripts/test-check-unit-hardening.sh` → `PrivateUsers=identity` passes; `yes`, `no`, a missing
  line and a duplicated line fail; the existing controls (TPM node, TCTI, `ProtectProc`, threshold
  10) still fail on their fixtures.
- Exposure score not above M5's → `just system-gates` (security-score plus the new ceiling) → the
  shipped service reports 0.7 or lower; the ceiling test shows a unit with `PrivateUsers=no`
  (0.8, F170) fails it.
- custodiod takes the passed socket by name → unit tests in `crates/custodiod` → a descriptor named
  for the Firefox socket is selected; an unnamed one, another name, a `LISTEN_PID` that is not the
  process and a count mismatch select nothing and leave the descriptor unused.
- Directory owned by root and writable by root alone is served → `snap_socket_dir.rs` → with `/usr`
  as the directory the socket is served: a client connects and reads end-of-file.
- Another owner, group-writable, other-writable, symlink are not served, and why is journaled →
  `snap_socket_dir.rs` (one test per case: tempdir owned by the test user, a tempdir chmod'ed
  `0775`, one chmod'ed `0757`, `/tmp`, a symlink to `/usr`) → no connection is served (the client
  sees no accept and close from the service), and the captured journal line names the socket and
  the reason of that case, different for each.
- The bus is unaffected → same test file → with a refused directory, a `ListKeys` call on the
  private bus still answers on the shipped interface.
- Nothing is served beyond accepting and closing → `snap_socket_dir.rs` → a served connection gets
  end-of-file without a reply, also after the client sends bytes; the service stays up and accepts
  a second connection.
- The unit changes and runs end to end → the new debian13 e2e case in `just e2e debian13` →
  after the install `/run/snap.firefox` is `root:root 0755`, the socket unit is active and
  listening on the path, a connection as an unprivileged user starts custodio.service, which is
  active and ends the connection with end-of-file; the service shows `PrivateUsers=identity`,
  a bus `ListKeys` still works, and the removal and purge cases of the run still pass with the
  socket stopped first.
- Cheap-level negative control for the e2e case → the case's check of the directory mode is run
  on a fixture value in the case's self-test (if the case ships one, as the other cases do): `0775` fails.
- Mutation coverage of the directory check and descriptor selection → `just mutants-diff F173` →
  no surviving mutant in the new code.
