# F167 — The documentation states the Debian 13 reading

## Scope
Reading in `docs/findings/F166.md` (run 2026-11-09, Debian 13.7, systemd 257.13, virtual TPM): **PCR 7 confirmed**,
a user-scoped credential has mask `0x80`. So the documents take the "confirmed" branch; the "refuted" wording is
not written.

Built (documents, plus the tests that check them against the code):
- `docs/api.md`, "Storage kinds": states that on Debian 13 (systemd 257) the daemon's credential is bound to PCR 7
  (mask `0x80`), **verified** in `docs/findings/F166.md` (cited); that the service refuses a credential with a
  nonzero mask, so `encrypted-tpm` is unavailable there when a TPM is present (the choice list: a TPM that lacks a
  capability then ends in `CredentialsUnavailable`, never in a weaker kind, as the section already says for faults);
  and that Alma 10 (also systemd 257) is **inferred** from the Debian 13 reading, not run.
- `docs/install.md`, "Supported systems": the same two facts in one short paragraph, citing F166.
- `docs/findings/F110.md` and its index line in `docs/findings.md`: the "inferred" PCR 7 statements (the default
  mask of 255-257, the Debian 13 / Alma 10 deviations) are corrected: Debian 13 verified by F166, Alma 10 inferred
  from it. Findings rules at the top of `docs/findings.md` are followed (conclusion first, verified/inferred marks).
- Tests: the existing documentation tests are extended, never grepping a citation or heading wording.
  `scripts/test-docs-install.sh` reads the mask the code refuses on a PCR-bound credential (the
  `HeaderError::PcrBound` test vector `0x80` in `crates/custodiod/src/creds/header/tests.rs`, and the systemd
  floor 257 from `packaging/nfpm.yaml`) and checks that "Supported systems" states that mask and that floor for
  Debian 13, and calls Alma 10 inferred. `scripts/test-docs-api.sh` / `docs_api_run.py static` checks the same mask
  in "Storage kinds" and that `encrypted-tpm` is one of the kinds `just api-contract` already ties to the code.
  If a check needs only a bare statement of fact in the code, it reads the code; otherwise it is left to the
  evaluator's review of the prose (not a test).
- Not here: the real Debian 13 run (F166, done); the e2e and package gates (checkpoints). The code is not changed.

Costs: both scripts are existing script tests running in parallel with the other script tests (inside `just quick`);
the additions are a few greps/awk calls on two small files, under 1 s each, no new suite and no e2e case. Nothing
touches the environment, so no environment probe is needed. Size: four small documents and two test edits, fits one
session (about 5 steps).
