# F195 — Import tells a wrong password from an unreadable file, in the service and the CLI, and the Firefox restart note

## Scope

Built here:

- **Service.** `ImportP12` tells three failures apart, from the file and the library's result and never from timing:
  (a) the file has a MAC and it does not verify with the password; (b) the file is not readable PKCS#12 whatever the
  password, or it is readable and holds no usable key and certificate (no private key, several, a key without a
  certificate); (c) the file has no MAC and does not decrypt, where the library cannot tell (a) from (b).
  Two new D-Bus errors for (a) and (b); `WrongPasswordOrBadP12` stays for (c) only. Journal: (a) and (c) keep
  `wrong_password`, (b) gets one new outcome. The file is still decoded only after polkit approves. `parse_p12`'s
  error type learns the distinction (today `ImportError::Parse(String)` covers all of it); the exact names of the two
  errors and the outcome are the builder's, documented in `docs/api.md` and `docs/audit.md` under their
  compatibility rules (names only added, none changed). The p12_parse fuzz target keeps building and running.
- **CLI.** `ServiceFailure` maps the two new names; the three messages are two lines each (line 1 what went wrong,
  line 2 the next step): (a) retype the password; (b) export the file again, pointing to the README section that shows
  how from Firefox; (c) both. After a successful `custodio import` and a successful `custodio delete`, the CLI prints
  the note that Firefox and any other running program that loaded the module see the change only after they restart.
  The note is not printed on failure, on a declined or non-interactive delete. Man page, `README.md` (its import and
  delete examples are run as written by `test-docs-readme.sh`; the new section on exporting from Firefox is prose) and
  the CLI's help text are updated to match.
- **Consumers of the old names.** `e2e/ops-lib.sh` (`OPS_WRONG_PASSWORD`), `e2e/jo-user.sh`, `e2e/cli-run.sh`,
  `scripts/docs_api_run.py` and the e2e cases that import a MAC-protected fixture with a wrong password now get the
  new (a) error. The builder finds them (`grep -rn "WrongPassword\|wrong password" e2e scripts`) and updates them in
  the same commit. Those scripts are proven by the run that uses them, at the checkpoint; no stub test.

Fixtures (real `.p12` files, `gen.sh` in both `crates/custodiod/tests/fixtures` and `crates/custodio-it/tests/fixtures`,
copied alike as today): a MAC-less file with a key and certificate (`openssl pkcs12 -nomac` or equivalent); for each of
the three unusable shapes (no private key, two keys, a key and no certificate) one file with a MAC and one without; and a
file of bytes that is not PKCS#12. That is seven (b) files: the non-PKCS#12 bytes, three with a MAC, three without. (a)
reuses an existing fixture with a wrong password. Step 1 first runs the real library on each and records, in `docs/findings/F195.md`,
which `Pkcs12Archive` / BER-path result each case gives and how the decoder reads "a MAC is present" from the file
(the outer `PFX` structure; the library returns `MacError` only after reading it). The classification rule is then built
on that evidence. The finding says, for each of the six unusable files and for each of the right and a wrong password,
what the library returns and so which of (a), (b), (c) the file gets, and it names the function that decides.
The classification is by the library's result, not by how the fixture was built (deviation F195 in
`SPEC_DEVIATIONS.md`, `pending`, proof in the finding): a MAC is present and does not verify = (a), whatever the
contents; no MAC and decryption fails = (c); the library returns a structural error (no key, no certificate, two
keys, a key without a certificate, not PKCS#12) = (b). With the right password every unusable file is (b); with a
wrong password (b) happens only for files whose defect is visible without decrypting (the non-PKCS#12 bytes and
MAC-less files with plain bags). The two-keys files, one with a MAC and one without, are made by a small generator
kept next to `gen.sh`.

Not built here: the storage-classifier finding, `doctor`, `fingerprint`, completions (other features). The
checkpoint runs `just e2e`, `just test-scripts` and the package gates; the updated e2e consumers are proven there.

Environment: needs `dbus-daemon` (already used by the `custodiod` and `custodio-it` bus tests), `openssl` for
regenerating fixtures (already used by `gen.sh`), nightly and cargo-fuzz for the fuzz recipes (as earlier fuzz
features). Nothing new: no command to try.

Sizing: about six steps; step 1 (finding and fixtures) is the riskiest. If a session runs short, the split is
(1-3 service) and (4-6 CLI). I do not edit features.json.

Cost of the tests (estimates from `import_polkit` and `import_errors`, which do the same work; the builder reports
the measured times in PROGRESS.md):

| Test | Time | How it runs |
|---|---|---|
| unit tests of the classification in `import.rs`, `error.rs`, `operation.rs`, `failure.rs` | under 1 s | parallel, in the lib test binaries |
| `crates/custodiod/tests/import_split.rs` (a `[[test]]` of its own in `Cargo.toml`, since `autotests = false`; a private bus, a fake polkit, one fixture per case, MAC derivation 10 000 iterations) | about 2 s | its tests run in parallel |
| `crates/custodio-it/tests/import_messages.rs` (the CLI binary against the real service on a private bus) | about 3 s | its tests run in parallel |

No e2e case is added: the behaviour does not depend on the distribution, and the service and CLI are proven against
the real service on a bus. The e2e consumers keep running in their existing cases.

## Evidence

- (a) MAC present, does not verify → `import_split` test "wrong password with MAC": fixture with a wrong password → the new
  wrong-password D-Bus error, journal outcome `wrong_password`, nothing stored. Fails if (a) returned the combined error or
  the unreadable one.
- (b) not readable PKCS#12, whatever the password → `import_split`: the non-PKCS#12 bytes with the right and with a wrong
  password → the new unreadable-file error and its new journal outcome both times. Fails if the password mattered.
- (b) no private key, several keys, a key without a certificate → `import_split`, one assertion per file and per password,
  by the library's result (finding table): with the right password each of the six files (three with a MAC, three
  without) → the unreadable-file error and its journal outcome. With a wrong password: a MAC file → (a) (the
  wrong-password error, `wrong_password`); a MAC-less file whose defect is visible without decrypting (plain bags, e.g.
  `nokey-nomac`) → (b); a MAC-less file with a shrouded key → (c) (`WrongPasswordOrBadP12`). The finding lists the
  cell of each of the six files, including both two-keys files, and the test asserts exactly those. Fails if any cell
  gets another error.
- (c) no MAC, does not decrypt → `import_split` on the MAC-less fixtures with a wrong password that fail on decryption
  (`good-nomac`, and the shrouded-key unusable ones) → `WrongPasswordOrBadP12`, journal `wrong_password`. And
  `WrongPasswordOrBadP12` is returned by no other case (asserted in the tests above).
- Two new D-Bus errors, `WrongPasswordOrBadP12` for (c) only, journal `wrong_password` for (a) and (c) and one new outcome
  for (b) → the same `import_split` assertions, plus the unit tests of `ImportOutcome::all/name/priority` and the
  error-name mapping (wildcard-free matches stop compiling when a variant is added).
- Decided from the file and the library's result, never from timing → the classification is a function of the bytes and the
  password, shown by the unit tests over fixtures (no clock, no sleep in the code under test); the finding records the rule.
  Review checks that the function the finding names has no time source.
- File never opened before polkit approves → `import_split` denied-polkit tests with a counting decoder around the real one:
  count 0, error `PolkitDenied`, journal `denied`, for a file of each kind (a), (b), (c); count 1 after an approved call.
  Fails if the decode moved before authorization. The bytes arrive over D-Bus, so decoding them is the only way the file is
  "opened"; the counting decoder measures exactly that.
- `docs/api.md` and `docs/audit.md` add the names under their compatibility rules; `just api-contract` checks them →
  `just api-contract` passes; the builder removes one new name from the document once, sees it fail, and records the command and result in
  PROGRESS.md (not a kept test: the existing contract test already enumerates the code's names). `scripts/test-docs-api.sh` runs the new `console`
  examples as written and its existing negative controls still fail.
- The p12_parse fuzz target still runs → `just fuzz-build && just fuzz-smoke` pass with `p12_parse` in the run.
- `custodio import` maps the two new errors and the combined one to two-line messages (a) retype the password, (b) export the
  file again (README shows how), (c) both → unit tests in `custodio-cli` over every name (line count 2, next step text per
  case) and `import_messages.rs`: the CLI binary against the real service with the F195 fixtures, one test per case, checks
  standard error has exactly two lines with the right next step, standard output is empty, exit status as the existing
  failure status. Fails if (a) and (b) share a message.
- After a successful `custodio import` and `custodio delete`, the note about Firefox and other running programs needing a
  restart → `import_messages.rs`: a successful import and a successful delete each print the note on standard output (the stream of the success line, and the only text there besides it); a failed import (each of
  the three cases), a declined delete and a delete of an absent key do not. Acceptances 13 and 15 (CLI part).
- Man page updated → `cargo test -p custodio-cli --test help` (man-page parity, runs in `just quick`) passes with the new

  `custodiod` import tests pass with the updated names; `just quick` green.
- The new code is tested → `just mutants-diff F195` reports no missed mutant.
