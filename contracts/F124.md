# F124 — The unit reaches the TPM and the credential service

## Scope
`data/custodio.service`, `scripts/check-unit-hardening.sh` and `scripts/test-check-unit-hardening.sh` change. Nothing else.

- **Unit.** It gains exactly the directives of the `Decision:` line of F109 (`docs/findings/F109.md`): `DeviceAllow=/dev/tpmrm0 rw`,
  `BindPaths=-/dev/tpmrm0`, `SupplementaryGroups=tss`, next to the existing `PrivateDevices=yes` and `PrivateUsers=yes`, which stay.
  Nothing names the raw `/dev/tpm0` or `/dev/tpm*`, and no TCTI override is set (no `Environment=`, `EnvironmentFile=`,
  `PassEnvironment=` or `UnsetEnvironment=`-defeating line carrying `TCTI`, nor `CUSTODIOD_TEST_SWTPM_TCTI`; see
  `docs/decisions.md`, "The test-only TPM socket variable").
- **Credential service.** F110 decided that the service speaks Varlink to `/run/systemd/io.systemd.Credentials` as uid `custodio`,
  scope `user`; its probes ran under the shipped unit minus `Type=dbus`/`BusName=`/`After=`/`Requires=`. Step 1 re-reads F110
  and records in the commit which unit directive, if any, that access needs. The shipped unit already has `AF_UNIX`, and `/run` is
  readable under `ProtectSystem=strict`; if F110 names no directive, none is added and the commit says so. If it names one, it is
  added and the check expects it. Nothing beyond what F110 names is added (no `After=`/`Wants=` on a unit F110 does not need).
- **Environment.** Dev container, `systemd-analyze security --offline=yes --threshold=10` on a copy of the unit with the three
  F109 directives: `Overall exposure level for custodio.service: 0.7 SAFE`, exit 0 (matches the 0.7 of F109). The threshold stays
  10; the F109 contract is that it is not raised. If a F110 directive pushes the score over 1.0, the builder writes `BLOCKED.md`.
- **Left to other features:** that the device filter really admits the real node, and a real TPM open under the unit
  (F147 hardware acceptance, per F109); the package creating or depending on the `tss` group (packaging features); the
  install/lifecycle and `just e2e` runs (F90, F100).

## Steps
- [ ] Re-read the `Decision:` lines of F109 and F110; note which directives the credential service needs (possibly none).
- [ ] Failing cases first in `scripts/test-check-unit-hardening.sh` (names in Evidence), run to see them fail.
- [ ] Extend `scripts/check-unit-hardening.sh`: each new directive expected exactly once (same whitespace-tolerant exact match as
      the existing three); refuse any `DeviceAllow=`/`BindPaths=`/`BindReadOnlyPaths=`/`DevicePolicy=`-granting line that names
      a raw TPM device or a wildcard that covers it, and any TCTI override. Update the header comment and the `justfile`
      `unit-hardening` comment, not the recipe's gating.
- [ ] Add the directives to `data/custodio.service` (with a comment citing F109/F110), plus any directive step 1 found.
- [ ] Run `just quick`, then the `verify` command, until green.

## Evidence
- Only the access F109 decided → `scripts/test-check-unit-hardening.sh` case "real unit passes" plus a case per new directive
  removed ("DeviceAllow missing", "BindPaths missing", "SupplementaryGroups missing"), each → the gate fails.
- The new directives are exact → cases changing each value (`DeviceAllow=/dev/tpmrm0 r`, `BindPaths=/dev/tpmrm0` without `-`,
  `SupplementaryGroups=wheel`), and duplicates of each (also spaced around `=`) → the gate fails.
- Nothing for the raw device → cases adding `DeviceAllow=/dev/tpm0 rw`, `DeviceAllow=/dev/tpm0 rw` beside the good line,
  `BindPaths=-/dev/tpm0`, `DeviceAllow=char-tpm`/`/dev/tpm*` → the gate fails; the real unit has no `tpm0` token (the passing
  case above is the control that the checker does not reject `tpmrm0`).
- No TCTI override → cases adding `Environment=TSS2_TCTI=device:/dev/tpm0`, `Environment=TPM2TOOLS_TCTI=...`,
  `Environment=CUSTODIOD_TEST_SWTPM_TCTI=swtpm:path=/x`, and an `EnvironmentFile=` / `PassEnvironment=TCTI` line → the gate fails.
- Credential service access → the Step-1 note in the commit; if a directive was added, a missing-directive case as above. With
  none added, `grep -c` of the unit shows no line beyond F109's (the diff of the unit in the commit is the three lines).
- Exposure gate passes at its threshold → `just system-gates` (`security-score` at 10, bare-unit control, `unit-verify`,
  `unit-hardening`, `bus-policy`) → exit 0, score line `SAFE`; the threshold-11 and unreadable-threshold cases that already
  exist in the test script still fail the gate.
- Existing three settings and threshold still enforced → the existing cases in `scripts/test-check-unit-hardening.sh` keep passing.
