# F41 — Confirm whether polkit 124 reads ProcessFD from the bus

## Scope
A research feature with one conditional follow-on. It settles the SPEC.md open question "polkit 124
and the bus pidfd": does polkit 124 (Ubuntu 24.04) take the pidfd of a system-bus-name subject from the
`ProcessFD` key of the bus's `GetConnectionCredentials` reply, or does it fall back to the PID?

The reading is done by a subagent (CLAUDE.md: outside material goes to subagents) and the builder
records only conclusions. It must read the polkit 124 release source (the upstream tag and the Ubuntu
24.04 source package, since Ubuntu's patches may change this code), covering at least the system-bus-name
subject code (`polkitsystembusname.c`) and whatever turns that subject into the process that
`polkit_backend_*` authorizes against. "Reads `ProcessFD`" means more than the key being parsed: the
pidfd obtained from the bus must be what identifies the process in the authorization check, and a
missing `ProcessFD` must be a visible difference (fallback or failure), not a silent PID path when the
key is present. If 124 only parses the key but still checks by PID, it falls short. If the evidence is
ambiguous, the answer is "falls short" (the conservative option), and the findings say which part was
ambiguous.

The answer is a single verdict with two outcomes:
- **A, 124 reads `ProcessFD`:** only `docs/findings.md` changes. The open question is settled there and
  the existing section 3 sentence "Which polkit release first did this is not pinned down" is corrected
  to what was found. Packages keep `>= 124`, Ubuntu 24.04 stays supported (with `dbus-broker`).
- **B, 124 falls short:** the same findings, plus: the first polkit release that does read it is
  identified from source (not from NEWS alone); the minimum polkit declared by every package format
  (`packaging/nfpm.yaml`: deb, rpm, Arch) is raised to it; Ubuntu 24.04 is removed from the supported
  set in the docs and from the e2e matrix; `BLOCKED.md` asks the person approving the milestone to
  confirm, and the session stops after committing. Changing `SPEC.md` is not allowed (CLAUDE.md), so
  the docs that follow the spec (`docs/milestones.md`, README/docs lists, `e2e` targets and the
  `just e2e all` list) are the ones edited; the contradiction with SPEC.md is stated in `BLOCKED.md`.
  The refusal-case target for Ubuntu 24.04 is F50's, which depends on this answer, so only existing
  files are edited here, and a missing file is not created.

Left for other features: any Ubuntu 24.04 work (F50 refusal e2e, install docs F51, the `dbus-broker`
switch), changing the runtime check in `custodiod` (F39/F40 are unaffected), and reading polkit
versions other than 124 beyond what is needed to name the first good release in outcome B.

Size: four steps.
