# F100 — Checkpoint: end-to-end cases and documentation

## Scope
Nothing new is built. This feature runs the whole milestone's suites and fixes whatever fails, at its cause, with no gate
weakened (no `#[ignore]`, no lowered threshold, no `#[allow]` without a justification, no recipe turned into a no-op,
no case changed except where the case is wrong). It runs the whole `verify`:
`just check && just api-contract && just e2e && just package-gates`.

What the checkpoint proves, and where:
- `just check`: lint (including `deps-check`), every unit and integration test of the workspace (`custodio-it`), the
  system gates and the script tests (package-gate, install-script, e2e selector/self-tests, docs tests including
  `scripts/test-docs-api.sh` and `scripts/test-docs-manual-m3.sh`).
- `just api-contract`: acceptance 12 (client document against the live service: methods and arguments, error names,
  policy actions).
- `just deps-check` (inside `just check`): neither `custodio-cli` nor `custodio-pkcs11` reaches `custodiod`, in every
  dependency kind. Its negative control lives in `scripts/test-deps-check.sh` (part of `script-tests`).
- `just e2e` on all six targets (alma10, arch, debian13, fedora44, ubuntu2404, ubuntu2604): every case of
  `e2e/cases.list` exactly once per target, run or skipped as listed in that target's `skip.list`. This covers the M0–M2
  cases (acceptance 13) and the M3 cases of F91–F97 (ownership, replace, delete, journal, app-id, CLI, upgrade with
  two accounts: acceptance 1–11 as automated). The accounting fails on a missing, unknown or duplicated case.
- `just package-gates`: package, parity, glibc ceiling, package lint on the .deb, .rpm and Arch package.
- Not proven here: acceptance 14–16 (manual); F99 ships their written steps and a person runs them at the milestone.
- Not re-proven here: any individual behaviour already owned by an earlier feature's evidence; this feature only shows
  the suites still pass together.

Environment (commands run in the dev container, 2026-11-02): `podman info` succeeds; `nfpm`, `rpm`, `bsdtar`,
`lintian`, `cargo-deny`, `pkttyagent`, `setpriv` and `busctl` are present. `rpmlint` and `namcap` are not on the host,
so `package-lint` uses its container path. Images are pulled the first time; if an image cannot be pulled or a target
cannot boot systemd in the engine, that is a `BLOCKED.md` question for a person's run, not a reason to skip a target or
a case.

- [x] Run `just e2e-cases debian13` with one cheap case first, then the whole target, to confirm the shared set-up works

      is wrong, never to make it pass; skips stay exactly those in each target's `skip.list`.
- [x] Run `just package-gates`; fix every finding. Add to `packaging/lint/*.txt` only with a reason per entry and only
      for findings that are not defects.
- [x] Run the whole `verify` once, in order, from a clean tree; note the result and the per-target case counts in
      `PROGRESS.md`.
