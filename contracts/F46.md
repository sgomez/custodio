# F46 — End-to-end targets Fedora 44 and Alma 10

## Scope
Built here:
- Targets `fedora44` and `alma10`: `e2e/targets/<t>/` with `Containerfile` (`fedora44` from `docker.io/library/fedora:44`; `alma10` from
  `docker.io/library/almalinux:10`), `skip.list`, install step, probe and package pattern (`custodio-*.rpm`). The package is the `.rpm` of
  F44, mounted and installed with `dnf` (not copied into the image). Each target runs the shared guest of F45, with the cases of
  `e2e/cases.list` (including `journal-catalog` from F59) run or on its `skip.list`. A new target is a new directory: no shared script
  is edited to add one, except where a shared script is wrong for rpm distributions (then the change is small, keeps `debian13` and
  `ubuntu2604` passing, and is named in `PROGRESS.md`).
- The images carry the distribution's real polkit and its DEFAULT system bus daemon. This matters here: Fedora's default is expected to be
  `dbus-broker` (not installed in the base image; `docs/findings.md` section 3 says "inferred"), Alma's base image may have `dbus-daemon`
  or `dbus-broker`. The builder installs what the distribution pulls in by default for a booted system, the probe reads the daemon from
  the running bus (as F45 does), and the findings correct section 3 if the observed daemon differs from what it says. `probe.sh` must
  work for whatever daemon runs (including `dbus-broker`, whose `--version` output differs).
- Tool availability, settled by building the images. Checked while writing this contract (dev container, network available, images pulled):
  - `podman pull docker.io/library/fedora:44` and `docker.io/library/almalinux:10` → succeed (Fedora 44, Alma 10.2). `docker.io/almalinux/10`
    does not exist; use `almalinux:10`.
  - Fedora 44 (`fedora`, `updates`): `systemd` 259, `dbus-daemon` 1.16.2, `polkit` 127, `p11-kit`, `pkcs11-provider` 1.1, `opensc` 0.27.1,
    `nss-tools`, `python3-dbus` 1.4.0, `python3-gobject-base`, `openssl`, `procps-ng`, `util-linux` all have a candidate.
  - Alma 10.2 (`baseos`, `appstream`, `crb`, `extras`; no EPEL): `polkit` 125, `pkcs11-provider` 1.0 (baseos), `opensc` (baseos), `nss-tools`
    (appstream), `dbus-daemon` 1.14.10 (appstream), `python3-gobject-base` (baseos), `openssl`, `procps-ng`, `util-linux`; `systemd` 257 and
    `p11-kit` are already in the image. **`python3-dbus` has no candidate** in these repositories (`dnf list` shows only unrelated
    `python3-dbus-*-gen` packages). `e2e/agent.py` (the test authentication agent) uses the Python D-Bus bindings, so this gap is real.
    The builder checks the rest again in the image and also whether the RHEL 10 `pkcs11-provider` 1.0 does what the provider cases need.
  - The rpm requires `polkit >= 124`, `systemd`, `dbus`, `p11-kit`, `glibc`, `libgcc`; both targets satisfy them.
- How the Alma Python gap is handled, in this order, deciding within these limits: (1) look for a way for the agent to talk to polkit with
  what the base and AppStream repositories offer (for example `python3-gobject-base`'s Gio D-Bus, which exists on all five distributions);
  a change of `agent.py` for that must keep `debian13`, `ubuntu2604` and `fedora44` passing and is justified in the commit. (2) Only if
  that cannot work, skip-list entries for the cases that need the agent, each with the reason, and the findings say which acceptance
  evidence is therefore not produced on Alma. (3) EPEL is NOT used unless `BLOCKED.md` was answered with the approver's consent; asking
  is a step below, only if (1) fails and (2) would skip the approval/denial cases, which are the point of the suite.
- Journald's default storage on each of the two targets, checked in the booted containers and recorded in `docs/findings.md`. Nothing in
  the package changes journald's configuration (SPEC section 6).

Not here: Debian, Ubuntu and Arch targets, the upgrade and purge cases (their own features), rpm-ostree (SPEC section 4: containers do
not run it), CI wiring, `docs/install.md`.

Size: about seven steps; no split needed.

## Steps
- [x] Write the failing tests first, in `scripts/test-e2e-host.sh`:
      (a) split `target_problems` by distribution family, so a correct Fedora/Alma target is accepted and no existing check is dropped for
      Debian/Ubuntu: polkit package `polkitd` for `debian*`/`ubuntu*`, `polkit` (as a whole word, not `polkitd`) for `fedora*`/`alma*`;
      bus daemon: `debian*`/`ubuntu*` keep "no `dbus-broker`, no forced `dbus-daemon`"; `fedora*`/`alma*` must install the `dbus` meta package
      (which pulls in the distribution's default, `dbus-broker`) and must name neither `dbus-daemon` nor `dbus-broker` explicitly;
      (b) `fedora*`/`alma*` must install the mounted file with `dnf` (`dnf install` of `"$1"`; `rpm -i` alone is rejected);
      (c) a control fixture per new rule that must be rejected, in the style of the `ubuntu9999` one: a `fedora9999` with `polkitd` instead
      of `polkit`, one that installs `dbus-daemon`, one that installs `dbus-broker` explicitly, one with `rpm -i` only; and an accepted
      variant for each (`polkit` + `dbus` + `dnf install "$1"`);
      (d) include the new targets in the stub-engine run (build, `--privileged`, read-only mount, record), in the expected "available
      targets" line, and in the shellcheck list. Run it red before the directories exist.
- [x] Create `e2e/targets/fedora44/` (Containerfile with systemd as PID 1, the distribution's polkit and default bus daemon, the test

      must not contain the package or a bus daemon other than the distribution's default. Settle the tool availability by building it.
- [x] Run `just e2e fedora44` until it passes; each suite failure is either a defect of the target (fix it there), a defect of a shared
      script that is wrong for rpm distributions (small fix, other targets still green), or a real gap (skip-list entry with a reason).
      SELinux or `dnf` behaviour in the container that blocks a case is investigated, not skipped blind.

      would be skipped, write `BLOCKED.md` with the options (skip, EPEL with consent), commit, and stop; otherwise continue.
- [x] Run `just e2e alma10` until it passes, with the same rules as for Fedora. Outcome with EPEL only: if `BLOCKED.md` was answered with
      consent, add EPEL to `alma10`'s Containerfile only for the tools that are missing from the base repositories and say so in the
      findings; otherwise mark this step `- [-]`.
- [x] Write `docs/findings.md`, heading `### End-to-end targets Fedora 44 and Alma 10` containing: per tool and per target whether it

## Evidence
- Targets exist and are run like any other → `scripts/test-e2e-host.sh` (in `test-scripts`, stub engine) and `verify`'s greps
  (`fedora:44` in fedora44's Containerfile, `alma` in alma10's, both `skip.list` files exist) → the stub log shows a build of each
  Containerfile, a `--privileged` run, the package mounted read-only and the shared guest executed; no shared script differs per target.
- `dnf` installs the `.rpm`; the image does not contain it; real polkit and default bus daemon → the per-target loop of the same test
  (no `COPY`/`ADD` of a package; `install.sh` runs `dnf install` on the mounted file for `fedora*`/`alma*`, control fixture with `rpm -i`
  only rejected; the per-family polkit package check (`polkitd` vs `polkit`) and the per-family bus-daemon check of step 1, each with a
  rejected control fixture) → pass for all four real targets and fail for each control; this is the static proof that no bus-daemon package
  is forced against the distribution's default.
- The distribution's default bus daemon actually runs → the REQUIRED real runs: `target/e2e/fedora44.record` contains `bus-daemon=dbus-broker`
  (and `alma10.record` too), asserted by the builder with `grep -qx` and pasted in `PROGRESS.md`. If the findings show a different observed
  default on a target, section 3 of `docs/findings.md` is corrected with the evidence, and the asserted value and the static rule of step 1
  change with it. `probe.sh` must report the broker's own process: `GetConnectionUnixProcessID` of `org.freedesktop.DBus` is checked against
  `dbus-broker`'s pid and not `dbus-broker-launch`'s, and the findings say which process it is.
- The suite runs on Fedora 44 and Alma 10 → REQUIRED real runs `just e2e fedora44` and `just e2e alma10` (no stub) → exit 0, "e2e: passed:
  <t>", every case in `cases.list` reported as run or on that target's `skip.list`, and `target/e2e/<t>.record` naming the bus daemon,
  version, polkit version and target. `just e2e` (all) exits 0 with all four targets, and `debian13`/`ubuntu2604` still pass after any shared
  change.
- Availability of pkcs11-provider, OpenSC, the NSS tools and the Python D-Bus bindings is settled, each gap a skip-list entry with a
  reason → the findings section lists the four tools for both targets with their source repository; `scripts/test-e2e-skips.sh` and
  `e2e/check-cases.sh` (F45) validate that every skip is `case: reason`, known and accounted for; a tool that is missing and whose cases are not
  on the skip list makes the real run fail (the accounting fails on a case that does not run). For Alma's `python3-dbus` the expected
  result is the Scope order (1)→(2)→BLOCKED, and the findings state which way was taken, with the command output that shows the package
  is absent. A skip list entry whose tool IS available on that target is a defect the evaluator checks against the findings.
- EPEL used only with consent → `grep -ri epel e2e/targets` is empty unless `BLOCKED.md` (answered; the answer is in the commit that
  added it) approved it; the findings say so either way.
- Result recorded with each target's journald default → `grep -n '^### End-to-end targets Fedora 44 and Alma 10' docs/findings.md`; both
  target names and the `Storage=` and `/var/log/journal` outputs sit under it, with the commands, so a reader can repeat them, and it says
  the result comes from the minimal base images. The catalog case `journal-catalog` and the audit-entry cases must pass on whatever the
  default is (volatile included); this is shown by the real runs.
- Shellcheck and syntax of the new scripts → `just check` and `bash -n e2e/*.sh` (both in `verify`) → pass.
