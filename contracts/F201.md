# F201 — Research: the double prompt with the global switch and an override

## Scope

A research feature: one finding, `docs/findings/F201.md` (headed `## F201`, one index line in `docs/findings.md`, written under the
rules at the top of that page: conclusions first, each marked **verified** or **inferred**, versions, only the lines of output that prove it).
It changes no product code, no test, no case list, no `justfile` recipe, no gate and no document other than the finding and its index line.
It settles SPEC open question 5 (double fingerprint prompt) with a `Decision: ` line that F202 implements. Not built here: the `doctor`
check and its tests (F202), the GDM question and the Debian/Alma question (other open questions), any change to `custodio fingerprint enable`.

**The run.** Ubuntu 26.04 VM started by the existing tooling (`e2e/vm/vm.sh`, the F200 staging: virtual sensor drop-in, enrolled finger,
text agent `pkttyagent` with `pkcheck`, `e2e/vm/fingerprint-check.sh` and `fingerprint-pty.py` as models; docs/findings/F200.md says what
works and what does not, e.g. `pkexec` cannot be the client). The run's driver is a throwaway script kept outside the repository
(the finding quotes the commands and the lines that matter, enough to repeat it); nothing is added to `e2e/vm/cases.list`. It is a one-off
research run, not a suite member: it adds no test time to any later loop run. One VM run is about 3–6 minutes (boot 14 s, install 8 s,
fprintd install 15–40 s, each prompt case 2–15 s, the no-touch ones 10 s plus a margin); it fits one command and one session. The builder
runs the cases of a configuration against one VM, one after another (one fprintd, one sensor, one `/etc/pam.d`); waits are on a condition
(the agent's prompt, the socket, the unit state), not a fixed `sleep` except the 10-second timeout itself, awaited on the agent's event with a bound.

**Configurations** (each with `/etc/pam.d/polkit-1` as the thing varied; the global switch is `pam-auth-update --enable fprintd`, which
puts `pam_fprintd.so max-tries=1 timeout=10` into `common-auth`, included by `/usr/lib/pam.d/polkit-1`):

- A. the global switch only (no `/etc/pam.d/polkit-1`) — the baseline: what polkit asks;
- B. the switch plus Custodio's override file as `custodio fingerprint enable` writes it (the packaged binary writes it, not a hand copy);
- C. the switch plus an Omarchy-style file (a `pam_fprintd.so` auth line of its own as Omarchy's polkit agent reads it; the builder takes the
  exact content from docs/findings/F56.md and the repository's fixtures/SPEC, and says in the finding where it came from);
- D. the override only (switch off) — the control that shows what one prompt looks like.

**Cases per configuration**, each observed by the text agent's output (`pkttyagent` prompt lines), the events of the driver, fprintd's
journal and D-Bus state (`VerifyStart`, scans consumed, `verify-match`/`verify-no-match`) and the final status, so that the observation
would differ if the module were or were not reached the second time: a matching finger; a wrong (unenrolled) finger; no touch. For each:
how many finger prompts polkit showed, how many fprintd verifications were started, in what order the password prompt came, how long the
no-touch case took in total (two 10 s timeouts would show as ~20 s), and whether the action was approved. The harness's own pam_permit
`/etc/pam.d/polkit-1` is set aside and put back as F200 does (an exit trap), so that the VM is left as found.

**Environment** (checked by step 1, recorded in the finding): `/dev/kvm` and working VM runs (F168, F200 passed on this host); the archive
serves `fprintd`/`libpam-fprintd` and libfprint holds `FP_VIRTUAL_DEVICE` (F200 recorded both: the finding cites F200 rather than
repeating). If the VM cannot be started, that is a `BLOCKED.md`, not a guess marked **verified**; what was not observed is marked **inferred**.

## Steps

- [ ] Environment: start the VM with the existing tooling and stage the sensor, an enrolled finger and the agent as F200 does; record
      the versions (polkit, fprintd, libfprint, libpam-fprintd, pam, the image) with the commands that print them.
- [ ] Write the throwaway driver and run configurations A and D (baseline and control): matching finger, wrong finger, no touch; note the
      prompts, verification counts and times.
- [ ] Run configurations B and C (the switch plus Custodio's file; the switch plus the Omarchy-style file) with the same three cases;
      confirm that `/etc/pam.d/polkit-1` was read in preference to `/usr/lib/pam.d/polkit-1` (the module list that was loaded, or the
      auth lines polkit evaluated), and that `common-auth` was reached or not. Leave the VM as found and stop it.
- [ ] Write `docs/findings/F201.md` and its index line: a table of configuration × case, conclusions first, the versions, the
      commands and proving lines, the `Decision: ` line (see Evidence), then `just quick`.
