# F87 — custodio list

## Scope
Adds `custodio list` next to `import`, through the documented `ListKeys` (`a(ssay)`, `docs/api.md`)
and the client crate only (no dependency on `custodiod`; `just deps-check`, F64, not repeated).
Built here:
- A list entry point in the `custodio-cli` library with the same shape as import: a trait for the
  service side (like `Importer`), a D-Bus implementation in `bus.rs`, a `run_list` function that
  writes to a `Write`, and `main` dispatching `list` (no arguments; any extra argument is a usage
  error, status 2, usage text updated to name both commands).
- Output: one line or block per key with id, key type, certificate subject and end of validity
  (`notAfter`), parsed from the DER certificate on the client side (the builder picks the parser;
  `x509-cert`/`der` are already used by the workspace, so no new family of dependencies; if a new
  crate is needed, `just quick`'s deny/audit gates decide). Control characters in the subject
  are not written raw to the terminal. A certificate that cannot be parsed never hides the key: its
  id and type are shown with a fixed "certificate unreadable" marker and the status is 1.
- No keys: a fixed sentence saying there are none, status 0. Output order is stable (as the
  service returned it, or sorted by id; the builder picks and the test fixes it).
- Failures reuse F86's typed `ServiceFailure` (ten documented names, service absent, transport,
  unknown name) with the same fixed messages and `exit_status` mapping (1; usage 2). The service's
  free text never appears.
- `list` asks no polkit: observed on a private bus, not re-proven in the service (F72 owns
  "asks no polkit" and "other uid's keys never listed"; here it is observed through the CLI).
- `packaging/custodio.1` documents `list` (synopsis, description of the output, no keys, exit
  status, that it asks no polkit).

Not here: `delete` (F88), `pkttyagent` (F89), the service's uid scoping (F72), the PKCS#11
module, package/install/e2e runs (F90/F100). The real binary needs no terminal for `list`, so
the binary is run directly where a test needs it.

## Evidence
- Calls only the documented method → `cli.rs`-style test with a recording service or bus
  monitor: exactly one call, `ListKeys`, to `BUS_NAME`/`OBJECT_PATH`/interface from the client
  constants, no arguments → pass.
- Several keys, each with id, key type, subject, end of validity → bus test: import an RSA key
  and an ECDSA key (fixtures with known subjects/validity) for one uid, run `run_list`: output
  has each id, `rsa2048`/`ecdsa-p256`, the exact subject and the exact `notAfter` of each
  fixture, and the pairs are not mixed up between keys → pass.
  The same test asserts the output order (the order chosen in the steps).
- No keys → bus test with an empty store: output is the fixed "no keys" sentence, `exit_status`
  0, nothing on stderr → pass. Also asserts this sentence does not appear when keys exist.
- Error shows the name's message, non-zero → the name table is F86's (`failure/tests.rs`), not
  repeated; here one bus test proves the list path reaches that mapping, where the
  authorizer-less caller identity fails (service answers `AuthorizationUnavailable`, e.g. via
  the replaceable credentials double) shows that name's message and prints no key lines → pass.
- Unavailable service → bus test with no name owner: the "cannot talk to the service" message,
  status 1, no key lines; binary with `DBUS_SYSTEM_BUS_ADDRESS` to a missing socket: status 1
  (not 2) → pass.
- Two uids → bus test through the replaceable credentials interface: uid A imports a key, uid B
  imports another (one with the same id as A's, with a different subject); A's and B's entries for that id each show their own subject; A's list shows only A's, B's only B's, a
  third uid's shows the none sentence; no other uid's id or subject appears in the output → pass.
- Asks no polkit → in the same bus tests the fake polkit records zero calls for every list run
  above (several keys, none, two uids), while the preceding imports recorded theirs → pass.
- Unparseable certificate, escaping → unit tests: garbage DER yields the id, type and the
  unreadable marker and status 1; a subject with an escape sequence and a newline: the output has no raw byte below 0x20 or 0x7f except the format's own line separators
  → pass.
- Usage → unit and binary tests: `list extra`, `list --id x` give status 2, usage on stderr,
  nothing on stdout; `import` usage cases from F86 stay green → pass.
- No certificate bytes in output → the failure tests assert the DER bytes (as text or hex) are not printed → pass.
- Man page documents it → a test run by `just test` (not a package gate) reads `packaging/custodio.1`
  and checks: `custodio list` in SYNOPSIS; the fields (id, key type, subject, end of validity); the
  none case; the exit status; that it asks no polkit → pass; it fails if any of them is removed.
- `just quick` → exit 0.
