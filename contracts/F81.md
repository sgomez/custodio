# F81 — Read the app-id from hostile input within bounds

## Scope
F67 decided **(c)** (`docs/findings.md` `## F67`, "What a reader needs"), so the source is the cgroup scope of the
process pinned by the bus's `ProcessFD`, not `/.flatpak-info`; the (d) clause of the description does not apply and
no deviation is written. This feature builds the reader behind a replaceable interface; F80's pure `app_id::classify`
parses each scope name and is not re-proven here. The reader returns `AppIdOutcome` (`Read`, `None`, `Undetermined`).

- **Interface.** A trait in custodiod (module `app_id_source`, its own file, declared in `lib.rs`) takes the pinned
  process (the borrowed pidfd and the credentials' uid) and returns an `AppIdOutcome`. It is never an error and never
  panics out: every failure is `Undetermined`. The caller always gets an answer within the time bound. Two
  implementations: the real reader and a fake source with the three cases (read, none, undetermined) that F82's
  audit tests use. Wiring into the entries is F82; this feature does not touch the entries, `dbus.rs` or polkit.
- **Real reader**, following the finding: pid from the pidfd's `fdinfo` `Pid:` (`0`, `-1`, missing → undetermined),
  the caller's `app.slice` of `user@<uid>.service` with `<uid>` from the credentials, the direct children that are
  directories (never following a symlink), the `cgroup.procs` of each, a decimal-only pid list; the child listing the
  pid is the scope whose name goes to `classify`. A finished scan without a flatpak scope is `None`. The builder's
  first step decides how the cgroup2 directory is found (direct path or mountinfo) and records it in the code and
  `docs/findings.md` only if the e2e nested root forces it. The optional `PIDFD_GET_INFO` shortcut is not built.
- **Bounds** (constants, documented in the module and in the finding's terms): `cgroup.procs` at most 1 MiB, at most
  4096 children of `app.slice`, one deadline of 1 s for the whole lookup. Regular file only: opened with
  `O_NOFOLLOW | O_NONBLOCK | O_NOCTTY | O_CLOEXEC`, then `fstat` must say regular file before any read; a FIFO,
  device or symlink is refused without blocking.
- **Same process afterwards.** After the scan the pidfd's `Pid:` is read again; it must be equal and not `-1`,
  otherwise `Undetermined`.
- **Time bound and stuck reads.** Blocking I/O runs on a thread (the existing `offload` pattern) awaited with the
  deadline. When the deadline passes the call returns `Undetermined` at once and the thread is left. The number of
  such threads still running is capped (a documented constant); at the cap a new lookup returns `Undetermined`
  immediately without starting a thread. A stuck thread that later finishes frees its slot. A lookup whose
  thread cannot start is `Undetermined`.
- **Not loosened.** No change to `data/custodio.service`, seccomp or capabilities; `just system-gates` passes
  (it is in `verify`). The real filesystem path with a real scope, uid and `ProcessFD` of a flatpak caller is proven at
  the e2e checkpoint (F95, `appid-*` cases, acceptance 9), not here; here the real reader runs against a fixture
  directory tree under a temp dir (the root is a parameter of the reader, fixed to `/sys/fs/cgroup` only in the
  constructor used by the service).
- **Left for others.** Entries and `docs/audit.md` (F82); fuzz (F83); the parser (F80, done).
  Size: about six steps; no split.

Environment: needs only the dev container (temp dirs, `mkfifo`, threads). Checked by the builder in step 1 with
`mkfifo` on a temp dir and `ulimit`-free thread creation; if `mkfifo` is not possible the FIFO tests use
`rustix::fs::mknodat` and say so in `PROGRESS.md`.

## Steps
- [ ] Failing tests first: the fake source and the real reader's tests against fixture trees (one group per Evidence
      row), with the trait and outcome plumbing stubbed.
- [ ] The trait, the fake source (three cases) and the bounded-file open-and-read helper (no-follow, regular only,
      size cap, non-blocking open); its tests pass.
- [ ] The scan: pid from fdinfo text, `app.slice` listing, `cgroup.procs` parsing, `None`/`Read`/`Undetermined`
      mapping through `classify`, the post-scan same-process check.
- [ ] The deadline and the stuck-thread cap around the scan; the reader-that-never-returns tests pass.
- [ ] Add the new files to the `mutants` recipe in `justfile`, keep files under the file-size gate.
- [ ] `just quick`, `just system-gates`, then `just mutants-diff F81` until clean; append `PROGRESS.md`.

## Evidence
Unit tests under `crates/custodiod/src/app_id_source/` on fixture trees in temp dirs, with literal expected values.
- Source F67 decided on is used → `reads_flatpak_scope_of_pinned_pid`: a tree with `app-flatpak-org.example.App-5151.scope`
  listing the pid in `cgroup.procs` and other scopes listing other pids → `Read("org.example.App")`; also the
  escaped id (`My_App\x2dName`) → `Read("org.example.My_App-Name")`.
- The three cases → `fake_source_returns_the_three_outcomes` (fake yields read, none, undetermined as configured);
  `non_flatpak_scope_is_none` (pid listed only in `app-gnome-gedit-99b.scope`); `pid_in_no_scope_is_none`
  (scan finished, pid absent); `no_app_slice_directory_is_none`; `invalid_scope_name_is_undetermined` (the pid is in
  `app-flatpak-..bad-1.scope`: `Undetermined`, and nothing of the name appears in the `Debug` of the outcome).
- Uses the credentials' uid → `only_the_callers_uid_slice_is_read`: pid listed in another uid's `app.slice`
  only → `None`, never `Read`.
- Symlink not followed → `symlinked_scope_dir_is_skipped` (a symlink to a directory with the pid: not entered, the scan
  finishes, result `None`) and `symlinked_cgroup_procs_is_undetermined`.
- FIFO → `fifo_cgroup_procs_is_undetermined_within_bound` (a `mkfifo` named `cgroup.procs` with no writer; returns
  `Undetermined`, well under the deadline, asserted by elapsed time < deadline).
- Device → `device_is_refused_as_not_regular`: `/dev/zero` opened directly through the bounded-open helper is
  refused as not regular (no `mknod`, which needs CAP_MKNOD).
- Oversized → `oversized_cgroup_procs_is_undetermined` (1 MiB + 1 bytes → `Undetermined`; exactly 1 MiB of valid
  pids with the pid at the end → read; boundary both sides) and `too_many_children_is_undetermined` (4097
  children → `Undetermined`, 4096 → scanned).
- Pid list is decimal only → `non_decimal_pid_list_is_undetermined` (`12x`, `-1`, `+5`, an overlong number, NUL).
- Pid from the pidfd → `fdinfo_pid_zero_or_minus_one_is_undetermined` and `fdinfo_missing_pid_is_undetermined`.
- Still the same process → `pid_changed_after_scan_is_undetermined` (a test hook returns `Pid: 5` before and `Pid: -1`
  or `Pid: 6` after → `Undetermined`; same twice → `Read`).
- Slow file/ reader that never returns, injected as a blocking hook inside the real reader so it runs under the same
  deadline and cap wrapper the service uses (not under a test-only timeout) → `blocked_reader_returns_undetermined_within_bound` (a source helper that
  blocks forever, run under a test deadline of a few tens of ms: result `Undetermined`, elapsed within
  deadline + a margin, the production deadline constant is asserted to be 1 s).
- Stuck reads bounded in number → `stuck_lookups_are_capped`: start cap+1 never-returning lookups; the first `cap`
  each take one deadline then `Undetermined`, the next returns `Undetermined` immediately (elapsed far below the
  deadline) and no extra thread is started (counter); `released_stuck_thread_frees_its_slot` (unblock one, a new
  lookup works again).
- A failure never refuses or delays beyond the bound → covered by the rows above (each failure kind returns an
  outcome, none panics or returns an error: the trait signature has no error type, asserted by compile) and
  `panicking_reader_is_undetermined`.
- Replaceable → `lookup_through_the_trait_object` uses `&dyn`/generic with the fake and the real reader the same way.
- Unit not loosened → `just system-gates` (in `verify`) passes.
- Mutation → `just mutants-diff F81` (verify): no missed mutant in the new files.
- Negative control: during step 3 or 4 one hostile-input test (the FIFO or the size bound) is run against a
  deliberately weakened reader (`O_NONBLOCK` removed, or `>` changed to `>=`), shown red, and reverted; noted in
  `PROGRESS.md`.
- If F67 had decided (d): not applicable; F67 decided (c).
