# F23 — Miri, AddressSanitizer and fuzzing for the new FFI entry points

## Scope
Proves, with the tools the repository already has, that the FFI entry points added or changed by
F19–F22 are free of undefined behaviour and cannot be crashed by arbitrary arguments or call
orders. Production code changes only if a tool finds a bug.

- **Miri / ASan (unit tests).** `just miri` and `just asan` already run all `--lib` tests of
  `custodio-pkcs11`, which use the fake service. Nothing in them is gated off (no `cfg(miri)`, no
  `#[ignore]`; the builder confirms this and may not add either). What is added: tests in the
  existing files `src/ffi/tests/{composed,multipart,login}.rs` (or a new `src/ffi/tests/sanitizers.rs`,
  to stay under the 5000-token file gate) for the gaps in the Evidence table. Tests that already
  cover a row are cited, not copied.
- **Fuzz target.** `ffi/fuzzing.rs` (`step`, `% 17` ops) gains: `C_SignUpdate`, `C_SignFinal`,
  `C_Login`, `C_Logout`; the six composed mechanism types (`CKM_SHA{256,384,512}_RSA_PKCS`,
  `CKM_ECDSA_SHA{256,384,512}`) in the `C_SignInit` mechanism choice and in `C_GetMechanismInfo`;
  and the `C_Sign` op keeps its sizes. Any order, any sizes: every op is chosen from the script
  bytes with no state kept by the harness. If the file would pass the token gate, the new ops go
  in `src/ffi/fuzzing/` submodule(s); the `--exclude` of `just crap` is then extended to those
  files only (the same harness-only exclusion that exists for `fuzzing.rs`) and `docs/decisions.md`
  is not touched. `fuzz/Cargo.toml` and `fuzz_targets/pkcs11_args.rs` stay as they are unless a
  second target is wanted (not planned).
- **`forbid(unsafe_code)` outside FFI.** Today the crate has no such attribute (only the doc
  comment in `lib.rs`; `ffi`, `unsupported` hold the `unsafe extern "C"` functions). Add
  `#![deny(unsafe_code)]` to `lib.rs`, `#![allow(unsafe_code)]` (with the comment justifying it) in
  `ffi.rs` and `unsupported.rs` only, and `#![forbid(unsafe_code)]` in `module.rs`, `composed.rs`,
  `token.rs`, `backend.rs` and `fake.rs`. Test modules under `ffi/` inherit the FFI allowance.
- **Environment.** The pinned nightly `nightly-2026-10-26` with `miri`, `rust-src` and
  `llvm-tools-preview` must be installed (`just setup` does it); earlier sessions could not run
  `just miri` for lack of it. If it cannot be installed (no network), write `BLOCKED.md`.

Left for other features: running the fuzzer for long (CI/nightly campaigns), the audit journal,
e2e. No change to `features.json`, `SPEC.md` or the justfile recipes `miri`, `asan`, `fuzz-build`,
`lint-fuzz`. The feature fits in five steps; no split.

## Steps
- [ ] Install the pinned nightly; run `just miri` and `just asan` on the tree as it is and record
  the baseline (pass/fail, test count) in the session notes; fix any UB or leak they report, test
  first.
- [ ] Write the missing unit tests (Evidence rows marked "new"), red/green against the current
  code, and run each by name under Miri and ASan.
- [ ] Extend the fuzz harness: new ops, composed mechanism types, `C_Login` arguments; add the
  `--features fuzzing` unit tests that replay hand-built scripts; `just fuzz-build`,
  `just lint-fuzz` and `just lint` green.
- [ ] Add the `unsafe_code` lint structure; prove it with a throwaway `unsafe` block.
- [ ] Mutation checks (below), then run `just miri && just asan && just fuzz-build && just
  lint-fuzz` and `just check`; append `PROGRESS.md`.

## Evidence
- Nothing hides tests from the sanitizers → `grep -rnE 'cfg\(miri\)|cfg_attr\(miri|#\[ignore' crates/custodio-pkcs11/src` → no output; `cargo +nightly-2026-10-26 miri test -p custodio-pkcs11 --lib --locked -- --list` (and the same with `-- --list` under `just asan`'s flags) lists every test named below.
- `C_GetMechanismList` with the composed mechanisms: length query (NULL list), exact size, too-small, larger buffer → `ffi::tests::list_outputs_respect_the_callers_sizes` (existing, covers the 4-entry list) plus **new** `ffi::tests::mechanism_list_sizes_with_composed`: NULL list gives `CKR_OK` and the full count; a buffer one short gives `CKR_BUFFER_TOO_SMALL` with the count set and the buffer untouched (sentinel bytes intact); a larger buffer writes exactly `count` entries, the sentinel after them intact, and the entries contain all six composed types → passes under `just miri` and `just asan`.
- `C_GetMechanismInfo` with the composed mechanisms → `ffi::tests::composed::composed_mechanism_info` (existing; fills a `MaybeUninit`, rejects NULL) → passes under Miri and ASan, run by name.
- `C_SignInit` with composed mechanisms (parameter NULL/non-NULL, NULL mechanism pointer) → `ffi::tests::composed::composed_sign_init_parameter` (existing) plus **new** `ffi::tests::composed_sign_init_null_mechanism`: NULL mechanism pointer gives `CKR_ARGUMENTS_BAD` for each of the six types' sessions and no operation is left active (a following `C_SignInit` is `CKR_OK`) → passes under Miri and ASan.
- `C_Sign` with composed mechanisms, length query and too-small buffer, for all six types → **new** `ffi::tests::composed_sign_length_query_and_small_buffer`: per type, `C_Sign` with NULL signature returns `CKR_OK` and the true length and leaves the operation active; with a buffer one byte short returns `CKR_BUFFER_TOO_SMALL` with the length set, buffer untouched, operation still active; the retry with the right size gives `CKR_OK` and the signature equals the one `module` tests expect (fake answer); the guard bytes after the buffer are intact → passes under Miri and ASan.
- `C_SignUpdate` / `C_SignFinal`, including NULL part, zero length, huge length, NULL length pointer, length query, too-small buffer → `ffi::tests::multipart::sign_update_and_final_arguments` and `sign_update_rules_through_the_c_functions` (existing) plus **new** `ffi::tests::multipart_final_small_buffer_keeps_operation`: `C_SignFinal` with a short buffer returns `CKR_BUFFER_TOO_SMALL`, the next `C_SignFinal` with room returns `CKR_OK` with the same bytes as a one-shot `C_Sign` of the concatenated parts; guards intact → passes under Miri and ASan.
- `C_Login` / `C_Logout` including NULL and empty PIN pointers → `ffi::tests::login::login_accepts_any_pin`, `login_never_dereferences_the_pin`, `login_invalid_session`, `login_security_officer_fails`, `logout_is_ok` (existing; cover NULL with length 0 and 4, empty slice pointer, dangling pointer, `CK_ULONG::MAX` length) → pass under Miri and ASan, run by name. (Miri's strict provenance checks make the dangling-pointer test fail if the module ever reads the PIN.)
- Sanity that the sanitizers can fail on these functions → one-off mutation, results recorded in `PROGRESS.md`, not committed: (a) make `C_GetMechanismList` write `count + 1` entries; (b) make `C_SignFinal` write one byte past `*len`; (c) make `C_Login` read `*pin`. Expected: (a)(b) `just miri` and `just asan` each fail; (c) `just miri` fails (ASan may not) while the tree is otherwise green; tree restored with `git checkout` and `git status` clean before committing.
- Fuzz target covers the new mechanisms → **new** `ffi::fuzzing::tests::script_reaches_composed_mechanisms` (cfg `feature = "fuzzing"`): a hand-built byte script calls `C_GetMechanismInfo` on a composed type and `C_SignInit` + `C_SignUpdate` + `C_SignFinal` with `CKM_SHA256_RSA_PKCS`; the test asserts the fake recorded exactly the expected sign (call counter and `LAST_INPUT` under `cfg(test)`, the SHA-256 DigestInfo of the parts) → `cargo test -p custodio-pkcs11 --features fuzzing --lib fuzzing::` passes; fails if the op is not wired or the composed type is not selectable. The command is added to the `test` recipe of the justfile so CI runs it (an addition only).
- Arbitrary multi-part sequences in any order and with any sizes → **new** `ffi::fuzzing::tests::sequences_in_any_order`: for every permutation of {init, update, final, sign} (24) and for sizes 0, 1, 129, 4096 (and a NULL part), a script built by the test runs through `fuzzing::run` without panic and leaves the module finalized (`C_Initialize` afterwards returns `CKR_OK`, `C_Finalize` too); plus a deterministic xorshift-generated set of 2000 random scripts of length ≤ 512 → no panic, no abort. Fails if an op is missing (the permutation test asserts through the fake's counters that update and final each ran at least once in the script that contains them).
- Arbitrary `C_Login` arguments → **new** `ffi::fuzzing::tests::login_arguments`: scripts using the login op with random session, user type (valid and invalid), NULL/non-NULL PIN and lengths up to `CK_ULONG::MAX` run without panic, and the fake's counters show the service was never contacted by the login op → passes. The harness never allocates a PIN buffer shorter than the length it passes, except when the length is far larger than any buffer, in which case the pointer is NULL or dangling: documented in the module comment, because `C_Login` never reads it (a read would crash under the fuzz build's ASan, which `just asan`-style run below shows).
- The target builds → `just fuzz-build` → exit 0, builds `pkcs11_args`; `just lint-fuzz` → exit 0 (clippy clean, release guard still refuses `fuzzing`).
- The fuzzer actually runs with the new ops → `cd crates/custodio-pkcs11/fuzz && cargo +nightly-2026-10-26 fuzz run pkcs11_args -- -max_total_time=60` → ends without a crash artefact; one-off mutation (b) above makes it find a crash within the same 60 s (recorded in `PROGRESS.md`, mutation reverted).
- Lint of the new code → `just lint` → exit 0 (includes the `--features fuzzing` clippy).
- `forbid(unsafe_code)` holds outside FFI → `grep -n 'forbid(unsafe_code)' crates/custodio-pkcs11/src/{module,composed,token,backend,fake}.rs` prints one line per file, and `grep -n 'deny(unsafe_code)' crates/custodio-pkcs11/src/lib.rs` one line; `grep -rln 'unsafe' crates/custodio-pkcs11/src` lists only files under `ffi`, `unsupported.rs`, `lib.rs` (comment). `cargo build -p custodio-pkcs11` passes. Throwaway check: adding `unsafe { }` to `module.rs` or `token.rs` or `module/signing.rs` makes `cargo build` fail with "usage of an `unsafe` block"; removed afterwards. The rest of the workspace keeps its `#![forbid(unsafe_code)]` (`grep -rn forbid crates/*/src/{lib,main}.rs` unchanged).
- Whole feature → `just miri && just asan && just fuzz-build && just lint-fuzz` → exit 0; `just check` → exit 0.
