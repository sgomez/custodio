# F39 — custodiod refuses a Sign call whose bus credentials lack ProcessFD

## Scope
Built: `custodiod` reads `ProcessFD` from the `GetConnectionCredentials` reply together with
`UnixUserID` and `ProcessID`. A reply without a usable `ProcessFD` (absent, or not a file
descriptor) is a missing-credentials error, the same path the missing pid takes today. The Sign call
is then refused before polkit is asked and leaves exactly one M1 journal entry with the
"authorization not possible" outcome (`Outcome::AuthorizationUnavailable`). Every fd received or
opened by the credential code is closed, never leaked and never written to logs, `Debug` or errors.

Also built, required (SPEC.md section 3; `docs/findings.md` M1.2 marks it verified under
`ProtectProc=invisible`/`ProcSubset=pid`): the pidfd/pid cross-check. The code reads the `Pid:` line
of `/proc/self/fdinfo/<fd>` for the received pidfd and compares it with `ProcessID`. A mismatch,
`Pid: -1` (the process has exited), a missing or unparsable `Pid:` line, or an unreadable fdinfo all
return `CredentialsError::Missing`. The only exception is a fact found while building that
contradicts M1.2; that goes through a contract amendment, not a silent skip. The exposure gate
threshold does not change.

`custodiod` must obtain pidfds in tests without `unsafe` (a safe rustix call such as
`pidfd_open` on a known pid, or an fd taken from a real bus reply); `unsafe` is allowed only in the
PKCS#11 FFI layer. All of this code lives in `crates/custodiod/src/credentials.rs` (or another file
already in the `just mutants` list).

Whether the entry says why authorization was not possible is decided by the builder under the
additive-change rule of `docs/audit.md`. No D-Bus interface or audit field name changes. If a field
or value is added, `docs/audit.md` documents it.

Left for other features: the package-install bus check, the end-to-end runs on each target, and
passing the pidfd to polkit.

## Steps
- [x] Write failing unit tests (`credentials/tests.rs`): the parser rejects a map with `UnixUserID`
      and `ProcessID` but no `ProcessFD`, and a map where `ProcessFD` has the wrong type; a pure
      fdinfo-text parser accepts a matching pid and rejects a different pid, `-1`, no `Pid:` line
      and garbage; a complete map with a real pidfd still gives the right uid and pid.
- [x] Implement the `ProcessFD` requirement and the fdinfo `Pid:` cross-check against `ProcessID`,
      with every fd closed on every path (including errors). Safe code only.
- [x] Add integration tests in `tests/audit` (fakes keep the real `UnixUserID` and `ProcessID`
      and go through the real parser): (a) reply with `ProcessFD` dropped; (b) `ProcessFD` of the
      wrong type; (c) a real pidfd with a mismatching `ProcessID`. In each the key is imported first.
- [x] Real-bus tests: a Sign call through `BusCredentials` still succeeds and records the test
      process's own uid and pid; a fd-leak test in its own test binary.
- [x] Decide the optional "why" field; if added, document it in `docs/audit.md` and add its
      wire-format test.
- [x] Run `just check`, `just test-integration` and `just mutants`; kill every surviving mutant in
      the credential-reading code with tests, not exclusions.

## Evidence
- Reply without `ProcessFD` is refused → unit test in `credentials/tests.rs` calling the parser
  with a map lacking it → `Err(CredentialsError::Missing)`; deleting the new check makes it fail.
- Wrong-typed `ProcessFD` is refused (unit) → unit test with a `u32` or string value → `Missing`.
- Wrong-typed `ProcessFD` through the real parser end to end → `tests/audit` test, key imported,
  fake sends `ProcessFD` as a `u32`/string with right uid and pid → no signature, `asked()` empty,
  one `AuthorizationUnavailable` entry.
- Complete reply still accepted → unit test with all three fields, a real pidfd of the test process
  → `Ok` with the expected uid and pid.
- fdinfo parser → unit tests of the pure text parser: `Pid:\t<n>` matching → `Ok`; different pid,
  `Pid:\t-1`, no `Pid:` line, non-numeric garbage, empty text → `Err`.
- Cross-check with a real pidfd → unit test pairing a real pidfd (own process, obtained without
  `unsafe`) with a wrong `ProcessID` → `Missing`; with the right `ProcessID` → `Ok`. Unreadable
  fdinfo (an fd that is closed or not a pidfd) → `Missing`.
- Sign refused, no signature → `tests/audit` test: key imported first, fake keeps the right
  `UnixUserID` and `ProcessID` and drops only `ProcessFD` → the call returns an error with the
  access-denied name and no signature bytes. With the key present, this proves the ProcessFD check
  is what refused the call; deleting the new check makes the call sign and the test fail.
- Polkit not asked → same test → `f.asked()` is empty.
- Exactly one journal entry with the "authorization not possible" outcome → same test, `MemorySink`
  → one entry, `Outcome::AuthorizationUnavailable`, key id and mechanism filled in, caller absent.
  It must also pass through the journal wire format: the outcome value read from the entry matches
  the documented value in `docs/audit.md`.
- Mismatching pid refused → `tests/audit` test, key imported, real pidfd with wrong `ProcessID` →
  no signature, `asked()` empty, exactly one `AuthorizationUnavailable` entry.
- Real bus still works → named integration test with `BusCredentials` on the test bus (an existing
  audit test that asserts `Signed`, or a new one if none does) → a signature is returned, the entry
  is `Signed`, and its `Caller` uid and pid equal the test process's own `getuid` and `std::process::id()`
  (this fails if the code asks for a field the bus never gives, mishandles the fd type, or reads a
  wrong fd or pid).
- "Why" field, if added → test reading it back from the journal wire format → equals the value
  documented in `docs/audit.md`.
- No D-Bus interface or field name change → `git diff` of `docs/audit.md`, the interface XML and
  the audit field list shows only additions; the existing audit tests (`just test-integration`)
  still pass unchanged.
- No fd or secret leakage in messages → test that `Debug` and `Display` of `CredentialsError`
  contain no fd number.
- No fd leak → test in its own test binary (or serialized, so no parallel test opens fds) that
  calls `BusCredentials::credentials` many times (e.g. 200) on the real test bus and shows the
  entry count of `/proc/self/fd` after equals the count before (after one warm-up call); it also
  covers the refusal paths (wrong pid) with a fake that supplies a pidfd. Fails if the dup'ed
  `ProcessFD` or the fdinfo fd is not closed.
- Code stays in mutated files → `just mutants` → `crates/custodiod/src/credentials.rs` is still in
  the recipe's `--file` list; `target/mutants/mutants.out` of the verify run shows zero `missed` and
  zero `timeout` mutants in `credentials.rs` (read from `missed.txt`/`timeout.txt`, not only the exit code).
- Everything passes → `just check && just test-integration && just mutants` → exit 0.
