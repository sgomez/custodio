# F39 — custodiod refuses a Sign call whose bus credentials lack ProcessFD

## Scope
Built: `custodiod` reads `ProcessFD` from the `GetConnectionCredentials` reply together with
`UnixUserID` and `ProcessID`. A reply without a usable `ProcessFD` (absent, or not a file
descriptor) is a missing-credentials error, the same path the missing pid takes today. The Sign call
is then refused before polkit is asked and leaves exactly one M1 journal entry with the
"authorization not possible" outcome (`Outcome::AuthorizationUnavailable`). The received fd is
closed, never leaked and never written to logs, `Debug` or errors.

Optional, decided by a step: the pidfd/pid cross-check from SPEC.md section 3. The step checks
whether it works within the current unit hardening. If it does, a mismatch is treated like a
missing `ProcessFD`. If it does not, the presence check alone is the requirement and the reason is
recorded in `docs/findings.md` or the commit. The exposure gate threshold does not change.

Whether the entry says why authorization was not possible is decided by the builder under the
additive-change rule of `docs/audit.md`. No D-Bus interface or audit field name changes. If a field
or value is added, `docs/audit.md` documents it.

Left for other features: the package-install bus check, the end-to-end runs on each target, and
passing the pidfd to polkit.

## Steps
- [ ] Write failing tests: the credential parser rejects a map with `UnixUserID` and `ProcessID` but
      no `ProcessFD`, and a map where `ProcessFD` has the wrong type. A complete map still gives the
      right uid and pid.
- [ ] Extend the credential reading to require `ProcessFD`, closing the fd after the check. Keep the
      code in `credentials.rs` (or another file already listed in `just mutants`).
- [ ] Add an integration test in `tests/audit`: a credentials fake whose reply lacks `ProcessFD`
      and goes through the real parser. A Sign call returns no signature, the fake polkit authority
      is not asked, and the journal sink holds exactly one entry with the outcome.
- [ ] Add an integration test against the real bus fixture (`BusCredentials`) showing that a
      present `ProcessFD` still lets a Sign call succeed, so the new requirement does not refuse
      every call.
- [ ] Decide the pidfd/pid cross-check and the optional "why" field; record the outcome. If a field
      is added, document it in `docs/audit.md`.
- [ ] Run `just check`, `just test-integration` and `just mutants`; kill every surviving mutant in
      the credential-reading code with tests, not exclusions.

## Evidence
- Reply without `ProcessFD` is refused → unit test in `credentials/tests.rs` calling `caller_from`
  with a map lacking it → `Err(CredentialsError::Missing)`; deleting the new check makes it fail.
- Wrong-typed `ProcessFD` is refused → unit test with a `u32` or string value → `Missing`.
- Complete reply still accepted → unit test with all three fields → `Ok` with the expected uid and pid.
- Sign refused, no signature → `tests/audit` test with a no-`ProcessFD` fake → the call returns
  an error with the access-denied name, no signature bytes.
- Polkit not asked → same test → `f.asked()` is empty.
- Exactly one journal entry with the "authorization not possible" outcome → same test, `MemorySink`
  → one entry, `Outcome::AuthorizationUnavailable`, key id and mechanism filled in, caller absent.
  It must also pass through the journal wire format: the outcome value read from the entry
  matches the documented value in `docs/audit.md`.
- Real bus still works → integration test with `BusCredentials` on the test bus → a signature is
  returned and the entry is `Signed` (this fails if the code asks for a field the bus never
  gives, or mishandles the fd type).
- No D-Bus interface or field name change → `git diff` of `docs/audit.md`, the interface XML and
  the audit field list shows only additions; the existing audit tests (`just test-integration`)
  still pass unchanged.
- No fd or secret leakage → a test that the `Debug` and `Display` of `CredentialsError` contain
  no fd number; the fd is closed (a test counting open fds in `/proc/self/fd` before and after
  repeated parser calls shows no growth).
- Cross-check decision → `docs/findings.md` or the commit records either that the check is
  implemented, with a mismatch test returning `Missing`, or why it cannot be done.
- Code stays in mutated files → `just mutants` → exit 0, no surviving mutant, and
  `crates/custodiod/src/credentials.rs` is still in the `--file` list of the recipe.
- Everything passes → `just check && just test-integration && just mutants` → exit 0.
