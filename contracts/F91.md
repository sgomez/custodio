# F91 — End-to-end ownership cases with two real accounts

## Scope
Built: the `owner-*` cases of `e2e/cases.list`, run by the e2e guest with two real accounts, `alice` (A, already
there) and a second ordinary account (B, created by the guest, with its own logind session and its own test polkit
agent: the agent registers per session and keeps its request log apart from alice's). Acceptance 1 and 2 of SPEC.md,
end to end, through the shipped service, polkit, the CLI and the PKCS#11 module.

Parts:
- A new step group `owner` in `e2e/select.sh` (`case_group`, `phase_runs`), so `just e2e-cases debian13 'owner-*'`
  runs the setup and this step only, and `just e2e` runs it too. It does not change the counts the `journal-*`,
  `upgrade-*` and `lifecycle-*` cases rely on (`TOTAL`, the ledger, the state they start from): the builder places it
  where that holds and shows it (the ids it imports are its own; it leaves no key behind that a later case counts, or
  it removes them with `custodio delete`).
- Every shell-level helper has a container-free test (`just test-scripts` scripts, as F63's), like the existing
  selection tests.
- Calls the CLI does not offer (sign by id of a key B does not own, replace certificate) are made with `busctl`
  against the system bus, as the user; the per-case error name is read from the reply. The builder documents in the
  script which call is used for which case.

Not built: new service, CLI or module behaviour (F72, F76, F78, F87 own that and their integration tests; this
feature only proves it on real accounts). Other targets (`just e2e`, all six) run at the checkpoint F100; package
gates at F90/F100. Per-operation journal content and the `custodio list` format are proven by F87/F72/F76/F78's own
tests; here only what differs between "another uid's id" and "an id nobody has".
The feature is about five steps; no split.

Environment (run in this session): `podman run --rm --privileged --cgroupns=host alpine echo ok` → `ok`; local
images `custodio-e2e-*` exist, so the dev container builds and boots targets; `busctl` is present.
If the second account cannot get a logind session via `su -l` like alice, that is a finding for the builder to
resolve (e.g. `machinectl shell` or `loginctl`), recorded in `docs/findings.md`; it is not a deviation.

## Steps
- [ ] Failing container-free tests first: `select.sh` maps `owner-*` to the `owner` group, `phase_runs owner` is true
      only when an owner case is selected (and nothing else runs for an owner-only selection beyond the setup); the
      accounting reports every owner case exactly once. Add the case ids to `e2e/cases.list`.
- [ ] Guest side: create B, give A and B each a session with a running test agent (separate agent directories and
      request logs), and run the owner step as each user in the right order, with placement that leaves the existing
      cases' counts unchanged.
- [ ] Acceptance 1: A imports a key; A's `custodio list` has it, B's does not; as B, sign, delete and replace
      certificate on that id each fail with the same error name as the same call on an id nobody has (a control id
      B never imported, called alongside; the replace calls use the same certificate argument and differ only in
      the id, so an argument check cannot explain a match or a difference); B's agent log and A's agent log gain no request from B's calls; the
      journal of `custodio.service` has the same entries for B's calls on A's id as for the control id (none for
      either, per `docs/audit.md`), and A's key is still listed, still signs and still has its certificate afterwards.
- [ ] Acceptance 2: A and B each import a key with the same id (with different keys and certificates); each signs
      with their own (PKCS#11 module, one polkit request each in their own agent) and each signature verifies with
      `openssl` against that uid's certificate and fails against the other's.
- [ ] Negative controls (run, shown red, reverted): (a) make the "foreign" calls as A, the owner, on A's id, so the
      calls succeed or ask polkit and the error-name, agent-log and journal checks go red; (b) in acceptance 2's
      verification swap the certificates (A's signature against B's certificate, expecting success), so the case goes red.
- [ ] Placement: the keys of both acceptances are removed with `custodio delete` (as their owners, with the agent
      approving) at the end of the owner step, which runs after the `journal` step, so the journal ledger window,
      `TOTAL`, and the upgrade/lifecycle starting state are unchanged.
- [ ] Run `just quick`, then `just e2e-cases debian13 'owner-*'` until both pass.

## Evidence
- `owner-*` are in `e2e/cases.list`, reported exactly once each, and the selection reaches only this step →
  `scripts/test-e2e-select.sh` and `scripts/test-e2e-skips.sh` (via `just quick`) → pass; a case missing from the
  guest output fails.
- A imports a key, A's list shows it, B's list does not → case `owner-list-isolated` → A's `custodio list` output
  contains the id; B's, run as B in B's session, does not and exits 0; fails if list were unfiltered.
- B's sign, delete and replace certificate on A's id fail with the same error name as an id nobody has → case
  `owner-foreign-id-no-such-key` → for each of the three calls, the error name of the call on A's id equals
  `com.rfirma.Custodio1.Error.NoSuchKey` and equals that of the call on the control id; the three calls succeeding
  or giving any other name fails the case.
- No polkit dialog for those calls → case `owner-foreign-id-no-polkit` → request logs of both agents have the same
  line count before and after B's three calls on A's id (and on the control id); a request logged fails the case.
  A request for B's call would land in B's session agent's log; that logs requests at all is shown by the
  one-request-per-signature check of `owner-same-id-own-key` in each agent.
- Journal behaves as for a missing id → case `owner-foreign-id-journal` → all entries of `custodio.service` (any uid
  field) between a marker before and one after B's calls on A's id: count equal to that for the control id's calls,
  and zero, per `docs/audit.md`; A's own
  import entry is present, so the query is shown able to find entries; B's calls changed nothing of A's key (still
  listed, still signs with one request).
- Same id for both accounts, each signs with their own, each verifies against that uid's certificate → case
  `owner-same-id-own-key` → both imports succeed; each user signs with the PKCS#11 module under the shared id; `openssl`
  verifies A's signature with A's certificate and B's with B's, and each verification against the other's fails.
- Negative controls → (a) foreign calls made as the owner; (b) swapped certificates in the verification → each shown
  red once, then reverted.
- Whole feature → `just quick && just e2e-cases debian13 'owner-*'` → exit 0, the accounting lists the owner cases
  and no other.
