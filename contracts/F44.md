# F44 — Lifecycle scripts of the .rpm

## Scope
The rpm scriptlets wired in `packaging/nfpm.yaml` under `overrides.rpm` (today `pre` and `post`; this feature adds the ones it needs,
among `preun`, `postun`, `posttrans`) and the tests that run them. SPEC design section 2 decides the behaviour and F43 is the model:
the same decisions as the `.deb` (`contracts/F43.md`, `docs/decisions.md`), expressed with rpm's own conventions. Fedora's
`%systemd_post`, `%systemd_preun`, `%systemd_postun_with_restart` and sysusers handling decide what SPEC leaves open: their behaviour
is copied, not their text, and nfpm scriptlets are plain shell, so no rpm macro may be left unexpanded in a script.

Built here:
- Argument counts. rpm passes the number of instances of the package that will remain: `1` install, `2` upgrade, `0` erase. On an
  upgrade the OLD package's `%preun`/`%postun` run (with `1`) after the new package's `%pre`/`%post`, and they come from the old
  package, not from this tree. So the restart and the "stop only on erase" decisions must hold when the old package is the previous build
  of this one and when it is a package with other (or no) scriptlets, which is the case for the next release after the first nfpm rpm.
- Account: created in `%pre` (install and upgrade, after the F42 bus check, which stays unchanged), before rpm unpacks the bus policy,
  from the sysusers content embedded as in F43 and under the same sync gate against `data/sysusers.d/custodio.conf`. If the tool is
  missing or fails, `%pre` fails, so nothing is installed. A step researches (subagent; record in `docs/findings.md`) how Fedora 44 and
  Alma 10 get the account made at that point: `Requires(pre)` on the provider of `systemd-sysusers`, rpm's sysusers generator and
  `user()` provides, or the `rpm-ostree` handling of users. It decides within these limits: one account definition (the sysusers file),
  the tool is guaranteed present when `%pre` runs, never a silent skip, and no `useradd` fallback. If the research shows nfpm cannot
  express the dependency, the builder amends this contract (evaluator approval) or writes `BLOCKED.md`; it does not choose a fallback alone.
- `%post` ($1 = 1 or 2): `daemon-reload`, then reload the bus, then update the journal catalog, in that order, each tolerating failure
  (no bus, no systemd running, read-only `/var`). Never enable, never start, no preset.
- Restart on upgrade: once, after the new files, the daemon reload and the bus reload, and only if the service was running. A step
  decides how, given that `%postun` belongs to the old package (candidates: a marker written by `%pre` and consumed later; `%posttrans`;
  `try-restart` from the old package's `%postun` as `%systemd_postun_with_restart` does). The choice is recorded in `docs/decisions.md`
  with the F43 reasoning about `try-restart` weighed, and it must pass the "ran once, after the bus reload, only if running" evidence
  with a real rpm upgrade between two builds. If `%posttrans` is used, the header states what it receives (its `$1` cannot tell install
  from upgrade) and the argument-count evidence covers it.
- Erase ($1 = 0): stop the service (`%preun`); in `%postun` reload systemd and the bus, keep the state directory and the account, and
  print the notice (state directory path, account kept, deleting by hand destroys the keys), on the same stream as F43 (stderr). An
  upgrade ($1 >= 1 in `%preun`/`%postun`) neither stops the service nor prints the notice; the header lists the exact call list of
  `%preun 1` and `%postun 1` (nothing, or the reloads it decides), and the tests compare against it.
  Whether `rpm-ostree uninstall` runs `%preun`/`%postun` at all is NOT assumed: rpm-ostree composes a new deployment and may run
  only `%pre`, `%post`, `%posttrans` and file triggers. The research step answers it (with sources) in `docs/findings.md`. If erase
  scriptlets do not run there, the stop and the notice that SPEC section 2 asks for on `rpm-ostree uninstall` cannot come from `%preun`
  or `%postun`; the builder looks for a mechanism that does run (for example a `%posttrans` or file trigger, or a notice at the next
  install) within the limits of this contract, and if none exists, writes `BLOCKED.md` with the options instead of covering it with a
  stubbed erase case. Real rpm-ostree runs belong to the e2e features (SPEC section 4, Limits: containers do not run it).
- Offline: every scriptlet exits 0 where the F43 equivalent tolerates failure when there is no bus socket, `systemctl` fails with
  "not booted with systemd", `/run` has no `custodio` marker directory, and `/var` is read-only (a failing write of a marker must not
  fail the scriptlet). The F42 notice for "no bus" still appears and installation goes on.
- `just test-scripts` gains: a static test of the scriptlets (state-path allowlist with reasons, forbidden commands) as for the deb,
  a stubbed lifecycle test over every argument count (`scripts/test-rpm-lifecycle.sh`, call lists in its header), and a real-`rpm` test
  (`rpm -i/-U/-e --root` in a user-namespace chroot, as `test-install-real.sh` does), all listed in the `test-scripts` recipe.
- The package gates, fixture tests and lint lists that assume "only `pre` and `post`" for the rpm are updated (inverted, not dropped);
  rpmlint exceptions, if any, carry reasons.

Not here: the deb (F43, unchanged except for helpers shared with it), the Arch script (F58), real Fedora, Alma, Bazzite or rpm-ostree
runs (F45 and later), `docs/install.md` (F51), any change to the bus policy, polkit action or unit hardening, and the F42 check itself.

Size: about eight small steps; no split needed.

## Evidence
- Argument counts are the real ones → `test-rpm-lifecycle.sh` runs each scriptlet with `1`, `2` and `0` where rpm calls it, and the real
  `rpm -i`, `rpm -U`, `rpm -e` test records the `$1` each scriptlet received (a logging wrapper fixture package, or `rpm -q --scripts`
  plus a stub that logs `$1`) → install: `%pre`,`%post` get 1; upgrade: new `%pre`,`%post` get 2 and old `%preun`,`%postun` get 1;
  erase: `%preun`,`%postun` get 0. Mutants testing `$1 -eq 1` where `-ge 1` is meant (and the reverse) fail the suite.
- Account before the bus policy → real `rpm -i --root` with a `systemd-sysusers` stub that records whether
  `/usr/share/dbus-1/system.d/com.rfirma.Custodio1.conf` exists in the root when called and adds the account to the root's
  `/etc/passwd` → record says "absent", account present after unpack; the mutant "account creation moved to `%post`" says "present"
  and fails; the script-level install case logs `systemd-sysusers` before any bus reload. The embedded sysusers content equals
  `data/sysusers.d/custodio.conf` (sync gate in `check`; a mutated copy of the rpm scriptlet fails it).
- Account tool present at `%pre` → built `.rpm` dependency data (`rpm -qp --requires` with the pre-flag, or the mechanism the research
  chose) → names the provider of `systemd-sysusers`; a fixture without it fails the check (`test-check-packages-deps.sh`); the F42
  `test-bus-check*.sh` and `check-bus-check-sync.sh` still pass unchanged.
- Failing account creation is not hidden → stub `systemd-sysusers` exiting non-zero, and none on `PATH` → `%pre` exits non-zero with a
  stderr message naming the tool, real `rpm -i` fails and installs no file; mutant `|| true` fails the test.
- Install does daemon-reload, reloads the bus, updates the catalog, in that order, once each → install case → log shows
  `systemctl daemon-reload`, the bus reload, `journalctl --update-catalog` (the order the header states) exactly once each.
- No enable or start, ever → install, upgrade and erase cases → no `enable`, `start`, `preset`, `restart` (except the one upgrade
  restart below) call to `systemctl` in the log; mutant adding `systemctl enable` or a `%systemd_post` expansion that presets fails.
- Restart on upgrade only if running, once, after the bus reload → real `rpm -U` between two builds with the stub reporting active,
  and one reporting inactive; and the script-level cases for each scriptlet that takes part → active: exactly one restart of
  `custodio.service` after the new package's `%post` (the two builds ship byte-identical files, so the stub also records the rpmdb
  version of `custodio` at the restart: it must be the new one), after daemon-reload and after the bus reload of the NEW package's `%post`; inactive:
  no restart and no start (the stub models state, so a `try-restart` passes only when it should). Mutants: unconditional restart,
  restart before the bus reload, restart twice (once in `%post`, once in `%postun`) fail.
- Upgrade from a package with other scriptlets → real `rpm -U` over a fixture old package with only the F42-era `%pre`/`%post`
  (as the M1 `.rpm` scriptlets) and no `%preun`/`%postun`, run twice: stub active → exactly one restart, after the bus reload of the new
  package's `%post` (the new `%pre`, which runs first, is what makes this possible without old-package scripts); stub inactive → no
  restart, no start. Both: exit 0, state tree unchanged, no error. A mutant that restarts only from the old package's `%postun` fails the
  active case.
- Upgrade keeps state directory and account → upgrade cases → tree listing with content hash, owner, mode, mtime of the state directory
  identical before and after (and a root without the directory: still not created); no `userdel`, `groupdel`, account-removal call;
  `custodio` uid unchanged; `%preun 1` makes no `stop` call; `%postun 1` prints no notice.
- Erase stops the service, keeps state and account, prints the notice → `%preun 0` and `%postun 0` cases and real `rpm -e` → log has
  one stop, the reloads; the state tree is identical; the account remains in `/etc/passwd`; every packaged file is gone; the notice is
  on stderr (stdout asserted empty), names the state directory and says deleting it by hand destroys the keys; mutant deleting the
  directory fails. The service is not left running (stub state after `%postun`).
- rpm-ostree uninstall meets SPEC → the research finding says which scriptlets rpm-ostree runs on uninstall; the stop and the notice are
  proven on the path that finding names (a test that runs exactly those scriptlets, and no other, under the offline setup: no bus socket,
  `systemctl` fails, `/var` read-only, `/run` not writable) → exit 0, notice printed, nothing written under `/var`. If no mechanism
  exists, `BLOCKED.md` is written; a stubbed `%postun 0` case alone does not satisfy this item.
- Erase scriptlets offline → `%preun 0` and `%postun 0` under the same offline setup → exit 0, notice printed (this is the dnf offline /
  chroot case, not the rpm-ostree claim).
- Offline install and upgrade → install and upgrade cases under that offline setup, and real `rpm -i` and `-U` with it → exit 0 (the rpm database is kept writable by placing it outside `/var` with `--dbpath` or by making read-only
  only `/var` minus the rpmdb; "nothing written under `/var`" excludes the rpmdb, named explicitly); the
  F42 "no bus" notice appears; reloads fail and are tolerated; no marker write error escapes; the account is still created (or the
  research's rpm-ostree mechanism is shown to do it) and the failure of the account creation is still fatal.
- No script touches the state directory → static gate over every rpm scriptlet in the nfpm configuration and the built rpm (`rpm -qp
  --scripts`) greps `/var/lib/custodio`, `StateDirectory` and `/var/lib/private`, allowing only the notice text and a named allowlist
  (file and exact text) with a reason per entry; stubs for `rm chown chmod cp cat mv ln` fail the test when called with a path under it;
  a control test with a deliberately bad scriptlet (`rm -rf` of it, a redirection into it) makes the state comparison fail, proving the
  check sees the path the scripts use, and the cases run inside the root.
- No widening of policy, action or hardening → grep gate: no scriptlet writes, seds, copies or installs onto the bus policy, polkit
  action or unit path, or runs `systemctl edit`, `set-property` or `systemd-run`; the existing unit-hardening, bus-policy and polkit
  gates in `check` still pass.
- Parity with the deb → a test lists the observable decisions (account before policy, reload order, no enable or start, restart
  condition, notice text, state untouched) and compares the rpm and deb call lists for them in matching scenarios → equal, except the
  documented format differences in the header; the notice text of both formats is identical (one comparison, mutant changing one word
  in the rpm fails).
- Scriptlets are plain shell → shellcheck over the rpm scriptlets (`just lint` list covers them whatever their names), and no unexpanded
  `%{`, `%systemd_`, `%sysusers_` in any scriptlet of the built rpm (`rpm -qp --scripts`) → clean; a fixture with a macro fails.
- Package contents and lint → `just package && just package-lint` → the built `.rpm` carries every scriptlet the header lists
  (`rpm -qp --scripts`), `check-packages` lists them, rpmlint shows no new finding outside the list with reasons; the `.deb` and Arch
  packages are unchanged.
- Whole feature → `just check && just test-scripts && just package && just package-lint` → all pass.
- Test hygiene → the account-before-unpack mechanism and the restart mechanism are each named in the test header; the header states what
  the stubs cannot cover (a real systemd, a real rpm-ostree and a real Fedora or Alma, left to F45 and later).

## Amendments
- 2026-10-30: nfpm 2.48.0 cannot write `Requires(pre)` (`rpm.requires` has only `post`; a `(pre)` suffix in a name is taken literally; checked by
  building packages). The plain `Requires: systemd` that the `.rpm` already has is the mechanism instead: rpm orders every non-weak `Requires`
  before the package that has it, including its `%pre` (`lib/order.c`, `addSingleRelation`), and nothing requires `custodio`, so no
  dependency loop passes through it; the pre flag only changes which edge rpm breaks in a loop. The step "the dependency that makes the
  sysusers tool present at `%pre`, with its check on the built rpm" and the evidence "Account tool present at `%pre`" read: the built rpm's
  `rpm -qp --requires` names `systemd` (the provider of `systemd-sysusers`), a fixture without it fails `test-check-packages-deps.sh`,
  `%pre` itself fails with a message naming the tool when it is not on `PATH`, and the rpm creates no `user()` provide (rpm's own sysusers
  step would create the account before the F42 check; SPEC says the check runs before anything changes).
