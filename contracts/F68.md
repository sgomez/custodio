# F68 — Research: service detection through xdg-dbus-proxy

## Scope
Built: a section `## F68` in `docs/findings.md`. No Rust, no unit, no policy change, nothing shipped.
It settles the SPEC open question "Detection through the flatpak proxy". The client documentation that
will carry the detection steps, and acceptance 15 itself (a real flatpak run), are other features; the
section only gives them the steps.

Source: `xdg-dbus-proxy`'s filtering code (`flatpak-proxy.c`), read at a named release tag (version and
file named, with the function or rule table that decides each call). Network is reachable from the dev
container (`curl -sI https://raw.githubusercontent.com/flatpak/xdg-dbus-proxy/main/flatpak-proxy.c` →
`HTTP/2 200`, run in this session); use a subagent for reading outside material. `xdg-dbus-proxy` and
`flatpak` are not installed in the dev container (`which` finds only `dbus-daemon` and `busctl`).

Reading is the minimum. Where it is cheap, the builder also runs it: a bus with a test service file
(`Exec=/bin/false`, and one with a real running service), and `xdg-dbus-proxy` (installed in a throwaway
container, e.g. `debian:trixie`, if packaged; or built from the same tag) started with
`--system-talk-name=com.rfirma.Custodio1` against that bus, with the five calls made through it. Anything
that was only read and not run is labelled as such in the section. If the proxy cannot be run anywhere
available, the section says which command failed, and states the proxy results as source-derived.

The four situations are 'service installed and running', 'installed but not activatable
(`Exec=/bin/false`, not started)', 'not installed' and 'name not allowed by the sandbox'. For each, the
section gives the error name or result on the host (plain bus) and through the proxy. Whether
`StartServiceByName` on the non-activatable file really fails with `org.freedesktop.DBus.Error.Spawn.*`
(and which) is shown by running it on a bus, not assumed.

Not here: changing the SPEC, `docs/decisions.md`, or the D-Bus policy; if the finding contradicts SPEC
line 116 or acceptance 15, the section says so and the builder lists it in `PROGRESS.md` (SPEC is not
edited).

## Steps
- [ ] Read the proxy's filtering source (tag, file, function named) for the bus-driver calls NameHasOwner,
      ListActivatableNames, StartServiceByName, GetNameOwner and a method call to an unowned activatable
      name, under `--system-talk-name`, and for names not allowed by the filter. Record the result of each.
- [ ] Host baseline: on a private `dbus-daemon` (system-bus style config) with test service files, run the
      five calls for the four situations and record the exact error name or result of each.
- [ ] Through the proxy: run, if obtainable, the same calls via `xdg-dbus-proxy` with and without the
      `--system-talk-name`; record results, or the failing command and the source-derived result.
- [ ] Write `## F68`: the table of call × situation (host, proxy), the `Detection steps` for the client
      documentation (ordered, each with what it concludes), and the final line `Detection:` summarising them
      (it must be a line starting `Detection:`). Check it against SPEC line 116 and acceptance 15 and note any
      conflict. Run the feature's `verify`.

## Evidence
- Which bus-driver calls pass for `--system-talk-name=com.rfirma.Custodio1` (NameHasOwner,
  ListActivatableNames, StartServiceByName, GetNameOwner, call to an unowned activatable name) → `## F68`
  names the xdg-dbus-proxy version and file and gives one pass/blocked/rewritten entry per call, citing the
  function or rule → `verify` finds all five names and `system-talk-name` (exit 0); the evaluator checks
  the entries against the cited source.
- The error or result a client sees for each of the four situations, on host and through the proxy →
  table in the section with exact error names (e.g. `org.freedesktop.DBus.Error.ServiceUnknown`,
  `…Spawn.…`, `…AccessDenied` or whichever are measured) and a marker `run` or `read` per cell → no cell
  empty; every `run` cell has the command and output beside it.
- 'Installed but not activatable' → section includes `Exec=/bin/false` and the result of a real
  `StartServiceByName` against such a file → `verify` finds `Exec=/bin/false`; output shown.
- Host results are real, not derived → commands and outputs from the private `dbus-daemon` run → present,
  and different between the 'running', 'not activatable' and 'not installed' cases, so the test could have
  failed.
- Detection steps for the client documentation → ordered list in the section, each step tied to the table
  rows it separates → the four situations are all distinguished, or the section says which two cannot be
  told apart through the proxy and why.
- Summary line → a line `Detection:` in the section → `verify` finds `Detection:`; as a negative control
  the same `verify` on a copy of `docs/findings.md` without the `Detection:` line exits non-zero.
- Feature verify → run the `verify` string from `features.json` → exit 0.
