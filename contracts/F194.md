# F194 — Certificate text escaped, `custodio list` as a table and `custodio list <id>` in full

## Scope

Built here:

- A module of custodio-cli (its own file, not `list.rs`, because `mutants` lists files) that decodes from a
  certificate's DER the fields `list` shows: subject, issuer, serial, start and end of validity, SHA-256
  fingerprint. It accepts any bytes: a field that cannot be read is a placeholder, never a panic. Every
  control character (C0, DEL, C1) and every other non-printable character of a decoded string is escaped, so
  nothing a certificate holds can drive the terminal or forge a line or a row. The same module escapes the
  key id and key type that come from the service. How a subject is shown (common name or RFC 4514) is the
  builder's choice, written in the help and the man page; the full view shows the whole name.
- `custodio list`: a table, one row per key (id, key type, storage kind, subject, end of validity), one row
  always one line. One note at the foot, only when some key is `encrypted-tpm` or `encrypted-host`, saying the
  storage is weaker and pointing to the README. The M6 state-directory warning on stderr stays. No keys: says
  so and how to import one. The old five-line block per key and its per-key `note:` go.
- `custodio list <id>`: that key with everything in the row plus issuer, serial, start of validity and SHA-256
  fingerprint, selected from the `ListKeys` reply on the client side (no API change, no new D-Bus call). An
  id the person does not have is a two-line error (what, then `custodio list`), through the error module of
  F193 (new `ListFailure` case, escaped id). The parser, the command table, the help and `packaging/custodio.1`
  gain the optional argument and the description of the table and of how the subject is shown; the existing
  F193 help and man-parity tests then cover them (no new parity test).
- A fuzz target `cert_fields` in `crates/custodio-cli/fuzz`, added to `fuzz-smoke`'s default `expected`
  list. The new module joins the custodio-cli list of the `mutants` recipe.
- Consumers of the old format, changed in the same commit: `crates/custodio-it/tests/list.rs` (it asserts the
  block layout), the README example of `custodio list`, and the e2e scripts that read the block
  (`e2e/cli-lib.sh`, `ops-lib.sh`, `rd-lib.sh`, `upgrade-accts-lib.sh`, the `*-user.sh` that grep `^id: `, and
  their `*-selftest.sh`). The e2e scripts are proven by their selftests (in `just test-scripts`, run at the
  checkpoints) and by the e2e run that uses them; no stub engine is built. Keep the lines they match stable
  where cheap (the none sentence "You have no keys in the custodio service." stays a substring).

Left to other features: `fingerprint` and `doctor` (F197, F202), completions asking `custodio` for ids
(F205 etc.; the table must not be what they parse, they will use their own call), colour of the table
(not required; if added it uses the F193 rule), and all package and e2e gates, proven at the checkpoints.
Acceptance 8 and 9 parts that run on a real system through `just e2e` are proven there, not here.

Environment: `dbus-daemon` and `openssl` are already used by the `custodio-it` tests; nothing else is
needed. The hostile certificate is a fixture DER built with `openssl` (added to `fixtures/gen.sh`, output
committed) with the same public key as an imported fixture key, so `replace_certificate` accepts it. Fuzz
steps need the nightly toolchain and cargo-fuzz as in F193. SHA-256 comes from a crate already in
`Cargo.lock` if it passes `cargo-deny` and `cargo-machete`; the builder chooses.

Cost of the tests (estimates from similar tests; the builder reports measured times in PROGRESS.md):

| Test | Time | How it runs |
|---|---|---|
| `crates/custodio-cli/tests/cert_text.rs` (certificates built in the test or from fixtures, no process) | under 1 s | own test binary, tests parallel |
| unit tests of the table, full view, error text (in the crate's lib tests) | under 1 s | parallel |
| `crates/custodio-it/tests/list_view.rs` (private dbus-daemon, fake polkit, as `list.rs`, which takes about 3 s) | about 3 s | own binary; tests parallel, one rig each |
| `cert_fields` in `fuzz-smoke` | 2000 runs, about 1 s plus one more target build | the recipe's loop |
| `just mutants-diff F194` | new module, table and view code: expect 80 to 150 mutants, 3 jobs, 8 to 15 minutes | one command; if it risks 30 minutes, split with `--file` and say so |
| e2e | no new case: the existing cases that call `list` are updated and run at the checkpoints | none here |

The feature is larger than five steps; the steps below are ordered so a session can hand over after step 3
or step 5 without rework. Suggested split if needed: (1) steps 1 to 3 (module, fuzz target), (2) the rest.

## Steps

- [x] 1. Write `tests/cert_text.rs` first (failing): fields of real fixture certificates (subject, issuer,
      serial, both dates, fingerprint equal to the value `openssl x509 -fingerprint -sha256` gives); subject
      and issuer with control characters, ESC sequences, newlines, DEL, C1 bytes and bidirectional or other
      non-printable code points; malformed DER (empty, truncated, trailing bytes, wrong tags, huge lengths,
      invalid UTF-8 or invalid times inside an otherwise valid certificate) each giving a placeholder per
      field and no panic.

      list and the module to the `mutants` list in the justfile.
- [x] 4. Unit tests first, then the table (`custodio list`): one line per key, columns aligned and a cell
      never able to contain a line end, the foot note once or not at all (kinds `tpm`, `encrypted-tpm`,

- [x] 5. Unit tests first, then `custodio list <id>`: parser (one optional id, extra arguments are usage

## Evidence

- Decoded fields (subject, issuer, serial, validity start and end, SHA-256 fingerprint) →
  `cargo test -p custodio-cli --test cert_text` (fixture certificates; fingerprint compared with the value
  OpenSSL prints for the same file, recorded in the test as a literal from `gen.sh`) → equal values.
- Tolerates any input; malformed field gives a placeholder, never a panic → `cert_text.rs` malformed-DER
  cases (empty, truncated, trailing garbage, wrong tags, huge length, bad UTF-8, bad time) plus the
  `cert_fields` fuzz target in `just fuzz-smoke` → each case returns placeholders; 2000 runs without a
  crash or a failed assertion.
- Every control character, DEL and non-printable is escaped in subject and issuer; no forged line or row
  (SPEC Design 3) → `cert_text.rs` on certificates with control characters, ESC sequences and newlines in
  subject and issuer → no output char below 0x20, no DEL, no C1, and the table lines count equals the keys;
  the fuzz target asserts the same on arbitrary input. A negative control: an unescaped sample string in the
  same test fails the same predicate.
- New fuzz target in the smoke list → `just fuzz-build && just lint-fuzz && just fuzz-smoke` → build, lint
  and run pass; `just fuzz-smoke` with `cert_fields` missing from the run fails (run once with a wrong
  name in the argument, as F193 did for `cli_args`).
- Module joins the `mutants` list → `just mutants-diff F194` → 0 missed.
- Table: id, type, kind, subject, end of validity on one row per key; not-one-line cells impossible →
  unit tests of the table in custodio-cli, and `list_view.rs` against the real service → expected rows.
- Weaker-storage note exactly once or not at all, pointing to the README, only for `encrypted-tpm` or
  `encrypted-host` → unit tests over the kind combinations (`tpm` only, mixed, unknown kind) → count 0 or 1;
