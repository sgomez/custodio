# F116 — New state format with the storage kind

## Scope
Built in `custodiod`, in the key store (`crates/custodiod/src/store.rs` and small files under `store/`, each under 5000
tokens; every new non-test file joins the `mutants` recipe's `--file` list), plus the minimum change to the callers the
new API forces:
- **One record per key**, one file `<root>/<uid>/<id>`, holding owner, id, kind, certificate and the protected key. The
  M3 layout (a key file plus a separate `<id>-cert` file, plain PKCS#8 and DER) is gone, so delete, replace certificate
  and import touch one file and their atomicity is that of one file. The record starts with a magic and a format
  version that no M3 file can start with (an M3 file is DER, first byte `0x30`).
- **The kind**: a Rust enum with three values (TPM; encrypted, TPM-bound; encrypted, host-bound), each with a wire
  string chosen once and documented on the enum for F119/F120 (the doc comment says "chosen once, only added to"). The
  on-disk tag and the wire string are separate things; the wire strings are pinned by a literal test.
- **The protected key** is a closed type with exactly two constructors from what protection returns: a TPM key (the
  F113 `Blob` plus the parent's name) and an encrypted credential (the raw credential bytes that `creds::seal` returns,
  with the binding its header gave). The store's write API takes only that type. No function of the store accepts
  `SecretSlice`, `&[u8]` or any other raw key bytes, so a plaintext key cannot be written, and the temporary file of a
  write holds only the framed record.
- **The framing readers** (read back from disk, bounded, refuse malformed input): the record, the TPM blob with its
  parent name (reuses and, if needed, extends `tpm::blob`), and the credential framing (bounded length, header read with
  `creds::header::inspect`, and the kind must agree with the binding the header names: a TPM-bound kind needs
  `Binding::Tpm`, host-bound needs `Binding::Host`, a TPM kind needs a blob). A stored record whose embedded owner or id
  differs from its path is refused.
- **The earlier format is only recognised**: a file in an owner area that lacks the magic is reported as `Legacy` by
  `get`, without its content being read beyond the magic, and the store lists such entries (owner, id) for F121's purge.
  There is no reader for it. The purge itself, and the journal entries for it, are F121.
- **Rules kept for every new file**: directory `0700`, file `0600` exactly, owner = service uid, no symlinks, a FIFO
  never blocks, refuse rather than repair, write to a temp file in the same directory, sync, `hard_link` into place
  (never overwrites), `.tmp-` leftovers removed at open, directory sync with `SyncFailed`. Replace certificate uses
  write + rename and keeps kind and protected key byte for byte. Remove (`remove_existing`) keeps "of two removers only
  one gets `Ok(true)`"; it checks the file rules but does not parse the content, so a record that no longer parses can
  still be deleted by a person (F118 needs this).
- **Callers**: `import.rs`, `dbus/{delete,replace}.rs`, `dbus.rs` sign, `main.rs` and the tests that call the store move
  to the new API. Decision for the transition, within these limits: no production path may write a plaintext key after
  this feature; no test is deleted, ignored or weakened (a test that needs a stored key builds a record with a test
  helper that produces a protected one, e.g. a credential from a fake `Credentials` access point); the choice of kind
  (F117), signing by kind (F118), the kind in the API and CLI (F119), the journal fields (F120) and the purge (F121)
  are not built here. If the builder finds the interim wiring of the daemon's import and sign cannot be done without
  building F117/F118, it writes the question in `BLOCKED.md` (or proposes the split under "Split" below) instead of
  weakening a rule. The interim wiring may only use the encrypted kinds, through the `Credentials` access point.
- **Left to other features**: fuzz targets for the readers (F122); the "No-plaintext check" and "Duplication check" over a
  whole installed state directory (checkpoints F132/F146); documenting kinds in `docs/api.md` and `docs/audit.md`
  (F119/F120). `docs/decisions.md` is edited only if a later session could undo a choice (for example, delete not
  parsing content, or the unknown-version refusal) without knowing why.
- **Split (proposed, not applied)**: if the callers' migration (above) grows past about five steps, split into F116a (the
  store, record, kind and readers, with the old API kept `pub(crate)` for callers only until F116b) and F116b (migrate
  the callers, remove the old API). The evaluator decides; features.json is not edited here.

Environment check: no privileges or devices are needed beyond what F113/F115 already use. Run in the `custodio-dev`
container (the host has no tss2 libs): `ls /usr/bin | grep -c tpm2_` shows the tools; the blob tests of this feature use
bytes produced by F113's import against `swtpm` (`tpm_import` fixtures) or hand-built structures, so `swtpm` is not
required for the store tests.

## Steps
- [ ] Inventory (read-only, no code): list the callers of `KeyStore::{put,get,replace_existing,list,remove*}` and the
      `cert_id` convention, and write the transition plan within the limits of Scope in the first line of the commit body
      of step 3. If it needs the split or a `BLOCKED.md`, say so now.
- [ ] Tests first, unit (`store` tests and the readers' tests): kind wire strings and tags; record encode/decode round
      trip for each kind; bounded refusal of every malformed record (empty, truncated at every length, bad magic, unknown
      version, unknown kind tag, oversized certificate/blob/credential/parent name, trailing bytes, inconsistent
      lengths); blob + parent name reader; credential reader and kind/binding mismatch; embedded owner/id mismatch.
- [ ] The kind, the protected-key type and the record framing (with the readers above) to green; extend `tpm::blob`
      only as the parent-name framing needs.
- [ ] Tests first for the store rules over the new record API (the M3 rule tests are ported, not dropped; see Evidence),
      then `put`/`get`/`list`/`remove_existing`/`replace_certificate`/legacy recognition on the new format; remove the old
      byte API.
- [ ] Migrate the callers and tests to the new API under the Scope limits; `just quick` green.
- [ ] Integration target `crates/custodiod/tests/state_format.rs` (public API of the store, no D-Bus): every rule, the
      concurrent import, the concurrent replace/read, the framing readers on a real `swtpm` blob. Add the new store files
      to the `mutants` recipe; run `just mutants-diff F116` until 0 missed.

## Evidence
- The record holds owner, id, kind, certificate and protected key → unit `store::tests::record_round_trip` for each kind
  (all five fields compared after `put` then `get` through the files on disk) → equal.
- The kind has three values with fixed wire strings → unit `kind_wire_strings_are_pinned` (three string literals, a
  parse round trip, an unknown string refused) → passes; fails if a string or tag changes or two collide.
- The API cannot accept an unprotected key → `compile_fail` doctest on `KeyStore::put` that passes a `SecretSlice<u8>` and
  a `&[u8]` (runs under `just quick`; if doctests are not run there, the same check as a `trybuild`-free negative control
  the builder documents) → fails to compile; and the grep in `state_format::write_api_takes_only_protected_types` over
  the public signatures of `KeyStore` finds no `SecretSlice`/`&[u8]` parameter → passes.
- Nothing written holds a plaintext key, temporary files included → `state_format::no_plaintext_anywhere`: a distinctive
  key is the input of a fake credential protector (the credential bytes are not the key); during `put`, a hook between
  the temp write and the link reads the temp file and, after the call, the whole state dir is swept, both for the key in
  raw, hex, base64 and PKCS#8-DER encodings → absent. Negative control: the same sweep over a directory in which the key
  was planted finds it.
- TPM blob and credential framing readers are bounded and refuse malformed input → unit
  `store::tests::framing::{blob_*, credential_*, record_*}` (list under Steps 2) and `state_format::framing_readers`
  on a real blob from `swtpm` (valid → accepted; every one-byte truncation, every size field raised past its bound,
  trailing bytes → a typed error, no panic, no allocation larger than the bound) → all refused except the valid one.
- A credential whose header does not match the kind is refused → unit `kind_binding_mismatch` (host header under a
  TPM-bound kind, TPM header under host-bound, null-key header, PCR-bound header) → each refused.
- A blob records its parent's name → `record_round_trip` (TPM kind) compares the parent name byte for byte; the check
  that the name equals the current parent's stays F113/F114's.
- Exact modes → `state_format::modes_are_exact` (root `0700`, area `0700`, record `0600`, whatever the umask, including
  `0o000` and `0o077`) → exact.
- Owner checks → unit `rejects_file_of_other_owner` and `rejects_area_of_other_owner` (the existing `file_uid` seam) →
  `BadOwner`; `state_format::record_of_another_owner_path_is_refused` (a record file copied into another uid's area) →
  refused as mismatch.
- No symlinks, no FIFO hang → `state_format::symlink_record`, `symlink_area`, `symlink_root`, `fifo_record`
  (get, list-then-get, replace, remove all refuse and never follow or remove the link) → `BadFileType`, no hang, the
  link's target untouched.
- Refuse rather than repair → `state_format::loose_modes_are_not_repaired` (area `0755`, record `0644`, root `0755`:
  get/put/replace/remove/open fail with `BadPermissions`, and the mode is unchanged afterwards) → unchanged.
- Atomic writes that never overwrite → `state_format::put_never_overwrites` (second `put` of the id → `AlreadyExists`,
  the first record byte for byte); `put_failure_leaves_no_partial_or_tmp` (injected failure before the link: no file
  under the id, no `.tmp-` left); a reader running during many puts sees either `NotFound` or a whole valid record →
  never a partial one; leftover `.tmp-*` removed at `open` → pass.
- Two concurrent imports of one id → `state_format::concurrent_put_one_id` (two `KeyStore` handles on one dir, 2 and 16
  threads, a barrier, 200 rounds, different kinds and certificates per thread): exactly one `Ok`, the rest
  `AlreadyExists`; the stored record equals the winner's in full (never a mix of one's certificate and another's key);
  no `.tmp-` left → holds every round. Negative control: a store variant that uses `rename` for `put` (test-only
  double) loses the exactly-one property in the same test.
- Delete keeps M3's atomicity → `state_format::concurrent_remove_one_winner` (N threads, exactly one `Ok(true)`, record
  and certificate gone together, nothing left) and `remove_deletes_unparsable_record` (a record with a good magic and
  a bad body is removed; a symlink or a record with mode `0644` is refused) → pass.
- Replace certificate keeps M3's atomicity → `state_format::replace_certificate_is_atomic` (a reader thread loops while
  the certificate alternates between two values: each read is a whole record with one of the two certificates and the
  same kind and protected key bytes; a failure between temp write and rename, via the `replace_with` seam in a unit test
  `replace_failure_keeps_old_and_leaves_no_tmp`, keeps the old record and no tmp); replacing a missing id →
  `NotFound`, creates nothing; a certificate over its bound → refused, old record intact → pass.
- Concurrent replace with delete never resurrects a record → `state_format::replace_racing_remove` → the id ends gone
  or whole, never recreated by the rename of a stale temp file (`replace` never creates).
- No reader of the earlier format, only recognition → `state_format::legacy_files_are_recognised_not_read` (an M3
  fixture: DER key `0x30…` and `<id>-cert` files under `tests/fixtures` or generated): `get` → `Legacy`, the
  legacy listing returns exactly their (owner, id), a record with the new magic is not listed there; the legacy
  content is never returned in any error or `Debug` output (searched) → pass. A file with the legacy-looking first byte
  under a bad mode is refused with the file-rule error, not `Legacy`.
- Store rules kept by the M3 tests → the existing store tests (`creates_directory_0700`, loose-mode rejection, owners,
  replace, list, stale temp cleanup, too-large, invalid ids, sync failure) are ported to records and still pass; none
  deleted or ignored (`git diff` of the test files shows ports, not removals).
- No production path writes a plaintext key after the callers moved → `rg 'SecretSlice' crates/custodiod/src/store*`
  shows no parameter of a write function; `cargo test -p custodiod --locked` (the existing import, delete, replace and
  sign suites, on the migrated callers) → green.
- Mutation coverage of the new store files → `just mutants-diff F116` → 0 missed.
- Gate → `just quick && cargo test -p custodiod --test state_format --locked && just mutants-diff F116` → pass.
