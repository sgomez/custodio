# F92 — End-to-end polkit cases for import, delete and replace certificate

## Scope
Built: the `ops-polkit-*` cases of `e2e/cases.list`, run by the e2e guest as an ordinary account (alice, her own
session and test agent) against the shipped service, the real polkit and the CLI. They prove acceptance 3 of SPEC.md
(import, delete and replace certificate each ask polkit exactly once per call; denied or polkit stopped, the call fails
with the documented error and the state is unchanged; a second call asks again) and the polkit-ordering half of
acceptance 4 (a wrong password, import denied by polkit, fails as denied; approved, it fails with the wrong-password error).

Parts:
- A step group `ops-polkit` in `e2e/select.sh` (`case_group`, `phase_runs`), so `just e2e-cases debian13 'ops-polkit-*'` runs
  the setup and this step only, and `just e2e` runs it too. It runs after the `owner` step and before `upgrade`; it leaves
  no key behind and restores polkit, so `TOTAL`, the journal window and the upgrade/lifecycle starting state are as before
  (the builder shows this, as F91 did).
- The case ids (the builder fixes the exact list; every point of Evidence is one or more of them, all named `ops-polkit-*`).
- Container-free tests of every new shell-level helper and judgement (selection, accounting, a judgement fed bad evidence),
  like F63's and F91's (`scripts/test-e2e-*.sh`, run by `just quick`).
- Calls the CLI does not offer (replace certificate; the error name of an import or a delete, which the CLI turns into
  text) are made by a GLib D-Bus script like `e2e/owner-call.py` (finding "F91" in `docs/findings.md`: `busctl call` loses
  the error name). The builder may extend `owner-call.py` or add a sibling, and documents each method and signature in it.
  Where the CLI is the subject (`custodio import`, `custodio delete`), its exit status and message are judged as well.

Not built, owned elsewhere: service, CLI or module behaviour (F73, F76, F78 and their integration tests, which prove the
decoder is never called without approval: the decoder half of acceptance 4 stays there); journal content of these calls
(F94); ownership (F91); the checkpoints F90/F100 (all six targets, package gates). Proven at the checkpoint only: the
cases on the other five targets (`just e2e`, F100).
The feature is about six steps; no split.

Environment (run in this session): `podman run --rm --privileged --cgroupns=host alpine echo ok` → `ok`; the six local
images `custodio-e2e-*` exist. Stopping and masking polkit and restoring it in the guest is already done by the
`unavailable` step of `e2e/guest.sh`, and the test agent (`e2e/agent.py`) takes its answer from `$E2E_DIR/mode` and logs
one line per request; this feature reuses both.

## Steps
- [ ] Failing container-free tests first: `select.sh` maps `ops-polkit-*` to its group; `phase_runs` is true only when an
      `ops-polkit` case is selected; the accounting reports every case exactly once. Add the ids to `e2e/cases.list`.
- [ ] Helpers and their self-test: the D-Bus call script (replace certificate, plus the error-name reading for import and
      delete), the snapshot of "state" (the state directory listing as `snapshot_state` in `e2e/upgrade-lib.sh`, `custodio list`,
      and the certificate each key shows), and the judgements (exact error name, request count delta, state equal), each with
      bad-evidence cases in a self-test that must fail.
- [ ] Guest side: place the step in `guest.sh`; alice starts with one key imported (and a second certificate for the same key
      plus a certificate for a different key prepared); with the agent set to approve, deny, or polkit stopped and masked, run
      import (new id), delete and replace certificate, and judge them as the Evidence says. Polkit is restored on every path
      (reuse the trap of the `unavailable` step).
- [ ] Wrong-password cases: a `.p12` with a wrong password, import with the agent denying, then (agent approving) with the same
      wrong password; and the same under polkit stopped.
- [ ] Negative controls (run, shown red, reverted): (a) count requests against the wrong agent log / expect two requests for a call
      so the exactly-once check goes red; (b) make the denied delete run with the agent approving, so the error-name and state
      checks go red; (c) the wrong-password-denied case with the correct password, so the "denied before the password is tried"
      check does not pass by accident (the call must succeed or give another name, and the case goes red).
- [ ] Run `just quick`, then `just e2e-cases debian13 'ops-polkit-*'` until both pass.

## Evidence
- `ops-polkit-*` are in `e2e/cases.list`, reported exactly once each, and the selection reaches only this step →
  `scripts/test-e2e-select.sh` and the accounting tests (via `just quick`) → pass; a case missing from the guest output fails.
- Import, delete and replace certificate each ask exactly once per call → cases `ops-polkit-import-asks-once`,
  `ops-polkit-delete-asks-once`, `ops-polkit-replace-asks-once`, agent approving → the request log of alice's agent gains exactly
  one line per call, whose action is the import / delete / replace-certificate action of the `.policy` file, and the call
  succeeds (key listed with the new id; key gone; new certificate shown by `custodio list`/the module); zero or two lines fail the case.
- Agent denying: each call fails with the documented name → case `ops-polkit-denied` → import, delete and replace give exactly
  `com.rfirma.Custodio1.Error.PolkitDenied` (CLI import and delete also exit non-zero), one request line each, and the state
  snapshot (state directory, list, certificate bytes) taken before equals the one after; any other name or a changed snapshot fails.
- Polkit stopped: each call fails with the documented name → case `ops-polkit-unavailable` → import, delete and replace give exactly
  `com.rfirma.Custodio1.Error.AuthorizationUnavailable` within a bound (no hang), the agent log gains no line, the state snapshot is
  unchanged, and polkit is active again afterwards.
- A second call asks again → case `ops-polkit-asks-again` → the same call made twice in a row (denied, then approved, for each of
  the three operations) logs one request per call, two in total per operation, and the second outcome follows the second answer
  (nothing was cached).
- Import with a wrong password, polkit denying → case `ops-polkit-wrong-password-denied` → fails as `PolkitDenied` (not the
  wrong-password name), one request, no key created (list and state unchanged); with polkit stopped, as
  `AuthorizationUnavailable`. Whether the decoder was tried is proven by the integration tests of F73, not here.
- Import with a wrong password, approved → case `ops-polkit-wrong-password-approved` → fails as
  `com.rfirma.Custodio1.Error.WrongPasswordOrBadP12`, one request, no key created, and the correct password with the same
  `.p12` then imports it (so the failure was the password, not the file).
- Negative controls → (a) wrong count expectation, (b) denied delete run approved, (c) correct password in the wrong-password case
  → each shown red once, then reverted.
- Whole feature → `just quick && just e2e-cases debian13 'ops-polkit-*'` → exit 0, the accounting lists the `ops-polkit-*`
  cases and no other.
