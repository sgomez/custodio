# F208 — Threat model, SECURITY.md, the release notes of 0.9.0 and the manual acceptance steps

## Scope
Builds the last documents of M7 and the script tests that run their commands, on what exists (F195 to F207). Files: `docs/threat-model.md`
(the new in-scope items of SPEC "Threat model" (the fingerprint command writes only `/etc/pam.d/polkit-1`, only when the vendor file it includes exists, refuses rather than guesses on a system that does not match, and must not lock anyone out of
polkit; it never destroys someone else's configuration, writes atomically with the mode, owner and label of other files in `/etc/pam.d/`;
`doctor` changes nothing; certificate text is untrusted; the completions ask nothing of polkit, write nothing, fail silently), its added
out-of-scope items (fprintd/libfprint/the driver, an administrator who edits PAM after `enable`, a compromised package), and the six "Not
guaranteed" items of M7: the override covers every polkit action; a finger is a weaker secret than a password; a finger at the machine can
approve a remote (ssh) request; the login and lock screens are not Custodio's; a vanished vendor file breaks polkit's password path and only
`doctor` notices; Debian 13 and Alma 10 were not run in a VM. The M0 to M6 limits already in the file stay), `SECURITY.md` (scope: `custodio fingerprint enable` writes `/etc/pam.d/polkit-1`), a new
`docs/release-notes-v0.9.0.md` (what is new, known limits, the Firefox restart, "Debian 13 and Alma 10 not run in a VM", the supported
systems), the README link to it, `docs/api.md` and `docs/audit.md` (read against F195 and F196), and four new sections of
`docs/manual-acceptance.md`, numbered after the last one (26 onward; the builder updates the page's title and the section list in its opening
paragraph): the steps of acceptance 22, the reviews of acceptance 20 and 21, and the result form. `docs/release-notes-v0.8.0.md` stays and
keeps the README link it has; the README gains a second link.

Scripts: `scripts/test-docs-release-notes.sh` is generalised: its version is no longer fixed to v0.8.0 by the decision in `docs/decisions.md`
(that decision names the first public release); the expected version is the one in the notes' file name, the title and every `vX.Y.Z` in the
text must equal it, and the default `DOC` becomes the 0.9.0 notes. So that the 0.8.0 notes stay gated, `test-scripts` in the `justfile` runs the
script twice, in parallel: once by default (0.9.0) and once with `DOC=docs/release-notes-v0.8.0.md`. The 0.9.0 notes do not name the old version
as `vX.Y.Z`: an upgrade note says "the previous release" and links the 0.8.0 notes by path (the test is not loosened). Its systems check, link check, block-kind check (now `--only-console`) and `console` run stay.
`scripts/test-docs-threat-model.sh` keeps passing (its rules and controls are unchanged; new links in the two documents must resolve).
`scripts/test-docs-api.sh` keeps passing and gains (definitely, because `scripts/docs_api_run.py` holds the error names as a hard-coded list) a
check that the error names of `docs/api.md`, the journal outcomes of `docs/audit.md` (F195's new outcome included) and the `StateStorageReason`
values of `docs/api.md` equal those the code defines, derived from the source, not copied from the documents. New: `scripts/test-docs-manual-m7.sh`.

Acceptance 16 (every command in the documents of Design 5 runs as written) covers this page and the 0.9.0 notes: their commands are `console`
blocks, run with the stand-ins F207 built (`scripts/test-docs-guide.sh`: `sudo`, `apt-get` over real dpkg, `ls`; `scripts/lib/docs-fprint-fixture.sh`).
Only what is a person at a screen or a finger (exporting the `.p12` from Firefox, `pkexec` with the finger, the real site, Tab at the shell)
is prose or a `text` block, listed by the script as "a person's". The page's old sections keep their `sh`/`sh vm` blocks; every new check
of this script applies to sections 26 onward only (the builder cuts the page there), and the new sections use only the kinds `console`, `bash`
(files and `openssl` material, run) and `text`. The 0.9.0 notes, and any command added to the threat model or SECURITY.md, are `console`
blocks (`--only-console` of F207), so a command in a `bash` block cannot slip past the run.

Left to other features: the real Ubuntu VM, the real reader and the people's reading (acceptance 20, 21, 22: prose is a person's; no test greps
for wording, headings or citations); `just api-contract`, package gates and `just e2e` (F206, F209). Acceptance 20's agreement with "the report"
is the person's reading. Debian 13 and Alma 10 statements are written from `docs/findings/F199.md` and `F201.md`; the builder reads, does not
re-research.

Environment (dev container, as measured in F207): `unshare -rm true`, `dpkg`, `sudo`, `openssl`, `dbus-daemon`, `nfpm` work; `gsettings`,
`pkexec`, `fprintd`, `firefox`, `snap` are absent. So the manual steps' commands that can run without a reader are the ones on files and on
fixtures: the `openssl` material commands, `custodio` commands on the fixture rigs of F207 (`scripts/lib/docs-fprint-fixture.sh`,
`docs-register-fixture.sh`), and the final checks against a fixture root. Commands of absent tools, and every step at a screen or with a finger,
are prose or `text` blocks (never `sh vm` in the new sections) and are listed by the script's output as "a person's".

The final checks of the form (`/etc/pam.d/polkit-1` absent, no Custodio entry in the Firefox profiles, no module copy, nothing left beyond what
the documents say removal keeps) are shown as commands. `test-docs-manual-m7.sh` runs each on a fixture root twice: after the documented way
back (`register --remove`, `fingerprint disable`, real `dpkg -r`/`-P` as in `test-deb-lifecycle-real.sh`) where each must report clean, and
on a fixture left dirty where each must report not clean (the negative control, one per check).

Sizing: six steps; no split.

Costs (estimates from `test-docs-release-notes.sh` about 20 s with 7 controls, `test-docs-guide.sh` 5 s, `test-docs-fingerprint.sh` 10 s; the
builder measures and writes the numbers in PROGRESS.md):

| Test | Time | How it runs |
|---|---|---|
| `scripts/test-docs-release-notes.sh` on the 0.9.0 notes, and again on the 0.8.0 notes | about 20 s each (unchanged, plus 1 control) | two entries in `test-scripts`, parallel with the others; each one's controls run at once |
| `scripts/test-docs-manual-m7.sh` (`openssl` material, the fixture rigs, one real dpkg install/removal of the `.deb` the script builds itself with `scripts/lib/package-fixtures.sh`, final checks clean and dirty, about 8 controls) | about 10 s, up to 30 s because of dpkg and the package build | script test in `test-scripts` (added to the `justfile` list), parallel; controls at once |
| `test-docs-threat-model.sh`, `test-docs-api.sh` | unchanged (each under 60 s) | existing |

No unit test, no e2e case, no mutants (`verify` has no `mutants-diff`). The new script is a script a person's steps rely on, not a gate the
harness runs on a stub: it is proven by its own run and its controls, which are broken copies of the page and a dirty fixture root.
