# F113 — Import a key into the TPM with TPM2_Import

## Scope
Built in `custodiod`, in the `tpm` module (small files under `crates/custodiod/src/tpm/`, none over 5000 tokens; every new
non-`tests.rs` file joins the `mutants` recipe's `--file` list):
- the **parent**: the transient ECC P-256 primary in the owner hierarchy, created from the TCG SRK template frozen in code
  (`docs/decisions.md` 2026-11-03 "TPM parent"; approved in F111), empty `unique`, no persistent object, no NV write. The module
  gives its **name** and a check "recorded parent name equals the current parent's name", which returns a distinct
  `ParentMismatch` error and sends no `TPM2_Load`. F114 calls that check before loading; F113 builds it and proves it.
- the **import**: a private key in `secrecy`/`zeroize` types, RSA 2048 or P-256 only (anything else is refused before any
  TPM call), imported with `TPM2_Import` under that parent. Result: a **blob** (the public area and the private area the TPM
  returned, as marshalled `TPM2B_PUBLIC` / `TPM2B_PRIVATE` that `tpm2-tools` can read, plus bounded parsing of a stored blob)
  and the **parent's name**. Nothing else is returned or retained from which the key could be recomputed (no seed, no
  inner-wrap key, no sensitive area).
- attributes of the imported key, from `docs/decisions.md` 2026-11-03 "the service pads": RSA 2048 `sign|decrypt`, not
  restricted, null scheme; P-256 `sign` only; both with empty `authPolicy`, empty `authValue`, `userWithAuth`, and
  (`TPM2_Import` requires it) `fixedTPM` and `fixedParent` clear. The builder picks `adminWithPolicy`; it must be set so that
  the admin role is unusable with an empty policy, unless a finding shows the TPM refuses the combination (then the commit says why
  and `tpm2_duplicate` still has to fail).
- **How the key reaches the TPM**: the sensitive area must never cross the TCTI in the clear. Which of the two ways the
  builder uses is settled by a research step (subagent on TCG TPM 2.0 Part 1, "Duplication", plus `tss-esapi`'s `import`
  and what its crypto backend offers): (1) outer wrap to the parent's public key (ECDH seed, KDFe/KDFa, AES-128-CFB, HMAC), or
  (2) an inner wrap whose symmetric key goes in an encrypted ESAPI session. Any new crate must pass `cargo deny` and
  `cargo machete` under the unchanged `deny.toml`; no new `unsafe`. The choice is in the commit message; it goes in
  `docs/decisions.md` only if a later session could undo it without knowing why.
- every object and session created is flushed by the end of the call, whatever the outcome.

Left to other features: signing and loading (F114; the load is only used here by `tpm2-tools` as an oracle), choosing the
storage kind and the import flow (F117: this feature does not re-run the F112 classification; a TPM that lacks something
surfaces as a TPM error), the on-disk layout, the journal and D-Bus errors (F119, F120), unit directives, and any run on a
hardware TPM (done in F111). The SPEC's "Duplication check" and "No-plaintext check" over a whole state directory and the
"No PCR dependency" and "Resource test" of the end-to-end suites are proven at the checkpoint features; this feature proves
the same properties of the blob it returns, at the cheapest level (below).

Environment check (dev container): `ls /usr/bin` shows `tpm2_readpublic`, `tpm2_load`, `tpm2_duplicate`, `tpm2_print`,
`tpm2_createprimary`, `tpm2_getcap`, `tpm2_clear`, `tpm2_startup`, `tpm2_sign`, `tpm2_rsadecrypt`; `swtpm` and
`custodio_it::swtpm::Swtpm` (with `tool_ok`, `clear`, `restart`) were used by F112's `tpm_access`; `TpmFilter` has fault rules
by command and `Lacks` (F112). The filter does not yet record the bytes it forwards: the step "recording" adds that to
`custodio-it` if the builder does not find another way, with its own test in the existing filter target.

## Steps
- [ ] Research (subagent, conclusions only): the wrap choice above and the TPM's checks on `TPM2_Import` (attributes it
      refuses, what it verifies between the public and the sensitive area). Record the conclusion in the commit; no code.
- [ ] Tests first, unit: refusal of other key types and sizes before any TPM call; `Debug`/`Display` of the key input, the
      blob, the result and every error contain no key bytes (a distinctive key, searched in every encoding the test can produce);
      blob serialisation round trip and bounded parsing (truncated, oversized, trailing bytes, inconsistent size fields).
- [ ] The parent (template frozen in code, name, `ParentMismatch` check) and the import over the `Session` seam of
      F112 (extended or sibling trait) with the `swtpm`/filter TCTI; the key bytes held in `secrecy`/`zeroize` types and
      zeroed on every path, including errors.
- [ ] `custodio-it`: if needed, a recording of the bytes the client sends through `TpmFilter`, with a filter test.
- [ ] Integration test target `tpm_import` in `crates/custodiod/tests/` (`tpm_import.rs`) against `swtpm`: attributes,
      independent parent, wrap, duplication, parent mismatch, flushes, repeated imports.
- [ ] New `tpm` files in the `mutants` recipe; `just quick`, `cargo test -p custodiod --test tpm_import`, then
      `just mutants-diff F113`; kill survivors with tests, not exclusions.

## Evidence
- Only RSA 2048 and P-256 → `tpm::tests::other_keys_refused` (unit) and `tpm_import::other_keys_refused` → RSA 1024, 3072 and
  P-384 give a typed refusal and the filter records zero commands for that call (control: RSA 2048 and P-256 succeed).
- Imports under the approved parent → `tpm_import::parent_is_the_approved_template` → on a fresh `swtpm`, the parent name in the
  result equals the name `tpm2_createprimary -C o` prints when run by the test with the SRK-template attributes written out in
  the test (ECC P-256, AES-128-CFB, SHA-256, `fixedtpm|fixedparent|sensitivedataorigin|userwithauth|noda|restricted|decrypt`);
  control: a template with one attribute changed gives another name, so the check can fail. After the call `tpm2_getcap
  handles-persistent` and `handles-nv-index` equal their values before (no persistent object, no NV write).
- Each attribute of the imported key → `tpm_import::attributes_per_key_type` → the test loads the returned blob with `tpm2_load`
  under its own `tpm2_createprimary` parent and reads the public area with `tpm2_readpublic` (and `tpm2_print -t TPM2B_PUBLIC` on
  the stored bytes): for RSA 2048, `sign` and `decrypt` set, `restricted` clear, scheme null, 2048 bits; for P-256, `sign` set, `decrypt`
  and `restricted` clear, curve P-256; for both: `authPolicy` empty (length 0), `userwithauth` set, `fixedtpm` and `fixedparent` clear,
  name algorithm SHA-256, and the public key equals the one derived from the private key the test generated. Mutation of
  any one attribute in the code fails this test (confirmed by `mutants-diff`).
- Empty `authValue`, no PCR policy → `tpm_import::empty_auth_and_no_pcr_dependence` → the loaded key signs (P-256, `tpm2_sign`) and
  decrypts (RSA, `tpm2_rsadecrypt`) with no password; control: the same command with `-p wrong` fails. After
  `Swtpm::extend_pcr` of PCR 7 and PCR 0 the same blob loads and signs again, and `authPolicy` stays empty.
- The sensitive area never crosses the TCTI in the clear → `tpm_import::private_key_not_on_the_wire` → through the recording
  `TpmFilter`, the bytes the client sent for an RSA and a P-256 import contain none of the private key in any encoding the test
  can produce (raw scalar, primes `p` and `q`, the private exponent, PKCS#1, PKCS#8, SEC1); control: a recording of
  `tpm2_import` of the same key without wrapping contains the raw scalar, so the search can fail.
- Result carries nothing from which the key could be recomputed → `tpm_import::result_holds_no_key_material` → the same
  encodings are searched in the blob bytes and the whole result (and its `Debug`): no match. Control: the search finds the key in a
  buffer where the test plants it. The result type has exactly the blob and the parent name (`tpm::tests::result_fields`, unit).
- The blob is not portable, and cannot be duplicated → `tpm_import::blob_does_not_load_elsewhere_and_cannot_be_duplicated` →
  `tpm2_load` of the blob in a second, independent `swtpm` fails; `tpm2_duplicate` on the loaded key fails (empty policy;
  control: `tpm2_duplicate` on a key created in the test with a duplication policy gets past authorisation, or the control is a
  `tpm2_load` in the first `swtpm` that succeeds).
- The private key stays in `secrecy`/`zeroize` types → `tpm::tests::key_input_is_zeroized` (unit) → the input and every
  intermediate buffer of the wrap implement `ZeroizeOnDrop` or are `secrecy` types, and a test with an observable drop shows the
  buffers are zero after success and after each error path; `grep` of the new files for `Vec<u8>`/`String` holding key bytes without a
  wrapper is done by the builder in review. Reached through `Debug` checks of the second Step.
- A blob of another parent is detected before use → `tpm_import::parent_mismatch_before_use` → (a) import, then `Swtpm::clear` (the
  owner seed changes): the check returns `ParentMismatch` carrying neither name in `Display`'s secrets and the filter records no
  `TPM2_Load`; (b) a second `swtpm`: same; (c) control: after `Swtpm::restart` without a clear, and on the same instance, the check
  passes (the primary is deterministic) and `tpm2_load` accepts the blob; (d) a fault rule that drops the connection on `TPM2_Load`
  does not change (a): the result is `ParentMismatch`, not a TPM error; (e) an owner hierarchy with an auth set is a TPM
  error of the F112 owner kind, not `ParentMismatch`. `tpm::tests::name_comparison` (unit) covers the comparison on equal, shorter, longer and
  single-byte-different names.
- Every object and session is flushed → `tpm_import::nothing_left_loaded` → after a successful RSA and P-256 import, and after
  an injected failure (fault rules from F112: an error response and a dropped connection) at each command the import sends
  (create primary, start session if any, import, read public, flush), `tpm2_getcap handles-transient` and
  `handles-loaded-session` (and `handles-saved-session`) on the same `swtpm` list nothing; control: the flush-free `tpm2_createprimary` of
  F112's control still leaves one handle. After a parent mismatch the same holds.
- More imports than the TPM has slots → `tpm_import::many_imports_in_a_row` → 20 imports (10 per key type) on one `swtpm` all
  succeed and `handles-transient` is empty afterwards.
- Stored blob parsing is bounded → `tpm::tests::blob_parsing_bounds` (unit) → each malformed input of the second Step is a typed
  error, none panics, and a size field larger than the input allocates nothing beyond the input.
- New files join `mutants` → for each file under `crates/custodiod/src/tpm*` that is not a `tests.rs`: `grep -c -- "--file
  crates/custodiod/src/<path>" justfile` → 1; after `just mutants-diff F113`, `missed.txt` is empty and each new file with mutants
  has at least one caught.
- Whole feature → the `verify` of F113 in features.json (`just quick && cargo test -p custodiod --test tpm_import --locked && just
  mutants-diff F113`) → exit 0.
