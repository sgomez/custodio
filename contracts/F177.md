# F177 — Only ListKeys and Sign on the socket, bounds, the API contract and the socket fuzz target

## Scope
Builds, on the connection F175/F176 already admit and serve:
1. **Surface.** On the socket every method of the interface but `ListKeys` and `Sign` fails as the standard
   `org.freedesktop.DBus.Error.UnknownMethod` (`ImportP12`, `DeleteKey`, `ReplaceCertificate`, a method
   that never existed, a wrong interface name, a wrong path), asks no polkit, writes no journal entry
   and changes nothing (no file in the key store). Introspection of the object lists exactly those two
   methods on `com.rfirma.Custodio1` (plus the standard `org.freedesktop.DBus.*` interfaces zbus adds; no
   properties or signals of Custodio). The builder checks what the interface macro gives and, if the
   write methods are still reachable, serves a separate object with only the two.
2. **Bounds** in custodiod on each socket: concurrent connections, message size, time in the handshake and
   time idle between messages. Hitting one closes that connection only. The message bound is no larger
   than what the bus allows for the same method (the bus limit is read from the bus daemon or the
   `Sign` argument bounds in `dbus.rs`; the builder records which, and the largest legal `Sign` call must
   still pass). Refused connections (over the connection bound, a refused peer) are logged at a bounded
   rate (a token bucket or a fixed window with a count of the lines suppressed); the numbers are
   constants documented with their reasons in `docs/api.md` (transport section) and the code's doc
   comments. The refusal line of F175 stays a line without label bytes.
3. **`docs/api.md`** gains a section on the socket transport (path, handshake, the two methods, error
   parity, the bounds with values and reasons, the refusal log rate). `just api-contract` (the
   `api_contract` test) additionally checks that exactly `ListKeys` and `Sign` are served on the socket,
   by introspecting a live socket peer, and that the document names exactly those two there.
4. **Fuzz target** `socket_message` in `crates/custodiod/fuzz` (a peer's bytes written to a socket pair,
   through the handshake and dispatch with the `test-seam` source giving the Firefox label), added to
   `just fuzz-smoke`'s expected list. The target must not hang (it relies on the bounds, and ends the
   connection after the input) and asserts no key file changed and no polkit call happened for
   input that is not a valid `Sign`.

Not here: the real polkit, journald and confinement; the VM and the e2e (checkpoint). The acceptance 7
claim "a bus client still lists and signs while a peer floods" is proven here with the private bus and
the scripted polkit, not with the real service.

Environment: `dbus-daemon` on PATH (as in `tests/polkit.rs`); `cargo +nightly fuzz` is used by `just
fuzz-build` already (F174's `peer_label` target runs in it). Nothing new is needed.

Cost of the new tests:
- `crates/custodiod/tests/snap_socket_surface.rs`: in-process, one scripted-polkit private bus per case
  (about 50 ms), about 8 cases, under 3 s; parallel with other integration tests.
- `crates/custodiod/tests/snap_socket_limits.rs`: about 8 cases. The time bounds are constants, so the
  service takes them as parameters of `Service` (short values, tens of ms to 1 s, in the tests; the
  shipped values are separate constants and a test pins them to the documented ones). Waits are on end of
  file or a reply, never a fixed `sleep`. Estimated under 8 s total, parallel with other tests.
- Unit tests of the limiter and the rate limit: milliseconds, with a fake clock.
- `api_contract` addition: one more live introspection, tens of ms. `scripts/test-docs-api.sh` is the
  existing script test (one run, within the `script *` budget of 120 s; the new section adds a static check
  and no example needs the socket).
- Fuzz target: `fuzz-smoke` runs 2000 inputs; each is a socketpair and a short connection, estimated
  under 20 s, plus the build in `fuzz-build` (as the other targets, shared dependency build).
- `just mutants-diff F177`: the diff is the limiter, the rate limit and the accept path; estimated 5 to 12
  minutes with 3 jobs, one command.
- No new script test, no e2e case: real systemd socket, real journald and the flood on the real service are
  the checkpoint's.
Fits in about six steps, one to two sessions; no split.

## Evidence
- Every method but the two is unknown → `snap_socket_surface::other_methods_are_unknown` (ImportP12 with
  valid-looking arguments, DeleteKey on an existing key, ReplaceCertificate, an invented method, the same
  names on another interface and another path) → each reply is `UnknownMethod`/`UnknownObject`/
  `UnknownInterface` as zbus gives for the bus's missing names, not a Custodio error.
- No polkit, no journal entry, nothing changed → same test, with the scripted polkit's call counter, the
  in-memory audit log and a directory listing with file contents of the store compared before and after
  → counter 0, no entry, store identical. Negative control: the same harness sees the counter at 1 and one
  entry after a real `Sign`.
- Introspection lists only the two → `snap_socket_surface::introspection_lists_exactly_two` → the
  Custodio interface's methods are exactly `{ListKeys, Sign}`; a copy of the expected set with `DeleteKey`
  added fails the comparison (negative control).
- `ListKeys` and `Sign` still work and match the bus's signatures → the F175/F176 tests stay green
  (`snap_socket_peer`, `snap_socket_sign`, run in `just quick`).
- Connection bound → `snap_socket_limits::connection_bound_closes_the_extra` (bound N set small; N held
  idle connections, connection N+1 is closed with end of file, and still closes after one of the N goes
  and a new one then gets served) → the extra one is closed, the N-th replacement served.
- Message size bound → `snap_socket_limits::oversized_message_closes_only_that_connection` (a message one
  byte over the bound closes that peer; a second peer and a `Sign` of the largest legal size (the bus's
  limit for `Sign`) on another connection succeed) → closed vs. served.
- Message bound vs. the bus → `snap_socket_limits::the_message_bound_is_not_above_the_buses` → the shipped
  constant is ≤ the bus's value for `Sign`, which the test reads from the same source the builder records.
- Handshake time → `snap_socket_limits::a_stalled_handshake_is_closed` (peer connects, sends nothing; and
  one that sends half of `AUTH`) → end of file within the test's short bound, then another peer lists.
- Idle time → `snap_socket_limits::an_idle_connection_is_closed` (finished handshake, no message) →
  closed after the bound; a connection that keeps calling inside the bound stays open.
- Hitting a bound closes that connection only; bus and others keep working → `snap_socket_limits::
  a_flood_does_not_stop_a_bus_client_or_another_peer` (a peer opens connections up to and past the bound,
  sends garbage and oversized messages in a loop while a private-bus client calls `ListKeys` and `Sign`
  with the scripted polkit and an accepted second peer lists and signs) → every call succeeds, no
  `AuditUnavailable`, every audit entry of the signatures present (acceptance 7).
- Refusals journaled at a bounded rate → unit test of the limiter with a fake clock
  (`rate_limit::*`: at most K lines per window, the suppressed count reported in the next line, a new
  window allows again) and `snap_socket_limits::refusal_lines_are_bounded` (a thousand refused peers with
  the test seam's refused source → at most the documented number of lines, none with label bytes) → counts
  within bounds; mutation of the bound is caught by `mutants-diff`.
- Values and reasons documented → `scripts/test-docs-api.sh` and `api_contract` check the section exists
  and that each documented value equals the shipped constant (the test reads the constants through the
  crate's public items); prose is for a person.
- `just api-contract` checks exactly ListKeys and Sign are served there → `api_contract::
  the_socket_serves_exactly_the_two_methods` (live introspection of a socket peer compared to the
  document's socket section; the document with `DeleteKey` added, or `Sign` removed, there fails) → pass;
  edited copies fail.
- Fuzz target → `just fuzz-build && just lint-fuzz && just fuzz-smoke` → `socket_message` builds, is clippy
  clean, appears in the expected list (`just fuzz-smoke "a b c"` negative control still fails when a target
  is missing) and runs 2000 inputs without a crash or a hang.
- Mutants → `just mutants-diff F177` → no surviving mutant in the limiter, the rate limit, the accept path
  and the surface code.
