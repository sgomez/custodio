# F209 — Checkpoint and last automated feature: the whole milestone

## Scope
Almost nothing is built. This feature runs every suite of its `verify` on the finished milestone (F189–F208) and fixes whatever fails,
at its cause, under the earlier checkpoints' rules: no `#[ignore]`, no lowered threshold, no `#[allow]` without a justification, no
recipe turned into a no-op, no guard loosened, no case changed except where the case is wrong, no skip added without a stated and
evidenced reason, no edit of `budgets.tsv`. The `verify` is
`just check && just api-contract && just fuzz-smoke && just memory-safety && just e2e && just package-gates && just coverage-gate && just e2e-vm full && just e2e-vm lacking`;
the loop runs it whole, a builder session never does. No new test, script, case or e2e target is added (no new cost). A fix may add a
regression test at the cheapest level that catches its cause and `PROGRESS.md` says what it costs.

**What this checkpoint adds over F206:** the work of F206 (its suites on F189–F205) is not repeated as a separate proof; the tree is
re-proven as a whole after F207 (docs, guide) and F208 (manual acceptance sections, release notes, `test-docs-*` scripts), which F206
never ran. The new part is the VM suite: `just e2e-vm full` and `just e2e-vm lacking`, with the `vm-fingerprint-*` group of F200.

**VM group, SPEC acceptance 18 and 19 (proven here):**
- Mode `full` runs the 12 `vm-fingerprint-*` cases of `e2e/vm/cases.list` (stage, polkit-finger, polkit-unenrolled, polkit-timeout, sudo,
  negative, disabled, sign, four fallbacks). All 12 must be `run`; none `skipped`, none `failed`. They are not in `e2e/vm/skip.list` for
  `full`. In mode `lacking` they are `skipped` with the reason in `skip.list`; that is the only allowed skip of the group.
- Acceptance 19: `vm-fingerprint-stage` fails (never skips) when the virtual driver (`FP_VIRTUAL_DEVICE` in libfprint) or its socket cannot be
  staged. The run is not allowed to turn that into a skip: `check-cases.sh` (`CHECK_VM=1`) refuses it, and `scripts/test-e2e-vm-fingerprint.sh`
  (in `check`) already holds the control. If the stage fails in the real run, the group fails and this feature fixes the cause or, if the
  guest cannot stage it, writes `BLOCKED.md`; never a skip entry.
- The `full` record carries `polkit_version`, `fprintd_version`, `libfprint_version`, `libpam_fprintd_version`, none `unknown` (acceptance 18, last sentence).

**Environment, checked while writing this contract (2026-11-16, dev container):** `/dev/kvm` exists; `qemu-system-x86_64` and `swtpm` are
installed; `bash e2e/vm/run.sh --check full` exit 0; `target/packages/` holds a deb, rpm and Arch package of 0.8.0 (`e2e-packages` rebuilds
them for the run; the guest installs them with apt `--no-install-recommends`); 12 cores, 30 GB RAM, 756 GB free. The old
`target/e2e/vm.full.*` is from F200's partial run of the fingerprint group only (phases: `vm-fingerprint` and setup, no other group) and
`vm.lacking.*` is old; both are removed before the runs so that a stale record cannot pass. If KVM, QEMU, swtpm, the network, or the guest
image are gone, that is `BLOCKED.md`, not a reason to skip a group or case. VM runs use KVM and the whole machine's memory
budget the budgets were measured with: they run one after the other and never alongside `just e2e` or the coverage run.

**Time and budgets** (`budgets.tsv`, set by a person; the builder compares and never edits):
- `just check`: ~2 min warm (`CHECK_FORCE=1` forces it; F206 measured 1:56 wall, 81 script tests in 65 s); ~10–15 min cold. Skipped on an
  unchanged tree through `target/check-ok`.
- `just e2e`: six records at once, wall = the slowest, debian13 (row 800 s; alma10 540, fedora44 570, arch 480, ubuntu2604 530). F206 measured
  173 s wall, every target far under its row.
- `just package-gates`: the lifecycle scripts have their own rows (`script *` 120 s, others up to 250 s).
- `just coverage` then `just crap`: one command each, `timeout 1700`; times recorded.
- `just e2e-vm full`: row 580 s. Measured by F168 at 503 s *before* the fingerprint group; F200 measured that group alone at 53 s of step
  time (82 s for the command), so the full run is expected at about 560–590 s, which may be at or over the row. `just e2e-vm lacking`: row
  500 s, measured 430 s (F168); the fingerprint group adds only skips there. Per-phase times are in `target/e2e/vm.MODE.phases.tsv`. A mode
  over its row is a request for a bigger row in `BLOCKED.md` with the measured times, written after every other step is done; no case is
  removed, skipped or shortened to fit. Budgets for the VM rows are "not read by the loop yet" (`budgets.tsv`), so a measured overrun is
  reported and does not by itself fail the gate.
- Limits: a command runs at most 30 min, a session 45 min. `just e2e`, `just memory-safety`, `just package-gates`, each coverage half, and each VM mode
  get a command of their own with `timeout 1700`. No step runs the whole `verify`. A fix may take more than one session; a step stays
  ticked only if its evidence passed on the final tree.

## Steps
- [x] Baseline, host side: `CHECK_FORCE=1 timeout 1700 just check` (a red script or test is run alone first), then `just api-contract`, then
      `just fuzz-smoke` (its default list must equal the fuzz targets `cargo fuzz list` shows for the three fuzz crates, 18 at F206; add any
      new one). Fix each failure at its cause, one commit per fix.
- [x] `timeout 1700 just memory-safety`; fix every finding at its cause (a Miri or ASan report is a defect, not a list entry).
- [x] Container end-to-end: environment checks (`podman info`, target directories); remove old `target/e2e/*` records; `timeout 1700 just e2e` once (six
      records at once); fix every failing case, set-up or accounting error at its cause; note the six results and wall times against
      `budgets.tsv` in `PROGRESS.md`.
- [x] `timeout 1700 just package-gates`; fix every finding (a lint list entry only with a reason, only for a finding that is not a defect). Note the
      lifecycle script times against their rows.
- [x] `timeout 1700 just coverage`, then `timeout 1700 just crap` (each its own command); fix every finding with a test of the behaviour, not by lowering a threshold.
- [x] VM, `full`: remove old `target/e2e/vm.*`; `bash e2e/vm/run.sh --check full`; `timeout 1700 just e2e-vm full`. Fix every failing case at its cause
      (debug with `just e2e-vm-cases full '<glob>'`, which is only a debugging run). Note per-phase times (`vm.full.phases.tsv`), the 12 `vm-fingerprint-*` results, and the four
      versions from the record in `PROGRESS.md`.
- [x] VM, `lacking`: `timeout 1700 just e2e-vm lacking` alone (after step 6 has finished); fix every failing case at its cause; note per-phase times.
- [x] Final: after the last fix, rerun every suite that ran before it, one per command (the VM modes after any change to the package, `e2e/`, or the guest
      scripts); recount the Evidence records; run `just quick` once. `BLOCKED.md` for a budget row only after every other step is ticked,
      with the measured times.
