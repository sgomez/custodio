# F120 — The journal names the storage kind

## Scope
`custodiod` writes the kind and the cause of a storage failure into the journal entries that F117 and F118 already leave;
`docs/audit.md` documents every new field and value and gives queries for them. F117 and F118 deliberately left `audit/`
untouched: today a failed import is one `import` entry with outcome `storage_failure` and a failed sign is one `sign` entry
with outcome `signing_failed`, with nothing saying which kind or why.

- **Import names the kind.** An import entry that has a kind (the key was stored) carries it in a new field whose values are
  the wire strings `store::Kind::wire` fixes (`tpm`, `encrypted-tpm`, `encrypted-host`); they are not renamed here. An
  import that stored nothing has no kind (it never chose one, or chose and stored nothing), and the field is omitted
  rather than guessed; `docs/audit.md` says so.
- **Import failures name their cause.** The failures F117 fails closed on (device present but unopenable, a TPM error
  during import, an unusable owner hierarchy, the credential service down, refusing or unable to encrypt, a binding that
  disagrees with the kind) are told apart in the entry by a cause drawn from a closed, documented list, split at least into
  "the TPM" and "the credential service" and finer where F117's tests already tell the failures apart. The cause is chosen
  from the typed error, never copied from a tool's output, a response code, a path or the input, so no secret can reach it.
  The outcome stays `storage_failure` unless the builder adds a new outcome under the compatibility rule (a documented
  outcome keeps its name and meaning).
- **Sign names the cause.** A sign that fails because the key no longer loads (`KeyLost`) or cannot be decrypted, and a sign
  that fails for a transient reason (`TemporarilyUnavailable`), are told apart in the entry, by a new outcome or a cause
  field, consistent with the two D-Bus classes F118 fixed. A sign that fails for any other reason (`Internal`) keeps
  `signing_failed` with no lost/transient cause. The sign entry also names the kind of the record it used, when known.
  Existing sign fields, outcomes and the priorities of existing outcomes do not change.
- **Docs.** `docs/audit.md`: the new fields in the Fields table, the new values (kinds, causes, outcomes) with meaning and
  priority, the message-text shapes, and a query for each new field and for a lost key and a failed import. The
  `data/custodio.catalog` entry text follows if it lists outcomes.
- **Left to other features.** The error names on the bus and the kind in the API (F117, F118, F119, proven there). The purge
  entry and its documentation (F121). The CLI's wording (F123). Installing the catalog and reading a real journal under the
  hardened unit are proven at the checkpoints (F132/F146); here the entries are read from the in-memory sink and the
  datagram `JournalSink` sends, as `audit` tests do.
- **Size.** About five steps; no split proposed. New non-test files under `src/audit/` join the `mutants` recipe's
  `--file` list; files stay under the check-files limit.

Environment: needs only what `storage_choice` and `sign_kinds` use (`swtpm`, the real `systemd-creds` where a row needs it,
the private bus with fake polkit); `kind_audit` reuses their rigs. No new tool. Both rigs already run green in `just quick`
and their own verify, so no extra environment command is needed.

## Steps
- [ ] Tests first for the typed layer: the closed cause list and its mapping from the typed import, TPM and credential
      errors (exhaustive matches, a table test over every variant, as F118 did), the new fields on `Entry` /
      `OperationEntry`, and their wire form. Then the code in `audit/` and the callers in `dbus/import.rs` and
      `dbus/sign_kind.rs`.
- [ ] Import: the kind in the stored entry, the cause in each failed entry, wired in the service; `kind_audit` import rows.
- [ ] Sign: lost/transient/other told apart in the entry, with the kind of the record; `kind_audit` sign rows.
- [ ] `docs/audit.md` (fields, values, shapes, queries) and the catalog; extend the existing docs/code consistency test in
      `audit/docs_tests` so every new field, outcome and cause value in the code is in the document and the reverse.
- [ ] `just quick`, `cargo test -p custodiod --test kind_audit`, `just mutants-diff F120` until 0 missed; hand off.

## Evidence
`kind_audit` runs the real service on the private bus with fake polkit and the in-memory sink, with `swtpm` and the real
`systemd-creds` where a row needs them (as `storage_choice` and `sign_kinds`). Entries are read as typed values and as the
fields/message text they produce. Each row that has a key type runs for RSA 2048 and P-256 unless stated.

- Import entry names the kind, for each kind → `kind_audit::import_names_kind` → success with TPM ready, TPM lacking a
  capability, and no TPM gives one `import` entry, outcome `stored`, kind field `tpm` / `encrypted-tpm` / `encrypted-host`
  respectively, equal to the kind in the stored record (read from the store files) and to the one `ImportP12` returned; key
  type still present.
- Each import failure names its cause → `kind_audit::import_failure_causes` → for every failure `storage_choice` injects
  (device unopenable, TPM error in the query, owner hierarchy unusable, TPM error during import, import refused with a
  lack-like code, credentials down with no TPM, credentials down with a lacking TPM, credentials cannot encrypt, binding
  disagreeing with each kind): exactly one entry, `import`, outcome as documented, the documented cause value for that
  failure (TPM failures carry the TPM cause, credential failures the credential cause; two causes that F117 tells apart
  are not merged), no kind field, key type present, store empty, and the D-Bus error name equals F117's. A table in the
  test lists failure → cause, so a swapped or constant cause fails.
- Failures before the choice keep their entries → `kind_audit::other_import_entries_unchanged` → denied, authorization
  unavailable, wrong password and unsupported key entries carry no cause and no kind, and their fields equal those
  documented before this feature.
- A lost key has its own outcome or cause → `kind_audit::sign_lost_key` → for a TPM record on a cleared `swtpm` and for an
  encrypted record whose credential cannot be decrypted (both key types, all three kinds): one `sign` entry, the documented
  lost-key value, the kind of the record, priority as documented, D-Bus error `KeyLost`; the record and the listing
  unchanged; `signing_failed` without the lost value is not what these produce.
- A transient failure is told apart → `kind_audit::sign_transient` → TPM absent/failing at sign and credential service
  unavailable give one `sign` entry with the documented transient value, not the lost value, D-Bus error
  `TemporarilyUnavailable`.
- Other sign failures and successes keep their entries → `kind_audit::sign_other_entries` → a signature of each kind gives
  `signed` with the kind of the record and the same mechanism field as before; denied and authorization-unavailable entries
  have no cause; a failure that is `Internal` is `signing_failed` with neither lost nor transient value.
- No secret reaches an entry → `kind_audit::no_secret_in_entries` → across every row above (all kinds, all failures), with a
  `.p12` and password carrying sentinel values, the key's DER, the credential/blob bytes and the TPM and tool error text
  injected as sentinels, none appears (raw, hex or base64) in `Debug`, `message()`, the fields, or the datagram the
  `JournalSink` sends; the cause and kind values are only the documented ones.
- Every new field and value is documented → the unit test in `audit/docs_tests` (run by `just quick`) → each field name,
  kind, cause and outcome value the code can emit appears in `docs/audit.md` with its priority, and every one the document
  lists is emitted; a removed row in an edited copy of the document fails the test (negative control).
- Queries are given and work → `kind_audit::documented_queries` → the queries for the kind, the cause and the lost-key
  outcome are extracted from `docs/audit.md`; each names `_SYSTEMD_UNIT` and `_UID` like the existing ones, and a match
  function applied to the entries of the rows above selects exactly the entries the query describes (an import of one kind;
  the lost-key sign) and none of the others. Running `journalctl` itself is proven at the checkpoints.
- Mutants of the new mapping and fields → `just mutants-diff F120` → 0 missed (a mutant that swaps lost and transient, drops
  the kind, or merges causes is killed by the rows above).
