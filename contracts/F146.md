# F146 — Checkpoint: end-to-end cases and documentation

## Scope
Nothing new is built. This feature runs the whole milestone's suites on the work of F104–F145 and fixes whatever fails,
at its cause, with no gate weakened (no `#[ignore]`, no lowered threshold, no `#[allow]` without a justification, no
recipe turned into a no-op, no case changed except where the case is wrong, no skip added without a stated and
evidenced reason, no `budgets.tsv` edit). The `verify` is
`just check && just api-contract && just fuzz-smoke && just e2e && just package-gates`; the loop runs it whole, a
builder session never does.

What the checkpoint proves, and where:
- `just check`: lint, every unit and integration test (the `custodiod` TPM suites on `swtpm` included), the system gates
  and all script tests, among them the ones added since F132 (`test-e2e-*`, `test-docs-manual-m4.sh`, the docs tests).
  Known red at HEAD per PROGRESS.md (F142, F141 entries): `test-e2e-host.sh`, `-host-oldpath.sh`, `-select-host.sh`,
  `-jobs-host.sh`, `-select.sh`, `-tpm-host.sh`. They are in `just check`, so they are fixed here, at their cause (a
  stale expectation of the test, or a real defect), not removed.
- `just api-contract`, `just fuzz-smoke` (its default target list must still name every fuzz target that exists; a
  target M4 added and the list lacks is added to the list).
- `just e2e` with `E2E_TPM` unset: all six targets with `swtpm`, and debian13 also with `none` (seven records,
  `tpm=swtpm` x6, `tpm=none` x1; run.sh runs `none` only on a target with a `tpm-none` marker). Every id owed by
  `e2e/cases.list` and the target's own list is accounted exactly once per record, run or skipped as `skip.list` says.
  This now includes the M4 cases (`tpm-*`, `tpm-slots-*`, `journal-kind-*`, `upgrade-*`, `upgrade-m3-*`, the F133–F144
  cases) which the earlier features proved only through `just e2e-cases debian13`; the other targets and the `none`
  and `lacking` combinations of those cases were never run in full, and this is where they first are.
- `just package-gates`: package, parity, glibc ceiling and package lint on the .deb, .rpm and Arch package.
- Not proven here: the `lacking` mode in a full run (each M4 case that needs it ran through `E2E_TPM=lacking just
  e2e-cases debian13 ...` in its own feature), and the manual acceptance steps of `docs/manual-acceptance.md` (hardware
  TPM, fwupd, reboot, Firefox, LibreOffice): they are a person's, and F145 marked them unverified.
- Documentation ("and documentation" in the title): no new text is written for its own sake. The documents M4
  promises (`docs/api.md` kinds and error names, `docs/audit.md` fields and queries, install and TPM docs, the manual
  acceptance page) are proven against the code or by running what they say, by tests that already run in `just check`
  (`test-docs-api.sh`, the audit queries test, `test-docs-install.sh`, `test-docs-manual-m4.sh`). If one is red here it
  is fixed in the document or the code, whichever is wrong. The F145 gap (SPEC acceptance 14 says `custodio list` prints
  a "weaker" sentence for `encrypted-host`; the CLI prints only `kind: encrypted-host`) is decided as follows: the
  builder checks `SPEC.md` and the CLI; if the sentence is required, it is added to the CLI with a test that runs the CLI;
  if the spec leaves it open, the choice is recorded in `docs/decisions.md` only if a later session could undo it unaware.
  It is not left open at the milestone's end.

Time and budgets (nothing new is added as a test, so no new test cost): the full `verify` is the cost.
- `just check`: earlier sessions measured ~10-15 min cold (the script tests run in parallel, p90 45 s each); a re-run on
  an unchanged tree is skipped through `target/check-ok` (`CHECK_FORCE=1` forces it).
- `just e2e`: seven runs at once, ~7-10 min wall on this 12-core host. `budgets.tsv` carries debian13 at 430 s, measured
  before F135–F144; PROGRESS.md sums the growth since at about +270 s (F135 20, F136 22, F137 23, F139 62, F140 31, F143 50,
  F144 18, F142 ~10, plus the m3 phase), so debian13 swtpm will exceed its budget and the other targets, which run the
  common cases only, may too (alma10 470, fedora44 500, ubuntu2604 460). A person sets budgets: step 3 measures each run
  and, if one is over, the builder writes `BLOCKED.md` with the measured times and the requested value, after finishing
  the rest. It does not edit `budgets.tsv` and does not remove or skip cases to fit.
- A single command runs at most 30 min and a session at most 45: `just e2e` of one target and mode is ~6–10 min, so steps
  3 and 4 run one target and mode per command, with `timeout 1700`. Earlier checkpoint F132 was cut five times when a
  session ran the whole `just e2e` (~60 min then); no step here runs it whole.

Environment: before step 3 run `podman info` and `swtpm --version` and note the result in `PROGRESS.md`. If podman has
lost its pause process (`podman info` fails), `timeout 120 podman system migrate` is the known remedy (F132). If an image
cannot be pulled or a target cannot boot, that is a `BLOCKED.md` question, not a reason to skip a target, mode or case.

## Steps
- [ ] Baseline: `just check` (run each script test that is red alone first, to see the cause), fix each failure at its
      cause, commit each fix when green; then `just api-contract` and `just fuzz-smoke`. `CHECK_FORCE=1` for a re-run on
      an unchanged tree.
- [ ] Decide the F145 gap as the Scope says; fix or record it, with a test that runs the CLI if the CLI changes.
- [ ] Run `E2E_TPM=swtpm timeout 1700 just e2e <target>` for each of alma10, arch, debian13, fedora44, ubuntu2404,
      ubuntu2604, and `E2E_TPM=none timeout 1700 just e2e debian13`, one per command. Fix every failing case, TPM set-up or
      accounting error at its cause (a case changes only if it is wrong); note each pass, its case counts and its wall time
      in `PROGRESS.md`. Compare each wall time with `budgets.tsv`; if over, `BLOCKED.md` as in Scope after the last step.
- [ ] Run `just package-gates`; fix every finding. Add to `packaging/lint/*.txt` only with a reason per entry and only for
      findings that are not defects.
- [ ] After the last fix, rerun each target and mode that ran before that fix, one per command, from a cleared
      `target/e2e/` (`just e2e` for a target only needs its own record, so clear it before the whole set), then check the
      Evidence record counts; run `just quick` once. The whole `verify` is not run in a session.
