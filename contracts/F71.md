# F71 — Upgrade cases start from an M3 build only

## Scope
Removes the end-to-end upgrade from the last cargo-deb .deb of M1 (F60), because the M3 state format
(F70) has no migration. Removed: `scripts/package-old.sh` and its host test `scripts/test-e2e-old.sh`;
`e2e/targets/debian13/old.pattern`; the six `upgrade-cargo-deb-*` ids in `e2e/targets/debian13/cases.list`
(the `purge-*` ids in that file stay); the `old` mode of `e2e/guest.sh`, `e2e/run.sh` (`packages_old`,
the second guest run, the `old.pattern` handling and its refusal-only check), `e2e/select.sh`,
`e2e/upgrade.sh`/`upgrade-lib.sh` comments; the `scripts/package-old.sh` line of `e2e-packages` in the
justfile (and the "old package of M1" wording of its comments); and every host test and fixture that
exercised the old package or its ids (`test-e2e-host.sh`, `test-e2e-select-host.sh`, `test-e2e-select.sh`,
`test-e2e-targets.sh`, `test-e2e-lifecycle.sh`, `test-e2e-refusal.sh`, `scripts/lib/e2e-host-fixtures.sh`,
the `test-e2e-old.sh` line in the justfile). Tests are adapted or deleted only where they test the
removed thing; the checks that stay (N to N+1, old path, other targets, accounting) keep their strength.
Kept, with the same behaviour: `upgrade-*` (N to N+1) and `upgrade-oldpath-*` (current tree with the
daemon at the old path), both built from this tree by `package-next.sh` / `package-oldpath.sh`, still
asserting that keys and certificates survive (cases `upgrade-state-unchanged`, `upgrade-keys-listed`,
`upgrade-signs-with-polkit` and their oldpath twins; the `upgrade-oldpath-*` run also covers the
M3 per-owner layout of F70, so the import in the guest must produce it).
Not here: the `.deb` lifecycle tests of F43 (`scripts/test-deb-lifecycle*.sh`) that simulate an M1 package
are package-script tests, not e2e upgrade cases; the postinst behaviour for a package without the
marker is unchanged and not touched (record it in PROGRESS.md if a step finds it dead). `CHANGELOG.md`
is generated and not edited. `docs/milestones/**` are history and not edited. The full `just e2e` and
the package gates run at F90/F100.
`docs/install.md` and the e2e catalog (`e2e/catalog-text.txt`, `docs/manual-acceptance.md`) have no mention of a pre-M3 package
today (checked with grep); the evidence keeps it so.

Environment: `podman info` works in the dev container (rootless). The `verify` runs `just e2e-cases debian13 'upgrade-*'`,
which needs a privileged systemd container; if it cannot start here, the builder writes `BLOCKED.md`
rather than weakening the check.

Size: about five steps; no split.

## Steps
- [ ] Delete `scripts/package-old.sh`, `scripts/test-e2e-old.sh`, `old.pattern` and the cargo-deb ids; drop the
      `package-old.sh` and `test-e2e-old.sh` lines of the justfile and fix the `e2e-packages` comment.
- [ ] Remove the old mode from `e2e/run.sh`, `e2e/guest.sh`, `e2e/select.sh`, `e2e/upgrade.sh`, `e2e/upgrade-lib.sh` (code and comments).
- [ ] Adapt the host tests and fixtures listed in Scope: delete only the assertions about the old package; keep (and where a
      negative control referenced the old package, retarget it to the old-path or N+1 package) the remaining ones.
- [ ] Check `docs/install.md`, `e2e/catalog-text.txt`, `docs/manual-acceptance.md`, and `README.md`, `harness/README.md` for
      any mention of upgrading from a pre-M3/M1/cargo-deb package; fix any found.
- [ ] Run `just quick`, then `just e2e-cases debian13 'upgrade-*'`; fix what the M3 layout breaks in the upgrade cases
      (e.g. key import in the guest) without weakening them; append the `PROGRESS.md` entry.

  selection is refused as an unknown case on debian13 → passes.
