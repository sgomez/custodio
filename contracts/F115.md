# F115 — Encrypted key storage with systemd-creds

## Scope
Built, in `custodiod`, a module named `creds` (not `credentials.rs`, which is the bus peer
credentials and is unrelated) in exactly three new files: `crates/custodiod/src/creds.rs` (access-point
trait, the two errors, the consuming function), `crates/custodiod/src/creds/systemd.rs` (the real
client) and `crates/custodiod/src/creds/header.rs` (credential header read-back and PCR guard). All
three join the `mutants` recipe's `--file` list. The module
- encrypts a private key with the real `systemd-creds` the way the `Decision:` lines of `## F110` in
  `docs/findings.md` fix (scope `user`, Varlink or the equivalent CLI call, no `withKey`; the
  explicit-device `--with-key=tpm2 --tpm2-pcrs= --tpm2-device=…` form for the TPM-bound case that
  the dev container can exercise), host-bound when no TPM is reachable and TPM-bound when one is;
- reads the stored PCR mask back from the credential header and refuses a credential with a
  nonzero mask or the null id (the F110 read-back guard), so "no PCR" holds whatever the default of
  the installed systemd; where the call can pass no-PCR itself (`--tpm2-pcrs=`) it does;
- decides TPM or host from one input: a configured TPM device/TCTI path (SPEC section 2: the platform
  exposes no TPM device means host); no configured path gives host-bound, a configured path TPM-bound;
- takes the plaintext on stdin / Varlink parameters, never argv, environment or a file, and returns
  the encrypted credential as the only form of the key;
- decrypts into `secrecy`/`zeroize` memory for one signature and keeps nothing;
- has two distinct errors, "credential service unavailable" and "cannot decrypt", mapped as the
  F110 `Decision:` lines say (connect failure or any Encrypt error other than a caller bug →
  unavailable; any Decrypt failure, TPM cleared and host key changed included → cannot decrypt);
- sits behind a trait (the access point) with the real client as one implementation, so tests inject
  both failures.

Left to other features: storing the credential in the state file and choosing the kind per key
(F120, the import flow), the TPM-blob path (F113/F114), polkit, the D-Bus API and CLI text,
packaging and unit changes, the SPEC_DEVIATIONS targets (debian13, alma10, ubuntu2404) beyond what
the read-back guard and an `unavailable` error already do, and everything that needs a kernel TPM
(a Varlink `Encrypt` that includes the TPM: the daemon refuses a TPM in a container, F110) —
proven in F147 / `just e2e-cases`, not here. Package gates, `just e2e` and lifecycle tests run at
the checkpoints.

Transports: host-bound cases go over Varlink directly to the user-scope daemon (the F110 `Decision:`
for systemd 257/259+); TPM-bound cases use the CLI with an explicit swtpm device. A Varlink+TPM case
is left to F147, consistent with the F110 finding.

Environment (run in the dev container, uid 1000, no PID 1, systemd 257.13, `swtpm` at
`/usr/bin/swtpm`; run from a directory on a real filesystem, not `/tmp` which is tmpfs):
- `unshare -m --map-root-user --map-users=auto --map-groups=auto` + tmpfs on `/run/systemd` + bind of a
  directory on `/var/lib/systemd` + `systemd-socket-activate -a --fdname=varlink -l
  /run/systemd/io.systemd.Credentials systemd-creds`, client as `setpriv --reuid=42 …
  systemd-creds --user encrypt|decrypt --name=k - -` → `enc=0`, `MARK dec=0`.
- `just with-swtpm unshare -m --map-root-user bash -c 'mount --bind <dir> /var/lib/systemd; printf MARK
  | systemd-creds encrypt --name=k --with-key=tpm2 --tpm2-pcrs= --tpm2-device="$TPM2TOOLS_TCTI" - - |
  systemd-creds decrypt --name=k --tpm2-device="$TPM2TOOLS_TCTI" - -'` → `MARK rc=0`.
So the host-bound case runs through the user-scope daemon and the TPM-bound case through the CLI with
an explicit swtpm device, both with the real binary and no fake. `strace` is not installed, so the
"no temporary file" proof does not use it.

## Evidence
- Encrypts with the real `systemd-creds` the way F110 decided, host-bound when no TPM →
  `creds::host_bound_round_trip` → real daemon as the service uid: encrypt then decrypt returns
  the exact bytes; the credential's header id is the scoped host id; decrypting as another uid fails.
- TPM-bound when reachable, against swtpm → `creds::tpm_bound_round_trip` → with the fixture's
  TCTI the credential decrypts to the same bytes and its header id is the TPM id (differs from the
  host one); the same client configured with no TPM path yields the host-bound id (tests the decision rule:
  configured path or not, not the test setup).
- Explicitly no PCR → `creds::credential_names_no_pcr` → the PCR mask read from the header of the
  host-bound and the TPM-bound credential is zero; negative control: `creds::pcr_guard_refuses` feeds
  the guard a real credential made with `--tpm2-pcrs=7` (swtpm) and a null-id credential
  (`--with-key=null`) and both are refused with an error, nothing returned.
- Plaintext without a temporary file; credential is the only form returned →
  `creds::no_plaintext_outside_memory` → a marker plaintext is not found in argv or environment of
  the spawned `systemd-creds` on the CLI (TPM-bound) path (recorded by an exec-wrapper that then runs
  the real binary; the host-bound Varlink path spawns nothing, so only the file search covers it), nor in
  any file under `/tmp`, `/var/tmp`, the state directory and the test's working directory after the
  call; the encrypt return type is the credential bytes only (the credential does not contain the
  marker).
- Decryption into `secrecy`/`zeroize` memory for one signature → `creds::decrypt_returns_secret`
  (the return type is `SecretSlice`/`Zeroizing<Vec<u8>>`, compile-checked by a trait-bound assertion
  `Zeroize`/`ZeroizeOnDrop`; `Debug` prints no key bytes) and a unit test where the test client owns the
  buffer it hands in and the code zeroizes it in place before release (checked in place, no read after free).
- Cleared TPM does not decrypt → `creds::cleared_tpm_cannot_decrypt` → encrypt against swtpm,
  `tpm2_clear` through the fixture, decrypt returns `CannotDecrypt` (not `Unavailable`); control: before
  the clear it decrypts.
- Host key changed → `creds::host_key_changed_cannot_decrypt` → replace the host secret directory,
  decrypt returns `CannotDecrypt`.
- The two errors are distinct, mapped by operation not by error name →
  `creds::unavailable_vs_cannot_decrypt` → separate assertions: (a) socket removed gives
  `Unavailable` for encrypt and decrypt; (b) `systemd-creds` missing from the path gives `Unavailable`
  on the CLI path; (c) a reachable daemon with no host secret (tmpfs, F110 "encrypt, no key" row) makes
  `Encrypt` return `Unavailable`, not `CannotDecrypt`; (d) a corrupted
  credential gives `CannotDecrypt`; the two variants are not equal and display differently.
- Replaceable access point, injected failures → `creds::injected_unavailable` and
  `creds::injected_cannot_decrypt` → a test client returning each error; the consuming function
  passes the right variant through unchanged, and no plaintext or partial credential is returned.
- Files join `mutants` → for each path P in `creds.rs`, `creds/systemd.rs`, `creds/header.rs`:
  `grep -c -- "--file crates/custodiod/src/P" justfile` → 1; after `just mutants-diff F115`,
  `target/mutants/mutants.out/outcomes.json` (or `caught.txt`) lists at least one mutant in each of
  the three files, and `missed.txt` is empty → exit 0.
- Whole feature → `verify` of F115 in features.json → exit 0.
