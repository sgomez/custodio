# F161 — VM cases: the kinds in full and lacking mode, the credential's key, and the silent fallback

## Scope
Built (acceptance 3, 4, 5 and 11; Design 2 use of the reader, Design 3):
- **Kind cases in a VM.** The five `tpm-kind-*` ids (import RSA, import EC, API list, `custodio list`, journal) join `e2e/vm/cases.list` and
  run in both VM modes with the existing scripts (`tpmkind-*`), whose expectation now depends on the mode: `full` (guest `E2E_TPM=swtpm`)
  → `tpm` for RSA 2048 and P-256 in all four places; `lacking` → RSA 2048 `encrypted-tpm` in the import result, `ListKeys`, `custodio list`
  and the journal entry (`CUSTODIO_STORAGE_KIND`), and the import text says the key is weaker and why ("the TPM of this machine lacks a
  capability…"). **P-256 in `lacking` is `tpm`**: `docs/findings/F152.md` shows P-256 would lack `Sign`, but F159's profile
  (`e2e/vm/lacking-rsa.json`) removes only `RSA_Decrypt`, so the case expects `tpm` for P-256 and says so in a comment and in its
  failure text. Container behaviour is unchanged: there `tpm-kind-*` stay run in `swtpm`, skipped in `none`/`lacking`.
- **`fallback-tpmbound-import` and `fallback-tpmbound-cli-list`** (already in the VM list, F160) are reported run in both VM modes, never
  skipped. `lacking`: the CLI import output and `custodio list` of an RSA 2048 key show `encrypted-tpm` and the weaker-and-why text
  (P-256: `tpm`). `full`: no `encrypted-tpm` key can exist, so the same cases judge that both keys are `tpm` and nothing is called
  weaker (F160 forbids skipping them in either mode). They keep their M4 containers behaviour: skipped.
- **The reader on every `encrypted-tpm` key.** After each import that gives `encrypted-tpm` in a VM run (here and in F162/F163, through a
  shared guest function), root in the guest runs `e2e/vm/credread.py --expect-tpm-bound --systemd-version N` on the stored credential of
  that key, with `N` read from the guest's `systemctl --version`. Only the reader's exit 0 passes; any other exit fails the case with the
  reader's reason. Where the credential lies is found by the builder in the state directory (read-only look at the real install).
  The function is a helper of the case scripts, not a case id; a case that expects `encrypted-tpm` and never calls it is a gap, so the
  self-test (below) greps the *scripts' calls*, not documents.
- **VM check rules** in `e2e/check-cases.sh` (flag `CHECK_VM`, as F160): `tpm-kind-*` and `vm-silent-*` must be run, never skipped, in a
  `lacking` VM run; in a `full` VM run `tpm-kind-*` must be run and `vm-silent-*` may be skipped (they need an `encrypted-tpm`
  import); the `vm-silent-*` skip reason is on `e2e/vm/skip.list`. The rules key on the value `check-cases.sh` receives (a `full` VM run is accounted as `swtpm`), so a `lacking` run cannot fall into the permissive branch. Container accounting is byte-identical (`test-e2e-skips.sh`,
  `test-e2e-tpm-kind.sh`, `test-e2e-vm-cases.sh` still pass unchanged).
- **Silent fallback** (`e2e/vm/silent.sh`, ids `vm-silent-import-fails`, `vm-silent-journal-cause`, `vm-silent-nothing-stored`,
  `vm-silent-no-key`, `vm-silent-restored-imports`; judged by functions the self-test also runs). `lacking` run only: the case hides
  the `libtss2-rc` library from systemd without removing the package (`dpkg-divert` or an equally reversible way the builder
  chooses and records), restarts what loads it, and proves the hiding worked (`systemd-analyze has-tpm2` no longer `yes`) before importing.
  With it hidden an RSA 2048 import (the type the `lacking` TPM sends to `encrypted-tpm`) must: fail with `CredentialsUnavailable`;
  leave one journal entry with cause `binding_mismatch` and no stored outcome; leave the state directory listing (names, modes, sizes,
  checksums) identical to before; leave no key of any kind for that id (`ListKeys` and `custodio list`). Then the library is restored
  and what needs it restarted, `has-tpm2` is `yes` again, and the *same* import (same id) gives `encrypted-tpm` and passes the reader.
  The restore is a guest `trap` plus a final unconditional restore, so it happens on any outcome, including a failed judge, and its
  success is checked (library file back, no diversion left, `has-tpm2` `yes` again). The case reuses the state-listing and journal helpers of `tpmfail-*`
  (`e2e/tpmfail-lib.sh`) where they fit. The new keys are deleted at the end so later counts are as before.
  A hiding that made the import fail with another cause (`tpm_error`, `credentials_unavailable`) does not pass: the cause must be
  `binding_mismatch`. If the real guest shows `binding_mismatch` cannot be reached this way (the cause is something else), the builder
  stops and writes `BLOCKED.md` with the evidence; it does not loosen the judgement.
- Self-tests `scripts/test-e2e-vm-kinds.sh` and `scripts/test-e2e-vm-silent.sh`, both added to `just test-scripts`; `scripts/test-e2e-fallback.sh`
  (in `verify`) is extended with the VM expectations of the fallback judgements and its container checks stay.

Not built (where): the sign, no-plaintext, PCR, TPM-clear and upgrade cases (F162, F163); the real full runs of `just e2e-vm full|lacking`
and the budgets row (F168 checkpoint); the guest-image/launcher (F158–F160, only called).

Environment (checked by this contract): `/dev/kvm`, swtpm 0.10.2 and the `lacking` profile were proven working in a real guest by F159/F160
(`vm.sh start lacking` boots; F160's real probe passed `full`). Steps 4 and 5 are builder probes of the new cases in `lacking`; the real proof is F168.

Cost: `test-e2e-vm-kinds.sh` 2–4 s (judges on fixtures; controls started together, no VM; real `credread.py` on small synthetic headers),
`test-e2e-vm-silent.sh` 2–4 s (judges plus a guest script run with stubbed `dpkg-divert`/`systemctl`/`journalctl` in a temp tree, as F160's
"guest" section), `test-e2e-fallback.sh` ~1 s more. All three run in parallel with other script tests under the `script *` budget (120 s).
The new guest work in a real `lacking` run: the kind step ~15 s (2 imports + 2 lists, as `tpmkind`), the fallback step ~15 s, the silent case
~30 s (two restarts of systemd's TPM users, two imports); no wait is a fixed sleep (conditions on the journal and the unit). These are the
e2e's cost, paid at the checkpoint, not by the loop's `verify`. Each step fits one session; the real run is one command (<10 min).

## Evidence
- `full`: RSA 2048 and P-256 both `tpm` (acceptance 3) → `test-e2e-vm-kinds.sh` "full": the judgements accept the good import/API/CLI/journal
  fixtures; controls: RSA `encrypted-tpm`, P-256 `encrypted-tpm`, `encrypted-host`, a "weaker" line, a missing kind each rejected, naming the key.
  Real guest: F168.
- `lacking`: RSA `encrypted-tpm` in import, API, CLI and journal; weaker-and-why text; P-256 `tpm` (acceptance 4) → "lacking" section: good
  fixtures accepted; each of the four places with kind `tpm` for RSA is rejected, as are no weaker text, a text without the reason, a journal
  entry of another id or outcome, and P-256 `encrypted-tpm` (the expectation is `tpm`). Real guest: F168.
- `fallback-tpmbound-*` run and not skipped → `test-e2e-vm-kinds.sh` "accounting": synthetic guest output for both modes passes with them run,
  fails with them skipped even with a skip-list entry; `tpm-kind-*` skipped in a `lacking` VM run fails; `vm-silent-*` skipped fails in `lacking`,
  passes in `full`; the same lines as a container run behave as before. Control: a `check-cases.sh` copy without the VM rule fails the test.
- Containers unchanged (acceptance 14 part) → `test-e2e-fallback.sh`, `test-e2e-skips.sh`, `test-e2e-tpm-kind.sh`, `test-e2e-vm-cases.sh` exit 0
  with no existing control edited.
- Reader on every `encrypted-tpm` key (acceptance 5) → "reader" in `test-e2e-vm-kinds.sh`: the helper, run against a stub reader and the real
  `credread.py` on synthetic credentials, passes a TPM-bound one and fails (with the reader's reason in the message) on host-only, null key, a
  nonzero PCR mask and a reader missing or exiting 2; a case script copy whose `encrypted-tpm` path skips the helper fails the call check
  (reads the scripts' calls). Real guest: step 4/5, the reader passes on the stored credentials. The reader's own discrimination → F157 (not repeated).
- `fallback-tpmbound-*` judged, not just reported → `test-e2e-fallback.sh` (VM section, fixtures): `lacking` good = RSA `encrypted-tpm` in the import
  output and `custodio list`, weaker line with the reason, P-256 `tpm`; each rejected: RSA `tpm`, RSA `encrypted-host`, kind wrong in the import only, in the
  list only, weaker line missing, reason (TPM lacks a capability) missing, P-256 `encrypted-tpm`. `full` good = both `tpm`, nothing weaker; rejected: either
  `encrypted-tpm`, a weaker line. The VM branch of `fallback-run.sh`, run on fixtures with a bad judgement, reports no case run and exits non-zero (a control
  copy that calls `case_run` unjudged fails); in a VM run it reports exactly `fallback-tpmbound-*` and never the `fallback-host-*` ids (not in the VM list).
- Silent fallback (acceptance 11) → `test-e2e-vm-silent.sh`: over fixtures of the guest's evidence, the good run (hidden: import fails with
  `CredentialsUnavailable`, `binding_mismatch` entry, identical state listing, id absent from both lists; restored: `encrypted-tpm`, reader
  ok, library back) passes; controls, each rejected naming the cause: an import that succeeds while hidden; a new file in the state
  listing; a changed checksum/mode; journal cause missing or another cause; a key left under another kind (`tpm`, `encrypted-host`,
  `encrypted-tpm`) for the id; `has-tpm2` still `yes` while hidden (hiding did not work); restored import still failing or giving another kind;
  reader failing after restore.
- The restore whatever the outcome → same test: the guest script run in a temp tree with stubs makes a judge fail midway (and, separately, is
  killed by a signal) and the log shows the undivert and the restart; a control copy of `silent.sh` without the trap leaves the diversion
  and fails the "restored" check; a restore that fails is reported and exits non-zero.
- Real hiding, real cause, real restore, real guest runs → proven at the checkpoint F168; steps 4 and 5 are builder probes recorded in PROGRESS, not evidence.
