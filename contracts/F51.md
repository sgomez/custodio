# F51 — Administrator documentation for installing and removing

## Scope
Built here: `docs/install.md` (new) and one link to it from `README.md`. Documentation only; no code, script or package changes.

Facts it must state truthfully (the builder reads them from the repository, not from memory, and cites no behaviour the packages do not have):
- Installation on Debian 13, Ubuntu 26.04, Fedora 44, RHEL/Alma 10 and Arch with each system's own tool, and on rpm-ostree systems by layering. Ubuntu 24.04 stays in
  the supported set (F41, `docs/findings.md` section "polkit 124 and ProcessFD", verdict A; no `BLOCKED.md`), so the dbus-broker section is required.
- Why a bus without `ProcessFD` is refused (polkit falls back to PID subjects that can be raced), by the package at install time and by the service at run time. On Arch the
  first installation only warns (SPEC section 2; F58); the doc says so. The messages in `packaging/bus-check.sh` that point to `docs/install.md` ("no system bus is running, so ProcessFD support was not checked"; "neither busctl nor dbus-send is installed"; "the system bus could not be queried for ProcessFD"; "the system bus does not provide ProcessFD") must each find their answer there, and any message added later that mentions `docs/install.md` must too.
- Ubuntu 24.04: install `dbus-broker`, reboot, check `ProcessFD` is returned; the package never switches the bus itself.
- Removal and purge (F43, F44, F58): the state directory `/var/lib/custodio` (real directory `/var/lib/private/custodio`), the keys and the `custodio` account stay; purge is the same as
  removal; the manual command that destroys the keys deliberately; the warning that deleting a file is not secure erasure (SPEC section 1 non-goals). On rpm-ostree
  `uninstall` runs no erase scriptlet (`docs/findings.md`, F44; `SPEC_DEVIATIONS.md`), so there the notice does not appear: the doc says that.
- Upgrade: a signature waiting for polkit while the service restarts fails closed, and never succeeds without its journal entry.
- Journal: how to check storage is persistent (`journalctl --disk-usage` / `/var/log/journal`, `Storage=persistent` in `journald.conf`), why it matters (volatile storage loses the
  audit trail at reboot), and that the package does not change journald's configuration. It links to `docs/audit.md` for the queries.

Left for other features: the packages and scripts themselves (F42-F44, F58), the e2e cases, audit queries (`docs/audit.md`), the manual acceptance run.

Environment: none needed. Commands the doc quotes must exist on the target (the builder checks the ones that can run in the dev container, e.g. `busctl`, `journalctl`; package-tool
syntax is checked against the e2e `install.sh` of each target, which are the commands that really ran).

Size: about four steps; no split.
