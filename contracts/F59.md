# F59 — End-to-end target Ubuntu 26.04 and the journal catalog check

## Scope
Built here:
- Target `ubuntu2604`: a directory `e2e/targets/ubuntu2604/` with `Containerfile` (Ubuntu 26.04 from `docker.io/library/ubuntu:26.04`,
  the distribution's own `polkitd` and default `dbus`, the same test tools as `debian13`), `skip.list`, and the target's install and
  probe steps and package pattern. The package is the same `.deb` as for `debian13`, mounted and installed by `apt` (not copied into
  the image). No shared script is edited to add the target (F45's rule), except for the catalog check below, which is shared.
- A new suite case, run on every target: after the signatures, a `custodio.service` entry (message id
  `29c3d30e6c4242406c6db3f120d36401`) viewed with `journalctl -x` shows the explanation text from `data/custodio.catalog`. The case
  is added to `e2e/cases.list`, so F46, F47 and the Arch feature get it with no change of their own; they only need it to pass or to
  be on their skip list.
- Journald's default storage on `debian13` and `ubuntu2604`, checked in the booted containers and recorded in `docs/findings.md`.
  Nothing in the package changes journald's configuration (SPEC section 6).

Not here: Fedora, Alma and Arch targets (their own features, which record their journald default), lifecycle cases, the Ubuntu 24.04
refusal, CI wiring.

Environment checks made while writing this contract (dev container, network available):
- `podman pull docker.io/library/ubuntu:26.04` → succeeds (Ubuntu 26.04.1 LTS).
- Inside it, after `apt-get update` (with `-o APT::Sandbox::User=root`), `apt-cache policy` has a candidate for systemd 259, systemd-sysv,
  dbus 1.16.2, dbus-user-session, libpam-systemd, polkitd 127, p11-kit, opensc, pkcs11-provider 1.2.0, libnss3-tools, python3-dbus,
  python3-gi and procps. So no skip-list entry is expected for missing tools; any that turns up during the build gets a reason.
- A booted systemd container works here since the dev container restart (F45, session 2); the real run is therefore required.

Size: about seven steps (the per-target test loop is small; if the builder finds it larger, say so and propose a split); no split needed.

## Steps
- [ ] Write the failing tests first: a test (in `test-scripts`, no container engine) for the catalog check's decision logic, with
      captured `journalctl -x` text as fixtures (one with the catalog text, one without, one with no entry at all), and extend the
      stub-engine test of F45 so that `ubuntu2604` is built and run like any target.
- [ ] Add the catalog check as a shared case (`journalctl -x` on a `custodio.service` entry, matching the explanation from
      `data/custodio.catalog`, not only the message), register it in `e2e/cases.list`, and keep the case accounting and the
      `bash -n e2e/*.sh` / shellcheck inputs green. Run it after the package postinst has registered the catalog, on a fresh journal
      entry from the run.
- [ ] Turn the per-target greps of `scripts/test-e2e-host.sh` (today hardcoded to `debian13`, except the COPY/ADD check) into a loop over
      every directory under `e2e/targets`, and tighten them for Ubuntu: `install.sh` of `ubuntu2604` must install the mounted file with
      `apt` (`apt install` / `apt-get install` of the path), not only `dpkg`; `debian13` keeps its own rule. Control: a fixture target
      whose `install.sh` uses only `dpkg -i` is rejected where `apt` is required. Write this test first, so it fails before the target exists.
- [ ] Create `e2e/targets/ubuntu2604/` (Containerfile, `skip.list` that exists even if empty, install step with `apt` on the mounted
      file, probe, package pattern), reusing `debian13`'s files only where they are correct for Ubuntu; the image must not contain the
      package or a different bus daemon or polkit.
- [ ] Check journald's default storage in the debian13 and ubuntu2604 containers (the effective `Storage=` setting, whether
      `/var/log/journal` exists after boot, and where the run's entries are) and write a section to `docs/findings.md` with the
      commands and results. If the default is volatile on a target, the catalog check and the audit-entry checks must still pass there.
- [ ] Update docs that list the targets or the cases (README, harness text, `docs/audit.md` only if it describes the check) and run
      `verify`.
- [ ] Real run, required: `just e2e ubuntu2604`, `just e2e debian13` and `just e2e` (all). Paste exit status, the per-case results
      (including the new case) and the `target/e2e/ubuntu2604.record` into `PROGRESS.md`. If it cannot run, write a finding and
      `BLOCKED.md`; do not fall back to the stub test.

## Evidence
- Target `ubuntu2604` exists and is run like any other → `scripts/test-e2e-host.sh` (in `test-scripts`) with the stub engine, plus
  `verify`'s `test -f e2e/targets/ubuntu2604/Containerfile` and `skip.list` → the stub log shows a build with that Containerfile, a
  `--privileged` run, the package mounted read-only and the shared guest executed; no shared script differs between targets.
- Apt installs the `.deb`, the image does not contain it, real polkit and default bus daemon → the F45 greps in the same test, which
  cover every directory under `e2e/targets`, now cover `ubuntu2604` (no `COPY`/`ADD` of a package; `install.sh` runs `apt` or `dpkg`
  on the mounted file; `polkitd` and `dbus` installed, no `dbus-broker`) → today only the COPY/ADD check loops over all targets and the
  rest is hardcoded to `debian13`; the step above makes them loop. Expected: pass for both targets, `ubuntu2604` requires `apt` in
  `install.sh` (fixture with only `dpkg -i` → rejected). The real run's record (`bus-daemon=dbus-daemon`, polkit version) is the runtime
  evidence for the bus daemon and polkit.
- The suite runs on Ubuntu 26.04 → REQUIRED real run `just e2e ubuntu2604` (no stub) → exit 0, "e2e: passed: ubuntu2604", every case
  in `cases.list` reported as run or on `skip.list`, and `target/e2e/ubuntu2604.record` naming `dbus-daemon`, its version, the polkit
  version and the target (the daemon is read from the running system bus, as F45 does). `just e2e debian13` and `just e2e` still
  exit 0 with the new case run.
- The journal catalog check, on every target → decision-logic test fixtures: output with the explanation text → accepted; output with
  the entry but without the explanation (catalog not registered) → rejected with a message that names the catalog; no
  `custodio.service` entry → rejected. The case is in `cases.list` and `grep -rq 'journalctl -x' e2e` holds (`verify`). In the real
  runs the case is reported as run on `debian13` and `ubuntu2604`. The fixture test calls the same function or `journal.py`
  subcommand that the guest case calls (no second copy of the matching logic). The explanation text matched is a line of the catalog
  body kept in step with `data/custodio.catalog` by a test (only `/e2e` is mounted in the guest, so the text is committed under `e2e/`
  and the test compares it to the catalog). The guest case never runs `journalctl --update-catalog` itself: it must fail if the
  package's postinst did not register the catalog.
- The check applies on every target → it lives in the shared guest scripts and in `cases.list`; the case-accounting test of F45
  fails a target that omits it unless it is on that target's `skip.list`. The other targets' real runs belong to F46, F47 and the
  Arch feature (Scope).
- Default journald storage of `debian13` and `ubuntu2604` → the required `docs/findings.md` section, with the command run in each
  booted container (effective `Storage=` and presence of `/var/log/journal`) and its output → the section names both targets and
  the observed default; a reader can repeat the commands. Heading: `### Journald default storage on debian13 and ubuntu2604`; the evaluator checks with
  `grep -n '^### Journald default storage' docs/findings.md` and that both target names and the `Storage=` / `/var/log/journal` outputs sit
  under it. The section says the result comes from the minimal `debian:trixie` and `ubuntu:26.04` images and where an installed system may differ.
- Shellcheck and syntax of the new scripts → `just check` and `bash -n e2e/*.sh` (both in `verify`) → pass.
