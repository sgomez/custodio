# F25 — One journal entry per Sign call that reaches authorization, failing closed

## Scope
Wires the F24 audit interface into `Sign` in `crates/custodiod`. Only `Sign` changes; `ListKeys`,
`ListCertificates` and `ImportP12` stay unaudited.

- **Credentials from the bus.** A new trait `CallerCredentials` (in `src/credentials.rs`, tests in
  `credentials/tests.rs`) with `fn credentials(&self, sender: &str) -> impl Future<Output = Result<Caller, CredentialsError>> + Send` (the
  `polkit.rs` pattern, so no `async_fn_in_trait` warning and the `#[interface]` handler gets a `Send` future).
  The production `BusCredentials` calls `org.freedesktop.DBus.GetConnectionCredentials` on the bus daemon for
  `sender`. A pure function `caller_from(map)` turns the reply into a `Caller`; a missing or wrongly typed
  `UnixUserID` or `ProcessID` is an error (no default, no zero). `Sign` has no uid or pid argument and gets none.
- **Same sender.** `Sign` reads the sender once from the message header and passes that same `&str` to
  `CallerCredentials` and to `Authorizer::authorize`.
- **Order in `Sign`.** (1) `parse_sign_request` (unchanged; refusals here leave no entry, an open question in
  SPEC, so no test asserts either way). (2) sender, then credentials. If either fails: one entry
  `AuthorizationUnavailable`, polkit is **not** asked, no key is read, the call returns `AccessDenied`
  ("authorization unavailable"). (3) polkit: `Denied` gives `Denied`; `BadSender` or `Unavailable` gives
  `AuthorizationUnavailable`. (4) key read and `sign`: success gives `Signed`; any failure here (store error,
  `SignError`) gives `SigningFailed`. (5) `sink.record` once, **before** the reply is built. If it errors, `Sign`
  returns `fdo::Error::Failed("audit unavailable")` for every outcome, and the signature is dropped. The
  original error of a refusal is replaced too (the call fails either way). The sink error is not copied into
  the reply.
- **Entry without a caller.** F24's `Entry` needs a `Caller`, and when the bus gives none there is no uid or pid
  to write. Add `Entry::without_caller(key_id, mechanism)` in `audit.rs`: its outcome is always
  `AuthorizationUnavailable`, `CUSTODIO_UID` and `CUSTODIO_PID` are omitted, and `MESSAGE` says `uid unknown pid
  unknown`. `Entry::new` and the `caller()` getter keep their F24 meaning (`caller()` becomes `Option<Caller>`;
  the F24 tests are updated for that and nothing else; no F24 test is weakened). Nothing is invented or
  defaulted to 0.
- **Key id and mechanism in the entry.** `KeyId::new(&request.id)` (cannot fail after `check_id`; an `Err` is
  treated like a sink failure and refuses the call) and `AuditMechanism::from(&request.mechanism)`.
- **Construction.** `Custodio<A, C>` is generic over `Authorizer` and `CallerCredentials`; `Custodio::new(store, authorizer, credentials, sink)` with `sink: Arc<dyn AuditSink>`. Call sites
  updated: `main.rs` (`BusCredentials`, `JournalSink::default()`), `tests/dbus.rs`, `dbus/tests.rs`,
  `custodio-cli/tests/cli.rs`, `custodio-pkcs11/tests/cryptoki/parent.rs` (these use `MemorySink` and a
  credentials fake or `BusCredentials`; their assertions do not change).
- **Build files.** `justfile`: `test-integration` gains `--test audit`; `just mutants` gains `credentials.rs`.
  `data/custodio.service` and the bus policy are not expected to change. If the bus policy must allow
  `GetConnectionCredentials`, only that allow is added, and `just system-gates` stays at threshold 10.
- **Not here.** The `journalctl` query and the admin document, the real-journal end-to-end test, the
  pre-authorization open question, fuzzing, and a startup check that the journal socket exists (a missing
  socket fails each `Sign` closed, which the test below shows).
- **Size.** About five steps; no split. Tests go in `tests/audit.rs` and helper files in `tests/audit/` (bus, fake polkit, scanner) included with
  `#[path = "audit/bus.rs"] mod bus;` (as `main.rs` does for `main_tests.rs`), so Cargo builds no extra test target; each file stays under the 5000-token file gate.

## Evidence
Unless stated, tests are in `crates/custodiod/tests/audit.rs` on a private `dbus-daemon` with a fake polkit like
`tests/polkit.rs`, the real `BusCredentials`, and `MemorySink` as the replaced sink.
- uid and pid from the bus → `sign_entry_has_test_process_uid_and_pid` (client is the test process; expected values come from `std::process::id()` and `rustix::process::getuid()`, already a dependency, not from any production helper) → pass; fails if uid/pid are zero, swapped or taken from elsewhere.
- Not the service's own pid → `entry_names_the_caller_not_the_service` (the client is a child process, the test binary re-run with an environment variable that makes it connect and call `Sign`; the service stays in the parent; the entry's pid equals `child.id()` and differs from `std::process::id()`; two clients on two connections each get their own pid) → pass; fails if the service's own credentials are used.
- Never from the arguments → `sign_has_no_uid_or_pid_argument` (the introspected `Sign` method has exactly the arguments `id`, `mechanism`, `hash`, `salt_len`, `data`; a call with two extra `u32` is rejected and leaves no entry and no polkit call) → pass.
- Same sender everywhere → `credentials_and_polkit_see_the_same_sender` (a recording credentials wrapper around `BusCredentials` and the fake polkit both record the name they were given; both equal the client's unique name; run with two clients so a cached or fixed name fails) → pass.
- Credentials from the bus reply → `credentials::tests::caller_from_*` (unit, in `src/credentials/tests.rs`: both fields present gives that `Caller`; missing `ProcessID`, missing `UnixUserID`, either of the wrong type, and an empty map are each `Err`; values 1234567 and 7654321) → pass; fails on a default or swapped field. `credentials_for_unknown_name_is_an_error` (in `tests/audit.rs`; `BusCredentials` for `:1.99999` on the private bus returns `Err`) → pass.
- Credentials unavailable refuses → `credentials_unavailable_refuses_and_records` (a credentials fake that always errors; `Sign` returns `AccessDenied`, no signature; polkit fake saw zero calls; `MemorySink` has exactly one entry: `AuthorizationUnavailable`, the right key id and mechanism, no uid or pid) → pass; fails if polkit is asked, a signature returns, or no/two entries are recorded. A second case: a fake whose error comes from `caller_from` on a map without `ProcessID` behaves the same. In both cases the key file is absent, and the outcome stays `AuthorizationUnavailable` (no key is read).
- Entry without a caller → `audit::tests::without_caller_*` (unit: outcome fixed, `caller()` is `None`, the encoded datagram has no `CUSTODIO_UID`/`CUSTODIO_PID`, `MESSAGE` is the exact literal with `uid unknown pid unknown`, priority 4) → pass.
- Outcome 1, signed → `outcome_signed` (polkit approves; the call returns a signature that verifies against the fixture certificate; one entry: `Signed`, test uid and pid, key id, mechanism) → pass.
- Outcome 2, signing failed → `outcome_signing_failed` (approved, then the signing fails: an RSA key with an ECDSA mechanism gives `MechanismMismatch`; a second case approves a well-formed id that is not in the store, a store error after approval; each gives one entry `SigningFailed`, an error and no signature) → pass.
- Outcome 3, denied → `outcome_denied` (polkit answers no, and separately "challenge"; each gives one entry `Denied` and an `AccessDenied` error; no key is read: the key file is made unreadable or absent and the outcome stays `Denied`, not `SigningFailed`) → pass.
- Outcome 4, authorization unavailable → `outcome_authorization_unavailable` (polkit not on the bus; polkit replies with an error; each gives one entry `AuthorizationUnavailable` with the test uid and pid, and `AccessDenied`) → pass.
- Exactly one per call → `exactly_one_entry_per_call` (a mixed sequence of eight calls over all four outcomes; after each reply, `MemorySink` holds exactly n entries, in call order, each with the outcome expected for that call; `ImportP12`, `ListKeys` and `ListCertificates` add none) → pass; fails on zero, two, or late entries.
- Entry is submitted before the reply → `entry_is_recorded_before_the_reply` (a sink whose `record` blocks on a channel the test controls; while it is blocked the client's call gets no reply within 200 ms; after release the reply arrives and the entry is there) → pass; fails if the entry is written after the reply or in a detached task.
- Fail closed, signed → `failing_sink_withholds_the_signature` (first a normal call with `MemorySink` records the deterministic RSA PKCS#1 signature; the same call with `FailingSink` returns an error, the reply is an error message, not a body; the error text contains neither the hex nor base64 of that signature, nor the data; error is `Failed`/"audit unavailable") → pass; fails if the signature is returned or the sink result is ignored (`let _ =`).
- Fail closed, all outcomes → `failing_sink_fails_every_outcome` (denied, signing failed, authorization unavailable and credentials unavailable, each with `FailingSink`: an error, never success; polkit approval plus a sink error never gives a signature) → pass.
- Fail closed with the real writer → `missing_journal_socket_withholds_the_signature` (`JournalSink::new` on a path in an empty tempdir; an approved call returns an error and no signature) → pass.
- Real writer end to end → `journal_sink_datagram_per_call` (`JournalSink` on a test-owned datagram socket; the approved call gives exactly one datagram that decodes, with a test decoder, to `CUSTODIO_UID`, `CUSTODIO_PID`, `CUSTODIO_KEY_ID`, `CUSTODIO_OUTCOME=signed`, `MESSAGE_ID`; then `WouldBlock`) → pass.
- No secrets in any entry → `entries_contain_no_secrets` (an import with password `P@ss-sentinel-…` followed by one call per outcome with distinctive data of 40 bytes and an ECDSA key; for each entry the `Debug` text, `message()` and the full datagram from `JournalSink` are scanned for: data, the digest if any, the signature, the password, each as raw bytes, lower- and upper-case hex, standard and URL-safe base64 with and without padding) → pass; fails if any appears.
- Rejected strings never reach an entry → `rejected_id_is_not_copied` (`Sign` with id `bad/LEAK-sentinel`, and one over 64 bytes; an error, polkit asked zero times; the sentinel is in no entry's `Debug`, `message()` or datagram, whether or not an entry exists, so the open question stays open) → pass.
- The scanner can fail → `leak_scanner_detects_planted_values` (the same scanner on a buffer with each encoded form planted, one at a time, reports each) → pass; this keeps the test above from being vacuous.
