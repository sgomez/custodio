# F89 — Start pkttyagent when no polkit agent answers

## Scope
`custodio import` and `custodio delete` get a polkit text agent when they need one. Built here:
- A helper in `custodio-cli` used by both commands, around the one bus call that makes the service
  ask polkit (after the delete confirmation and after the import password, never before: a
  declined or refused command starts nothing). It runs only when stdin is a terminal. It starts
  `pkttyagent` (found on `PATH`) registered for the CLI's own process only (its pid and its
  start time, `PID,START_TIME` as `pkttyagent --help` shows, so a reused pid cannot match; never `--system-bus-name`, never another pid, never a session-wide
  or parent/shell registration), and only when no polkit agent answers for the session.
- The agent is stopped when the call returns, on success, on failure, and on interruption
  (SIGINT, SIGTERM, SIGHUP): the child is terminated and reaped before the CLI exits; the exit
  status after a signal is non-zero. A CLI killed without a chance to clean up (SIGKILL) must not
  leave the agent running either. The mechanism must work without `unsafe` (`custodio-cli` is
  `#![forbid(unsafe_code)]`, and CLAUDE.md allows `unsafe` only in the PKCS#11 FFI layer), so no
  `CommandExt::pre_exec`. Allowed, in the order Step 1 tries them: (1) `pkttyagent` itself exits
  when its parent dies (shown by a container probe); (2) `setpriv --pdeathsig=KILL` run in front
  of `pkttyagent` (it execs, so the agent keeps the pid and its own `argv`; `/usr/bin/setpriv` is
  not pinned, so Step 1 records it as a runtime dependency for packaging in the finding, and the
  CLI falls back to starting without it only if the finding says the tool is optional, never
  silently weakening the kill guarantee); (3) a self-re-exec helper that sets the parent-death
  signal with rustix's safe API, checks `getppid` against the expected pid, and `exec`s
  `pkttyagent`, only if it adds no user-visible subcommand or flag (hidden surface is rejected by
  the help/man tests). If none works without `unsafe`, that is a deviation with its own finding,
  not a free choice. A parent-death signal fires when the parent *thread* exits, so the agent is
  spawned from the main thread (or the test runs on the multi-thread runtime and proves a spawn
  from a worker thread is not killed early).
- If `pkttyagent` is missing or fails to start/register, the call goes on without it and the
  usual `AuthorizationUnavailable` message appears; no new message text, no hang, no secret in
  output. The agent's own output is not parsed or relayed except through the terminal it owns.
- `packaging/custodio.1` gets a sentence on this (terminal, no agent, own process only).

Open question that Step 1 settles: how "no agent answers" is decided. polkit has no listing call;
candidates are `pkttyagent --fallback` semantics, or a side-effect-free probe. Limits: the probe
must not register an agent for anything but the CLI's process, must not authorize or cache
anything, and when it cannot tell, the conservative reading applies and is recorded in
`docs/decisions.md` only if a later session could undo it unknowingly. Step 1 writes the finding
(tool source or a command run, not a guess) in `docs/findings.md`; a subagent may read polkit and
systemd sources. Outcome A: a reliable check exists and is used. Outcome B: none exists; then the
requirement "not started when an agent answers" is met by the narrowest replacement that polkit
itself enforces (e.g. `--fallback` so an existing agent is never replaced), recorded as a deviation
in `SPEC_DEVIATIONS.md` with the amended evidence, per CLAUDE.md.

Registration order: like systemctl, the CLI starts the agent with a notify fd and waits for it to
close (bounded; a fake that exits without notifying must not hang the CLI) before making the
authorizing call. Step 1 records this. Note `--fallback` does not meet "not started when an agent answers": the
process still starts and only declines to replace an agent (systemd's `polkit_agent_open` always
spawns on a tty, with `--fallback`). So under Outcome B `--fallback` is a deviation from the
feature's wording, not a way around it.

Not here: the prompt, the service's polkit calls, and per-call authorization (F76/F88, no cache is
added); the real `pkttyagent` password dialog and a real agent's behaviour, which only a person
sees (manual, F100 / acceptance 11 manual steps); package, install and e2e runs (F90/F100).
Environment: `/usr/bin/pkttyagent` and `pkcheck` exist in the dev container; the tests use a fake
`pkttyagent` script first on `PATH` and a pseudo-terminal (`rustix` `pty`, as the `tty` tests),
so no real agent is registered. Step 1 also shows that the fake can record `argv`, its pid and be
signalled in the container. Command run: `pkttyagent --help` lists `--fallback`, `--notify-fd`,
`-p/--process=PID[,START_TIME]` and `-s/--system-bus-name` (installed from `polkitd`).

## Evidence
- Own process only → binary test (delete and import): the fake records its `argv`; its process
  argument is exactly `PID,START_TIME` of the CLI (the pid the test knows for the child it spawned;
  the start time equals field 22 of `/proc/<cli-pid>/stat`) and nothing else: no
  `--system-bus-name`, no second pid, no shell or parent pid; a unit test over the argument
  builder with several pids rejects any other shape → pass.
- Started when needed → same test: with stdin a terminal and no agent answering, the fake is started
  exactly once, during the authorizing call (after the delete answer / password), not before the
  prompt → pass.
- Not without a terminal → binary test with a controlling pty but stdin a pipe, and stdin a file (delete's refusal without
  `/dev/tty` already stops earlier: use import with the password supplied as F86/F87 tests do, or
  the unit test on the decision function for what the binary cannot reach): the fake is never
  started → pass.
- Not when an agent answers → Outcome A: test where the agent-check double (or a fake agent on
  the private bus, whichever the finding allows) answers: the fake `pkttyagent` is never started.
  Outcome B: the test of the replacement in the deviation. → pass
- Not before a declined or refused command → delete declined, delete without terminal, import with
  usage error: the fake is never started → pass.
- Stopped on success, failure, interruption → three binary tests (confirmed delete; polkit denial;
  SIGINT sent to the CLI while the fake polkit holds the call): after the CLI exits, the fake's
  pid no longer exists (waited with a bound, not slept), no zombie child while the CLI is still running (`/proc/<pid>/stat` checked before exit), and the
  interrupted run's status is non-zero. The same binary test is
  parameterized over SIGINT, SIGTERM and SIGHUP (the guard's signal path is proven only there) → pass.
- Registration before the call → test with a fake that closes the notify fd late: the fake polkit
  sees no call before it closes; a fake that exits without notifying does not hang the CLI → pass.
- No outliving on a kill → binary test (Step 1 mechanism, agent spawned from the main thread) where the CLI is not the pty session leader and the fake
  ignores SIGHUP (so a hangup cannot be what kills it): SIGKILL the CLI while the fake runs; the fake's pid is gone
  within a bound → pass.
- Missing or failing `pkttyagent` → tests with `PATH` lacking it and with a fake that exits 1:
  the CLI does not hang, prints the `AuthorizationUnavailable` or the real service result
  (fake polkit unavailable / approving) and no new text → pass.
- No secrets → the CLI output (stdout and stderr) contains neither the password, the id's
  key material nor any path of the input .p12 → pass.
- Negative controls → (a) a variant of the argument test with a spawner passing a different pid
  fails the test; (b) a guard that does not kill, and no parent-death mechanism, make the outlive and kill tests fail (shown once and
  reverted in the session notes) → pass.
- Man page → `tests/man.rs` style check that `packaging/custodio.1` mentions `pkttyagent`, the
  terminal condition and the own-process-only registration; fails if removed → pass.
- `just quick` → exit 0.
