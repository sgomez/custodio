# F66 — Client API document and the API contract check

## Scope
Built:
- `docs/api.md`, the client document for the interface as it is at this feature: `ListKeys`,
  `ListCertificates`, `ImportP12`, `Sign` (and any other method or property the live introspection shows).
  For each method: name, argument names and D-Bus signatures, result signature, and the bounds
  (key id length and charset, `.p12` size, password, digest/data sizes, mechanisms, salt as the code enforces
  them). Every error name of `ServiceError` (`ServiceError::ALL`, `error_name()`), each with when it occurs
  (including the pick for a `.p12` with no private key or several, as recorded in the error type's doc
  comment), and every action id of `data/com.rfirma.custodio.policy`. The format is the builder's, but it must
  be parseable by the test (for example fixed-shape headings or tables); prose around it is free.
- A test in `custodiod` (`tests/api_contract.rs`, name the builder's) that starts the service on a private bus,
  reads the live introspection XML of the object (methods, argument names/directions/signatures, properties
  with signature and access), and compares it with the document; compares the error names of
  `ServiceError::ALL` with the document; compares the `<action id>` values of the `.policy` file with the
  document. Both directions fail: an item in a source missing from the document, and an item in the document
  missing from its source. The comparison takes the document path as a parameter so negative controls can
  run on edited copies in a temp dir.
- A recipe `just api-contract` running only that test. The test is a normal workspace test, so `just test`,
  `just quick` and `just check` already run it (no recipe edits needed for that; if the builder finds it is
  not picked up, that is fixed, not worked around).

Not built: `DeleteKey`, replace certificate, the new import/delete/replace actions and the new error names,
if any, beyond F65 (later features add them to the document and the check keeps passing; F59-style policy
features list their actions in `docs/api.md` themselves). Prose guidance for client authors, busctl
examples, flatpak detection, ownership and audit narrative (the later documentation feature, whose
`scripts/test-docs-api.sh` is its own proof). The document is not checked for prose accuracy, only for the
listed items.

Environment: nothing beyond the dev container; the dbus tests of `custodiod` already start a private bus
(`crates/custodiod/tests/dbus.rs`). Size: about four steps; no split.

## Steps
- [ ] Write the failing test first: introspection parsing and the three comparisons as a function that takes
      the document text and returns the list of differences, with a first run against an empty or missing
      `docs/api.md` failing and naming the items. Add `just api-contract`.
- [ ] Write `docs/api.md` from the three sources until the test passes (methods, arguments, results, bounds
      checked against the code, every `ServiceError` name, the `sign` policy action).
- [ ] Add the negative controls on copies of the document and the sentinel checks (see Evidence), and the
      bounds check.
- [ ] Run `just quick` and `just api-contract`; write the `PROGRESS.md` entry.

## Evidence
- The document lists every method with arguments, results and bounds → `just api-contract` → green; the
  introspection side of the comparison compares method name, each argument's name, direction and signature,
  and each property's name, signature and access, so a signature differing in any one fails (see the control
  below). Bounds: the test also asserts that each method's section has a bounds entry and that the documented
  `.p12` size bound equals `custodio_client::MAX_P12_LEN` → green; a copy with a wrong value fails.
- Every error name of the service's error type is listed, and only those → same test, source
  `ServiceError::ALL.map(error_name)` against the names in the document (all ten at F65, no more) → green;
  negative control: a copy with one name deleted fails (source item missing), a copy with an extra name
  `com.rfirma.Custodio1.Error.Bogus` fails (document item missing from source).
- Every polkit action of the `.policy` file is listed, and only those → same test reading
  `data/com.rfirma.custodio.policy` (path resolved from the crate manifest dir) → green; negative controls:
  extra action `com.rfirma.custodio.bogus` in a copy fails; a copy without `com.rfirma.custodio.sign` fails.
- The comparison is against the live service, not a copy of its description → the test starts the service on
  a private bus and calls `org.freedesktop.DBus.Introspectable.Introspect` on the object path; it does not
  read the Rust source for methods → green. Also asserts the introspected set is non-empty and contains
  `Sign`, so an empty read cannot pass.
- Negative controls on copies of the document, each asserted to fail with a message naming the item: a method
  removed (e.g. the `ImportP12` section), a wrong argument signature (e.g. `Sign`'s digest `ay` written as
  `s`), an extra error name, an extra action; plus the unmodified document passes in the same test run (the
  controls differ from it only by the edit).
- `just api-contract` and `just test` run it → `just api-contract` green; `grep -n api_contract` shows the
  test file is in `custodiod/tests` (so `cargo test --workspace` in `just test` includes it) → expected.
- `just quick` → exit 0.
