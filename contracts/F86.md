# F86 — custodio import on the documented API, with error names

## Scope
Today `custodio import` already goes through `custodio-client` (bus name, path, bounds, the ten
error-name constants, F64/F65) and `crates/custodio-cli/src/bus.rs` maps each name to a fixed
message. What is built here, where the code falls short:
- `ImportP12` is called as `docs/api.md` describes: `(s id, ay p12, s password)` → `s`, with
  the client crate's `BUS_NAME`/`OBJECT_PATH`, nothing else from the service. Step 1 compares
  `bus.rs` and `lib.rs` with `docs/api.md` (including bounds the CLI checks before calling:
  `.p12` size, password size) and fixes any difference; if none, the step says so.
- Failures are values the CLI can tell apart, not one `String`: each of the ten documented
  names, "the service is not on the bus" and other transport errors, and the local failures
  (cannot read the file, too large, no password) each have their own message; the message for
  `PolkitDenied` (denied) and for `AuthorizationUnavailable` are different texts; the service's
  free text, the password, the file path of the rejected input and key material are never in a
  message. Unknown names are shown as unknown, with the name.
- Exit status: every failure is non-zero (1); usage errors (`ArgError`) keep status 2. The
  mapping is a function in the library so it can be tested, and `main` uses it.
- Tests against a service on a private `dbus-daemon` with the fake polkit (the setup of
  `crates/custodio-it/tests/cli.rs` / `custodiod/tests`; the service built with test doubles for
  the polkit authorizer, the audit sink and, where a case needs it, the .p12 decoder), through
  the real `DbusImporter` and `run_import`.

Not here: `list` (F87), `delete`, the confirmation prompt and `pkttyagent` (later features);
the man page text beyond what `import` needs; the service's own ordering, once-per-call polkit and
state-unchanged guarantees (proven in F73/F65 and `custodiod` tests, only observed here as the
outcome of a CLI call); that the CLI does not depend on `custodiod` (`just deps-check`, F64);
package, install and e2e runs (F90/F100). The real binary needs a terminal for the password, so
the exit status of a failed import is proven on the library function that `main` calls, and the
binary itself only for what needs no terminal (usage errors, an unreachable bus).

## Evidence
- Calls only the documented method, through the client crate → `cli.rs` test with a bus monitor or
  recording service: exactly one call, `ImportP12`, to `BUS_NAME`/`OBJECT_PATH`/interface from the client
  constants, arguments `(id, p12 bytes, password)` equal to what was given → pass. Dependency
  direction → `just deps-check` (F64), not repeated.
- Approval → test: fake polkit approves, `run_import` returns Ok, the output names the id and the
  type returned by the service, the store holds the key for the caller, polkit was asked once with the
  import action → pass.
- Denial → test: fake polkit denies; failure is the denied one, its message is the `PolkitDenied`
  text, differs from the unavailable text; store unchanged; wrong password with denial still shows
  denied (not wrong password) → pass.
- Unavailability → test: authorizer answers unavailable; message is the `AuthorizationUnavailable`
  text; store unchanged → pass.
- Each documented error name as its own message → table test over all ten names plus an unknown
  name and an empty-text case: every message is distinct from every other, equals the fixed text,
  ignores the service's free text (`SERVICE FREE TEXT` never appears); and one bus test per
  name that the service can produce through the CLI (invalid args via an oversized id or
  password with `--id`, id taken via a second import, wrong password, unsupported key with
  `rsa3072.p12`, certificate mismatch, audit unavailable via `FailingSink`, internal via a
  failing store or decoder double): the failure shown is that name's message, store as the
  service documents (no key after a failed call) → pass. A deliberately swapped table entry makes
  the table test fail (negative control, reverted).
- No secrets in messages → test: for every failure above, the password, the p12 bytes (as text
  or hex) and the file path are absent from `Display` and `Debug` of the failure and from
  everything written to stdout/stderr by `run_import` → pass.
- Service absent → test: no name owner on the private bus; failure is the "cannot talk to the
  service" message, not an error-name message; exit status 1 → pass.
- Local failures (missing file, oversized file, no terminal) → existing tests in `cli.rs` stay
  green; each yields a non-zero status through the exit function and never calls the service.
- Non-zero on every failure → test: the exit function maps every failure case (all of the
  above) to 1 and success to 0; negative control: mapping one case to 0 fails the test.
- Usage errors keep status 2 → `crates/custodio-cli/tests` run the built `custodio` binary with no
  arguments, `import` with no file, `--password x`, a repeated `--id`, and an unusable file
  stem without `--id`: status 2, usage/diagnostic on stderr, nothing on stdout. Binary with an
  unreachable bus address (`DBUS_SYSTEM_BUS_ADDRESS` to a missing socket) and a valid
  call that gets as far as the bus: status 1 (not 2).
- Reminder to delete the original stays only after success → existing tests stay green.
- `just quick` → exit 0.
