# F26 — Audit documentation for administrators and the journal catalog entry

## Scope
Documentation and packaging only; no change to the audit behaviour of F24/F25.

- `docs/audit.md`: the administrators' reference for the entries `custodiod` writes, written as a stable
  interface: `MESSAGE_ID`; every field (`MESSAGE`, `MESSAGE_ID`, `PRIORITY`, `SYSLOG_IDENTIFIER`,
  `CUSTODIO_UID`, `CUSTODIO_PID`, `CUSTODIO_KEY_ID`, `CUSTODIO_OUTCOME`, `CUSTODIO_MECHANISM`) with its meaning and
  when it is absent; the four outcome values with their priorities; the message text shape; a `journalctl`
  query matching only entries of `custodio.service` using trusted fields (`_SYSTEMD_UNIT=custodio.service`
  and `_UID=` of the service user, plus `MESSAGE_ID=`); example queries by uid, key and outcome; and a
  "not guaranteed" section: identity of a person (uid and pid are of the calling process only), pid reuse,
  rate limiting, volatile storage, imitation by other processes (user fields are forgeable; only `_`-fields count).
  It states the compatibility rule: names, identifier and priorities are not changed, only added to.
- `data/custodio.catalog`: a journal catalog file for `MESSAGE_ID`, shipped by the .deb as
  `usr/lib/systemd/catalog/custodio.catalog` (new asset in `[package.metadata.deb]`).
- A unit test (own file, `crates/custodiod/src/audit/docs_tests.rs`, not inline) that ties code, docs and catalog together.
- Left out: the e2e journal checks and the manual steps (other features); running `journalctl --update-catalog`
  in `postinst` (systemd rebuilds the catalog on its own; the catalog file is only shipped).

Fits in five steps.

## Steps
- [x] Declare `#[cfg(test)] mod docs_tests;` in `audit.rs` and write the failing tests in
      `audit/docs_tests.rs`. They build an `Entry` with caller and mechanism, take the field names from
      `Entry::fields()`, the id from `MESSAGE_ID`, and read `docs/audit.md` and `data/custodio.catalog`
      through `CARGO_MANIFEST_DIR`. Variants are enumerated by helpers with an exhaustive `match` (no
      wildcard) that returns the full list, so a new `Outcome` or `AuditMechanism` variant stops the
      test from compiling until it is listed and documented.
- [x] Write `data/custodio.catalog`.
- [x] Write `docs/audit.md` with all sections above.
- [x] Add the catalog asset to `crates/custodiod/Cargo.toml`; if `scripts/check-files.sh`, typos or
      `just lint` complain, fix the files, not the gates.
- [x] Run `just check`, `just package` and the feature's `verify` command; record in PROGRESS.md.

## Evidence
Matching rule for all names below: a name counts as present only as a delimited token, i.e. in
backticks (`` `NAME` ``) in the docs and the catalog; a bare substring does not count (so `MESSAGE` is
not satisfied by `MESSAGE_ID`).

- `MESSAGE_ID` documented → `docs_tests::message_id_in_docs_and_catalog` → the constant's value occurs in
  `docs/audit.md` and in the catalog; fails if the constant changes or either file lacks it.
- Every field name documented, none missed → `docs_tests::every_field_name_in_docs_and_catalog`: names come
  from `fields()` of a full entry, all of them (`MESSAGE`, `MESSAGE_ID`, `PRIORITY`, `SYSLOG_IDENTIFIER`
  and every `CUSTODIO_*`); each must appear as a token in both `docs/audit.md` and the catalog.
- Absent fields → `docs_tests::optional_fields_flagged`: names missing from `fields()` of an
  `Entry::without_caller(.., None)` (`CUSTODIO_UID`, `CUSTODIO_PID`, `CUSTODIO_MECHANISM`) must be on a
  docs line that also contains the word "absent" or "omitted"; the test computes the set by diffing the two
  entries, so it follows the code.
- Outcome values and priorities → `docs_tests::outcomes_and_priorities_documented` → for each `Outcome`
  (exhaustive helper), a docs table row has `name()` and `priority()` as separate cells
  (`| `signed` | 6 |`); fails on a wrong or missing row.
- Mechanism values → `docs_tests::mechanisms_documented` → every `AuditMechanism::name()` (exhaustive helper) as a token.
- Message text shape and field meaning → `docs_tests::message_example_in_docs`: the `Entry::message()` of an
  example entry per outcome appears verbatim in the docs; each field's table row has a non-empty meaning cell.
- Compatibility rule → `docs_tests::limits_and_compatibility_documented`: docs have a heading for "Not
  guaranteed" mentioning person identity, pid reuse, rate limiting, volatile storage and imitation, and a
  line stating that names, identifier and priorities are only added to, never changed.
- Catalog format → `docs_tests::catalog_format` → the first non-comment line is exactly `-- <MESSAGE_ID>` (no language tag: it is the default entry, and a tagged-only entry crashes `--list-catalog`), followed by one `Subject:` line and a
  `Defined-By: custodio` line; id is 32 lowercase hex. Plus, when `journalctl` is available, run by hand:
  `journalctl --root=<tmp> --update-catalog` with the file under `<tmp>/usr/lib/systemd/catalog/`, then
  `journalctl --root=<tmp> --list-catalog` must show the id. If it cannot run in the dev container,
  PROGRESS.md says so explicitly; the evaluator reviews that note.
- The documented query matches only `custodio.service` → `docs_tests::query_uses_trusted_fields`: one docs
  line starting with `journalctl` contains `_SYSTEMD_UNIT=custodio.service`, `_UID=` and
  `MESSAGE_ID=<constant's value>`; the docs say `_UID` is that of the `custodio` system user from
  `data/sysusers.d/custodio.conf` (found with `id -u custodio`). Example queries by uid, key and outcome are
  `journalctl` lines containing `CUSTODIO_UID=`, `CUSTODIO_KEY_ID=` and `CUSTODIO_OUTCOME=`, each also with
  the trusted unit match. The evaluator checks the query does not rely on user-set fields alone.
- Catalog ships in the .deb → `just package && dpkg-deb -c target/debian/*.deb | grep 'usr/lib/systemd/catalog/custodio.catalog'`
  → one line, mode `-rw-r--r--`.
- Drift is caught → by hand: (a) rename one `CUSTODIO_*` literal in `Entry::fields()`, (b) delete a row from
  the docs, (c) delete a field name from the catalog; each makes `cargo test -p custodiod --lib docs_tests`
  fail; revert each.
- Whole feature → `just check && test -s docs/audit.md && grep -q MESSAGE_ID docs/audit.md && grep -q _SYSTEMD_UNIT docs/audit.md && just package && dpkg-deb -c target/debian/*.deb | grep -q 'systemd/catalog/'` → exit 0.
