# F26 — Audit documentation for administrators and the journal catalog entry

## Scope
Documentation and packaging only; no change to the audit behaviour of F24/F25.

- `docs/audit.md`: the administrators' reference for the entries `custodiod` writes, written as a stable
  interface: `MESSAGE_ID`; every field (`MESSAGE`, `MESSAGE_ID`, `PRIORITY`, `SYSLOG_IDENTIFIER`,
  `CUSTODIO_UID`, `CUSTODIO_PID`, `CUSTODIO_KEY_ID`, `CUSTODIO_OUTCOME`, `CUSTODIO_MECHANISM`) with its meaning and
  when it is absent; the four outcome values with their priorities; the message text shape; a `journalctl`
  query matching only entries of `custodio.service` using trusted fields (`_SYSTEMD_UNIT=custodio.service`
  and `_UID=` of the service user, plus `MESSAGE_ID=`); example queries by uid, key and outcome; and a
  "not guaranteed" section: identity of a person (uid and pid are of the calling process only), pid reuse,
  rate limiting, volatile storage, imitation by other processes (user fields are forgeable; only `_`-fields count).
  It states the compatibility rule: names, identifier and priorities are not changed, only added to.
- `data/custodio.catalog`: a journal catalog file for `MESSAGE_ID`, shipped by the .deb as
  `usr/lib/systemd/catalog/custodio.catalog` (new asset in `[package.metadata.deb]`).
- A unit test (own file, `crates/custodiod/src/audit/docs_tests.rs`, not inline) that ties code, docs and catalog together.
- Left out: the e2e journal checks and the manual steps (other features); running `journalctl --update-catalog`
  in `postinst` (systemd rebuilds the catalog on its own; the catalog file is only shipped).

Fits in five steps.

## Steps
- [ ] Write the failing test `audit::docs_tests`: it builds an `Entry` with caller and mechanism, takes the
      field names from `Entry::fields()`, the id from `MESSAGE_ID`, the outcomes from every `Outcome`
      variant (`name()`, `priority()`) and every `AuditMechanism` name, and reads `docs/audit.md` and
      `data/custodio.catalog` through `CARGO_MANIFEST_DIR`.
- [ ] Write `data/custodio.catalog` (header `-- <MESSAGE_ID> <language>`, `Subject:`, `Defined-By:`, body
      explaining the entry and its fields).
- [ ] Write `docs/audit.md` with all sections above.
- [ ] Add the catalog asset to `crates/custodiod/Cargo.toml` and, if `scripts/check-files.sh`, typos or
      `just lint` complain, fix the files, not the gates; add the test module to `audit.rs`.
- [ ] Run `just check`, `just package` and the feature's `verify` command; record in PROGRESS.md.

## Evidence
- `MESSAGE_ID` documented, as a stable interface → `docs_tests::message_id_in_docs_and_catalog` → the constant's
  value occurs in `docs/audit.md` and in the catalog; fails if the constant changes or either file lacks it.
- Every field name documented, none missed → `docs_tests::every_field_name_in_docs_and_catalog`: names come from
  `fields()` of a full entry (so a new field added in code fails the test until documented); each must appear
  in `docs/audit.md`; those that the catalog describes (all `CUSTODIO_*`) must appear in the catalog.
- Outcome values and priorities → `docs_tests::outcomes_and_priorities_documented` → for each `Outcome`, `name()`
  appears in the docs and the line of its table row holds its `priority()` number; fails if a row is wrong or missing.
- Mechanism values → same test file, `mechanisms_documented` → every `AuditMechanism::name()` appears in the docs.
- Catalog is well formed → `docs_tests::catalog_format` → first non-comment line is `-- <MESSAGE_ID> en`
  (or similar), has `Subject:` and `Defined-By: custodio`, and the id is 32 lowercase hex characters;
  if `journalctl --root=<tmp> --update-catalog` is usable in the dev container, run it by hand once and
  note the result in PROGRESS.md (the catalog must be accepted by systemd).
- The documented query matches only `custodio.service` → `docs_tests::query_uses_trusted_fields` → docs contain
  `_SYSTEMD_UNIT=custodio.service`, `_UID=` and `MESSAGE_ID=`; and the example queries by uid, key and outcome
  use `CUSTODIO_UID=`, `CUSTODIO_KEY_ID=` and `CUSTODIO_OUTCOME=`. Review by the evaluator that the query
  does not rely on `SYSLOG_IDENTIFIER` or other user-set fields alone.
- "Not guaranteed" items → `docs_tests::limits_documented` → the docs have a heading for it and mention
  person identity, pid reuse, rate limiting, volatile storage and imitation (case-insensitive keywords).
- Catalog ships in the .deb → `just package && dpkg-deb -c target/debian/*.deb | grep 'usr/lib/systemd/catalog/custodio.catalog'`
  → one line, mode `-rw-r--r--`; and the verify command's `grep -q 'systemd/catalog/'` succeeds.
- Test fails when code and docs drift → mutation check by hand: rename one `CUSTODIO_*` literal in
  `Entry::fields()` (or delete a row from the docs) and see `cargo test -p custodiod --lib docs_tests` fail; revert.
- Whole feature → `just check && test -s docs/audit.md && grep -q MESSAGE_ID docs/audit.md && grep -q _SYSTEMD_UNIT docs/audit.md && just package && dpkg-deb -c target/debian/*.deb | grep -q 'systemd/catalog/'` → exit 0.
