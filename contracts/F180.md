# F180 — The encrypted state directory: classification, API and the CLI warning

## Scope
Builds Design 7 of SPEC.md, in this order of dependence:
1. **Finding.** `docs/findings/F180.md` (index line in `docs/findings.md`, in the form its rules fix, written
   before the code) settles, each **verified** by a command run in the dev container or by a source read, with
   versions: (a) how the service finds the block-device chain under its state directory with the access the
   unit already has (`PrivateDevices=`, `ProtectSystem=strict`, DynamicUser `StateDirectory=`) and no external
   tool: the mount table, `/sys/dev/block`, `slaves/`, `dm/uuid`; whether each of these is readable under the
   unit's sandbox (checked against `systemd-analyze`-visible settings or the unit file, and where a path is
   not readable the verdict is *unknown*, with the reason); (b) how dm-crypt is recognised (dm uuid prefix
   `CRYPT-`); (c) one verdict per case: plain partition, LUKS, LVM on LUKS, LUKS on LVM, dm-integrity under or
   over crypt, RAID (md) with and without crypt, btrfs over several devices, ZFS, fscrypt, NFS/CIFS/FUSE,
   overlay, tmpfs, bind mounts and a state directory reached by symlink. Default from SPEC: anything not
   proven dm-crypt is *unknown*; *not encrypted* only for a chain fully read that ends at physical devices
   with no dm-crypt in it. This closes the SPEC open question "Classifying the state directory".
   If a case cannot be shown by a command here (ZFS, fscrypt), the finding says so as **inferred** and the
   verdict stays *unknown*.
2. **Classifier** in custodiod, pure over a root path (so a fixture tree stands in for `/sys` and the mount
   table), returning encrypted / not encrypted / unknown. Never unknown-as-encrypted; every read error, loop,
   missing file or unexpected shape is *unknown*.
3. **Start-up journal entry** with the result (field named and documented in `docs/audit.md` under its
   compatibility rule).
4. **Bus API addition**, read-only, bus only (a property or a method; the builder chooses and documents it in
   `docs/api.md`, with the Compatibility rule). It is not served on the socket: F177's socket surface (exactly
   `ListKeys` and `Sign`, no properties) still holds. It asks no polkit and changes nothing.
   `just api-contract` and `scripts/test-docs-api.sh` check it against `docs/api.md`.
5. **CLI**: `custodio import` and `custodio list` read the value over the bus and print the warning (whoever
   takes the machine can use the keys, though not copy a `tpm` key; points to the README) for *not encrypted*
   and *unknown*; nothing for *encrypted*. Never blocks, never changes stdout of the data nor the exit status.
   If the service predates the addition (call fails / unknown name), no warning and no error. The README gains
   the full-disk-encryption section the warning points to, and the man page mentions the warning.

Not here: the real polkit/systemd sandbox and a real LUKS device (acceptance 14 on the real service is the
checkpoint's e2e/VM; the classifier here is proven on fixtures). The man page and README prose are not tested
by their wording, only that the CLI's pointer names a README anchor that exists is not checked either; the
warning's text is tested as CLI output.

Environment: reading `/sys/dev/block` and `/proc/self/mountinfo` works in the dev container (it has `dm-0`,
`dm-1` in `/sys/block`); the step 1 finding runs the smallest commands to show what is readable. No new tool.

Cost of the new tests:
- `crates/custodiod/tests/state_storage.rs`: one temp fixture tree per case (about 20 cases, one per case of
  the finding, plus unreadable/looping chain negative controls); pure filesystem, under 1 s total, parallel.
- `crates/custodiod/tests/storage_api.rs`: in-process service on a private `dbus-daemon` with the scripted
  polkit as in `api_kind.rs` (about 50 ms a case, about 5 cases, under 3 s), parallel; includes the socket
  not serving it.
- `crates/custodio-cli/tests/storage_warning.rs`: fake service client as in `storage_kind.rs`; milliseconds,
  about 8 cases, parallel.
- `api_contract` and `test-docs-api.sh` additions: tens of ms; within the `script *` 120 s budget.
- `just mutants-diff F180`: the diff is the classifier and the warning; estimated 5 to 10 minutes, one
  command.
- No e2e case, no script test of its own.
Fits in six steps; no split.

## Evidence
- Finding settles the open question, each case verified or marked inferred → `grep -qF '(findings/F180.md)' docs/findings.md` and `just quick` (file-size check) → pass.
- Chain found without external tool, per case: plain partition → *not encrypted*; LUKS (dm uuid `CRYPT-`) → *encrypted* → `state_storage` cases `plain_partition_is_not_encrypted`, `luks_is_encrypted` → pass.
- LVM on LUKS → *encrypted*; LUKS on LVM → *encrypted*; LVM without crypt → *not encrypted* → `state_storage` named cases → pass.
- dm-integrity, RAID (with and without crypt beneath/above), btrfs over several devices, ZFS, fscrypt, NFS/CIFS/FUSE, overlay, tmpfs → *unknown* (or the finding's verdict) → one `state_storage` case each → pass.
- Never unknown as encrypted: unreadable `dm/uuid`, missing `slaves`, a cyclic slaves graph, a mount entry that does not match, a `CRYPT-` uuid on a device not in the chain, a fixture that reads as encrypted when one link is made unreadable (negative control: flipping a link to unreadable must change *encrypted* to *unknown*) → `state_storage` cases `unreadable_link_is_unknown`, `cycle_is_unknown`, `crypt_off_chain_is_ignored` → pass.
- State directory resolved through a symlink and a bind mount to the right mount entry (longest prefix, mount escapes) → `state_storage` cases → pass.
- Result journalled at start → `storage_api.rs` (or the start-up test it names) reads the captured journal field after start for each of the three results → field present with the value.
- Bus API addition returns the result, read-only, no polkit call, no state change; the three values round-trip → `storage_api` cases → pass; not available on a socket peer (UnknownMethod/property absent; socket introspection still exactly `ListKeys`, `Sign`) → `storage_api` case plus `just api-contract` → pass.
- Documented and checked → `just api-contract && scripts/test-docs-api.sh` → pass; negative control: the `api_contract` fixture with the doc entry removed or its signature changed fails.
- Warning printed for *not encrypted* and *unknown*, not for *encrypted*; names the README; exit status and the data output identical with and without it; old service without the addition → no warning, no error → `storage_warning.rs` cases for both commands → pass.
- Man page mentions the warning (acceptance 14) → `cargo test -p custodio-cli --test man` already renders the page; the builder adds a check there against the page's rendered output only if it already tests content, otherwise it is covered by `just quick` doc checks → pass.
- Tests catch wrong code → `just mutants-diff F180` → no surviving mutant outside the allow-listed ones.
