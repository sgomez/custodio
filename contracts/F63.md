# F63 — Run a chosen subset of end-to-end cases on one target

## Scope
Built: `just e2e-cases <target> <case-or-glob>...`, which builds the packages exactly as `just e2e` does (same
dependencies, no copy of the build steps that can drift), boots that one target and runs the shared setup (install,
service, users, key import) plus only the selected cases. Parts:
- Selection on the host (`e2e/run.sh`): each argument is a case id or a shell glob matched against the whole id. The
  universe is what the target owes: `e2e/cases.list` plus the target's own `cases.list` (for a `refusal-only` target,
  only its own). The selected set is the union of the matches. An argument that matches no case, a missing argument
  list, or a target that is not one single directory of `e2e/targets/` (`all` included) is refused with the offending
  name in the message, before any engine call (no `build`, `run`, `exec`). Refusal before the packages are built is
  preferred (it saves minutes); before any container starts is the requirement.
- Selection in the guest: the host tells the guest which cases are selected. A case that is not selected is not run
  and not reported at all (not even as skipped). Work that only unselected cases need is not done (the extra guest
  runs on a fresh container for the old-package and old-path upgrades happen only when a selected case belongs to
  them; the polkit-unavailable and lifecycle steps likewise). Work that a selected case needs (a prior signature
  count, an installed N+1 state) is still done, unreported. A selected case must pass in the combinations the
  evidence and the `verify` lines of the later features run (alone, or with the others named there).
- Accounting (`e2e/check-cases.sh`): `check` gets the selected ids; each must be reported exactly once (run, or
  skipped and on the skip list), and any other reported id fails as before (unknown, twice) or as "not selected". A
  selected case a target skips still needs its skip-list entry.
- `just e2e` with no subset: unchanged behaviour, argument list, calls and accounting (all existing
  `scripts/test-e2e-*.sh` stay green without weakening).
Not built: running more than one target, a list/dry-run command, any new case. Cases that other features add are
selected by their own `verify` lines (F71, F72–F74, F91–F97 use this recipe); their content is not proven here.
The feature is about five steps; no split needed.

Environment (`docs/findings.md` records earlier real `just e2e all` passes, possibly on the host rather than this dev container): the dev container has podman, and a privileged container runs
(`podman run --rm --privileged --cgroupns=host alpine echo ok` → `ok`, exit 0). Booting a target image with systemd
and building it need network and were not tried in this session; the real run in `verify` is the proof for those, and
it is the builder's to run (if the image cannot be built or systemd cannot boot here, that is a `BLOCKED.md`
question, not a contract change).

## Steps
- [ ] Failing stub tests first, in `scripts/test-e2e-*.sh` (extend the stub engine in `scripts/lib/e2e-host-fixtures.sh`
      so a fake guest reports only the selected cases it is given), for every item under Evidence.
- [ ] Selection on the host: parse and validate names/globs against the target's universe; refuse unknown names, empty
      list and non-single targets before any engine call; pass the selection to the guest and the accounting.
- [ ] Accounting of a subset in `check-cases.sh` (with its tests in `scripts/test-e2e-skips.sh` or the host test).
- [ ] Guest side: honour the selection (unselected cases not run, not reported; unselected phases and extra upgrade
      runs not done; prerequisites still done silently), with a container-free test of the selection helper.
- [ ] The `e2e-cases` recipe in `justfile` sharing the package-building dependencies with `e2e`; comment on the recipe;
      the recipe is in the `just --list`. Run `verify` (real run on debian13) and fix until it passes.

## Evidence
- New recipe builds like `just e2e`, takes target then names → `scripts/test-e2e-host.sh`: the justfile has an
  `e2e-cases` recipe with the same package-building dependencies as `e2e` (compared by the test, not by name only) and
  passes target and names to `e2e/run.sh`, including a glob passed through `just` itself
  (`'nss-*'`) with a file matching it (`nss-x`) in the working directory, so a recipe that lets the shell expand the glob fails; `just e2e-cases debian13 x` with the stub engine calls `exec ... guest.sh`
  with the selection → expected: present.
- Boots one target, runs shared setup plus only the selected cases → stub-engine test: `e2e-cases`-style run
  `debian13 pkcs11-tool-approve-rsa 'nss-*'` → the log has one `build`, one `run`, the guest exec carries exactly
  `pkcs11-tool-approve-rsa nss-approve nss-deny nss-asks-again`; no old/oldpath second container (`run` count 1).
  Negative control: a stub that reports one case beyond the selection fails the run (below).
- Names and globs, both → the same test with an exact name only, a glob only, a glob that overlaps an exact name (the
  union has no duplicates), and a glob matching a target-own case (`upgrade-cargo-deb-*` on debian13 starts the old
  run container; on ubuntu2604 it is refused as matching nothing) → expected selections as stated.
- Accounting requires each selected case exactly once, no other → `scripts/test-e2e-host.sh` with the stub:
  `STUB_OMIT=<selected>` fails naming "not reported"; `STUB_DUP=<selected>` fails "reported twice"; `STUB_EXTRA=<an
  existing but unselected id>` fails (reported though not selected); `STUB_SKIP=<selected>` fails unless on the skip
  list and passes when listed; the same checks directly on `check-cases.sh check` with a selected-set argument in
  `scripts/test-e2e-skips.sh`. The accounting passes when exactly the selected cases are reported.
- Unknown name or glob fails before any container → host test: `no-such-case`, `'no-such-*'`, one good plus one bad name
  (whole run refused, nothing started), an empty list, `all` and an unknown target → exit non-zero, the bad name is in
  the message, the stub log has no `build`/`run`/`exec` line. Also a case of another target's own list (a debian13-only
  id asked of `alma10`) is refused.
- Stub tests cover selection, subset accounting and refusal, and run in `just test-scripts` → `just test-scripts` →
  green, and the new tests are listed in the `test-scripts` recipe (a test file not listed would not run).
- `just e2e` with no subset behaves as before → all existing `scripts/test-e2e-*.sh` pass unchanged (no edit that
  weakens an assertion; edits only add) and a stub run of `run.sh all` still reports and accounts for every case; the
  full list of engine calls of a no-subset run equals a list written into the host test (not a comparison with a run
  of the old code).
- Guest honours the selection, container-free → a test of the guest-side helper: for ids selected/unselected it
  reports only selected ones, and a selected case is reported by exactly the code path of its normal run (the
  unselected `case_run` prints nothing). Negative control: a helper that selects everything makes the test fail.
- Guest skips the work of unselected cases → container-free test of the guest's phase decision (a function or
  script that, given a selection, says which phases run: user cases, polkit-unavailable, journal check, upgrade,
  lifecycle, old/oldpath upgrade, refusal): e.g. selection `nss-*` runs none of unavailable/journal/upgrade/lifecycle;
  `journal-*` runs journal-check and the prerequisites it needs (signatures, polkit-unavailable) unreported;
  `upgrade-*` runs upgrade and the upgrade-cargo-deb/oldpath runs only for ids selected. Negative control: a decision
  that runs every phase fails the test. After `verify`, `target/e2e/debian13.log` has no line that only an unselected
  phase prints (e.g. `upgrade`/`purge` lines, `E2E-CASE run upgrade-`).
- Refusal-only target → host test: asking ubuntu2404 for a shared id (`nss-approve`) is refused as matching nothing;
  asking for its own id runs `refusal.sh` path with the selection (covered by the phase-decision test if `refusal.sh`
  reports through the same helper).
- Real behaviour in a container → `verify`: `just e2e-cases debian13 pkcs11-tool-approve-rsa 'nss-*'` exits 0 with
  `check-cases: 4 cases accounted for`; `! just e2e-cases debian13 no-such-case` exits non-zero and its message names `no-such-case`
  (a failure of another kind, such as a broken build, does not count; the no-container property is proven by the
  stub test).
