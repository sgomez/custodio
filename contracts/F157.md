# F157 — The harness's own credential reader

## Scope
Built:
- `e2e/vm/credread.py` (Python 3, stdlib only, run with `python3 -I`): reads one stored `systemd-creds` credential file and prints
  its key identifier by name (`host`, `host-scoped`, `tpm2`, `tpm2-with-public-key`, `host+tpm2`, `host+tpm2-scoped`,
  `host+tpm2-with-public-key`, `host+tpm2-with-public-key-scoped`, `null`, or `unknown <hex>`) and, for a TPM id, the PCR mask.
  It is written from the header table and identifier table in `docs/findings/F153.md`, imports nothing from `crates/` and
  copies no id or offset from it. The credential file is the base64 text that `systemd-creds encrypt` writes or the raw
  binary (the reader accepts both; F153 notes the CLI writes base64). Reading is as root in the harness; the reader itself
  needs only read access to the file.
- `--expect-tpm-bound` with `--systemd-version N` (257 or 259; the ids and offsets of F153 are the same in both, the version
  is kept so that a later version can differ and an unsupported one is refused naming it): exit 0 only for the user-scoped
  `host+tpm2` id `ef4ac136...` with PCR mask 0. Every other outcome exits non-zero with one line on stderr naming the reason:
  host-only (`host`, `host-scoped`), TPM-only without host (`tpm2`), null key, nonzero mask (the mask is printed), unknown id,
  malformed header (too short for a field it needs, a size that runs past the file, `iv_size` that does not fit, base64 that
  does not decode). The mask is read only after the id says TPM; a host or null credential prints no mask.
- A fixture maker `e2e/vm/mkcreds.sh DIR` that makes the credentials with the real `systemd-creds` against the TPM named by
  `TPM2TOOLS_TCTI`/`--tpm2-device` (the dev container's `swtpm` via `scripts/with-swtpm.sh` + `unshare -m --map-root-user`
  with a tmpfs on `/var/lib/systemd`, as F110 and F153; in the F151 guest later as plain root). F153 decided fixtures
  are live `systemd-creds` output, no committed byte strings; this script is that decision. It makes: user-scoped host+TPM
  (`--uid=1000 --with-key=host+tpm2`, mask forced to 0 with an empty `--tpm2-pcrs=` because 257 defaults to `0x80`; 259
  defaults to 0), the same user-scoped host+TPM bound to PCR 7 (`--uid=1000 --with-key=host+tpm2 --tpm2-pcrs=7`, so that only the
  mask differs from the accepted one; checked: id `ef4ac136...`, mask `0x80`), host-only (unscoped, `--with-key=host`), user-scoped
  host-only (`--uid=1000 --with-key=host`, id `55b9ed1d...`), null (`--with-key=null`), plus TPM-only and unscoped host+tpm2
  for the "not user-scoped" rows.
- `scripts/test-vm-credread.sh`, added to `just test-scripts` (and to `shell_scripts` if that list is by glob, nothing to add).
  It runs the maker, then the reader, then the controls below. Not built: any VM, guest, e2e case, or use of the reader by a
  case (F158 and later); `tpm2-with-public-key` and scoped-pk ids are covered by name only through synthetic ids in the control
  below, since F153 made them but a credential needing a PCR signature is not made here.

Environment (checked this session): in the dev container `scripts/with-swtpm.sh unshare -m --map-root-user bash -c 'mount -t tmpfs t /var/lib/systemd && systemd-creds --tpm2-device=swtpm:path=... --with-key=host+tpm2 encrypt --name=n - out'`
runs as user `dev`, 0.14 s, makes a 523-byte credential (systemd-creds **257.13**, `swtpm` 0.7.1). So the self-test proves
version 257 on real credentials; the 259.9 header layout is F153's verified read-back from the guest, and the reader's 259
path is the same code. The test does not boot the guest. If `swtpm`, `tpm2-tools` or `unshare` are missing the script
fails naming the tool (like `test-with-swtpm.sh`), it does not skip.

Cost: one `swtpm` session making ~6 credentials plus ~20 reader runs of a small Python script: estimated 2–4 s total. It is a
script test, runs in parallel with the others in `just test-scripts` under the `script *` budget (120 s); no new
budget needed. No e2e case, no container engine, no `sleep`. Every step fits one session; no split.

## Evidence
- Reads a stored credential's key id by name and PCR mask → `scripts/test-vm-credread.sh` "told apart", one name and one mask per fixture: user-scoped host+TPM → `host+tpm2-scoped`, mask 0; same bound to PCR 7 → `host+tpm2-scoped`, `0x80`; host-only → `host`, none; user-scoped host-only → `host-scoped`, none; null → `null`, none; TPM-only → `tpm2`; unscoped host+tpm2 → `host+tpm2` → equal to those strings, and all distinct where the kind differs.
- Each credential is genuine → in the same test `systemd-creds decrypt` (same sandbox, `--uid=1000` for the scoped one) returns the plaintext for the kinds that decrypt, so the fixtures are not malformed look-alikes → rc 0, plaintext equal.
- `--expect-tpm-bound` exits 0 only for user-scoped host+TPM with mask 0 → test: exit 0 for that credential; non-zero for each of the others.
- Given systemd version → test: the accepted credential exits 0 with `--systemd-version 257` and `259`; `258` exits non-zero and stderr names it; `--expect-tpm-bound` without `--systemd-version` is refused.
- Fails naming the reason for host-only, the null key, a nonzero mask, an unknown id, a malformed header → test: stderr of each contains its distinct reason word (`host-only` for both host kinds, `null`, `mask 0x80` for the PCR 7 credential whose id is the accepted one, `unknown`, `malformed`), and the five reasons differ from one another (a reader that fails with one generic message fails here).
- Unknown identifier → a real credential with its first 16 bytes replaced by a fixed value in no row of F153's table (rest untouched) → exit non-zero, `unknown`, not a crash.
- Truncated controls → each control decodes the real credential, cuts or patches the binary and passes the reader raw bytes (so it tests header bounds, not base64); the scoped credential cut to 0, 10, 31, 47, 60 and 350 bytes (inside id, sizes, iv, TPM section) → non-zero, `malformed`, no Python traceback, for every length.
- Corrupted controls → `iv_size` set to 0xffffffff; the blob size field set past the end; and, as its own control, non-base64 text → non-zero, `malformed`, no traceback.
- Mask is read only after the id says TPM, and at the offset from the table → test: the host credential reports no mask (reading byte 48 would show ciphertext, F153 negative control); the PCR 7 credential reports `0x80` from byte 48 and the scoped one is found by offset past the TPM section, not at 48 (an implementation that reads the mask at 44 or 56, or the scoped flags at 56, fails on the real files).
- Negative control that the test can fail → the test run once against a reader variant that treats the mask as ignorable (sed-patched copy in a temp dir) must make the PCR 7 (accepted id, mask `0x80`) case fail; the script first asserts the patched copy differs from the original, then asserts that failure. The decrypt check passes `--tpm2-device` to `decrypt` too.
- Shares no code with the service, built from F153 not `crates/` → the reader imports only the Python standard library, checked by the test running the reader with `python3 -I` from a new empty directory (no repository module on the path).
- `just test-scripts` includes it → the recipe's list contains `scripts/test-vm-credread.sh`; running `just quick` stays green (shellcheck covers the new `.sh` files).
