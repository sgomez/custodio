# F110 — Research: how the service uses systemd-creds without root

## Scope
Built: a section `## F110` in `docs/findings.md` that settles the SPEC open question "How the
service uses `systemd-creds` without root". Every claim is backed by a command and its output, run
in the target's own e2e container (`e2e/targets/<t>/Containerfile`, started as `e2e/run.sh` does,
rootless podman with `vfs` in the dev container, as F108 and F109 did), and marked verified or
*inferred* as the rest of the file does. Targets: debian13, ubuntu2404, ubuntu2604, fedora44,
alma10, arch. The unit is the shipped `data/custodio.service` text with the F109 decision's
directives, with only `ExecStart=` swapped for a probe script, started as a real unit by the
container's systemd; the probe runs as the unit's real uid (the finding states whether that is the
static `custodio` user or the `DynamicUser=yes` one) and sandbox. A probe run as root or from
`podman exec` is not evidence for a "from the service" claim. If a unit does not start in the
nested container, the error is recorded in the finding and the claim stays *inferred*. No file
in `data/`, no recipe, Containerfile or Rust code and not `SPEC.md` is changed by this feature.

Per target the finding reports:
- **Version.** `systemd-creds --version` / `systemd --version`, and whether `--user` and the
  Varlink interface `io.systemd.Credentials` exist in that version (the SPEC says v256 for both
  and that sources disagree on v257 or v258 for completeness; the finding settles it by what ran).
- **Scopes and calls from the service's uid.** For `systemd-creds --user` and for a direct Varlink
  call to `io.systemd.Credentials` (socket path found on the target, e.g. with `varlinkctl`),
  each of encrypt and decrypt: works or not, the exit status, the message. Which scope and call
  the service should use (a `--system`/root-only call that fails for a non-root uid is recorded as
  such). Whether the scope binds to uid, user name and machine-id, shown by decrypting under
  another uid and failing.
- **Key used.** With no TPM and with `swtpm`: which key `--with-key=` values work from the
  service's uid (`tpm2`, `host`, `host+tpm2`, `auto`, or the user-scope equivalents), and for the
  TPM case whether "TPM-bound" then means TPM alone or host plus TPM: shown by decrypting the
  same credential after the host key (`/var/lib/systemd/credential.secret`) or the user-scope
  secret is replaced, and after the TPM state is replaced. Whether the host key is readable by the
  service (it should not be) and what the service then gets.
- **No PCR, explicitly.** The exact argument that binds to no PCR whatever the version's default
  (`--tpm2-pcrs=` with an empty value, or what the version accepts), and proof from the
  credential's header or `systemd-creds` output that the stored policy has an empty PCR mask,
  compared with the version's default (run without the argument and show the default mask). If a
  version cannot bind to no PCR, that target gets a `Deviation:` line.
- **Plaintext without a temporary file.** How the plaintext reaches the encrypt call and how it
  leaves the decrypt call (stdin/stdout with `-`, or Varlink parameters), shown by an
  `strace -f -e trace=openat,creat` (or equivalent) of the call that lists no file written with
  plaintext, and by a plaintext marker not being found under `/tmp`, `/var/tmp` and the state
  directory. States whether the plaintext passes through argv (it must not) and which process
  environment/`/proc` exposures exist.
- **Errors.** The exit status and message (or Varlink error name) for: the credential service not
  reachable (socket missing or `systemd-creds` cannot start), no TPM or TPM unusable, a credential
  that cannot be decrypted (TPM state cleared, host/user secret changed, corrupted file, another
  uid), each mapped to "credential service unavailable" or "cannot decrypt" so the code can
  tell them apart; any pair that cannot be told apart is reported as such, and the conservative
  mapping is chosen.

**Dev container (no systemd as PID 1).** The finding says how integration tests there exercise the
real `systemd-creds` (not a mock): which of `--user`/Varlink/an explicit secret path or
`CREDENTIALS_DIRECTORY`/`$SYSTEMD_CREDENTIAL_SECRET`-style override works without PID 1 and
without root, and how `swtpm` (F108 route 2, unix socket) is reached for the TPM-bound case, with
the commands and output run in the dev container (systemd 257) as uid 1000. If the real binary
cannot do it there, the finding says which cases then belong to `just e2e-cases` and says so
plainly; no test is replaced by a fake of `systemd-creds`.

Ends with one line per target `Decision: <target>: ...` naming scope, call, key option, the
no-PCR argument and the two error mappings; a target that cannot do it gets `Deviation: <target>`
and, in that case, a pending `## F110` entry in `SPEC_DEVIATIONS.md` (format at the top of that
file; created with that header if absent) citing the finding. Never a plaintext key. If a
deviation touches the security rules of CLAUDE.md it is not recorded as one and the builder
writes `BLOCKED.md` instead.

The words listed in `verify` appear (`systemd-creds`, `io.systemd.Credentials`, `--user`, `PCR`,
`host`, `tpm2`, the six target names).

Left to other features: the storage feature that uses the decision (F120's encrypted key
storage), the unit/packaging changes, polkit, and the real-hardware run (F147). Package gates,
`just e2e` and lifecycle tests run at the checkpoints and are not run here.

## Evidence
- Systemd version and availability of `--user` and `io.systemd.Credentials` per target →
  `systemd-creds --version` and a `varlinkctl introspect`/`list-methods` (or the error) per target
  → one block per target, six blocks.
- Whether `--user` or Varlink encrypts and decrypts from the service's uid, which scope and call
  → probe unit's journal output per target: round-trip of a marker, exit status 0 and equal
  bytes; plus the same call with a different uid failing (negative control showing the binding)
  → output pasted; a unit that did not start has its error pasted and the claim marked *inferred*.
- TPM binding available that way, and TPM alone or host plus TPM → with `swtpm` in reach: encrypt
  `--with-key=tpm2` (and `host+tpm2`/`auto`) from the service's uid; decrypt after replacing the
  host/user secret and after replacing the TPM state, each expected result stated and shown
  → table per target of key option × change → decrypt ok/fail.
- Bind to no PCR whatever the default → the explicit argument versus the run without it, with the
  stored PCR mask read back from the credential (or the tool's output) → default mask non-empty
  or empty as the version has it, explicit run empty, per target; a negative control is the run
  without the argument on a version whose default is non-empty (if none, the finding says so).
- Plaintext without a temporary file → `strace` list of files opened for write by the call and a
  search for the marker under `/tmp`, `/var/tmp` and the state dir, and argv of the call
  → no match; per target (reference target in full, others by the same script).
- Errors for "credential service unavailable" and "cannot decrypt" → forced cases (socket
  missing, no TPM, cleared TPM state, changed secret, corrupted file, other uid), status and
  message/Varlink error each → table per target with the mapping; the two classes differ or the
  finding names the pair that does not.
- Dev container integration tests exercise the real `systemd-creds` against `swtpm` → the commands
  of the dev container step run as uid 1000 → a round trip with the real binary and `swtpm`
  succeeds there, or the finding says exactly which cases move to `just e2e-cases`.
- Decision lines and deviation rule → `verify` command of F110 in features.json → exit 0; one
  `Decision: <target>:` line per target (`grep -c '^Decision: ' ` in the section prints 6), and
  `Deviation: <target>` lines present only together with `## F110` in `SPEC_DEVIATIONS.md`.
- Nothing else changed → `git diff --stat` of the feature's commits lists only `docs/findings.md`,
  `PROGRESS.md`, the contract, and `SPEC_DEVIATIONS.md` if a deviation exists; `just quick` green.
