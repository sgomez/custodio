# F126 — Integration suites under each storage kind

## Scope
One new integration target, `kinds_suite` in `custodiod` (`crates/custodiod/tests/kinds_suite.rs` plus a directory of
modules). It runs the lifecycle suites of the service (import, list, sign, delete, replace certificate) on the real
service on a private bus with fake polkit, once per storage kind:

- **TPM**: the `swtpm` fixture serves everything (`Kind::Tpm`).
- **Encrypted, TPM-bound**: an `swtpm` behind `TpmFilter` that lacks a capability a key type needs, as `docs/findings/F107.md`
  settled (way (b): RSA needs `TPM2_RSA_Decrypt`; P-256 needs ECDSA with SHA-256; the filter and `Lacks` are F107's). The
  lack is the one of the key type under test, so import chooses `Kind::EncryptedTpm` for the same reason it would on a real
  TPM; the credential double is the TPM-bound one.
- **Encrypted, host-bound**: no TPM (`NoTpm`), `Kind::EncryptedHost`.

Both key types (RSA-2048, P-256) in each, and **every mechanism** the service offers: `CKM_RSA_PKCS` with a
`DigestInfo` per supported hash and with an opaque caller payload, `CKM_RSA_PKCS_PSS` with each supported hash and salt
length, `CKM_ECDSA` with SHA-256, SHA-384 and SHA-512 digests. Every signature is verified with the key's certificate by
`openssl` (independent of the service); a signature that must differ (another key's certificate, a flipped byte) is
rejected by the same verifier.

Reuse, not copy: the rigs of `sign_kinds`, `storage_choice`, `tpm_sign` (`oracle.rs`, whose mechanism lists and verifier
are the single source of the mechanism list) and `api_bus` helpers, through `#[path]` as the other targets do. What
those targets already prove at their own level is not re-proven: the failure classes and error names (F118
`sign_kinds`), the journal fields (F120 `kind_audit`), the API shape and docs (F119 `api_kind`, `api-contract`), the
choice rules (F117 `storage_choice`), and mechanism parity inside the TPM crate (F107/F114 `tpm_sign`). F126 adds the
matrix they lack: all mechanisms (`sign_kinds` signs one per family) through the whole lifecycle under each kind.
Not here: the CLI and PKCS#11 front ends, real `systemd-creds` and real hardware, package, install and lifecycle tests,
`just e2e` (checkpoints F90/F100 and the e2e features). No mutants: the `verify` has none.

Environment check (run while writing this contract): `which swtpm openssl` and the existing
`cargo test -p custodiod --test sign_kinds --locked signs_each_kind` run in the dev container; the builder repeats it.
Size: about five steps, no split.

## Steps
- [ ] Skeleton, tests first: `kinds_suite.rs` with a table of the three kinds × both key types as `Cell`s (storage,
      subject, how the TPM is arranged, the expected `Kind`), a setup that imports through the bus and asserts the kind,
      and one failing test per area below so the target compiles and fails before the code that satisfies it.
- [ ] Import and list under each cell: import returns the key type and the kind of the cell; list shows the key with its
      kind and certificate; for the lacking cell, the TPM lacks exactly the capability F107 lists for that key type and the
      other key type's cell is not accidentally lacking.
- [ ] Sign, every mechanism under each cell: the mechanism table is taken from `tpm_sign/oracle.rs` (not retyped), each
      signature verified by `openssl` with the certificate; plus the negative controls (another certificate, a flipped byte).
- [ ] Delete and replace certificate under each cell: replace with the recertificate of the same key succeeds and the
      key still signs, verified with the new certificate; replace with another key's certificate fails with the
      documented mismatch name and changes nothing; delete removes the key (list empty, `NoSuchKey` at sign) and
      afterwards the same id imports again.
- [ ] `just quick`, then the evidence commands below.

## Evidence
- Three kinds × two key types, the fixtures named under Scope → `kinds_suite::matrix_covers_every_kind_and_key_type` →
  the cell table has six cells with distinct (kind, key type) pairs and each import returns that cell's kind; a cell
  imported under the wrong arrangement (host-bound under a TPM) fails the assertion (control: the same test with the
  arrangement swapped in a helper test, expecting the failure).
- Import returns the kind and key type → `kinds_suite::import_each_kind` → per cell the reply names the key type and the
  kind, and the store holds the matching protected form (blob xor credential).
- The lacking TPM is the one F107 settled → `kinds_suite::lacking_cell_lacks_the_capability_f107_lists` → with the
  filter, the TPM answers the lack for the RSA decrypt (RSA) or the ECDSA signing (P-256) and not for the other key type's
  capability; import of that cell is `EncryptedTpm`, not `Tpm`, and not `EncryptedHost`.
- List → `kinds_suite::list_each_kind` → one entry per imported key with its kind and certificate; after delete, none.
- Sign, both key types, every mechanism, each kind, verified by an independent implementation →
  `kinds_suite::sign_every_mechanism_verifies` → every (mechanism, hash, salt, payload) of the oracle's table signs on
  all six cells and `openssl` accepts it with the key's certificate; the count of signatures equals cells × table size
  (asserted, so a skipped row fails).
- A wrong signature is rejected by the verifier → `kinds_suite::verifier_rejects_wrong_certificate_and_flipped_byte` →
  `openssl` rejects each signature with another key's certificate and with a flipped byte, in all cells.
- Where the signature is made → `kinds_suite::sign_path_follows_the_kind` → TPM cells open the TPM and never decrypt;
  encrypted cells decrypt per signature and never open the TPM (counters of the access points).
- Polkit asked for every signature, nothing cached → `kinds_suite::polkit_every_signature` → N signatures leave N
  polkit calls in each kind; a denied one signs nothing and leaves the key listed.
- Replace certificate → `kinds_suite::replace_each_kind` → matching certificate accepted and the key signs verifiably
  against it; mismatching one fails with the documented name and the record is byte-for-byte unchanged; the kind is
  unchanged in both.
- Delete → `kinds_suite::delete_each_kind` → key removed, list empty, `Sign` fails `NoSuchKey`, the same id imports again
  under the same kind.
- `just quick && cargo test -p custodiod --test kinds_suite --locked` → exit 0 (the feature's `verify`).
