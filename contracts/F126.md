# F126 — Integration suites under each storage kind

## Scope
One new integration target, `kinds_suite` in `custodiod` (`crates/custodiod/tests/kinds_suite.rs` plus a directory of
modules). It runs the lifecycle suites of the service (import, list, sign, delete, replace certificate) on the real
service on a private bus with fake polkit, once per storage kind:

- **TPM**: the `swtpm` fixture serves everything (`Kind::Tpm`).
- **Encrypted, TPM-bound**: an `swtpm` behind `TpmFilter` that lacks a capability a key type needs, as `docs/findings/F107.md`
  settled (way (b): RSA needs `TPM2_RSA_Decrypt`; P-256 needs ECDSA with SHA-256; the filter and `Lacks` are F107's). The
  lack is the one of the key type under test, so import chooses `Kind::EncryptedTpm` for the same reason it would on a real
  TPM; the credential double is the TPM-bound one.
- **Encrypted, host-bound**: no TPM (`NoTpm`), `Kind::EncryptedHost`.

Both key types (RSA-2048, P-256) in each, and **every mechanism** the service offers: `CKM_RSA_PKCS` with a
`DigestInfo` per supported hash and with an opaque caller payload, `CKM_RSA_PKCS_PSS` with each supported hash and salt
length, `CKM_ECDSA` with SHA-256, SHA-384 and SHA-512 digests. Every signature is verified with the key's certificate by
`openssl` (independent of the service); a signature that must differ (another key's certificate, a flipped byte) is
rejected by the same verifier.

Reuse, not copy, through `#[path]` as the other targets do: the bus helpers `audit/bus.rs` and `audit/common.rs`, the rig
`storage_choice/rig.rs` (it has `lacks_mechanism(rsa)`, the per-key-type lack F107 settled), `sign_kinds` helpers where
they fit, and `tpm_sign/oracle.rs`. The mechanism table does not exist as a single list today (`oracle.rs` has `HASHES`,
`pss_opts`, `digest_info_prefix`, `ecdsa_der`, `flip`; the salt lengths, opaque payloads and ECDSA digest lengths are
loops in `tpm_sign/every.rs`), so a step moves that table into `oracle.rs` and makes `tpm_sign/every.rs` use it.
`sign_kinds::Setup` builds the encrypted-TPM kind with `lacks_import()` and then swaps in a full TPM; F126 does not use
that arrangement: its lacking cell uses `lacks_mechanism(rsa)` for the key type under test and **keeps the filter in
place** for every call, so the suites really run "with a TPM lacking a needed capability".

Not re-proven here, because it is owned elsewhere: the failure classes and error names, the sign path counters, the
polkit-per-signature and denial behaviour, and the plain delete/replace assertions (F118 `sign_kinds`: `signs_each_kind`,
`polkit_every_signature`, `delete_each_kind`, `replace_each_kind`); the journal (F120 `kind_audit`); the API shape and
docs (F119 `api_kind`, `api-contract`); the choice rules and the filter's own behaviour (F117 `storage_choice`,
`custodio-it` `tpm_filter`); mechanism parity inside the TPM (F107/F114 `tpm_sign`). F126 adds the matrix they lack:
every mechanism under each kind, and the lifecycle on the lacking cell where the filter stays in place.
Not here: CLI and PKCS#11 front ends, real `systemd-creds` and hardware, package, install and lifecycle tests,
`just e2e` (checkpoints F90/F100 and the e2e features). No mutants: the `verify` has none.

Environment check (run while writing this contract): `which swtpm openssl` → `/usr/bin/swtpm`, `/usr/bin/openssl`;
`cargo test -p custodiod --test sign_kinds --locked signs_each_kind` → `1 passed`.
Size: about five steps, no split.

## Evidence
- Import returns the key type and kind, both key types, each kind, the lacking cell with its filter in place →
  `kinds_suite::import_each_kind` → per cell the reply names the key type and the cell's kind (the lacking cells give
  `EncryptedTpm`, not `Tpm` or `EncryptedHost`); the test asserts six distinct (kind, key type) cells ran, so a skipped
  cell fails.
- List → `kinds_suite::list_each_kind` → one entry per imported key with the cell's kind and its certificate; none after
  delete.
- Sign, both key types, every mechanism, each kind, verified by an independent implementation →
  `kinds_suite::sign_every_mechanism_verifies` → every row of the shared table signs on all six cells and `openssl`
  accepts it with the key's certificate; the same signatures are rejected with another key's certificate and with a
  flipped byte; the number of accepted signatures equals cells × table size (asserted, so a skipped row fails).
- Replace certificate on every cell, including the lacking one (F118 proves the plain behaviour) →
  `kinds_suite::replace_each_kind` → the recertificate of the same key is accepted and a later signature verifies with
  the new certificate; another key's certificate fails with the mismatch name, the record unchanged, the kind unchanged.
- Delete on every cell → `kinds_suite::delete_each_kind` → key gone from the list, `Sign` fails `NoSuchKey`, and the same
  id imports again under the same kind (the part F118 does not prove).
- The shared table is used by `tpm_sign` → `cargo test -p custodiod --test tpm_sign --locked` → passes, with the same
  number of tests as before.
- `just quick && cargo test -p custodiod --test kinds_suite --locked` → exit 0 (the feature's `verify`).
