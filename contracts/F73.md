# F73 — Import asks polkit before decrypting the .p12

## Scope
`ImportP12` becomes: arguments (bounds) → credentials → does the caller already have the id → polkit once,
`AllowUserInteraction`, under `com.rfirma.custodio.import-certificate` → only then decode the `.p12` and store.
What changes:

- **Order and action.** Today the `.p12` is parsed before any check of the id and polkit is never asked. The
  authorizer is asked about one action today (`ACTION_ID`, sign); the builder chooses how it learns the import
  action (the F69 note: the policy test switches from its hard-coded ids to the Rust constant). The
  `KeyIdTaken` check moves before polkit and before the decoder; the store's own `AlreadyExists` at write time
  stays (a concurrent import) and keeps its name. The caller's credentials failure stays
  `AuthorizationUnavailable` before anything is read (F72, unchanged tests stay green).
- **Decoder double.** The `.p12` decoder is called through a seam the integration tests can replace with a
  counting double. The seam is test-only plumbing: production uses the real parser, same results as today.
- **Errors after approval.** A wrong password or unreadable file → `WrongPasswordOrBadP12`; an unsupported key
  type → `UnsupportedKeyType`; both exist in `docs/api.md` already and keep their names. polkit fails closed
  as for signing: `Denied` → `PolkitDenied`; `Unavailable`/`BadSender` → `AuthorizationUnavailable`.
- **Docs.** `docs/api.md` `ImportP12` describes the order and the action, and drops the stale "Needs no polkit
  authorization"; the `PolkitDenied` text says "refused the call", not only "the signature".
- **e2e setup.** The test agent registers only for the logind session it runs in (`e2e/agent.py`), and each
  `su -l alice` is its own session, so the imports must run inside the script that starts the agent. A new
  user-side script `e2e/import-user.sh` (name the builder's) starts the agent with its own state directory
  (`$WORK/agent-import`, not `$WORK/agent`), sets `approve`, runs `import.py` for `rsa1` and `ec1`, then
  checks that the agent was asked exactly 2 times, and stops the agent. `guest.sh` runs it under one
  `su -l alice` in place of the two current import sessions; the `.p12` files are removed after it, as now.
  Because it runs always (main, old and oldpath modes, with or without `E2E_SELECT`), the setup is the same
  everywhere. The request accounting of `user.sh` (0 at `no-key-read`, then 1, 2, 3...) and `TOTAL` for
  `journal-check.sh` are unchanged: they read `$WORK/agent/requests`, a different file, so the two import
  requests are never counted there (no subtraction needed; the journal has no import entries from F73).
  `oldpath` mode: that fixture is the current package with the daemon at another path (`scripts/package-oldpath.sh`),
  so it asks polkit on import like any current build; the same `import-user.sh` covers it before `upgrade.sh`
  (which starts its own agent in `$WORK/agent-upgrade`). `just test-scripts` covers the changed scripts; the real
  run is `just e2e` at F90/F100.
- **Followers.** Tests of `custodio-it` (cli, cryptoki), `custodiod/tests/{import,audit,owners,errors,dbus}` and
  fixtures that import over D-Bus now need an approving authorizer; they are adapted, never deleted or weakened.
  Where a test imports through the store directly it needs no change.

Left for other features: journal entries for import (F74/F75; this feature writes none and must not break
M1's sign entries), delete and replace (F76+), the cross-uid proof with two real accounts and the
polkit-agent e2e cases (F90/F100). Size: about five steps; no split.

Environment: nothing beyond the dev container; D-Bus tests use the private `dbus-daemon` that
`tests/audit/bus.rs` starts (`just test` runs it today). No new tool, network or privilege.

## Evidence
- Arguments are checked against documented bounds, before the id lookup, credentials side effects, polkit or
  decoder → `import_refuses_bad_arguments_first`: three cases, each with exactly one bad field and the other two
  valid: bad id, `.p12` of `MAX_P12_LEN + 1`, password of 1025 bytes; each gives `InvalidArgs`; authorizer calls = 0, decoder calls = 0, and the caller already holding the id
  still gets `InvalidArgs`, not `KeyIdTaken`. `docs/api.md` states the bounds; `just api-contract` green.
- Already-has-the-id is checked before polkit → `import_own_id_taken_asks_no_polkit`: caller imports `k`, a
  second import of `k` gives `KeyIdTaken` with authorizer calls = 0 and decoder calls = 0 for that second call
  (answer Yes and answer No both give `KeyIdTaken`, so a polkit-first mutant fails); another uid's `k` does not
  give `KeyIdTaken` (F72's `import_is_per_owner` stays green).
- polkit asked once, `AllowUserInteraction`, under the import action → `import_asks_polkit_once_for_the_import_action`:
  one call, one authorizer call, the recorded action equals `com.rfirma.custodio.import-certificate` (the
  string, not the sign constant) and is not the sign action; at the wire level, a `polkit.rs`-style test of the
  `CheckAuthorization` request body shows the action id and flags `1` (AllowUserInteraction).
- Decoder never runs when polkit denies or is unavailable; a wrong password then fails as denied/unavailable →
  `import_wrong_password_is_denied_not_tried`: with the answer "denied", and with an authorizer that fails
  (`Unavailable`, and `BadSender`), import of a `.p12` with the wrong password gives `PolkitDenied`,
  `AuthorizationUnavailable`, `AuthorizationUnavailable`; decoder calls = 0 in all three; one approved call
  reaches the decoder exactly once (control that the double counts).
- After approval: wrong password or unreadable file, and unsupported key type, each their own error →
  `import_after_approval_errors`: wrong password and garbage bytes → `WrongPasswordOrBadP12` (the wrong-password
  case with approval and decoder calls = 1 is also the control of the test above, not a second test); an RSA
  3072 and an Ed25519 `.p12` (fixtures exist) → `UnsupportedKeyType`; the names differ from each other and from
  `PolkitDenied`; authorizer calls = 1 each, nothing stored (the list is empty).
- polkit asked exactly once per call, a second call asks again → `import_asks_again_on_every_call`: two
  imports with distinct ids (and a failed one between them) give authorizer calls 1, 2, 3 respectively; no
  approval is remembered: approve then deny gives success then `PolkitDenied`.
- Denial or unavailability leave the state unchanged → `import_refusal_leaves_state_unchanged`: after
  `PolkitDenied` and after `AuthorizationUnavailable` the caller's list and the state directory listing are
  identical to before (including no `-cert` file, no `.tmp-*`), and the same id imports afterwards with approval.
- Success path still works and returns the key type → `import_returns_the_key_type`: approved RSA and EC
  imports return `rsa2048` and `ecdsa-p256`, appear in `ListKeys` with the right certificate, and sign works.
- Credentials failure unchanged → F72's `import_fails_closed_without_credentials` stays green unmodified
  (still `AuthorizationUnavailable` with a malformed `.p12`, authorizer calls = 0).
- No journal entry is added or changed by import here → the existing `audit` tests for sign stay green
  unmodified; import journal behaviour is F75.
- Documentation → `docs/api.md` `ImportP12` section names the order (bounds, own id, polkit, decode) and the
  action, no longer says "Needs no polkit authorization": `! grep -n 'Needs no polkit' docs/api.md` exits 0;
  `just api-contract` green.
- Policy test uses the Rust constants → `cargo test -p custodiod --test policy` green; a test fails if the
  constant for the import action differs from the id in `data/com.rfirma.custodio.policy`.
- e2e setup approves the import through the test agent, in the agent's own session → a selftest in `e2e/`
  run by `just test-scripts`, which fails unless: (1) `import.py` is called only from the script that also
  starts `agent.py` (same `su -l` session), and not from `guest.sh`; (2) `approve` is written to the agent's
  mode file after the agent registered and before the first `import.py`; (3) the script checks the request
  count is exactly 2 after the imports; (4) the agent state directory is not `$WORK/agent`, so `user.sh`'s
  `expect_requests 0` at `no-key-read` and `TOTAL` stay as they are; (5) `guest.sh` runs this script before
  `user.sh`, `upgrade.sh` and in the oldpath branch (one call site before the `oldpath` test). Negative
  controls, each fails the selftest: a copy of `guest.sh` that keeps `su -l alice -c "... import.py ..."`;
  a copy of the script that imports before `approve` is set; a copy without the count check. The real
  signing cases run at F90/F100.
- Followers → `cargo test -p custodio-it -p custodio-pkcs11 -p custodio-cli` green, with import-over-D-Bus
  fixtures using an approving authorizer; no test deleted, `#[ignore]`d or weakened (diff reviewed in
  PROGRESS.md).
- Mutation coverage → `just mutants-diff F73` has no missed mutant in the changed code (in particular a
  mutant that moves polkit after the decode, or the own-id check after polkit, is caught by the tests above).
