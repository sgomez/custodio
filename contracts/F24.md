# F24 — Audit sink interface and native journal protocol writer in custodiod

## Scope
Builds, in `crates/custodiod`, a new module `audit` (`src/audit.rs` plus submodules `audit/wire.rs`,
`audit/journal.rs`, `audit/memory.rs`; tests in their own files `audit/tests.rs` etc., never inline, so the
5000-token file gate holds). It is exported from `lib.rs`. **Not wired into `Sign`**: calling the sink from the
D-Bus path, failing closed, uid/pid from the bus and the administrator documentation with the `journalctl`
query belong to later features. Outside `audit`, only these change: `lib.rs` (export), `store.rs` (the
key-id validation rule becomes one `pub(crate)` function that the store and the audit `KeyId` both use; behaviour
unchanged, its existing tests must still pass), `docs/decisions.md`, `PROGRESS.md`.

- **Interface.** `trait AuditSink: Send + Sync { fn record(&self, entry: &Entry) -> Result<(), AuditError>; }`.
  `Result` is `#[must_use]`, so a caller that ignores it fails clippy `-D warnings`. Test doubles in
  `audit/memory.rs`, public so later integration tests can use them: `MemorySink` (stores entries) and
  `FailingSink` (always errors).
- **Typed entry.** `Entry` has no free-text constructor and no public fields; it is built only by
  `Entry::new(outcome, caller, key_id, mechanism)`. Parts:
  - `Outcome`: `Signed`, `SigningFailed`, `Denied`, `AuthorizationUnavailable`. Each maps to a fixed `PRIORITY`
    (`Signed` 6, `Denied` 5, `SigningFailed` 3, `AuthorizationUnavailable` 4) and a fixed MESSAGE template built
    only from typed values.
  - `Caller { uid: u32, pid: u32 }`.
  - `KeyId::new(&str) -> Result<KeyId, InvalidKeyId>`, validated by the same `pub(crate)` function as the store
    (non-empty, at most 64 bytes, `[A-Za-z0-9_-]`). `InvalidKeyId` carries no copy of the input.
  - `AuditMechanism`: a closed enum with `From<&sign::Mechanism>` (exhaustive `match`, no wildcard, so a new
    `sign::Mechanism` variant breaks the build until mapped); each variant has a fixed `&'static str` name.
  - No `From<&str>`, `From<String>`, `From<Vec<u8>>` or `From<&[u8]>` for any entry part; the only function that
    takes a string is `KeyId::new`. `Debug` for `Entry` and `AuditError` prints only typed fields.
- **Fields written** (names fixed here, in the module docs): `MESSAGE`, `MESSAGE_ID` (a 128-bit id generated once
  from a random source, `pub const MESSAGE_ID: &str`, 32 lower-case hex digits), `PRIORITY`, `SYSLOG_IDENTIFIER=custodiod`,
  `CUSTODIO_UID`, `CUSTODIO_PID`, `CUSTODIO_KEY_ID`, `CUSTODIO_OUTCOME` (`signed`, `signing_failed`, `denied`,
  `authorization_unavailable`) and, when present, `CUSTODIO_MECHANISM`. The values live in the module docs; the
  administrator document is a later feature.
- **Production sink.** `JournalSink` is a small writer of our own (no new dependency): one `AF_UNIX`
  `SOCK_DGRAM` datagram per `record`, to `DEFAULT_JOURNAL_SOCKET = "/run/systemd/journal/socket"` by
  `JournalSink::default()` and to a path given to `JournalSink::new(path)`. Encoding: `NAME=value\n` when the
  value has no `\n`, else `NAME\n` + 8-byte little-endian length + value + `\n`. Uses
  `std::os::unix::net::UnixDatagram` (no `unsafe`), non-blocking send. An entry whose encoding exceeds
  `MAX_DATAGRAM` (a constant well below the kernel limit) gives `AuditError::TooLarge`; it is never truncated and
  never sent through `memfd`/`SCM_RIGHTS`. Every I/O error gives `AuditError::Io(kind)`; a send that returns
  fewer bytes than the datagram is also an error. Nothing is retried or dropped silently.
- **Unit.** `data/custodio.service` is not expected to change (`RestrictAddressFamilies=AF_UNIX` already allows
  the datagram). If it must change, only a restriction may be added.
- **Supply chain.** No dependency is added.
- **Decisions to record in `docs/decisions.md`** (a later session could undo them blindly): own writer rather than a
  crate; `TooLarge` rather than truncation or `memfd`; non-blocking send (a busy journal gives an error, which
  F25 turns into a refused signature). The `MESSAGE_ID` and field names are NOT recorded there; they are
  documented in the module and, later, the admin document.

## Steps
Each step writes its failing tests first, then the code.
- [ ] Types and sinks: tests `memory_sink_records_entries`, `failing_sink_returns_error`, `key_id_*`, `mechanism_names_*`, the `compile_fail` doctests, `message_*`; then `Entry`, `Outcome`, `Caller`, `KeyId` (with the shared store rule), `AuditMechanism`, `AuditSink`, `MemorySink`, `FailingSink`; export from `lib.rs`.
- [ ] Wire encoder (`audit/wire.rs`): tests for plain fields, newline values, `MESSAGE_ID`, per-outcome fields and the decode round trip; then the encoder.
- [ ] `JournalSink`: tests for one datagram per call, default path, missing, refusing and full socket, short send, oversize; then the implementation.
- [ ] `docs/decisions.md` entries, `audit/*.rs` added to the `just mutants` file list, the module docs listing the fields.
- [ ] `just system-gates`, `just check`, `PROGRESS.md`.

## Evidence
In "against the contract commit", `7db33ca` is the commit that added the first version of this contract.
- Interface tests can replace → `audit::tests::memory_sink_records_entries` (an entry sent through `&dyn AuditSink` comes back equal from `MemorySink::entries()`; two calls give two entries) and `audit::tests::failing_sink_returns_error` → pass; fail if nothing is stored or `FailingSink` returns `Ok`.
- One entry per call → `audit::tests::one_datagram_per_call` (three `record` calls; the test-owned socket receives exactly three datagrams, then a non-blocking `recv` gives `WouldBlock`) → pass; fails if an entry is split or batched.
- Plain wire encoding → `audit::tests::wire_plain_fields` (the datagram received on the test-owned socket equals a full byte-string literal typed into the test file for a `Signed` entry with mechanism, in the documented field order, including the literal 32-hex `MESSAGE_ID` and every field name; it uses no module constant or encoder helper to build the expectation) → pass; fails on any name, order, separator, priority or id change.
- Values with newlines → `audit::tests::wire_value_with_newline` (sent through the same private `send_fields(path, fields)` that `JournalSink::record` uses, to the test-owned socket; the received bytes equal `NAME\n` + `3u64.to_le_bytes()` (8 bytes) + `a\nb` + `\n`; also a value that ends in `\n`, a value that is only `\n`, and an empty value `NAME=\n`) → pass; fails if the text form is used, or the length is big-endian or off by one.
- Round trip → `audit::tests::all_entries_decode_to_expected_fields` (every combination of four outcomes, with and without each mechanism, several `KeyId`s; a test decoder implementing the protocol, written independently of the encoder, yields exactly the expected field map) → pass; fails if a field is lost, merged or duplicated.
- Fixed MESSAGE_ID → `audit::tests::message_id_is_32_hex_and_in_every_entry` (the constant equals a 32-digit hex literal typed in the test; it is not all zeros; every outcome's received datagram has `MESSAGE_ID=` + that literal) → pass.
- uid, pid, key id, outcome, mechanism, PRIORITY → `audit::tests::fields_per_outcome` (table over the four outcomes; uid 1234567 and pid 7654321 so a swap fails; PRIORITY exactly 6, 3, 5, 4; `CUSTODIO_OUTCOME` string; `CUSTODIO_MECHANISM` absent for `None`, present for `Some`) → pass.
- MESSAGE → `audit::tests::message_text_per_outcome` (the exact MESSAGE string for each of the four outcomes with fixed uid, pid and key id; two outcomes sharing a phrase or a missing pid fails) → pass.
- Mechanism names cannot drift → `audit::tests::every_sign_mechanism_has_a_name` (each `sign::Mechanism` value, including each `PssHash`, maps to a non-empty name from the `From` impl; the exhaustive `match` fails the build on a new variant) → pass.
- Typed fields keep secrets out → `compile_fail` rustdoc examples on `Entry` and `KeyId`, each paired with a sibling example that differs only in the allowed construction and must compile: `KeyId::from("x")`, `"x".into()` for `KeyId`/`Entry`, a `String` or `Vec<u8>` passed as key id, mechanism or caller to `Entry::new`, and `Entry { .. }` as a struct literal from outside the module → `cargo test --doc -p custodiod` passes, the compile_fail ones only because of those errors (the sibling examples prove imports and names are right).
- `KeyId` validation → `audit::tests::key_id_rejects_bad_strings` (empty, 65 bytes, `\n`, `=`, space, NUL, non-ASCII, `.`, `../x`: each `Err`, and `format!("{err:?}{err}")` contains no part of the input) and `audit::tests::key_id_matches_store_rule` (for a list of strings, `KeyId::new` accepts exactly those that `KeyStore::get` does not reject as an invalid id) → pass; fails if the rules diverge.
- Debug does not leak → `audit::tests::debug_prints_only_typed_fields` (`Debug` of an `Entry` and of every `AuditError` variant has the key id and numbers but not the socket path) → pass.
- Default path → `audit::tests::default_socket_path` (`DEFAULT_JOURNAL_SOCKET == "/run/systemd/journal/socket"` and `JournalSink::default().path()` equals it) → pass.
- Missing socket → `audit::tests::missing_socket_is_an_error` (path in an empty tempdir; `record` returns `Err(AuditError::Io(NotFound))`) → pass.
- Refusing socket → `audit::tests::refusing_socket_is_an_error` (a datagram socket bound at the path and then dropped, leaving the file: `Io(ConnectionRefused)`; and a regular file at the path: `Err(Io(_))`) → pass.
- Full socket → `audit::tests::full_socket_is_an_error_without_blocking` (test socket's buffer filled without reading; `record` runs in a thread and the test waits with `recv_timeout(1s)` so a hang fails; the result is `Err(Io(WouldBlock))`) → pass.
- Short send → `audit::tests::short_send_is_an_error` (the byte-count check is a private `check_sent(sent, expected)` tested directly: equal gives `Ok`, fewer gives `Err`; `JournalSink::record` must return `check_sent(sent, len)?`-style directly, which the evaluator checks by reading `audit/journal.rs`, and `audit/journal.rs` is added to the `just mutants` file list in this feature so a mutated call is caught) → pass.
- Oversize → `audit::tests::oversize_entry_is_too_large` (the sink is built with `JournalSink::with_max(path, 64)`, so a normal entry exceeds the limit; result `Err(TooLarge)` and the test socket receives nothing) → pass.
