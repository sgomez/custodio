# F24 — Audit sink interface and native journal protocol writer in custodiod

## Scope
Builds, in `crates/custodiod`, a new module `audit` (`src/audit.rs`, plus `src/audit/` submodules and
test files so the 5000-token file gate holds; tests live in their own files, never inline). It is
exported from `lib.rs`. **Not wired into `Sign`**: calling the sink from the D-Bus path, failing
closed, uid/pid from the bus and the `journalctl` documentation belong to later features (F25 and
after). Nothing outside `custodiod` changes except the files named under "Unit" and "Supply chain".

- **Interface.** `trait AuditSink: Send + Sync { fn record(&self, entry: &Entry) -> Result<(), AuditError>; }`.
  The method returns `Result`, which is `#[must_use]`, so a caller that ignores it fails clippy `-D warnings`.
  Tests replace the sink with an in-memory `MemorySink` (in `audit/memory.rs`, public so integration tests
  of later features can use it) that stores entries, and with a `FailingSink` that always errors.
- **Typed entry.** `Entry` has no free-text constructor. Its parts are:
  - `Outcome` enum: `Signed`, `SigningFailed`, `Denied`, `AuthorizationUnavailable`. Each maps to a fixed
    `PRIORITY` (`Signed` 6 info, `Denied` 5 notice, `SigningFailed` 3 err, `AuthorizationUnavailable` 4 warning)
    and a fixed `MESSAGE` template; the message is built only from the typed values.
  - `Caller { uid: u32, pid: u32 }` (numbers only).
  - `KeyId`: a validated newtype (`KeyId::new(&str) -> Result<KeyId, InvalidKeyId>`), non-empty, at most
    64 bytes, only `[A-Za-z0-9._-]`. The error carries no copy of the input. A string that fails validation
    can therefore never be in an entry.
  - `Option<AuditMechanism>`: a closed enum of the mechanism names the service supports (the variants map
    to fixed `&'static str`s); no string constructor.
  - No type in the module can hold bytes or `String` from outside: no `From<&str>`, `From<Vec<u8>>` or `From<String>` for any entry part, so keys, passwords,
    data, digests, DigestInfo and signatures have no way in.
  - `Debug` of `Entry` and `AuditError` prints only the typed fields / a fixed description.
- **Fields written** (names fixed once, uppercase as journald requires): `MESSAGE`, `MESSAGE_ID`
  (a 128-bit id generated once from a random source, stored as a `pub const` hex string of 32
  lower-case digits, and recorded in `docs/decisions.md` because changing it breaks administrators' queries),
  `PRIORITY`, `CUSTODIO_UID`, `CUSTODIO_PID`, `CUSTODIO_KEY_ID`, `CUSTODIO_OUTCOME` (`signed`, `signing_failed`,
  `denied`, `authorization_unavailable`) and, when present, `CUSTODIO_MECHANISM`. `SYSLOG_IDENTIFIER=custodiod`
  is also sent. The documentation for administrators is F-later; the names are listed in the module docs here.
- **Production sink.** `JournalSink` writes the Native Journal Protocol itself (a small writer of our own, no new
  dependency): one `AF_UNIX`/`SOCK_DGRAM` datagram per call, to `/run/systemd/journal/socket` by default and to a
  path given to `JournalSink::new(path)` (so tests use their own socket). Encoding: `NAME=value\n` when the value
  has no `\n`; otherwise `NAME\n` + 8-byte little-endian length + value + `\n`. It uses `std::os::unix::net::UnixDatagram`
  (no `unsafe`, no new crate; `forbid(unsafe_code)` stays). An entry larger than one datagram (the encoded size is
  checked against a constant well below the kernel's limit) returns `AuditError::TooLarge` and is not truncated;
  the sink never uses `memfd`/`SCM_RIGHTS`. Every I/O error (socket missing, connection refused, would block,
  short send) returns `AuditError::Io(kind)`; the sink uses a blocking-free send (`set_nonblocking`) so a full journal socket gives an error and does not hang the service.
  Nothing is retried silently, nothing is logged-and-dropped.
- **Unit.** `data/custodio.service` is not expected to change: `RestrictAddressFamilies=AF_UNIX` and the
  read-only-but-connectable `/run` already allow the datagram. If the builder finds that a change is needed, it
  may add only a restriction or a `ReadWritePaths`-free directive, and the evidence below (score at threshold 10,
  `CapabilityBoundingSet=` empty, `AmbientCapabilities=` empty) must still hold.
- **Supply chain.** No dependency is added to `custodiod/Cargo.toml` (`cargo deny check` and `cargo machete` stay green).
  `tempfile` (already a dev-dependency) gives the test socket directory.
- **Left for other features**: use in `Sign`, uid/pid from the bus, fail-closed behaviour, the journal catalog file,
  administrator documentation and `journalctl` query, real-journal end-to-end checks, the `just mutants` file list
  (extended when the sink is wired in).

## Evidence
- Audit interface tests can replace → `audit::tests::memory_sink_records_entries` (entry passed to `record` through `&dyn AuditSink` is returned by `MemorySink::entries()` equal to what was sent) and `audit::tests::failing_sink_returns_error` → pass; the first fails if `record` stores nothing, the second if `FailingSink` returns `Ok`.
- Production implementation sends one entry per call → `audit::tests::one_datagram_per_call` (call `record` three times; the test socket receives exactly three datagrams, then `recv` with nonblocking gives `WouldBlock`) → pass; fails if the writer sends two datagrams per entry or batches.
- Wire encoding of plain fields → `audit::tests::wire_plain_fields` (the datagram equals the exact expected byte string for a full `Signed` entry with mechanism: each `NAME=value\n`, in the documented order) → pass; fails on any change of name, order, separator or priority digit.
- Wire encoding of values with newlines → `audit::tests::wire_value_with_newline` (the encoder is given a field value `"a\nb"`, which is reachable at the encoder level through the private `wire` API; the bytes equal `NAME\n` + `3+1+1`-byte LE u64 length `3` + `a\nb` + `\n`, and a value ending with `\n` and an empty value are also checked) → pass; fails if the text form is used for such values, or the length is big-endian or off by one.
- Newline cannot come from an entry → `audit::tests::entry_fields_never_contain_newline_ambiguity` (every combination of the four outcomes, mechanisms and `KeyId`s decodes back, with a test decoder implementing the protocol, to the exact expected field map) → pass; fails if a field is lost or merged.
- MESSAGE_ID is fixed and 128-bit → `audit::tests::message_id_is_32_hex_digits_and_constant` (the constant is 32 lower-case hex digits, is not all zeros, and equals the literal in `docs/decisions.md`, read by the test via `include_str!`) and the datagram carries `MESSAGE_ID=<that constant>` in every outcome → pass; fails if the id differs between outcomes or is the wrong length.
- uid, pid, key id, outcome, optional mechanism, PRIORITY per outcome → `audit::tests::fields_per_outcome` (table of the four outcomes; uid and pid chosen as distinct numbers such as 1234567 and 7654321 so a swap fails; PRIORITY exactly 6, 3, 5, 4 as listed; `CUSTODIO_OUTCOME` string checked; `CUSTODIO_MECHANISM` absent when `None` and present when `Some`) → pass; fails on a swapped uid/pid, a wrong priority or an outcome mapped to another.
- MESSAGE is human-readable and built only from typed values → `audit::tests::message_mentions_uid_key_and_outcome` (the MESSAGE contains the uid, pid, key id and a different phrase per outcome) → pass.
- Typed fields keep secrets out → `audit::tests::key_id_rejects_bad_strings` (empty, 65 bytes, `\n`, `=`, space, NUL, non-ASCII, `../x`: each is `Err`, and `format!("{err:?}{err}")` contains none of the input) and `audit::tests::no_free_text_constructor` (a `cargo`-free source check: `grep -E 'impl From<(&str|String|Vec<u8>|&\[u8\])>' crates/custodiod/src/audit*.rs crates/custodiod/src/audit/` finds nothing, and `Entry`, `KeyId`, `Caller` have no `pub` field of type `String`, `&str` or `Vec<u8>`; the test reads the source files with `include_str!` and fails on a match) → pass; the compile-time guarantee itself is `pub` API review by the evaluator: `cargo doc -p custodiod --no-deps` public items of `audit` list no function taking `&str`/`String`/bytes except `KeyId::new`.
- Debug does not leak → `audit::tests::debug_prints_only_typed_fields` (`format!("{:?}", entry)` and of every `AuditError` variant contain the key id and numbers but no path of the socket and no raw bytes) → pass.
- Socket missing gives an error → `audit::tests::missing_socket_is_an_error` (`JournalSink::new` of a path in an empty tempdir; `record` returns `Err(AuditError::Io(NotFound))`, never `Ok`) → pass; fails if errors are swallowed.
- Socket that refuses gives an error → `audit::tests::refusing_socket_is_an_error` (a path that is a bound datagram socket whose receiver was dropped, giving `ConnectionRefused`; and a path that is a regular file, giving an error; both `Err`) → pass.
- Full socket does not block or drop silently → `audit::tests::full_socket_is_an_error_without_blocking` (the test socket's receive buffer is filled without reading; `record` returns `Err` within one second, and the test does not hang) → pass.
- Oversize entry is not truncated → `audit::tests::oversize_entry_is_an_error` (the encoder with a field above the limit returns `AuditError::TooLarge`, nothing is received on the test socket) → pass.
- Failure is visible to callers → a `compile_fail` rustdoc example on `AuditSink::record` (`#![deny(unused_must_use)]`, calls `sink.record(&e);` without using the result) → `cargo test --doc -p custodiod` passes only because the example fails to compile.
- Library stays `forbid(unsafe_code)` and adds no dependency → `just lint` (`cargo deny check`, `cargo machete`, clippy) and `git diff --stat -- Cargo.lock crates/custodiod/Cargo.toml` shows no change → pass.
- Hardening does not loosen → `just system-gates` → exit 0, with `security-score` at the default threshold 10 (the justfile default is not edited), and `grep -E '^(CapabilityBoundingSet|AmbientCapabilities)=$' data/custodio.service` prints both lines; `git diff main -- data/custodio.service justfile` shows no removed hardening line and no changed threshold.
- Whole feature → `just check` → exit 0.
