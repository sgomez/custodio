# F83 — Fuzz targets for the new methods, certificates and the app-id parser

## Scope
Built here:
- Entry points in `custodiod` that the fuzz crate can call without I/O, polkit or a bus, for the
  argument checks of `DeleteKey` (the id) and `ReplaceCertificate` (the id and the certificate
  bound and parse). They are the same checks the `delete_call` / `replace_call` paths use, not
  copies, so a fuzz target cannot pass while the service differs. Names and shape are the
  builder's. Sign, import and list keep their current arguments (`list` takes none).
- Fuzz targets in `crates/custodiod/fuzz`: new `delete_args`, `replace_cert_args`, `app_id`;
  `dbus_args` extended so it covers the current `parse_sign_request` and `parse_import_request`
  signatures (all their arguments, the full ranges of mechanism, hash and salt) and the list
  arguments (none: the target states that in a comment). `p12_parse` stays.
- `just fuzz-smoke`: every fuzz target of every fuzz workspace in the repo (custodiod's and
  custodio-pkcs11's), a fixed number of runs, a fixed seed, no dependence on the local
  (gitignored) corpus, nothing written into the repository tree. It fails on a crash and when a
  target named in the recipe (`delete_args`, `replace_cert_args`, `app_id`, `dbus_args`,
  `p12_parse`, `pkcs11_args`) is not among the targets `cargo fuzz list` reports, or when a
  listed target is not run.
- `lint-fuzz` also lints the custodiod fuzz workspace (`clippy --all-targets -D warnings`), as it
  does for the PKCS#11 one today.

Not here: the argument parsing logic itself (F76, F78), the app-id module (F80); running the
fuzzers for long (nightly/CI); `just e2e` and package gates (F90, F100). The sandbox shows
`cargo +nightly-2026-10-26 fuzz list` works in both fuzz workspaces (custodiod: `dbus_args`,
`p12_parse`; pkcs11: `pkcs11_args`).
The smoke probe: `fuzz-smoke` was shown to run a built target (2000 runs, fixed seed, temp corpus) by the evaluator; the builder confirms it with the recipe itself.
Size: about four or five steps; no split.

## Steps
- [ ] Add the entry points for delete and replace-certificate arguments, and make `delete_call` and
      `replace_call` use them. If they only make `check_id`, `within_bound` and `is_certificate`
      reachable, the existing tests (`dbus/replace/tests.rs`) are enough and no test is copied; a
      new test, written first, is needed only if new logic is added.
- [ ] Add the targets `delete_args`, `replace_cert_args`, `app_id` and extend `dbus_args`; register
      them in `crates/custodiod/fuzz/Cargo.toml`.
- [ ] Add `just fuzz-smoke` (and a negative-control test of its missing-target check) and extend
      `lint-fuzz` to the custodiod fuzz workspace.
- [ ] Run `just quick`, then the `verify` chain; record the smoke settings in `PROGRESS.md`.

## Evidence
- `delete_args` fuzzes the argument parsing of delete → `just fuzz-smoke` → the target runs the
  fixed number of runs and exits 0; the target calls the entry point the service itself uses
  (sharing is checked by reading the code: `delete_call` calls the same function).
- `replace_cert_args` covers the arguments and the certificate input → same run → exits 0; the
  input is `(id, certificate bytes)` and reaches the id check, the size bound and the DER parse.
  Entry-point unit tests: bound exactly passes size check, bound + 1 refused, non-certificate and
  trailing bytes refused, valid certificate accepted → `cargo test -p custodiod <filter>` → pass.
- `app_id` fuzzes the F80 parser → same run → exits 0; the target feeds arbitrary bytes to
  `validate` and `classify` and asserts the invariant that an accepted id passes `validate` again
  and is within `MAX_APP_ID_LEN` (so the target can fail, not only crash).
- `dbus_args` extended to the changed import, list and sign arguments → `just fuzz-build` builds
  it against the current signatures (it fails to compile if a signature changes) and the smoke run
  exits 0; the target takes every argument of `parse_sign_request` and `parse_import_request`.
- All targets build → `just fuzz-build` → exit 0 (it finds both fuzz workspaces).
- `fuzz-smoke` runs every target with a fixed number of runs and a fixed seed → `just fuzz-smoke`
  → exit 0, and its output shows the runs and seed per target (`-runs=` and `-seed=` visible).
- `fuzz-smoke` does not use or change the local corpus → `git status --porcelain --ignored` for
  `crates/*/fuzz/{corpus,artifacts}` identical before and after `just fuzz-smoke` → no diff.
- `fuzz-smoke` fails on a crash → negative control: a temporary `panic!` on a fixed input prefix in
  one target (reverted) → `just fuzz-smoke` → non-zero exit naming the target.
- `fuzz-smoke` fails on a missing target → negative control: a target removed from
  `Cargo.toml` (or the list of expected names given an extra unknown one) (reverted) →
  `just fuzz-smoke` → non-zero exit naming the missing target.
- Lints of the fuzz workspace pass → `just lint-fuzz` → exit 0, and its recipe contains the
  custodiod fuzz workspace (a deliberate clippy warning there, reverted, makes it fail).
- Nothing else regresses → `just quick` → exit 0.
- Mutation testing is not part of this feature's `verify`; no mutant set is built.
