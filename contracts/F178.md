# F178 — The module chooses its transport; the module–service compatibility is pinned

## Scope
Builds, in `custodio-pkcs11` (`backend.rs`, the one place that talks to the service) and the tests in `custodio-it`:
1. **Choice.** `SNAP_INSTANCE_NAME` set (even empty: set but invalid) → the socket
   `/run/snap.$SNAP_INSTANCE_NAME/custodio.sock` and never the bus (no `Connection::system`, no bus address read).
   Unset → the bus as today.
2. **No slots, not an error.** An invalid instance name (the snap instance-name grammar: `<snap>` or `<snap>_<key>`;
   the builder takes the rules from snapd's documentation through a subagent and lists them in the code docs, and
   rejects anything with `/`, `..`, NUL, uppercase, a leading `-`, or a path that escapes `/run`), a missing socket, a
   refused connection, and a directory that is not owned by root or is writable by group or others → `Unavailable`,
   which the module already shows as no slots. The directory is inspected the way the service does it
   (`custodiod::snap_socket::check_dir`: open without following a final symlink, `fstat`, write bits before owner); the
   module may not link `custodiod`, so it carries its own copy of the rule and a test pins both to the same table of
   cases. The check happens on every call (a connection per call), with no cache.
3. **Same rules as the bus.** One connection per call, dropped after it, no thread or lock outliving a call, mutex held
   across `fork` as today (`docs/decisions.md`, "a connection per call"). Error mapping unchanged: the existing
   `error_for_name`/`map_error` apply to socket replies (acceptance 9: "a refusal in a call maps as on the bus").
4. **The base directory (`/run`) is overridable only in tests**: a Cargo feature of `custodio-pkcs11` that is off in
   every shipped build (as `fuzzing` and F173's `test-seam` are), not an environment variable of the shipped module (a
   confined process controls its environment). A script/unit check shows the feature is not default and the shipped
   cdylib ignores the override (the same style as `scripts/check-test-label.sh`; the builder extends that script or adds
   a sibling, run in `just quick`).
5. **Compatibility pin.** A test records the calls this release's module makes, on the bus and on the socket: the
   destination, path, interface, member, input signature and the reply signature it accepts for `ListKeys` and `Sign`,
   and the error names it maps (`Denied`, `Invalid`, `Unavailable`) including a name it does not know. The pin is
   written once from the module's actual behaviour, as a literal table in the test (a change to it is a deliberate
   edit). `docs/api.md` gets a rule under "Compatibility rule": a future incompatible change must give an old module
   copy no slots and a journal entry, never a wrong signature (a stale module is code in the user's home that no
   update replaces). The module side of that promise is part of this feature: if the service replies with a signature the
   module does not expect, the module returns `Unavailable` (no slots, `CKR_DEVICE_ERROR` on sign), never a guessed
   value; a test proves it with a service double that answers `ListKeys`/`Sign` with a different signature, on both
   transports. The service's side (the journal entry) is a promise for a later incompatible change, with no code now.
6. `docs/api.md` states the transport choice for clients and the compatibility rule (a docs check against the code, not
   against wording: the paths and the variable name appear in `api_contract`'s existing document-vs-code comparison
   only where that already compares values; no grep test of prose).

Not here: confinement, AppArmor, real polkit and journald, the real systemd socket, `snap run --shell` (F179 and the
checkpoint e2e prove those); the registration command (F183). "Real service" in the two integration tests means the
service code in-process (`custodiod::snap_socket::serve` with the `test-seam` source giving the Firefox label, scripted
polkit, `MemorySink`) and, for the bus, the `Custodio` object on a private `dbus-daemon`, as `tests/cryptoki` and
`list.rs` do.

Environment (checked in this dev container, uid 1000, not root): `/run` is root-owned and not writable, so a socket
cannot be made in a root-owned directory directly. `unshare -Ur stat -c '%U %a' <tmpdir>` prints `root 700`, rc 0: a user
namespace in which the test user is mapped to root shows a directory the user made as root-owned. The positive case
("a root-owned, root-only directory works") therefore runs the module child (and, if the peer uid matters, the in-process
service) inside such a namespace. If the builder finds the service refuses uid 0 peers in that arrangement, only the
child is namespaced, or the service rig runs in the same namespace with the peer-uid seam; the choice is the builder's
and is noted in the test's header. Negative cases (user-owned dir, group- and other-writable dir, symlink, a file, missing)
use real directories outside the namespace and need nothing special.

Cost of the new tests:
- `crates/custodio-it/tests/snap_transport.rs`: about 14 cases. Each starts an in-process service on a socket in a
  tempdir (a few ms) and runs the module child (this test binary re-executed, like `tests/cryptoki`, because the
  environment cannot be set in a threaded process; about 30–60 ms each; the namespace cases add a few ms). Cases: socket
  used and the bus untouched (a private bus with a counter of connections and no service; zero connections); the bus
  used when the variable is unset; list and sign through the socket against the real service, signature verified,
  polkit asked once per sign about the peer; invalid names (table of about 15, in one case, one child each only where
  the module cannot be called in-process: the name check is a pure function tested in unit tests, and the child proves
  one invalid name yields no slots and no connect); missing socket; a socket file with no listener (refused); directory
  cases; fork (a parent with the mutex held calls through the socket after `fork`; the child lists and signs); threads
  (8 threads call at once; the service sees 8 connections, each closed after its call, and the thread count after
  is the count before); error mapping (polkit denied, invalid args, unknown error name, the same results as on the bus,
  by running the same table through both transports). Estimated 4–8 s total, cases in parallel (libtest default); no case
  sleeps; waits are on the child's exit and the service's counters.
- `crates/custodio-it/tests/module_compat.rs`: about 8 cases in-process or one child each, estimated 2–4 s, parallel.
- Unit tests in `custodio-pkcs11` (name grammar table, the directory rule table, selection function): milliseconds.
- The feature-off script check: one run inside `just quick`, under a second.
- `just mutants-diff F178`: the diff is transport selection, name validation, directory rule and reply-signature
  handling in `backend.rs`; `custodio-pkcs11` is already in the mutants file list (the builder adds new files to it).
  Estimated 4–10 minutes, one command, within the per-feature budget.
- No e2e case and no VM case here (F179 and the checkpoint cover confinement and the real service).
About five steps; one to two sessions; no split.

## Evidence
- With `SNAP_INSTANCE_NAME` set the module connects to `/run/snap.$SNAP_INSTANCE_NAME/custodio.sock` and never the bus
  → `snap_transport.rs::socket_is_used_and_the_bus_is_never_touched` (a private bus with a connection counter and no
  `custodiod`; a service on the socket; list and sign succeed; the counter is 0) → passes; negative control: the same
  child without the variable makes the bus count 1 (`unset_uses_the_bus`) → fails if the choice were inverted or fixed.
- Outside a snap it uses the bus as today → `snap_transport.rs::unset_uses_the_bus` and the existing `tests/cryptoki`
  suite (unchanged, still green in `just quick`'s coverage of `custodio-it`; run by F178's verify only through
  `module_compat.rs`) → list and sign through the bus.
- An invalid instance name gives no slots → unit table in `custodio-pkcs11` (valid and invalid names, including `..`,
  `/`, empty, NUL, uppercase, too long, `_` misuse) + `snap_transport.rs::an_invalid_instance_name_gives_no_slots`
  (child: no slots, and the service on a socket at the path the invalid name would escape to sees 0 connections) →
  pass; mutants of the validator are caught by the table.
- A missing socket and a refused connection give no slots → `snap_transport.rs::a_missing_socket_gives_no_slots`,
  `a_stale_socket_file_gives_no_slots` (a socket file with no listener) → `C_GetSlotList` returns zero slots and
  `C_Initialize` still succeeds, as when the service is absent.
- A directory not root-owned and root-only writable gives no slots → `snap_transport.rs` directory cases: user-owned,
  group-writable, other-writable (even if root-owned in the namespace), symlink to a good directory, a file in place of
  the directory → no slots and the service sees 0 connections; control
  `a_root_owned_root_only_directory_serves` (in the user namespace) → slot and key present. The module's rule and
  `custodiod::snap_socket::check_dir` agree on one shared table (`directory_rule_matches_the_service`) → passes.
- One connection per call with the existing fork and thread rules → `snap_transport.rs::each_call_opens_and_closes_its_own_connection`
  (service-side count equals call count, each closed before the next accept finishes or by the end of the call),
  `a_forked_child_can_call_through_the_socket` (mutex held at `fork`), `concurrent_calls_use_separate_connections`
  (8 threads; no thread left behind) → pass.
- Error mapping unchanged → `snap_transport.rs::errors_map_the_same_on_both_transports` (one table: PolkitDenied,
  AuthorizationUnavailable, InvalidArgs, NoSuchKey, an unknown name, UnknownMethod; run on the bus and the socket; equal
  CKR results and equal to the table in the existing `backend/tests.rs`) → passes.
- The socket's base directory is overridable only in tests → the check script (feature not in `default`, not enabled by
  any shipped build recipe, the override symbol absent from a release build of the cdylib built without it) plus a
  test run in a child with the override environment variable set on a build without the feature: it is ignored and the
  module uses `/run` (no slots) → passes; the script has a control (a copy of the manifest with the feature in `default`
  fails it), in `scripts/test-*.sh` style as F175's.
- A test pins the calls this release's module makes on the bus and the socket →
  `module_compat.rs::the_modules_calls_are_pinned` (a recording service on each transport; the literal table of
  destination, path, interface, member, input signature, accepted reply signature for `ListKeys` and `Sign`) → equals
  the table; changing the argument order or a type in the module makes it fail (negative control in the same file: the
  recorded call of a deliberately altered double differs from the table). `mutants-diff` covers the module code.
- A stale copy keeps working within the release series → `module_compat.rs::a_current_service_answers_the_pinned_calls`
  (the real service on both transports answers exactly what the pinned calls expect: reply signatures and the error
  names, derived from the live introspection) → passes; this fails the day the service changes a signature or an error
  name without the pin being edited.
- An incompatible service gives an old copy no slots, never a wrong signature →
  `module_compat.rs::a_changed_reply_signature_gives_no_slots_and_no_signature` (double answers `ListKeys` with a
  different type and `Sign` with a non-byte-array, on both transports) → zero slots and `CKR_DEVICE_ERROR`, nothing
  returned as a signature.
- `docs/api.md` states the future-change rule → `just api-contract` and `scripts/test-docs-api.sh` still pass (the
  document is checked against the code and the live service, not by its wording); the rule's behaviour (no slots for a
  changed signature) is what the previous item runs.
- Proven elsewhere: confinement, `snap run --shell`, AppArmor denial of the bus, real systemd socket activation → F179
  and the checkpoint e2e; the service's refusals and bounds → F175–F177.
