# F40 — Cross-check that the caller's pidfd and pid name the same process

## Scope
F39 already built the cross-check (`check_pidfd_info` and its call `check_pidfd_info(&info, caller.pid)?`
in `caller_from`, `crates/custodiod/src/credentials.rs`, reading the `Pid:` line of
`/proc/self/fdinfo/<fd>`). `docs/findings.md` M1.2 marks that read as usable under
`ProtectProc=invisible`/`ProcSubset=pid`, so the first branch of the feature applies: the cross-check
stays, `data/custodio.service` is not loosened, and no `docs/decisions.md` entry is written. This
feature does not re-implement it. It proves the points F39 tested only in part.

Already in F39 and not counted as new: `sign_refused_with_pidfd_of_another_process`
(`tests/audit.rs`, constant checks through `refused_for_process_fd`), `pidfd_of_another_process_is_refused`,
`process_fd_that_is_not_a_pidfd_is_refused` and the pure parser test (`credentials/tests.rs`), the
missing-`ProcessFD` journal wire test, and `tests/fd_leak.rs` for the success path.

New here:

- mismatch refused *exactly like* missing `ProcessFD`: the two cases are compared with each other
  (D-Bus error name and message, `asked()`, the whole journal entry), not each against constants;
- the exited-process and unreadable-fdinfo forms get evidence at both levels, and the journal wire
  test uses a mismatching pidfd;
- fd-leak coverage of the mismatch and exited paths;
- the cross-check works under the `/proc` view the unit gives (`ProtectProc=invisible`,
  `ProcSubset=pid`, `PrivateUsers=yes`);
- the unit and the threshold are unchanged, and a check fails if either is loosened.

Mismatch forms and their expected result (all `CredentialsError::Missing`):
1. pidfd of another live process (the test's parent), `ProcessID` of the caller;
2. pidfd of a child that has exited **and been reaped** (`wait()` before the fdinfo read): fdinfo
   shows `Pid: -1`. A zombie (exited, not reaped) still shows its real pid and **is accepted**; that is
   correct (the pid still names that process) and one unit test pins it so nobody "fixes" it;
3. unreadable fdinfo: a fd without a `Pid:` line (`/dev/null`), and a `ProcessFD` whose number is not open
   in the process (a pidfd closed before `caller_from` runs; the fd number is read from `fdinfo` so the
   read fails with ENOENT).

Evidence for the hardened view: the dev container has no systemd as PID 1, so `systemd-run` transient
units are **not** the evidence. Instead a test re-runs a helper in `unshare -Urpm --fork` with a fresh
`/proc` mounted `hidepid=invisible,subset=pid` (the mount options behind `ProtectProc=invisible` and
`ProcSubset=pid`; the user and pid namespaces stand for `PrivateUsers=yes`). It runs in `just test`
(hence `just check`) as `crates/custodiod/tests/hardened_proc.rs`. If unprivileged user namespaces are
unavailable the test fails with a clear message; it does not skip. Any other fallback needs an
amendment the evaluator approves. In addition, the M1.2 source citation in `docs/findings.md` and the
unit-settings check below are part of the evidence.

Size: five steps. Left for other features: passing the pidfd to polkit, the security label,
`PIDFD_GET_INFO`.

## Steps
- [ ] Unit tests in `credentials/tests.rs`: reaped child's pidfd → `Missing`; zombie child's pidfd
      → `Ok`; closed `ProcessFD` number → `Missing`. Each of the three mismatch/unreadable tests must fail
      with `check_pidfd_info(&info, caller.pid)?` removed from `caller_from` (the closed-fd case fails
      through the read, so it additionally fails with the read mapped to a default).
- [ ] Integration tests in `tests/audit.rs`, using a shared helper that runs a Sign with a given
      `ProcessFD` edit and returns the D-Bus error (name and message), `asked()` and the entry: (a)
      `mismatch_is_refused_identically_to_missing_process_fd`: parent's pidfd versus no `ProcessFD`, same
      fixture type → equal error name, equal message, both `asked()` empty, entries equal as a whole
      (`Entry` equality or all accessors, timestamp excluded); (b) the same comparison with a reaped
      child's pidfd; (c) `mismatching_pidfd_reaches_the_journal_as_authorization_unavailable`, a copy of
      the missing-`ProcessFD` wire test using the parent's pidfd: one datagram with
      `CUSTODIO_OUTCOME=authorization_unavailable`, then a nonblocking `recv` shows no second datagram.
      Each fails with the cross-check line removed (the sign would succeed or poll polkit).
- [ ] Extend `tests/fd_leak.rs` with the mismatch (parent's pidfd) and reaped-child paths: `/proc/self/fd`
      count equal before and after. It runs under `just test` (`cargo test --workspace`), not
      `test-integration`.
- [ ] Add `crates/custodiod/tests/hardened_proc.rs`: the test runs itself as a helper
      (`unshare -Urpm --fork`, then `mount -t proc -o hidepid=invisible,subset=pid proc /proc`, then
      the helper mode) and asserts exit codes: the helper's own pidfd with its own pid → accepted; the same
      pidfd with a different `ProcessID` → `Missing`; a pidfd inherited from outside the namespace (the
      parent's) → `Missing` (fdinfo shows no usable pid there); a reaped child's pidfd → `Missing`. The
      test also fails if the helper reports the check was bypassed (see Evidence for the mutation).
- [ ] Add `unit-hardening` to `system-gates` in `justfile` (so `just check` runs it) calling
      `scripts/check-unit-hardening.sh`: asserts `data/custodio.service` has `ProtectProc=invisible`,
      `ProcSubset=pid` and `PrivateUsers=yes`, and that the `security-score threshold="10"` default,
      read from the `justfile` line, is 10 (and fails if it cannot parse it). Add
      `scripts/test-check-unit-hardening.sh`, wired into `shell-scripts-test`, with fixtures: the real
      files pass; `ProtectProc=default`, `ProcSubset=all`, `PrivateUsers=` removed, each line missing,
      and a justfile with `threshold="11"` each fail. Then run `just check`, `just test-integration` and
      `just mutants`; no surviving or timed-out mutant in `credentials.rs`.

## Evidence
- Mismatch refused like missing `ProcessFD`, with another process's pidfd →
  `tests/audit.rs::mismatch_is_refused_identically_to_missing_process_fd` → error name, error message and
  whole entry equal across the two cases; `asked()` empty in both; fails if the mismatch signs, asks
  polkit or logs a different outcome. Constants stay covered by the existing `refused_for_process_fd`.
- Same with a reaped child's pidfd → the (b) test above → equal in the same way.
- Mismatch on the journal wire → `tests/audit.rs::mismatching_pidfd_reaches_the_journal_as_authorization_unavailable`
  → exactly one datagram with `CUSTODIO_OUTCOME=authorization_unavailable`; a second `recv` errors.
- Exited and reaped process → `credentials/tests.rs` reaped-child test → `Missing`; zombie test → `Ok`
  (documented behaviour).
- Unreadable fdinfo → existing `process_fd_that_is_not_a_pidfd_is_refused` (`/dev/null`, no `Pid:`
  line) and the new closed-fd unit test → `Missing`; through the fixture, covered by (a)/(b)'s helper
  with a closed-fd edit is not required, the unit level is the evidence.
- Each new test fails without the check → durable proof is `just mutants`: cargo-mutants replaces the
  body of `check_pidfd_info` (`-> Result<(), CredentialsError>` with `Ok(())`) and `caller_from`'s
  comparison; both mutants must be caught, none in `missed.txt` or `timeout.txt` for `credentials.rs`.
  The builder also removes the call once by hand, runs the new tests and notes in PROGRESS.md which
  failed.
- Cross-check under the unit's `/proc` view → `cargo test -p custodiod --test hardened_proc` (inside
  `just test`, so `just check`) → helper exit codes as in step 4; a bypassed check (helper built with
  the call removed, by the same manual removal) makes the mismatch cases fail. Plus M1.2 in
  `docs/findings.md` unchanged.
- The unit is not loosened → `just check` runs `unit-hardening` → passes on the real files;
  `scripts/test-check-unit-hardening.sh` fixtures (`ProtectProc=default`, `ProcSubset=all`,
  `PrivateUsers=` removed, missing lines, `threshold="11"`) each make it fail.
  `git diff 02424bd -- data/custodio.service` is empty for the whole file.
- Exposure gate keeps its threshold → `just security-score` → exit 0 with the default 10 unchanged
  (`git diff 02424bd -- justfile` shows no change to that line); its bare-unit negative check still fails.
- No new `unsafe`, no fd leak → `grep -rn unsafe crates/custodiod/src crates/custodiod/tests` has no
  new hit; `tests/fd_leak.rs` passes under `just test` with the new paths.
- No `docs/decisions.md` entry needed → `git diff 02424bd -- docs/decisions.md` empty.
- Everything passes → `just check && just test-integration && just mutants` → exit 0.
