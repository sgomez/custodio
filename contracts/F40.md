# F40 — Cross-check that the caller's pidfd and pid name the same process

## Scope
F39 already built the cross-check (`check_pidfd_info` and its call in `caller_from`, reading the
`Pid:` line of `/proc/self/fdinfo/<fd>`). `docs/findings.md` M1.2 marks that read as usable under
`ProtectProc=invisible`/`ProcSubset=pid`, so the first branch of the feature applies: the
cross-check stays, `data/custodio.service` is not loosened, and no `docs/decisions.md` entry is
written (nothing is undone, so the "cannot be done" branch is not taken). This feature does not
re-implement it. It proves the remaining points, which F39 tested only in part:

- a mismatch is refused exactly like a missing `ProcessFD` (same error, same answer to the caller, no
  polkit query, one journal entry with the same outcome, also on the journal wire), for every
  mismatch form (other process's pidfd, exited process, unreadable fdinfo);
- the cross-check works under the real hardening of the unit, not only in the test process;
- the unit and the exposure gate threshold are unchanged, and a check fails if one is loosened.

If a fact found while building shows the read does not work under the hardening, the builder
amends this contract (evaluator approval) and takes the other branch: record the reason in
`docs/decisions.md` and keep the unit-unchanged check. No other deviation.

Left for other features: passing the pidfd to polkit, the security label, `PIDFD_GET_INFO`.
Expected size: three small steps.

## Steps
- [ ] Add tests (failing against a version without the cross-check: temporarily remove it to see
      them fail, then restore) that a pid mismatch gives exactly the missing-`ProcessFD` result
      in the same fixture: same D-Bus error name, empty `asked()`, one entry that equals the
      missing-`ProcessFD` entry in outcome, key id, mechanism and absent caller; plus a journal
      wire test with a mismatching pidfd (one datagram, documented outcome value). Include a pidfd
      of a child that has exited and been reaped-or-zombied (`Pid:` -1 or a different pid).
- [ ] Prove the cross-check under the unit's hardening: run the credential code (or a test helper
      binary calling `caller_from` on a real pidfd of another user's or another process) in a
      transient unit with `ProtectProc=invisible`, `ProcSubset=pid`, `PrivateUsers` and the other
      settings relevant to `/proc`, taken from `data/custodio.service`, with a matching and a
      mismatching pid. Where `systemd-run` cannot do this in the dev container or CI, the
      builder researches the limit and falls back to a check that `data/custodio.service` still
      has those settings plus the findings.md reference, and says so in `PROGRESS.md`.
- [ ] Add a check, in `just check`, that `data/custodio.service` still sets `ProtectProc=invisible`
      and `ProcSubset=pid` and that the `security-score` threshold default is 10; with a test
      that it fails on a unit or recipe with either loosened. Run `just check`,
      `just test-integration` and `just mutants`; no surviving mutant in `credentials.rs`.

## Evidence
- Mismatch refused like missing `ProcessFD` → `tests/audit` test comparing the two cases in one
  fixture → equal error name (access denied), `asked()` empty, one entry each with
  `Outcome::AuthorizationUnavailable`, same key id and mechanism, caller `None`; fails if the
  mismatch path signs, asks polkit, or logs a different outcome.
- Mismatch on the journal wire → `tests/audit` test with `JournalSink` and a mismatching real
  pidfd → exactly one datagram containing `CUSTODIO_OUTCOME=authorization_unavailable`.
- Exited process's pidfd → unit test in `credentials/tests.rs` (child spawned, killed, pidfd
  obtained before, fdinfo read after) → `Missing`; the same case through the fixture → refused.
- Cross-check works under the unit's hardening → script test running the helper in a transient
  unit with the unit's `/proc` settings → matching pid accepted, mismatching pid `Missing`
  (exit codes asserted, and the helper seen to fail when the check is removed); or, if the
  fallback applies, a documented finding plus the unit-settings check below.
- The unit is not loosened → `just check` recipe/test → passes on `data/custodio.service`;
  test fixtures with `ProtectProc=default`, `ProcSubset=all`, a missing line, and a default
  threshold above 10 each make it fail. `git diff main -- data/custodio.service` shows no
  change to `[Service]` hardening lines.
- Exposure gate keeps its threshold → `just security-score` → exit 0 with the default threshold
  10 unchanged in `justfile`; the bare-unit negative check inside it still fails a bare unit.
- No new `unsafe`, no fd leak → existing `tests/fd_leak.rs` still passes and also covers the
  mismatch and exited-process paths (count of `/proc/self/fd` equal before and after).
- No `docs/decisions.md` entry needed → `git diff -- docs/decisions.md` empty, since the
  cross-check was done within the hardening.
- Mutation coverage → `just mutants` → `target/mutants/mutants.out` `missed.txt` and
  `timeout.txt` have no entry in `credentials.rs`.
- Everything passes → `just check && just test-integration && just mutants` → exit 0.
