# F132 — Checkpoint: the TPM service, clients, unit and packages

## Scope
Nothing new is built. This feature runs the whole milestone's suites on the work of F104–F131 and fixes whatever fails,
at its cause, with no gate weakened (no `#[ignore]`, no lowered threshold, no `#[allow]` without a justification, no
recipe turned into a no-op, no case changed except where the case is wrong, no skip added without a stated and
evidenced reason). It runs the whole `verify`:
`just check && just api-contract && just fuzz-smoke && just e2e && just package-gates`.

What the checkpoint proves, and where:
- `just check`: lint (including `deps-check`), every unit and integration test of the workspace (`custodio-it`, which
  includes the TPM suites on `swtpm`), the system gates (security score, unit hardening, unit verify, bus policy) and
  the script tests (package-gate, install-script, e2e selector and self-tests, docs tests).
- `just api-contract`: the client document against the live service, with the TPM-related methods, errors and actions.
- `just fuzz-smoke`: every fuzz target in the recipe's list runs (`delete_args replace_cert_args app_id dbus_args
  p12_parse pkcs11_args tpm_blob cred_frame record_decode tpm_sign_input`); a missing or non-running target fails the
  recipe. If a feature of M4 added a fuzz target that is not in that list, the builder adds it to the default list.
- `just e2e` with `E2E_TPM` unset: all six targets (alma10, arch, debian13, fedora44, ubuntu2404, ubuntu2604), each in
  both modes (`swtpm` and `none`): every case of `e2e/cases.list` exactly once per target and mode, run or skipped as
  that target's `skip.list` says, plus the "installed unit has no drop-in" step accounted like a case. Records are
  `target/e2e/<target>.<mode>` files carrying `tpm=<mode>`.
- `just package-gates`: package, parity, glibc ceiling and package lint on the .deb, .rpm and Arch package, including
  the TPM2 stack dependencies (F125) and the unit's TPM device directives.
- Not proven here: the `lacking` mode of `just e2e` (not part of the full run; belongs to the M4 e2e-cases features),
  and any manual acceptance steps. Not re-proven here: any behaviour already owned by an earlier feature's evidence;
  this feature only shows the suites still pass together.

Environment: before step 2 the builder runs `podman info` and `swtpm --version` in the dev container and notes the
result in `PROGRESS.md`. F131 recorded that the dev container runs rootless podman and `swtpm` on the debian13 target
(`docs/findings/F131.md`); `podman info` succeeded at the time this contract was written. If an image cannot be pulled
or a target cannot boot systemd or run `swtpm` in the engine, that is a `BLOCKED.md` question (or, when a finding proves
it, a `SPEC_DEVIATIONS.md` entry), not a reason to skip a target, a mode or a case.

## Steps
- [ ] Baseline: run `just check`, `just api-contract` and `just fuzz-smoke`; fix each failure at its cause and record the
      fix in the commit (`CHECK_FORCE=1` for a re-run of `check` on an unchanged tree).
- [ ] Run `just e2e-cases debian13` with one cheap case in each mode (`E2E_TPM=swtpm`, `E2E_TPM=none`) to confirm the
      shared set-up works with the final binaries; fix what fails.
- [ ] Run `just e2e` (all targets, both modes); fix every failing case, TPM set-up or accounting error at its cause. A
      case changes only if it is wrong, never to make it pass; skips stay exactly those in each `skip.list`.
- [ ] Run `just package-gates`; fix every finding. Add to `packaging/lint/*.txt` only with a reason per entry and only
      for findings that are not defects.
- [ ] Run the whole `verify` once, in order, from a clean tree; note the result and the per-target, per-mode case
      counts in `PROGRESS.md`.

## Evidence
- Full suites → `just check` → exit 0 (includes `just lint`, `just test`, `system-gates`, `script-tests`).
- Integration tests are real → `git diff main -- crates e2e scripts | grep '^+.*#\[ignore'` → prints nothing; `just test`
  runs the `custodio-it` TPM suites (e.g. `kinds_suite`, `tpm_sign`, `tpm_duplicate`, `no_plaintext`) and they pass.
- API contract → `just api-contract` → exit 0.
- Fuzz smoke run → `just fuzz-smoke` → exit 0, and the output names each target of the list as run; the recipe's own
  negative control (`just fuzz-smoke "a b c"` exits non-zero because a listed target is missing) still fails as designed.
- `just e2e` in both TPM modes on every target → `just e2e` → exit 0; the report accounts each id of `e2e/cases.list`
  exactly once per target and mode (twelve passes), skipped ids are exactly those in each `skip.list`
  (`scripts/test-e2e-skips.sh` green inside `just check`), and `ls target/e2e/*.record` shows one record per target and
  mode, each with its `tpm=` line (`grep -h '^tpm=' target/e2e/*.record | sort | uniq -c` → six `tpm=swtpm`, six
  `tpm=none`).
- Installed unit has no drop-in → the accounted drop-in step of every target and mode in the `just e2e` report → passed
  in all twelve passes.
- Package gates → `just package-gates` → exit 0.
- No gate weakened → `git diff main -- justfile deny.toml scripts/check-* e2e/targets packaging/lint` reviewed in the
  final diff: no raised thresholds, removed checks or added skips without a stated, evidenced reason in the commit.
- Final run → `just check && just api-contract && just fuzz-smoke && just e2e && just package-gates` from a clean tree →
  exit 0.
