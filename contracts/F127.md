# F127 — No-plaintext check

## Scope
Two things:

1. `scripts/check-no-plaintext.sh <state-dir> <p12>`, password on stdin (never on the command line). With the `openssl`
   CLI it derives every encoding of the private key in the `.p12` it can: for EC the raw scalar, SEC1 and PKCS#8; for RSA
   the raw primes (and private exponent), PKCS#1 and PKCS#8; always the `.p12` file itself. Each is searched for as raw
   bytes and as its PEM/base64 and hex text forms, in every regular file under the state directory (hidden files and
   nested directories included, symlinks not followed). Exit 0 means no match; a match exits 1 and names each file that
   contains one (not the key bytes, not the password). The script fails closed: bad usage, an unreadable state directory
   or `.p12`, a wrong password, or any derivation that fails is a different non-zero exit and never an empty "clean"
   result. The public certificate and public key are not secrets and must not trigger a match.
2. The integration target `no_plaintext` in `custodiod` (`crates/custodiod/tests/no_plaintext.rs`, reusing the F126/F117
   rigs through `#[path]`): after each import, under every kind (TPM, encrypted TPM-bound with the lacking filter in place,
   encrypted host-bound) and both key types, it runs the script on the service's real state directory. A negative control
   plants each encoding in a file and sees the script fail naming that file.

Not here: the e2e cases `noplain-*` and the manual steps, which reuse the script (the e2e feature that lists them and the
manual-acceptance feature); the "no unencrypted key file exists" part of acceptance 3 belongs to that e2e feature too.
Mutants: the `verify` has none. Script tests are not added to `scripts/test-*.sh`; the cargo target proves the script.

Environment check (run while writing this contract): `openssl version` → `OpenSSL 3.5.7 9 Jun 2026`;
`which swtpm` is covered by F126 (`kinds_suite`, same rigs). Fixture `.p12` files with the sentinel password
`P@ss-sentinel-7f3a91c4` exist for both key types (`crates/custodiod/tests/fixtures/*-sentinel.p12`).
The encrypted cells use `MemoryCreds`, a test double, not real `systemd-creds`: they prove the service writes no
plaintext next to the credential; real `systemd-creds` is covered by the e2e `noplain-*` cases.
Size: four steps, no split.

## Steps
- [x] Tests first: `no_plaintext.rs` with the six cells and the failing script tests below (the script does not exist yet).
- [x] The script: derivation of the encodings per key type (the builder checks that `openssl` 3.5 reads the fixture
      `.p12` files, legacy ones included, or fails clearly), the search, naming, exit codes, password only on stdin.
- [x] Expose the service's state directory to the test and run the script after each import in each cell.
- [x] Negative controls: plant each encoding (and the `.p12`) in a file at several depths, and a hidden file; each fails
      naming that file. Then `just quick` and the evidence commands.

## Evidence
- Clean state passes, every kind and key type, right after import →
  `no_plaintext::clean_after_import_each_kind` → on all six cells the script exits 0 on the state directory with the
  sentinel `.p12`; the test asserts six cells ran and that the state directory held at least one key file (a script
  searching an empty or wrong directory would pass vacuously).
- The search can fail, for every encoding → `no_plaintext::planted_encoding_is_found` → for each key type and each of raw
  scalar/primes and RSA private exponent, PKCS#1 (RSA), SEC1 (EC), PKCS#8, and the `.p12` itself, planted in a file in the state directory (also
  in its PEM/base64 and hex forms, in a nested directory, and in a hidden file), the script exits 1 and its output names
  exactly that file; the same state without the plant exits 0. With two files planted in one run both are named. A file reachable only
  through a symlink is not followed (exit 0). The test generates the encodings itself with `openssl`
  (independently of the script's code path) so the script cannot agree with itself.
- The script finds the cell's own kind failing if a store ever kept plaintext → `no_plaintext::plaintext_key_in_store_is_found`
  → writing the PKCS#8 of the imported key into the live state directory of one cell after import makes the script exit 1
  naming that file.
- Public material is not a match → `no_plaintext::certificate_is_not_a_match` → the certificate and public key of the key
  planted in the state directory leave the exit at 0.
- Fails closed → `no_plaintext::bad_input_is_not_clean` → missing arguments, nonexistent state directory, nonexistent
  `.p12`, wrong password and a file that is not a `.p12` each exit with a non-zero code different from 1, and none exits 0;
  an empty password on stdin with the sentinel `.p12` is likewise not clean.
- Password stays off the command line and out of output → `no_plaintext::password_only_on_stdin` → the script runs with a
  `PATH` shim `openssl` that records its argv and passes through to the real one; the password appears in none of the
  recorded argv, and, on a match and on a failure, neither stdout nor stderr contains the password or any encoding of
  the key.
- `just quick && cargo test -p custodiod --test no_plaintext --locked` → exit 0 (the feature's `verify`; `just quick`
  includes shellcheck of the new script).
