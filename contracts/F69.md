# F69 — polkit actions for import, delete and replace certificate

## Scope
Built: three new `<action>` elements in `data/com.rfirma.custodio.policy` (import, delete, replace
certificate), next to the unchanged `com.rfirma.custodio.sign`; the policy test extended to all four
actions; the three actions listed in `docs/api.md` under "Polkit actions"; the action list in
`README.md` (which lists the actions at line 14) brought in line; `packaging/custodio.1` does not list them. The builder picks the
ids (lower-case, distinct, under `com.rfirma.custodio.`).

Left for other features: asking polkit for these actions in the service (the import, delete and replace
features; the Rust constants for the ids belong to the first feature that uses them, so none are added
here), and "polkit asked once per call" tests (the F70+ features and the fake polkit).

Packages: `packaging/nfpm.yaml` already ships the whole `data/com.rfirma.custodio.policy` into
`/usr/share/polkit-1/actions/` for deb, rpm and Arch, so no packaging change is expected; that the shipped
file carries the new actions, and the package gates, are proven at the checkpoints (F90, F100), not here.
No environment dependency: everything runs in `just quick`.

## Steps
- [ ] Policy test first: extend `crates/custodiod/tests/policy.rs` so it parses every `<action>` block
      (comments stripped) and checks per action: id set equals the four expected ids exactly; the three
      `allow_*` defaults are `auth_self`; the owner annotation is `unix-user:custodio`; `<message>` is
      non-empty; exactly one each of the three `allow_*` tags; and messages are pairwise distinct across all four. Keep the `_keep` check on the whole
      file. Run it and see it fail.
- [ ] Add the three actions to the policy file with their own `description` and `message` (each naming
      the operation), the same defaults and annotation as signing, and a comment that `_keep` is never
      used. Do not change the signing action.
- [ ] List the three actions in `docs/api.md` (`- action \`id\`: asked on every ..., \`auth_self\`, never
      kept`), and update `README.md`. Word the doc lines without claiming service behaviour that does not exist yet, and leave the method docs (e.g. `ImportP12` "needs no polkit") to the import, delete and replace features, with a note in `PROGRESS.md`.
- [ ] Run the policy test and `just api-contract`, then `just quick`.

## Evidence
- Three new actions, one each for import, delete, replace certificate, signing unchanged →
  `cargo test -p custodiod --test policy` (`defines_exactly_the_four_actions`, exact id set; a
  signing-block text comparison against the original is `git diff` showing no changed line inside the
  `com.rfirma.custodio.sign` element) → passes; fails if an action is missing, extra or misnamed.
- Each has its own message text → policy test `messages_are_distinct_and_non_empty` → passes; negative
  control: a unit test on the helper with two equal messages (or an empty one) makes the check report
  failure.
- `auth_self` on allow_any, allow_inactive and allow_active for every action → policy test
  `defaults_are_auth_self_for_every_action` (per action, not first match) → passes; negative control:
  the helper applied to a block whose `allow_active` is `auth_admin` or missing is rejected.
- Never a `_keep` variant → `no_keep_variant_anywhere` (whole file, comments stripped) → passes; the
  existing `comment_stripping_works` keeps a commented `_keep` from faking or hiding a value.
- Owner annotation as the signing action → policy test `every_action_is_owned_by_the_service_user`
  (per action) → passes; negative control as above for a block without it.
- `docs/api.md` lists the actions → `just api-contract` → passes (it diffs the doc against the
  `<action id>` lines of the shipped policy in both directions; its existing negative controls cover
  a missing and an extra action).
- Packages ship the file and pass the package gates → proven at the checkpoints F90 and F100 (see
  Scope); here `grep -n 'custodio.policy' packaging/nfpm.yaml` shows the file is shipped unchanged.
- Whole feature → `just quick && just api-contract` → both green.
