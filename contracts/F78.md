# F78 — Replace the certificate of a key

## Scope
A new method `ReplaceCertificate(id: s, certificate: ay)` on `com.rfirma.Custodio1` (`Custodio::replace_call`, same
shape as `delete_call`; a new `src/dbus/replace.rs` if `dbus.rs` nears the file-size gate) replaces the stored
certificate `<id>-cert` of one of the caller's keys with a DER X.509 certificate for the same public key. The key
file is never read for writing or changed.

- **Order.** (1) `id` against the existing key-id bound, and `certificate` against a documented size bound and
  against parsing as one DER X.509 certificate (nothing else, no trailing bytes): `InvalidArgs`, with no credentials
  lookup, key, file or polkit touched; (2) the caller is identified (no sender or failed credentials →
  `AuthorizationUnavailable`, no polkit); (3) the id is looked up among the caller's keys only (`NoSuchKey`, no
  polkit, identical for a missing id and another uid's id; a key that F77 made unusable is `NoSuchKey` too);
  (4) polkit is asked once per call under `REPLACE_ACTION_ID` (`com.rfirma.custodio.replace-certificate`, shipped by
  F69) with `AllowUserInteraction` (`PolkitDenied`; `AuthorizationUnavailable` for unavailable/`BadSender`);
  (5) the certificate's public key is compared with the key's public key (computed from the stored private key, as
  `import.rs` does for a `.p12`): any difference, including a certificate whose key is of another type or not RSA
  2048 / P-256, is `CertificateMismatch` and nothing changes; (6) the certificate is stored. Nothing is cached.
  The mismatch is decided after polkit because it needs the private key and F79 counts it as an authorized outcome.
- **No other checks.** No chain, revocation, validity-date, key-usage or subject checks; an expired or self-signed
  certificate for the key is accepted. Replacing with the byte-identical certificate succeeds.
- **Atomic.** The store gets a replace operation (temp file written and synced, then `rename` over `<id>-cert`,
  directory synced, mode `0600`, owner checks and no-symlink rules of `get`/`put`, refusing a non-plain-file
  target). A concurrent `ListKeys` sees the old or the new certificate, never an error or a missing one. A failure
  leaves the old certificate and no temp file; it is `Internal`.
- **Against delete.** Replace and delete of one (owner, id) must not interleave: a replace never leaves a
  certificate behind for a key a delete removed, and a replace that finds the key gone is `NoSuchKey`. The builder
  reuses F77's per-(owner, id) lock and unusable mark (`delete_state`) or an equivalent; the Evidence row decides.
- **Docs.** `docs/api.md` gets `### Method ReplaceCertificate` (in `id: s`, `certificate: ay`, no out, the bounds
  line with the certificate size in bytes, the order above, no chain/date checks, atomicity), names the method under
  `PolkitDenied`, `NoSuchKey`, `CertificateMismatch` and `Internal`, and `InvalidArgs` covers a bad certificate.
  `just api-contract` checks it against the live introspection.
- **Left for other features.** The journal entry, `AuditUnavailable` and its restore (F79: this feature writes no
  entry and calls no sink; `ReplaceOutcome` stays unused); the CLI command (not in M3); the PKCS#11 module
  re-reading the certificate (it only reads `ListKeys`; its cases are F90/F100 e2e); package gates and `just e2e`
  (checkpoints). Size: about five steps; no split.

Environment: nothing beyond the dev container. The tests use the private `dbus-daemon`, the async polkit double of
`tests/audit/bus.rs` and the name→uid credentials fake, as F76 does. `openssl` 3.5.7 is present
(`/usr/bin/openssl`), which `tests/fixtures/gen.sh` already uses; the second certificate over an existing fixture key
comes from extending `gen.sh` (fixture checked in). Tests that need an unwritable store skip as root.

## Evidence
All rows in `crates/custodiod/tests/replace.rs` unless stated; the store is inspected on disk and through
`ListKeys`/`Sign` over the private bus; polkit asks are read from the double (`asked()` with action and flags).
- Bound and parse, before anything → `replace_rejects_bad_arguments`: a bad id (empty, 60 bytes, bad byte, ending
  in `-cert`), a certificate of bound+1 bytes, an empty one, random bytes, a valid certificate with one trailing
  byte, a truncated certificate, and a DER SEQUENCE that is not a certificate each give `InvalidArgs`; `asked()`
  empty, the credentials fake not consulted (counting), store bytes unchanged. Run with an existing key and with a
  missing id (the answer must still be `InvalidArgs`, not `NoSuchKey`). Fails if any check runs after the lookup or
  polkit. The exact bound (`len == bound` passes the size check) → unit test in `dbus/tests`.
- Lookup before polkit → `replace_missing_equals_foreign`: uid 1000 owns `k`; 1001 replaces `k`, 1001 replaces
  `absent`, 1000 replaces `absent`, all with a valid matching certificate: same error name and message
  `NoSuchKey`, `asked()` empty, 1000's certificate byte-identical; repeated with polkit answering Yes, Deny and
  Unavailable. A key made unusable by a pending delete (F77 hold) gives `NoSuchKey` too.
- Credentials → `replace_without_credentials_is_unavailable`: no sender / failing lookup / no `ProcessFD` →
  `AuthorizationUnavailable`, no polkit, certificate unchanged.
- polkit once, right action → `replace_asks_polkit_once_with_interaction`: one approved replace shows exactly one
  ask, action `com.rfirma.custodio.replace-certificate`, flags `AllowUserInteraction`, the caller's connection as
  subject; two replaces show two asks (nothing cached, also after an approved sign and after an approved replace
  of another id); a mismatch also shows exactly one ask.
- Denied or unavailable change nothing → `replace_denied_and_unavailable_keep_the_certificate`: Deny →
  `PolkitDenied`; Unavailable and `BadSender` → `AuthorizationUnavailable`; the key and certificate files are
  byte-identical, `ListKeys` shows the old certificate, signing works.
- Match accepted, key untouched → `replace_with_matching_certificate`: for an RSA 2048 and a P-256 key, replace
  with a second certificate over the same key (different serial and subject), also an expired one and a
  self-signed one (no date or chain check), also the byte-identical one: reply empty; `ListKeys` shows exactly the
  new DER and the same key id and type; the key file is byte-identical and its mtime and mode unchanged; the owner's
  other keys and certificates are untouched; the area holds no temp file; modes are `0600`/`0700`.
- Mismatch → `replace_mismatch_changes_nothing`: certificates of another key of the same type, of the other
  supported type (RSA cert for a P-256 key and the reverse), a P-384 and an Ed25519 certificate: each
  `CertificateMismatch` (message "certificate does not match the key"), exactly one polkit ask, certificate and key
  files byte-identical, `ListKeys` unchanged.
- Signature after replacement → `sign_after_replace_verifies_with_the_new_certificate`: import, replace, `Sign`
  (approved); the signature verifies with the public key in the new certificate returned by `ListKeys` (RSA PKCS#1
  and ECDSA), and the old certificate is gone from `ListKeys`.
- Two uids → `replace_leaves_other_uids_alone`: 1000 and 1001 each import `my-key` (different `.p12`); 1001 replaces
  `my-key` with a matching certificate; 1000's certificate is byte-identical on disk and in `ListKeys`; 1001
  replacing with 1000's certificate is `CertificateMismatch`, and 1000 replacing `my-key` with 1001's old
  certificate is `CertificateMismatch` too; pair 0/1000 as in `owners.rs`.
- Atomic → `concurrent_list_sees_old_or_new` (`replace/concurrent.rs`): one client replaces alternately with
  certificates A and B at least 50 times while another lists in a tight loop; every `ListKeys` succeeds, lists the
  key, and the certificate equals A, B or the original, byte for byte; never an error, an empty or a partial value.
  Store unit test `replace_is_atomic`: the target path exists with old or new content at every moment, checked with
  a failure injected between writing the temp file and the rename (old content stays, temp file removed). Negative
  control: the same reader check against a deliberately non-atomic write (remove then write) fails.
- Store failure → `replace_store_failures` (skipped as root): the area made unwritable by the polkit double after
  the lookup, and the `<id>-cert` entry replaced by a directory or symlink: `Internal`, the old certificate (or the
  foreign entry) untouched, no temp file left, `Sign` still works.
- Against delete → `concurrent_replace_and_delete` (`replace/concurrent.rs`): at least 20 rounds of a replace and a
  delete of one id with the polkit double holding both until both asked: the final state is either "key and the new
  certificate present" or "neither file present, replace saw `NoSuchKey`"; never a certificate without its key; the
  delete always succeeds; a following import of the id works in the second case.
- Documented → `just api-contract`: `ReplaceCertificate` with `in id: s`, `in certificate: ay`, no out, a bounds line
  that states the certificate size, matches the live introspection both ways; the error list names the method; the
  `replace-certificate` action stays in the policy. A docs test checks that the stated byte bound equals the
  constant in code and that the doc states the order, "no chain, revocation or date checks" and atomicity.
- No journal entry yet → the existing `MemorySink` counts in `owners.rs` and the audit tests stay unchanged and green
  in `just quick`; no `replace_leaves_no_entry_yet` test is written (F79 owns entries).
- Existing behaviour intact (import, sign, list, delete, owners) → the adapted existing tests pass in `just quick`.
- Mutants → `just mutants-diff F78` reports no surviving mutant in the changed code (order of checks, bound
  comparison, key/certificate comparison, action constant, error mapping, rename vs. overwrite, lock use).
