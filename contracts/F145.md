# F145 — Written manual acceptance steps for M4

## Scope
Builds the M4 part of `docs/manual-acceptance.md` (new sections after `## 19. M3 result form`, numbered 20 onwards,
with the title line and intro of the page extended to name M4 acceptance 13 to 15) and the test
`scripts/test-docs-manual-m4.sh`, added to `test-scripts` in the `justfile`. Nothing else changes: no product code, no
other document except the pointers the new part needs. The M1 to M3 sections are not edited beyond the intro.

The part holds one section per acceptance and a result form:

- **Acceptance 13, hardware TPM.** Import an RSA 2048 and a P-256 `.p12` (`custodio import`, section 3 of the page);
  both show kind `tpm` in the import output and in `custodio list`. As root, the stored public area of each key shows an
  empty `authPolicy` (`tpm2_readpublic`) and `tpm2_duplicate` fails. Then, in this order, a reboot, an upgrade to the
  next M4 package (the install steps of `docs/install.md`) and a `fwupd` `dbx` update (`fwupdmgr`), or where none is
  pending the documented substitute that changes PCR 7 (`tpm2_pcrextend` on PCR 7). After each of the three events:
  PCR 7 is read before and after (the substitute and the `dbx` update must show a change; if it does not, the step says
  the event proved nothing), `custodio list` still shows both keys with kind `tpm`, and Firefox and LibreOffice sign with
  both keys after the polkit dialog (by pointing at the Firefox and LibreOffice sections of the page, not copying them).
  A table has one row per event and per application.
- **Acceptance 14, VM without a TPM.** `custodio import` prints the `encrypted-host` notice (weaker, no TPM, host key)
  and `custodio list` shows kind `encrypted-host`; after a reboot the key still signs from Firefox or LibreOffice.
  Known gap, found while writing this contract: `custodio list` (`crates/custodio-cli/src/list.rs`) prints the kind and
  no "weaker" sentence, while SPEC acceptance 14 says it does. The page states what the command prints, never a
  sentence it does not print. The builder notes the gap in PROGRESS.md for a person; whether the CLI should change is
  not decided here (no code is changed by this feature).
- **Acceptance 15, state directory copy.** As root, a copy of the whole state directory (`/var/lib/private/custodio`,
  the real directory behind `/var/lib/custodio`, see `docs/install.md`) is taken preserving everything, and
  `scripts/check-no-plaintext.sh <copy> <p12> < password` is run on it for each imported `.p12`, on both machines (the
  hardware TPM one and the VM without a TPM). Expected exit 0; exit 1 names the files, 3 means the check did not run
  (never a pass). The copy and the password never reach a log, and the copy is removed afterwards.
- **Result form** with a row per acceptance (13, 14, 15), as the M3 one.

Dependencies on the environment, checked in this session:
`swtpm`, `tpm2_readpublic`, `tpm2_duplicate` and `tpm2_pcrextend` are installed in the dev container
(`which` finds them), so the `tpm2-tools` commands of acceptance 13 can be run against `scripts/with-swtpm.sh` while writing the
page, using the procedure `e2e/tpmdup-run.sh` already proves (parent template, `tpm2_load`, `tpm2_readpublic`,
policy-session `tpm2_duplicate`). A hardware TPM, `fwupd`, a reboot and Firefox/LibreOffice cannot be run here: those
commands are marked **unverified** on the page as the earlier parts do, and the page says which ones were run.
`check-no-plaintext.sh` can be run for real in the container on a fixture state directory. If the builder finds that the
`tpm2-tools` check cannot be written as commands a person types (it needs the parent template, so a helper script may be
needed), it may ship the smallest helper under `scripts/` and the test covers that helper too; this is decided in the
step that researches it, not here.

Not here: the automated proofs of `authPolicy`, `tpm2_duplicate`, PCR 7 and the plaintext scan (F136, F137, F123 and the
`check-no-plaintext` tests); a person's actual run of the steps (the milestone approver); the CLI notice text itself (F127).
Everything that only a checkpoint proves (`just check`, `just e2e`, package gates) is the checkpoint's.

Cost of the new test: `scripts/test-docs-manual-m4.sh` is a script test in `test-scripts`, parallel with the other script
tests, estimated 10 s wall (the M3 sibling, same design, measures 9.4 s with its controls; the real-file check alone 0.14 s).
It adds no e2e case and no process beyond `sed`, `awk`, `grep` and one `python3 -I` call if a manifest-like file is
parsed. Default script budget in `budgets.tsv` is 60 s, so it fits. A subprocess run of `check-no-plaintext.sh`
inside the test, if the builder includes one, uses a tiny fixture and stays under 5 s.

## Evidence
- Each M4 section is found exactly once, and a duplicate or renamed heading is refused → `scripts/test-docs-manual-m4.sh`
  (section finder, M1 to M3 sections never searched for an M4 item) → ok; controls: heading duplicated, heading renamed,
  an item present only in an M3 section.
- Acceptance 13: both key types imported with `custodio import`, kind `tpm` expected in the output and in `custodio list`;
  `tpm2_readpublic` with empty `authPolicy` expected; `tpm2_duplicate` expected to fail; the three events in the order
  reboot, upgrade, `dbx` or substitute (line order checked); PCR 7 read around the events; the Firefox and LibreOffice
  checks after each event, each pointing at an existing heading of the page → `scripts/test-docs-manual-m4.sh` → ok;
  controls: each of those items removed or reordered fails the test.
- The `dbx` event and its substitute both name a command, and the substitute is a command that changes PCR 7 →
  `scripts/test-docs-manual-m4.sh` plus the findings run of the `tpm2_pcrextend` against swtpm → ok.
- Acceptance 14: the `encrypted-host` notice quoted on the page equals the text of `kind_text` in
  `crates/custodio-cli/src/lib.rs` (checked against the code, not by wording of the page alone); the `custodio list` expectation is
  `kind: encrypted-host` as `crates/custodio-cli/src/list.rs` prints it and the page claims no "weaker" line for `list`; a
  reboot step and a signing step are present → `scripts/test-docs-manual-m4.sh` → ok; controls: the quoted notice altered,
  a `list` claim the code does not print, the reboot removed.
- Acceptance 15: the command is `scripts/check-no-plaintext.sh <state copy> <p12>` with the password on stdin (never as an
  argument), the usage and exit codes (0, 1, 3) equal the header of that script, the state directory path equals the one in
  `docs/install.md`, and both machines are covered → `scripts/test-docs-manual-m4.sh` → ok; controls: the argument order
  swapped, the password passed as an argument, an exit code changed, the path altered.
- Commands against `docs/api.md`: every `busctl` command of the M4 part is a `busctl --system call` whose destination, path,
  interface, method and signature appear in a fenced example of `docs/api.md`; every polkit action id is in `docs/api.md`;
  every error name is in `docs/api.md` → `scripts/test-docs-manual-m4.sh` → ok; controls: method, signature, action id and
  error name each altered.
- Commands against `docs/audit.md`: the journal query is the base query of `docs/audit.md`, each `CUSTODIO_*` field and each
  `CUSTODIO_STORAGE_KIND` value named is in `docs/audit.md` → `scripts/test-docs-manual-m4.sh` → ok; controls: query changed,
  invented field, invented kind.
- Scripts the part names exist, are executable and their usage matches → `scripts/test-docs-manual-m4.sh` → ok; control: a
  named script path altered.
- The result form has a row for each of 13, 14 and 15 → `scripts/test-docs-manual-m4.sh` → ok; control: a row removed.
- The test can fail: every control above is a fixture that must differ from the real file and must make the check fail →
  `scripts/test-docs-manual-m4.sh` exits 1 with a message if a fixture equals the real file or a broken file passes.
- Verify → `just quick && scripts/test-docs-manual-m4.sh` → exit 0; `shellcheck` clean (run by `test-shell-scripts`
  at the checkpoint).
