# F192 — zsh, fish and bash-completion in the dev container and CI

## Scope
Built:
- `harness/Containerfile` installs `bash-completion`, `zsh` and `fish` from Debian, in an `apt-get install` with a comment
  saying why (the completion test of F205 drives the real shells).
- Every job of `.github/workflows/ci.yml`, `mutants.yml` and `mutants-diff.yml` that runs the CLI's tests (cargo test or nextest,
  directly or through `just`: today `test`, `coverage`, `full` in mutants.yml, the job of mutants-diff.yml; the builder lists
  the rest by reading the jobs) installs the same three packages, with a comment saying why. Jobs that only lint, package, fuzz
  or aggregate need not; each such job is in a short commented exempt list of the check, never silently skipped. `e2e.yml` and
  `e2e-vm.yml` run the CLI inside targets, not the cargo tests, so they are exempt (F205's e2e cases, not this feature, decide what
  the targets need).
- A script test and a check in the style of F104's `scripts/check-tpm-install-sync.sh` (a new script, or the existing one made
  generic over a package list; the builder picks, but the F104 check and its test must still pass), wired into `just test-scripts`
  / `just quick` like it.

Left to other features: the completion files, the test that drives the shells (F205), F191's decisions.

Environment (checked in this session): `command -v zsh fish` prints nothing and `/usr/share/bash-completion` is absent in the dev
container, so the `verify` cannot pass until a person rebuilds it. Until then the builder proves only the sync check. The last step writes
`BLOCKED.md` asking for the rebuild and stops; the session after the rebuild runs the `verify`. No hand-installing packages
into the running container, no deviation needed.

Costs: one script test of about 1 s (copies of two small files, a few `sed`s), parallel with the other script tests like
`test-tpm-install-sync.sh`. No unit, no e2e case. CI gains a few seconds of apt per job (the packages are small).
Proven at the checkpoint, not here: CI going green with the packages.

## Evidence
- Containerfile installs the three packages, with a comment → sync check script test → passes on the tree; negative control: a
  temporary copy lacking `fish` (and one lacking the comment) fails and names the package or the comment.
- Every CI job that runs the CLI's tests installs them, with a comment → the same check over the workflows → passes; negative
  control: a temporary copy of a workflow with a test-running job lacking the install fails and names the job.
- Existing TPM install check still holds → `scripts/test-tpm-install-sync.sh` → passes.
- Lints → `just quick` → passes.
- bash-completion present → `test -r /usr/share/bash-completion/bash_completion` → exit 0 (rebuilt container).
- zsh works with completion → `zsh -fc 'autoload -U compinit && compinit -u -D && print ok'` → prints `ok` (rebuilt container).
- fish works → `fish --no-config -c 'echo ok'` → prints `ok` (rebuilt container).
