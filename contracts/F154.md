# F154 — Packages: the .deb depends on libtss2-rc0t64 and every package requires systemd 257

## Scope
Design 4 and Design 5, packages. Built here:
- `packaging/nfpm.yaml`: the `.deb` Depends gain `libtss2-rc0t64` beside the other libtss2 packages, with a comment that systemd loads
  `libtss2-rc` by `dlopen` and Ubuntu only recommends it. The `.rpm` and Arch package keep `tpm2-tss` (it ships every libtss2 library), unchanged.
  The `.deb` Pre-Depends rises to `systemd (>= 257)`; the comment citing ubuntu2404 as the reason for 255 is replaced. The `.rpm` and Arch keep `systemd >= 257`.
- The reference lists in `scripts/package_expected.py` (the `.deb` dlopen list, `SYSTEMD`, the comments citing 255) follow the new values.
- Dependency gate (`scripts/check-tss-deps.sh` / `check_tss_deps.py`, run by `just package`): requires `libtss2-rc0t64` in the `.deb`'s Depends; a `.deb`
  without it, or with it only in Recommends (or only in Pre-Depends), fails with a message naming `libtss2-rc0t64`. The gate may take it from the same table as the
  `dlopen` TCTI, since the binary does not link `libtss2-rc` (no NEEDED soname).
- Package gate (`scripts/check-packages.sh` / `check_packages.py`, run by `just package`): for each of the three formats, the systemd requirement is read from
  the package and compared as a version (not only as an exact string): it fails with a message naming the format and `systemd` when there is no systemd requirement
  or when the bound is below 257 (or unversioned).
- Self-tests: `scripts/test-check-packages-deps.sh` and `scripts/test-check-packages.sh` get the negative controls below. The existing cases that
  write `systemd (>= 255)` as the good value are updated to 257.
- `scripts/test-deb-lifecycle-real.sh` gets a case where real dpkg refuses the `.deb` on a root whose installed systemd is 255. Like every lifecycle test it runs at the
  checkpoint, not in this `verify`; the builder only runs it if it fits in a command (see Cost) and otherwise states that in PROGRESS.md.
- Left for other features: the e2e targets and VM harness (ubuntu2404 no longer being installable is theirs), and any other doc that says 255 outside the files above
  (a step greps for leftovers and fixes the ones in packaging/scripts comments; anything in SPEC.md is not edited).

Environment: all tests use nfpm fixtures and `dpkg-deb`/`rpm`/`bsdtar` already used by the current suites; no new tool. The lifecycle case uses the real
`dpkg` in a user namespace like the existing cases (`bf_in_root`).

Cost (estimates, from the existing suites; neither is listed in `budgets.tsv` today, the loop measures them): each new fixture case builds three packages with nfpm,
about 1–2 s, parallel-safe because each has its own output dir; about 12 new cases, so +15–25 s on the two script tests, which run in parallel with the other
script tests. The cases are built independently, and the builder starts them in one batch if the helper already supports it, otherwise keeps the existing loop style.
The lifecycle case is one dpkg run (~2 s) added to a suite that measures 73 s worst against budget 100 s (`test-deb-lifecycle.sh`); the real suite is run at the checkpoint.
No e2e case.

- `.rpm` and Arch keep `tpm2-tss` → the existing `rpm-no-tss` / `arch-no-tss` cases still pass, and the good set passes with no `libtss2-rc*` name in rpm or arch.
- Dependency gate fails without it → `test-check-packages-deps.sh` cases `deb-no-tss-rc` (dep removed), `deb-tss-rc-recommends` (moved to Recommends), `deb-tss-rc-predepends`
  (moved to Pre-Depends) → each exits non-zero with `libtss2-rc0t64` in the output; the good set before the edit proves the test can pass.
- `.deb` Pre-Depends is `systemd (>= 257)`; rpm and Arch `>= 257` → good-set case of `test-check-packages-deps.sh` against the real nfpm.yaml; the old `deb-no-systemd`,
  `deb-systemd-only-in-depends`, `deb-systemd-in-both` cases still pass with the 257 string.

  plus `*-systemd-unversioned`, plus a package with no systemd requirement in each format (`deb-no-systemd`, `rpm-no-systemd`, `arch-no-systemd`) → each fails with the format label and `systemd` in the output.
  A fixture at 258 passes the version comparison (shows the check is a lower bound, not string equality), in a case that is expected to fail only for the unrelated string-table reason or is
  checked directly against the version comparison function by the test.
- Real dpkg refuses on systemd 255 → new case in `scripts/test-deb-lifecycle-real.sh`: dpkg without `--force-depends` exits non-zero, output names `systemd` and the installed version `255`, and the
  root has no custodio files installed → proven at the checkpoint (not in this `verify`). The same case against a 257 root installs, which is the control.
- `just quick` is green → run once when all steps are ticked.
