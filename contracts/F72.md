# F72 — Scope list, sign and import to the caller's uid

## Scope
F70 already keeps keys per owner and `dbus.rs` already takes the owner from `CallerCredentials` for
`ListKeys`, `ListCertificates` and `ImportP12`, and from the sender's credentials for `Sign`. This feature
makes that behaviour complete and proves it through D-Bus with two uids. What changes:

- **List.** Today the pair returns ids only and `(id, certificate)` only; neither says the key type, which
  the feature requires. Step 1 chooses one method or the pair, within one limit: a client gets, for each of
  the caller's keys, its id, key type and DER certificate, and the PKCS#11 module needs no other method. The
  choice and its reason go into `docs/api.md`. A removed method disappears from the service, the document,
  the module and the tests. List asks no polkit, never returns another uid's key, and with no sender, a bus
  that gives no uid, or a failed `ProcessFD` cross-check fails as `AuthorizationUnavailable`, never an empty
  or unfiltered list. A key whose certificate cannot be read is not silently dropped from the answer
  (store failure → `Internal`), because "each with id, key type and certificate" would otherwise be false.
- **Sign.** Order becomes: arguments → credentials → look the key up among the caller's keys → polkit →
  sign. A missing id and another uid's id give `NoSuchKey`, with no polkit call. Credentials failure keeps
  today's behaviour (`AuthorizationUnavailable`, no polkit). Journal behaviour of the new `NoSuchKey`
  refusal is a decision for step 2, within this limit: it is the same for a missing id and another uid's id
  (the tests compare them), it never contains the key's owner or any other uid's data, and it is recorded
  in `docs/decisions.md` only if a later session could undo it unknowingly. The default, if `SPEC.md` stays
  silent (it calls this question open), is M1's behaviour for a refusal before authorization: no entry,
  as for invalid arguments. Entries after polkit (denied, unavailable, signed, signing failed) are unchanged.
- **Import.** Stores under the caller's uid; succeeds for an id another uid uses; `KeyIdTaken` only for
  the caller's own id; no sender / no uid / failed cross-check → `AuthorizationUnavailable` before the `.p12`
  is read. Import still asks no polkit here (F73 adds it); the stale sentence in `docs/api.md` is F73's.
- **Followers.** `crates/custodio-pkcs11` (backend, fake, tests) moves to whatever list the step 1 choice
  gives, `crates/custodio-cli` and the e2e setup (`e2e/*.py`, `e2e/guest.sh`, cases) only if they use the
  changed method. The builder greps and records which needed a change; a follower with no use needs none.
- **Root** is a uid like any other: a test with uid 0 as one of the two callers.

Left for other features: polkit for import, journal entries for import (F73–F75), delete and replace
certificate. The unprivileged-real-process two-uid proof, package gates and `just e2e` run at F90/F100;
here two uids are simulated through the replaceable `CallerCredentials` interface, which the feature
names. The store-level separation is F70's. The feature is about five steps; no split is needed.

Environment: nothing beyond the dev container. The integration tests use the private `dbus-daemon` that
`crates/custodiod/tests/audit/bus.rs` already starts (the dev container runs it today with `just test`).

      connection to a uid, a counting polkit, the in-memory sink) and the list tests below. Then decide
      the list shape, change service, `docs/api.md` and the module/fake/tests, until `just api-contract`
      and the list tests pass.
- [ ] Sign: failing tests for missing vs foreign id (result, polkit calls, journal), then reorder the

      changed.

## Evidence
- Owner from bus credentials, never an argument → no method signature in `docs/api.md` and the live
  introspection has an owner/uid argument: `just api-contract` (existing item compare) green; and the
  two-uid tests below use the same call with only the connection's uid changing → different results.
- List returns only the caller's keys, each with id, key type and DER certificate →
  `tests/` D-Bus test `list_is_scoped_to_the_caller`: uid A imports an RSA and an EC key, uid B one EC key
  and another with A's id; each caller's list equals exactly its own `(id, type, cert)` set, types
  `rsa2048`/`ecdsa-p256` as in the import reply, certificate bytes equal the `.p12`'s certificate.
  The negative control is the mutant run (an unfiltered list), not a store double.
- List with no uid or failed cross-check → `list_fails_closed_without_credentials`: fakes returning
  `Missing`, `Bus`, and the real `BusCredentials` on a bus whose reply lacks `ProcessFD` (existing
  `Answer`/stub helpers) each give `AuthorizationUnavailable` for every list method, with keys present
  for the caller's uid (so an empty list would be visible), and polkit calls = 0.
- List asks no polkit → same test asserts the counting polkit saw 0 calls on success too.
- Documented choice, module needs nothing else → `docs/api.md` states the choice; `just api-contract`
  green; `cargo test -p custodio-pkcs11` green with the backend calling only methods the document lists;
  if a method is removed, `! grep -rn '<removed name>' crates e2e scripts docs/api.md` exits 0; its
  remaining uses in `tests/errors.rs`, `audit.rs`, `audit/timing.rs` and `dbus.rs` move to the new method
  and keep what they prove (none deleted).
- Import under the caller's uid, succeeds for another uid's id, `KeyIdTaken` only for own id →
  `import_is_per_owner`: A imports `k`; B imports `k` OK and both keys exist (A signs with A's, B's list
  has its own); A imports `k` again → `KeyIdTaken`; B's key and A's key unchanged after.
- Import with no credentials → `import_fails_closed_without_credentials`: `AuthorizationUnavailable` and
  nothing stored, for the same fakes as list; the call carries a malformed `.p12`, so the expected
  `AuthorizationUnavailable` (not the bad-`.p12` error) proves the check precedes reading the file.
- Unreadable certificate is not dropped → `list_reports_a_key_without_readable_certificate`: a stored key
  whose certificate entry is missing gives `Internal`, not a shorter list.
- Sign: missing id and another uid's id give `NoSuchKey`, with no polkit call → `sign_foreign_equals_missing`:
  with A owning `k` and B calling `Sign` on `k` and on `nope`, both error names equal `NoSuchKey`, polkit
  call count 0 for both; A's own sign of `k` still asks polkit exactly once and succeeds (control that the
  test can fail).
- Same polkit calls and same journal behaviour for foreign vs missing → the same test compares the full
  list of polkit subjects and the sink's entries (count and content) after each of the two calls, and
  asserts they are equal, plus the chosen behaviour (default: no entry). Run it for approve and deny
  answers so a polkit-before-lookup mutant fails.
- Credentials failure on sign unchanged → existing sign credentials tests stay green, unmodified.
- Root is a uid like any other → the two-uid test set is run once with caller uids 0 and 1000 (and
  not only the pair 1000/1001): root sees only its own keys, and is `NoSuchKey` on the other's.
- PKCS#11 module, CLI, e2e follow list → `cargo test -p custodio-pkcs11 -p custodio-cli` green; the grep
  for the removed method (if any) over `crates e2e scripts docs` returns only historical files
  (`CHANGELOG.md`, `PROGRESS.md`, `docs/milestones`, `contracts`); `just test-scripts` only if an e2e script
  changed; the e2e cases themselves run at F90/F100.
- Mutation coverage → `just mutants-diff F72` has no missed mutant in the changed code.
