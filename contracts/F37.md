# F37 — Package parity and C library ceiling gates

## Scope
Built here:
- `just package-parity`: `scripts/check-parity.sh [DIR [EXCEPTIONS]]` extracts the `.deb`, `.rpm` and
  `.pkg.tar.zst` in `target/packages` (same extraction approach as `scripts/check-packages.sh`) and lists every
  installed entry as path, type, mode, owner, group (and the target for symlinks). It fails if the three lists
  differ, except for the entries in `packaging/parity-exceptions.txt`. Each exception has a path, the packages it
  applies to, the differing field and a reason; the gate rejects an entry without a reason, an entry that matches no
  real difference (stale), and an unparsable line. The file is expected to hold no entries after F36 (comments
  only). Package metadata (`.PKGINFO`, `.MTREE`, `.INSTALL`, deb control, rpm header) is not an installed path and
  is not compared; metadata present in only one format is never a difference.
- Directory rule: a directory listed in all three formats is compared like any other entry. A directory listed in
  only some formats is ignored only if it is `0755 root root` (what rpm and pacman create for an implicit parent,
  which a deb records); any other mode or owner on it is a difference. The builder confirms this against the real
  listings and records the final rule in the script header; the rule is tested (see Evidence).
- Owner normalisation: only uid/gid `0` and the name `root` map to `root`. Any other owner, named or numeric
  (for example `1000 1000`), stays as it is and so is a difference.
- Fail-closed inputs, for both gates: the gate exits non-zero when `DIR` is missing or holds no package, when a
  format is missing or present more than once, and (glibc gate) when a package holds no ELF file or `readelf`
  fails on a file. A gate that checked nothing must not pass.
- `just glibc-ceiling`: `scripts/check-glibc-ceiling.sh [DIR [CEILING_FILE]]` extracts every package, finds every
  ELF file by magic bytes (not by a fixed path list, so a new binary is covered), reads its symbol version
  requirements (`readelf -V` / `--dyn-syms`, `GLIBC_x.y` only; `GLIBC_PRIVATE` is reported as a failure) and
  fails when the highest is above the ceiling. Versions are compared numerically per component, never as strings.
  The ceiling lives in `packaging/glibc-ceiling.txt` with its source: the glibc of each target (Debian 13,
  Ubuntu 26.04, Ubuntu 24.04, Fedora 44, Alma 10, Arch) with where the number was taken from. Arch is a rolling
  release, so it is listed with the version found at research time and the date, and is never the minimum (it
  must be newer than or equal to the others; the test checks it is not the minimum). Expected ceiling 2.39
  (Ubuntu 24.04 and Alma 10) unless the research finds a lower one. The script reads the number from that file
  (or from `CEILING_FILE`) and prints the highest version found per ELF file.
- `just package-gates`: new aggregate recipe, `package` then `package-parity` and `glibc-ceiling`. `check-slow`
  includes it. In `.github/workflows/ci.yml` each gate is its own named step in the existing `package` job (which is
  already in the `ci` job's `needs`), after the step that runs `just package`. Any later
  package gate (F38) is added to the same recipe by its own feature.
- Self-tests `scripts/test-check-parity.sh` and `scripts/test-glibc-ceiling.sh`, added to `package-gate-test`
  (so they run in `just check`), using fixture packages from `scripts/lib/package-fixtures.sh`.

glibc self-test mechanism: `just check` runs on hosts with different glibc (ubuntu-24.04 CI has 2.39, the dev
container 2.41), so no test may depend on the host's glibc relative to the committed ceiling. `test-glibc-ceiling.sh`
compiles (or reuses) one fixture ELF and reads its real highest `GLIBC_x.y` requirement from `readelf` (for example
2.34 for a program using a symbol that moved to 2.34). It then passes its **own** `CEILING_FILE`, written in the
test, set around that real version: the previous minor below it (must fail), equal to it (must pass), and above it
(must pass). The committed `packaging/glibc-ceiling.txt` is exercised separately (see Evidence).

ELF files with no `GLIBC_` requirement (for example a static fixture): the gate prints the file with the highest
version `none`, counts it as an ELF file for the "at least one ELF per package" rule, and passes it. It never prints
a blank version and never crashes on the empty set. A test pins this.

`GLIBC_PRIVATE` fixture: a tiny C program (or assembler file) with a `.symver` directive that references a real
`GLIBC_PRIVATE` symbol exported by the host libc (for example `__libc_enable_secure@GLIBC_PRIVATE`; the test picks
one that `readelf -Ws` shows on the host libc and skips nothing silently: if none is found the test fails). The
resulting ELF is run through the real gate, so the test exercises version extraction, not a text helper. If the
linker refuses the reference (for example binutils on the Ubuntu 24.04 CI runner), the test fails; it does not
skip and there is no fallback. The run on Ubuntu 24.04 CI is what proves the fixture works there, and the step that
writes it says so.

Numeric-vs-string fixtures: to prove `2.10` > `2.9` without needing such a symbol in the host libc, the test copies
the fixture ELF and byte-patches the version name of the `GLIBC_2.34` requirement in `.dynstr` (the `vna_hash` field
is irrelevant to `readelf`). `GLIBC_2.9` is written NUL-terminated into the 10-byte slot of `GLIBC_2.34`;
`GLIBC_2.10` fits the same slot, and a 2.99 patch likewise. The patched string must not be shared with another
entry in `.dynstr` (the test checks the name occurs once), and `readelf -V` must show exactly the patched name for
that `vna` entry. The test asserts this before using the file, so a broken patch fails the test rather than passing
vacuously.

Current state found while reading: the three shipped ELF files need at most `GLIBC_2.34`, so the ceiling is met
today without build changes. The builder confirms this in the dev container (Debian 13, glibc 2.41); the
"how the build meets the ceiling" choice is therefore "built on the dev container, verified by the gate", and
the gate is what keeps it true (a new dependency or a toolchain bump that raises it fails the gate). Left for
other features: lintian, rpmlint, namcap (F38), installing on real targets (e2e features), dependency and
soname checks (already in F36's gate; not duplicated here).

## Steps
- [ ] Research with a subagent the glibc version of Debian 13, Ubuntu 24.04, Ubuntu 26.04, Fedora 44, Alma 10 and
      Arch (distribution package pages or release notes, not memory); write `packaging/glibc-ceiling.txt` with the
      ceiling, each target's version and each source (Arch with the date).
- [ ] Tests first for the ceiling gate: `scripts/test-glibc-ceiling.sh` with fixture packages carrying the
      fixture ELFs described above (own `CEILING_FILE`s, `GLIBC_PRIVATE`, 2.9/2.10 patches, off-list deb-only ELF,
      non-ELF `.so`, fail-closed cases); wire it into `package-gate-test`. Then `scripts/check-glibc-ceiling.sh`
      and the `glibc-ceiling` recipe.
- [ ] Tests first for the parity gate: `scripts/test-check-parity.sh` (differing mode, owner including numeric
      non-root, missing path, extra path, symlink target, directory rule, metadata-only entries, fail-closed
      inputs, exception file cases). Then `scripts/check-parity.sh`, `packaging/parity-exceptions.txt` and the
      `package-parity` recipe.
- [ ] Add the `package-gates` recipe, include it in `check-slow`, and give each gate its own CI job or step
      (building or downloading `target/packages` first, tools installed as in the `package` job) and add the jobs
      to `ci` `needs`. Update the recipe comments of `check`/`check-slow`.
- [ ] Run `just check`, `just package`, `just package-parity`, `just glibc-ceiling` and `just package-gates`; run
      actionlint/zizmor via `just check` for the workflow; record the ceiling and its rationale in
      `docs/findings.md` and add a `docs/decisions.md` entry only if a rejected alternative (for example
      building against an old sysroot) deserves one.

## Evidence
- Parity compares installed paths, modes and owners of the three packages in target/packages →
  `scripts/test-check-parity.sh`: gate passes on three fixture packages from one file list, and on the real
  `target/packages` via `just package-parity` → exit 0.
- Fails if they differ (path) → test: one format lacks a file, then has an extra file → non-zero exit; output
  names the path and the format.
- Fails if they differ (mode) → test: one format has 0644 instead of 0755 on a file → non-zero exit, output
  shows both modes.
- Fails if they differ (owner) → test: one format has owner/group other than root → non-zero exit; the Arch
  fixture with numeric `0 0` against `root root` in the others → passes; the Arch fixture with numeric `1000 1000`
  → fails (normalisation maps only uid/gid 0 to root).
- Symlink target difference → test → non-zero exit.
- Directory rule → test: a directory that every format owns explicitly, with a mode differing in one format →
  non-zero exit; a directory present only in the deb at `0755 root root` → passes; present only in the deb at `0700`, or with
  owner `1000` → fails.
- Metadata is not compared → test: `.PKGINFO`, `.MTREE`, `.INSTALL` present only in the Arch fixture → passes.
- Differences listed in a committed file, each with a reason → test: an exception entry with a reason makes the
  fabricated difference pass; the same entry without a reason fails; an entry matching no difference fails
  (stale); a malformed line fails; an exception for the `mode` field on path X does not hide an `owner` difference on
  the same path X, nor a `mode` difference on X in a package the entry does not name, nor the same field on
  another path.
- The committed file is expected to be empty after F36 → `just package-parity` on the real packages passes with
  `packaging/parity-exceptions.txt` holding no entries (a command in the test greps that no non-comment line
  exists, so an added exception shows up in review).
- Parity gate fails closed → test: `DIR` missing, `DIR` empty, a format missing, a format present twice → each
  non-zero exit with a message naming the problem.
- Self-test for parity: a fabricated difference makes it fail → the cases above, all run by `just check` through
  `package-gate-test` → pass only because the gate exits non-zero on each.
- Reads every ELF file in every package → test: an ELF placed at a path not on any list, in the deb only, is
  found and checked (too-new version there fails); a non-ELF file with a `.so` name is ignored; `just
  glibc-ceiling` on the real packages prints, for each of the deb, rpm and Arch packages, the three ELF files
  `/usr/lib/custodio/custodiod`, `/usr/bin/custodio` and `/usr/lib/custodio/libcustodio_pkcs11.so` (nine lines in
  total) with their highest version → exit 0; the test asserts at least one ELF per package.
- Fails if any needs a glibc symbol version newer than the ceiling → self-test with its own `CEILING_FILE`
  around the fixture's real highest version V (read by `readelf`, independent of the host glibc): ceiling below V
  → non-zero exit naming file, package and version; ceiling equal to V → passes; ceiling above V → passes. A
  `GLIBC_PRIVATE` fixture (real `.symver` reference) → non-zero exit.
- Versions compare numerically → test: byte-patched fixture needing `GLIBC_2.10` with ceiling 2.9 → fails;
  fixture needing `GLIBC_2.9` with ceiling 2.10 → passes (a string comparison gets both wrong).
- Committed ceiling is honoured → test: a fixture ELF byte-patched to require `GLIBC_2.99`, run without
  `CEILING_FILE` → non-zero exit, and the output shows the committed number; with the committed file a fixture
  at 2.0 passes.
- ELF without `GLIBC_` requirement → test: a static fixture in a package passes, its line shows `none`, no crash.
- Glibc gate fails closed → test: `DIR` missing, `DIR` empty, a format missing, a format present twice, a package
  with no ELF file, and `readelf` failing on a file (a truncated ELF with valid magic, or `readelf` replaced by a
  failing stub on `PATH`) → each non-zero exit with a message naming the problem.
- Ceiling is the oldest glibc among the targets, including Ubuntu 24.04 and Alma 10, source recorded →
  `packaging/glibc-ceiling.txt` lists all six targets (Debian 13, Ubuntu 26.04, Ubuntu 24.04, Fedora 44, Alma 10,
  Arch) with versions and sources; a test checks that the ceiling the script uses equals the minimum of the six
  listed target versions (so editing one without the other fails), that Ubuntu 24.04, Alma 10 and Arch are listed,
  and that Arch is not the minimum (rolling release).
- Works in the dev container → `just glibc-ceiling` and `just package-parity` run there with only tools of
  `harness/Containerfile` (readelf, dpkg-deb, rpm, bsdtar, python3); the verify command is run there.
- Also run by `just package-gates`, which `check-slow` and CI include → `just --dry-run package-gates` lists
  both recipes; `just --dry-run check-slow` lists `package-gates`; `grep` of `.github/workflows/ci.yml` shows
  one named step per gate in the `package` job, each after the step that runs `just package`, and `package` in
  the `ci` job's `needs`; actionlint and
  zizmor pass within `just check`.
- Verify command → `just check && just package && just package-parity && just glibc-ceiling` → exit 0.
