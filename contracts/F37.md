# F37 — Package parity and C library ceiling gates

## Scope
Built here:
- `just package-parity`: `scripts/check-parity.sh [DIR [EXCEPTIONS]]` extracts the `.deb`, `.rpm` and
  `.pkg.tar.zst` in `target/packages` (same extraction approach as `scripts/check-packages.sh`) and lists every
  installed entry as path, type, mode, owner, group (and the target for symlinks). It fails if the three lists
  differ, except for the entries in `packaging/parity-exceptions.txt`. Each exception has a path, the packages it
  applies to, the differing field and a reason; the gate rejects an entry without a reason, an entry that matches no
  real difference (stale), and an unparsable line. The file is expected to hold no entries after F36 (comments
  only). Package metadata (`.PKGINFO`, `.MTREE`, `.INSTALL`, deb control, rpm header) is not an installed path and
  is not compared. Directories are compared only where all formats own them explicitly; the builder pins down
  which when it sees the three listings, and records it in the script header. Numeric and named root owner are
  normalised (bsdtar shows `0 0` for Arch).
- `just glibc-ceiling`: `scripts/check-glibc-ceiling.sh [DIR [CEILING_FILE]]` extracts every package, finds every
  ELF file by magic bytes (not by a fixed path list, so a new binary is covered), reads its symbol version
  requirements (`readelf -V` / `--dyn-syms`, `GLIBC_x.y` only; `GLIBC_PRIVATE` is reported as a failure) and
  fails when the highest is above the ceiling. The ceiling lives in `packaging/glibc-ceiling.txt` with its source:
  the glibc of each target (Debian 13, Ubuntu 26.04, Ubuntu 24.04, Fedora 44, Alma 10) with where the number was
  taken from. Expected ceiling 2.39 (Ubuntu 24.04 and Alma 10) unless the research finds a lower one. The script
  reads the number from that file and prints the highest version found per ELF file.
- `just package-gates`: new aggregate recipe, `package` then `package-parity` and `glibc-ceiling`. `check-slow`
  includes it. In `.github/workflows/ci.yml` each gate is its own job (or step with its own name) and is in the
  `ci` job's `needs`. Any later package gate (F38) is added to the same recipe by its own feature.
- Self-tests `scripts/test-check-parity.sh` and `scripts/test-glibc-ceiling.sh`, added to `package-gate-test`
  (so they run in `just check`), using fixture packages from `scripts/lib/package-fixtures.sh`.

Current state found while reading: the three shipped ELF files need at most `GLIBC_2.34`, so the ceiling is met
today without build changes. The builder confirms this in the dev container (Debian 13, glibc 2.41); the
"how the build meets the ceiling" choice is therefore "built on the dev container, verified by the gate", and
the gate is what keeps it true (a new dependency or a toolchain bump that raises it fails the gate). Left for
other features: lintian, rpmlint, namcap (F38), installing on real targets (e2e features), dependency and
soname checks (already in F36's gate; not duplicated here).

## Steps

      (distribution package pages or release notes, not memory); write `packaging/glibc-ceiling.txt` with the

- [ ] Tests first for the ceiling gate: `scripts/test-glibc-ceiling.sh` with fixture packages carrying a real
      ELF (a tiny C program, or a copy of a system binary) linked to a too-new symbol version; wire it into
      `package-gate-test`. Then `scripts/check-glibc-ceiling.sh` and the `glibc-ceiling` recipe.
- [ ] Tests first for the parity gate: `scripts/test-check-parity.sh` (differing mode, owner, missing path,
      extra path, symlink target in one format; exception file cases). Then `scripts/check-parity.sh`,
      `packaging/parity-exceptions.txt` and the `package-parity` recipe.
- [ ] Add the `package-gates` recipe, include it in `check-slow`, and give each gate its own CI job or step
      (with the tools installed as in the `package` job) and add the jobs to `ci` `needs`. Update the recipe
      comments of `check`/`check-slow`.
- [ ] Run `just check`, `just package`, `just package-parity`, `just glibc-ceiling` and `just package-gates`; run
      actionlint/zizmor via `just check` for the workflow; record the ceiling and its rationale in
      `docs/findings.md` and add a `docs/decisions.md` entry only if a rejected alternative (for example
      building against an old sysroot) deserves one.

## Evidence
- Parity compares installed paths, modes and owners of the three packages in target/packages →
  `scripts/test-check-parity.sh`: gate passes on three fixture packages from one file list, and on the real
  `target/packages` via `just package-parity` → exit 0.
- Fails if they differ (path) → test: one format lacks a file, then has an extra file → non-zero exit; output
  names the path and the format.
- Fails if they differ (mode) → test: one format has 0644 instead of 0755 on a file → non-zero exit, output
  shows both modes.
- Fails if they differ (owner) → test: one format has owner/group other than root → non-zero exit; and the
  Arch numeric `0 0` against `root root` in the others → still passes (normalisation does not hide real owners).
- Symlink target difference → test → non-zero exit.
- Differences listed in a committed file, each with a reason → test: an exception entry with a reason makes the
  fabricated difference pass; the same entry without a reason fails; an entry matching no difference fails
  (stale); a malformed line fails.
- The committed file is expected to be empty after F36 → `just package-parity` on the real packages passes with
  `packaging/parity-exceptions.txt` holding no entries (a command in the test greps that no non-comment line
  exists, so an added exception shows up in review).
- Self-test for parity: a fabricated difference makes it fail → the cases above, all run by `just check` through
  `package-gate-test` → pass only because the gate exits non-zero on each.
- Reads every ELF file in every package → test: an ELF placed at a path not on any list, in the deb only, is
  found and checked (too-new version there fails); a non-ELF file with a `.so` name is ignored; `just
  glibc-ceiling` on the real packages prints the three ELF files with their highest version → exit 0.
- Fails if any needs a glibc symbol version newer than the ceiling → self-test: fixture ELF requiring a version
  above the ceiling (and one exactly at the ceiling passes, one just below passes) → non-zero exit naming file,
  package and version; `GLIBC_PRIVATE` fails.
- Ceiling is the oldest glibc among the targets, including Ubuntu 24.04 and Alma 10, source recorded →
  `packaging/glibc-ceiling.txt` lists all five targets with versions and sources; a test checks that the
  ceiling the script uses equals the minimum of the listed target versions (so editing one without the other
  fails) and that Ubuntu 24.04 and Alma 10 are listed.
- Works in the dev container → `just glibc-ceiling` and `just package-parity` run there with only tools of
  `harness/Containerfile` (readelf, dpkg-deb, rpm, bsdtar, python3); the verify command is run there.
- Also run by `just package-gates`, which `check-slow` and CI include → `just --dry-run package-gates` lists
  both recipes; `just --dry-run check-slow` lists `package-gates`; `grep` of `.github/workflows/ci.yml` shows
  one job or step per gate and both in the `ci` job's `needs`; actionlint and zizmor pass within `just check`.
- Verify command → `just check && just package && just package-parity && just glibc-ceiling` → exit 0.
