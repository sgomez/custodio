# F170 — Research: who the socket peer is, as the service sees it

## Scope
Research only. It writes `docs/findings/F170.md` (headed `## F170`, under 5000 tokens, conclusion first,
each claim marked **verified** or **inferred**, ends with `Decision: ` lines), its index line in
`docs/findings.md`, and, only if the first question has no answer, `BLOCKED.md`. No product code,
no unit change, no edit to `SPEC.md`. Recording the handshake choice in `docs/decisions.md` is left to
the feature that builds the socket (it reads the `Decision:` lines here).

The three questions are the SPEC open questions "The real uid under `PrivateUsers=`" and "polkit's
`unix-process` pidfd subject", and the handshake of Design 1. The other open questions are other features'.

Environment, probed in this session (the contract's builder repeats nothing but the measurement it needs):
- `podman run --rm --privileged docker.io/library/alpine true` works (pulls over the network), so the
  privileged systemd container that `just e2e` uses is available, and `scripts/vm-host-check.sh` reports
  swtpm, seed tool and keyring OK with `/dev/kvm` openable, so `e2e/vm/vm.sh` (Ubuntu 26.04) can boot too.
- `systemctl --version` here is systemd 257 (257.13); `systemd-analyze security --offline=true
  data/custodio.service` gives 0.7 SAFE. That is M5's score, the number to keep.
- The dev container itself has no systemd as PID 1, so the socket-activation probe runs in the ubuntu2604
  test container (`e2e/targets/ubuntu2604/Containerfile`, systemd 259-class) or, if nested
  `PrivateUsers=` does not work there, in the VM. The finding says which, and the systemd version used;
  the shipped floor is systemd 257, so the 257 behaviour is taken from its source or man page when
  the probe's version is newer, marked **inferred**.

Cost: no new test, suite, e2e case or script in the repository. Probes are scratch files outside the
repo (not committed); the finding quotes the commands and the lines of output. The container probe takes
about 1 to 2 minutes per run (image build is cached by e2e), the VM fallback about 4 minutes; the loop's
`verify` is a few greps, well under a second. Nothing here touches `budgets.tsv`. Package gates, install
and lifecycle tests, `just e2e`: not run, and nothing here is proven only by them.

The feature fits in five steps; no split.

## Steps
- [ ] Question 1, measure: under a copy of the shipped unit (`DynamicUser=yes`, `PrivateUsers=yes`) with a
      socket-activated test socket, record what `SO_PEERCRED` (and `SO_PEERPIDFD`) reports for a peer of
      another uid, in the test container or the VM.
- [ ] Question 1, candidates: for `PrivateUsers=identity` (systemd 257 floor; man page or source for 257),
      any other kernel-guaranteed source of the real uid that works inside the namespace, and dropping the
      user namespace, record what the service sees, whether the unit still starts, and the
      `systemd-analyze security` exposure score of the changed unit against M5's 0.7 (same command).
- [ ] Question 2: read zbus's server-side authentication (the version in `Cargo.lock`) and run a minimal
      peer-to-peer server under the same unit with `ANONYMOUS` and with `EXTERNAL`, a client of another
      uid; record which handshakes succeed, and what identity the server can take only from the kernel.
- [ ] Question 3: from polkit's sources (a subagent reads them), for each of 124, 125, 126, 127 and the
      version each target ships (debian13, ubuntu2604, fedora44, alma10, arch; from the distribution's
      package metadata), whether a `unix-process` subject `{pidfd, uid}` is accepted when asked by a trusted
      caller (`org.freedesktop.policykit.owner`) for another uid; then measure it once on ubuntu2604 with the
      shipped policy file.
- [ ] Write the finding with `Decision: ` lines, add its line to `docs/findings.md`; write `BLOCKED.md`
      only if no uid route keeps the exposure score (otherwise skip it with `- [-]`-style note in PROGRESS);
      append `PROGRESS.md`; run `just quick`; commit `docs(F170): ...`.

## Evidence
- Real uid under `PrivateUsers=` (what `SO_PEERCRED` reports for another uid: 65534 or the real one) →
  the probe command and its output line in the finding, with the systemd version and where it ran → a
  stated uid value, marked **verified**; it would fail if the probe printed a value the finding does not match.
- Candidates (identical-uid mode on systemd 257, another kernel source, dropping the namespace) → per
  candidate, the probe's output and the `systemd-analyze security` score line → a table with, for each,
  the uid seen, the score against 0.7, and whether the unit starts; an option that raises the score above
  0.7 is marked as breaking the rule, not chosen.
- "If no uid route keeps the exposure score, `BLOCKED.md`" → the table above → either a `Decision:` line
  naming the route that keeps the score, or `BLOCKED.md` with the question and options, committed.
- Handshake (ANONYMOUS versus EXTERNAL) → zbus source lines read (file and line) plus the probe's result
  for each mechanism with a client of another uid → a stated outcome per mechanism and a `Decision:` line
  naming the mechanism under which identity comes only from the kernel.
- polkit `unix-process` `{pidfd, uid}` acceptance → source file and lines per polkit version, the
  version each target ships (package metadata line) → a table version/target/accepts, **verified** where
  the source was read, **inferred** where not.
- Measured on ubuntu2604 → the `CheckAuthorization` (or equivalent) call by a trusted caller for another
  uid and its reply line, and the same without the `owner` annotation → accepted with it, refused without;
  a `Decision:` line says what the service does where the version does not accept (fail closed).
- Verify keywords and structure (`## F170`, the ten words, a **verified**/**inferred** mark, a `Decision: `
  line, the index line) → the loop's `verify` command → exit 0.
- Index line in `docs/findings.md` and the file under 5000 tokens → `just quick` (`scripts/check-files.sh`)
  → green.
