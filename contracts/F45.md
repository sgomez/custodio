# F45 — End-to-end harness per target, with Debian 13

## Scope
Turn the single-distribution `e2e/` harness into a per-target one and add the first target.

Built here:
- `just e2e <target>` and `just e2e all` (the default). A target is a directory `e2e/targets/<target>/` holding its `Containerfile`, its
  `skip.list` and whatever the target needs for the steps that differ between distributions (how the package is installed, how the
  bus daemon and polkit versions are read). Adding a target adds a directory and touches no shared script. `all` runs every directory
  under `e2e/targets/`, so F46 and F47 only add directories.
- The host script builds the packages (`just package`), builds the target image, boots it as a privileged systemd container, and
  runs one shared guest script. The package reaches the container as a mounted file and is installed by the target's own tool
  (`apt`/`dpkg` for `debian13`). The image never contains the package. The existing suite (composed and raw signing, polkit asked
  once per signature, denial, polkit unavailable, NSS, journal checks) is reused unchanged in meaning; moving files is allowed.
- The record of the run: the system bus daemon actually running and its version, the polkit version, and the target name, printed
  and saved to a file under `target/`.
- Skip lists and their enforcement: a per-target committed `skip.list` (case and reason per entry), a mechanism by which the
  suite reports the cases it skipped, and a check that fails the run for any skipped case not on that target's list. The check is a
  script testable without a container engine.
- Target `debian13`: the current `e2e/Containerfile` (Debian trixie, real `polkitd`, default `dbus-daemon`) moved there. Its skip
  list may be empty if nothing is skipped; the file must exist.

Not here: Ubuntu, Fedora, Alma and Arch targets (F46, F47, Ubuntu's own feature), the lifecycle cases (upgrade, removal, purge,
reinstall, refusal on a bus without `ProcessFD`), CI wiring, the manual runs. Those other features' own `verify` commands name
their images. Running the suite in a container needs podman or docker and is not part of `just check`; `test-scripts` proves the
host logic with a stub engine, and one real run proves the whole.

Size: about six steps; no split needed.

## Steps
- [ ] Decide in the header of the new test where each behaviour is checked (stub-engine test, skip-enforcement test, real run) and
      write the failing tests first: the skip-enforcement test and the stub-engine test, both added to `test-scripts`.
- [ ] Skip lists: define the file format (case and reason, comments allowed), write the enforcement script and make the existing
      suite report skipped cases in the form it reads. Reject an entry without a reason or a malformed line.
- [ ] Create `e2e/targets/debian13/` (Containerfile moved, `skip.list`, the target's install and version-probing steps) and make the
      shared guest script target-neutral: it calls the target's install step instead of `dpkg -i`.
- [ ] Rewrite the host script to take a target (default `all`), validate it, build the packages, build the image, mount the package
      and run the guest; make `just e2e` take the argument; `all` iterates the directories; a failed target does not stop the others
      from running but fails the whole command.
- [ ] Record the bus daemon and the polkit version: read inside the container from the running system, print them and save them to
      a file named by the target under `target/`.
- [ ] Update docs that mention `just e2e` or `e2e/Containerfile` (README, harness text, shell-script lists, lint inputs), run `verify`,
      and run `just e2e debian13` and `just e2e` (all) for real if an engine is available; record the output lines in `PROGRESS.md`.

## Evidence
- `just e2e <target>` builds the packages, boots a privileged systemd container from `e2e/targets/<target>/Containerfile` and runs
  the guest → `scripts/test-e2e-host.sh` (in `test-scripts`) with a stub `podman` on `PATH` that logs its arguments → the log
  shows, in order, a build with that target's `Containerfile`, a `run` with `--privileged`, an `exec` of the shared guest script,
  and `just package` (or its recipe) having been run before; with a target name that has no directory, the script exits non-zero
  and names the available targets, and the engine is never called.
- Default is `all`, and `all` covers every target directory → same test with two fake target directories in a temporary tree
  (the test points the script at it) and no argument: both are built and run; with one made to fail, the other still runs and the
  exit status is non-zero. This is also the proof that adding a target is a new directory only: the second fake directory is
  copied in with no edit to any script.
- The package is installed by the target's own tool, never by copying, and the image does not contain it → the same test asserts
  that the engine call mounts the package read-only and that no `COPY`, `ADD` or `cp` of a package appears in any
  `Containerfile` under `e2e/targets` (grep in the test, with a control: a fixture Containerfile that copies a `.deb` is
  rejected); `e2e/targets/debian13` install step runs `apt` or `dpkg` on the mounted file (`grep` in the test), and the shared
  guest script contains no `dpkg`, `apt`, `rpm` or `pacman` call and no `cp`/`install` into `/usr` or `/etc`.
- The real distribution's polkit and default bus daemon are used → `Containerfile` of `debian13` installs `polkitd` and `dbus` from
  the distribution and installs no other bus daemon (`dbus-broker`) or polkit, asserted by grep in the test and proven by the
  run record below; the real run's record names `dbus-daemon` for Debian 13.
- Each run prints and saves which bus daemon and polkit version it used → the stub-engine test has the fake `exec` print the
  record the guest would, and asserts the host prints it and writes the file under `target/` with target name, daemon and version;
  in the real run (`just e2e debian13`) the saved file names the daemon running as the system bus (read from the process
  listening, not from the package list) and the version `pkaction --version` / the polkit package reports; both lines are in
  the output. A guest whose probe returns nothing fails the run (negative control in the stub test).
- Target `debian13` exists and has the required files → `verify` (`test -f` on `Containerfile` and `skip.list`, `grep -i polkit`
  under `e2e/targets`), and `bash -n e2e/*.sh` passes; shellcheck covers the new scripts through `just check` (the file list
  includes `e2e/targets/**` scripts: the test asserts the list contains them).
- The existing suite runs through one shared guest script → real run `just e2e debian13` passes with the cases of M1 (composed
  and raw signing, polkit asked once per signature, denial, polkit unavailable, NSS, journal): exit 0 and the guest's per-case
  results listed. Not run without an engine; then `PROGRESS.md` says so and the stub test is the evidence for the host side.
- A committed skip list per target in a stated format → `test-e2e-skips.sh` (in `test-scripts`) accepts a well-formed list with
  comments and blank lines, and rejects an entry without a reason, a line without a case, a duplicate case, and a missing file.
- The suite fails if any case is skipped that is not on the list, and `just test-scripts` tests that enforcement → the same test
  feeds the enforcement script reports of skipped cases: (a) none skipped → pass; (b) a skipped case on the list → pass; (c) a
  skipped case not on the list → non-zero exit naming the case; (d) a case listed for another target but skipped here → fails;
  (e) the case name matches on the whole name, not a prefix. These are the negative controls. Wiring: the guest or the host
  runs the enforcement on the real report, proven by the stub-engine test having its fake `exec` report an unlisted skip and the
  host script exiting non-zero, and a listed skip exiting zero. Also, a skip that the suite does not report at all must not be
  possible: the test greps the suite scripts to show there is one reporting function and no other way to skip (no bare
  `exit 0` before the end of a case) and the report is read from the guest after the run, not from its exit status alone.
- Entries on the list that no longer match a skipped case are reported (not failed) so the list does not rot → covered in the
  same test, as a message on stderr and exit 0.
- Nothing weakened → `just check && just test-scripts` (verify) pass with no gate, threshold or existing test altered; the
  M1 e2e scripts keep their `bash -n` and shellcheck status.
