# F125 — Packages declare the TPM2 Software Stack

## Scope
`packaging/nfpm.yaml`, `scripts/package_expected.py` (the soname table and the expected dependency lists), a new
`scripts/check-tss-deps.sh` (with a Python helper if the builder wants one), `scripts/test-check-packages-deps.sh`, the justfile only if the
new script needs a recipe line, and `docs/install.md`. Nothing else.

- **Starting point (dev container, run in this session).** `cargo build --release -p custodiod --locked` then `readelf -d` shows
  `custodiod` NEEDs `libtss2-esys.so.0`, `libtss2-tctildr.so.0` and `libtss2-mu.so.0` besides libc/libgcc_s. `scripts/check_packages.py`
  already fails any soname missing from `NEEDED` in `package_expected.py`, so the package gate is red for the new binary until the table
  and `nfpm.yaml` follow; this feature makes the "package checks expect the new dependencies" part true. The dev container has
  `libtss2-*` 4.1.3 and `tpm-udev` installed (`dpkg -l`), so the Debian-family package names can be confirmed here (`dpkg -S`, `dpkg-query`);
  the RPM and Arch names come from the findings (F109: `tpm2-tss` owns the rules and the `tss` group on fedora44, alma10 and arch) and
  from `rpm`/`pacman` metadata the builder can reach; any name that can only be inferred is said so in the commit.
- **Dependencies declared** in each format: the package providing each of the three sonames; the package that creates the `tss` group
  (F109: `tpm-udev` on the Debian family, `tpm2-tss` on RPM and Arch); and the `systemd` version that F110's decisions need for
  `systemd-creds` (the builder reads the F110 `Decision:` lines and declares the lowest version that the per-target decisions rely on;
  if F110 needs none beyond what is declared, the commit says so). Names follow the existing per-format style (deb `Depends`, rpm, Arch).
  `systemd` stays a `Pre-Depends` in the deb; a version bound goes there, not in `Depends` as well.
- **`scripts/check-tss-deps.sh <binary> <nfpm.yaml>`.** Reads the binary's NEEDED entries, picks every `libtss2` one, maps each to the package
  name for deb, rpm and Arch (one shared table with `package_expected.py`, not a second copy), and checks the `nfpm.yaml` overrides declare
  it for each format. It fails, naming the soname, the format and the missing package, when one is missing; when a `libtss2` soname has no
  entry in the table; and when the binary has no `libtss2` soname at all (an exit status and message of their own). It names a missing tool
  (`readelf`) and a missing file. It checks only `libtss2` sonames; libc and libgcc stay with `check-packages.sh`.
- **`docs/install.md`** lists the TPM2 Software Stack packages per distribution family and the `tss` group source, as the declared lists say.
- **Proven at the checkpoints, not here:** installing the packages on the six targets and `custodiod` starting with its libraries
  (F90, F100); the real `tss` group at install time (F109 inferred whether `tpm-udev` tolerates an existing group; F147/e2e).
- **Size:** about five steps; no split.

## Steps
- [ ] Failing cases first in `scripts/test-check-packages-deps.sh` (names in Evidence); run them to see them fail.
- [ ] Extend the soname table and the expected dependency lists in `package_expected.py`; add the `tss`-group and `systemd` version
      expectations; confirm the package names per format (record any inferred one in the commit).
- [ ] Add the dependencies to `packaging/nfpm.yaml` for deb, rpm and archlinux.
- [ ] Write `scripts/check-tss-deps.sh` and make the table the single source for it and the package gate.
- [ ] Update `docs/install.md` (its list is tested against `nfpm.yaml` and the table by running the check, not by grepping prose; the
      builder picks the smallest test that fails when the list and the packaging disagree).
- [ ] Run `just quick`, then the `verify` command and the evidence below.

## Evidence
- Declared TSS libraries (all three sonames, each format) → `scripts/check-tss-deps.sh target/release/custodiod packaging/nfpm.yaml` → exit 0.
- Package gate expects them → `test-check-packages-deps.sh` cases `deb-no-tss-esys`, `rpm-no-tss-esys`, `arch-no-tss-esys` (and the same for
  `tctildr` and `mu`, as a loop) delete the dependency from a fixture package → the gate fails and names the package; the good set passes.
- Group and systemd version → cases `deb-no-tss-group`, `rpm-no-tss-group`, `arch-no-tss-group` (the package that creates `tss`) and
  `*-systemd-too-old` (a bound below the decided one) → the gate fails naming it; the deb case also fails with the version bound added to
  `Depends` as well as `Pre-Depends`.
- A new soname the table lacks → existing `needed-unknown` style case with a `libtss2-foo.so.0` → the gate fails naming the soname.
- `check-tss-deps.sh` negative controls (new section of `test-check-packages-deps.sh`, on fixture `nfpm.yaml` copies edited with
  `nfpm_edit.py` and on ELF fixtures patched with `elf_patch.py`): one dependency removed per format → exit non-zero, output names soname,
  format, package; an unknown `libtss2-*.so.9` soname → fails naming it; a binary with no `libtss2` soname (libc only) → fails with the
  "needs no libtss2" message, distinct from the missing-dependency one; missing binary file, missing `readelf` → fails naming it; the real
  binary and real `nfpm.yaml` → passes (the positive control).
- Table is shared → a case that adds a soname only to the table (not to a second list) shows both the gate and `check-tss-deps.sh` see it.
- `docs/install.md` lists them → the test the builder picks fails when a name in the list differs from `nfpm.yaml`/the table (negative control
  on an edited copy of the document) and passes on the real files.
- Whole feature → the `verify` command: `just quick && scripts/test-check-packages-deps.sh && cargo build --release -p custodiod --locked &&
  scripts/check-tss-deps.sh target/release/custodiod packaging/nfpm.yaml` → exit 0.
