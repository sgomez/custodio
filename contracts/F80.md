# F80 — Parse and validate the flatpak app-id

## Scope
F67 decided **(c)** (`docs/findings.md` `## F67`, "What a reader needs"): the app-id source is the name of the
caller's cgroup scope, `app-flatpak-<E>-<N>.scope`, not `/.flatpak-info`. This feature builds only the pure part: a
module `app_id` in custodiod (`crates/custodiod/src/app_id.rs`, declared in `lib.rs`) with no I/O, no clock, no
logging and no dependency on a bus, a file or a process. It is added to the `mutants` recipe in `justfile`.

- **Input.** Bounded bytes: the scope name (a directory-entry name, bytes not text). Anything longer than the bound
  the finding fixes (255 bytes, including `.scope`) is "could not be determined" without being scanned further.
- **Three outcomes**, one public type the later entries use (F82): `Read(AppId)`, `None` (the caller is not in a
  flatpak scope) and `Undetermined`. `AppId` can only be built by the validator and holds a validated string; the
  invalid text is never returned, stored, or put into a `Debug`, `Display` or error value.
- **Parsing** per the finding: prefix `app-flatpak-`, suffix `.scope`, exactly one `-` in the middle (split at the
  last `-`), instance id of 1 to 10 decimal digits fitting a u32, `<E>` unescaped accepting only `\x2d`, then
  validated as a flatpak application id (`flatpak_is_valid_name`: not empty, at most 255 characters, at least three
  elements, elements of `[A-Za-z0-9_-]`, no element empty, none starting with a digit, `-` only in the last element,
  no leading `.`). The portal's regex is not used.
- **None vs undetermined.** A name that does not start with `app-flatpak-` (for example `app-gnome-gedit-99b.scope`,
  `init.scope`) is `None`; a name that does start with it but fails any rule is `Undetermined`. The module only
  classifies one name; deciding that a whole scan found no flatpak scope (also `None`) is F81's reader.
  The absent case at this level is the absent input: no name given → `None`.
- **Left for other features.** Reading the pinned process, the cgroup tree, deadlines, the same-process check (F81);
  fields in entries and `docs/audit.md` (F82); fuzz target for the parser (F83). Pure parsing proven here is not
  proven again there. Size: about four steps; no split.

Environment: nothing beyond the dev container (no I/O, so no environment check is needed).

## Steps
- [ ] Failing tests first: `app_id` unit tests (in a `tests` submodule, under the file-size gate), one group per
      Evidence row, with the three-outcome type stubbed.
- [ ] The validator for a flatpak application id (every rule) and the `AppId` type; its tests pass.
- [ ] The scope-name parser (prefix, suffix, one `-`, instance id, unescape, bounds) and the three outcomes; the
      tests pass.
- [ ] Add `crates/custodiod/src/app_id.rs` to `mutants` in `justfile`.
- [ ] `just quick`, then `just mutants-diff F80` until clean (kill survivors with tests); append `PROGRESS.md`.

## Evidence
All are unit tests in `crates/custodiod/src/app_id/tests.rs` (or the module's `tests`), table-driven, with literal
expected values.
- Valid ids are read → `valid_scope_names_are_read`: `app-flatpak-org.example.App-123.scope` style names for a
  3-element id, a many-element id, `_` in any element, `-` in the last element only, digits not at the start of an
  element, an id of exactly 255 characters (the scope name bound allowing), `\x2d`-escaped `-`
  (`org.example.My_App\x2dName` → `org.example.My_App-Name`); the result equals the literal id and the instance id
  does not appear in it.
- Every validation rule has a rejecting case, one test each, each failing if its rule is removed → 
  `rejects_fewer_than_three_elements` (1 and 2 elements), `rejects_empty_element` (`..`, trailing `.`),
  `rejects_leading_dot`, `rejects_leading_digit_in_any_element`, `rejects_dash_outside_last_element`,
  `rejects_bad_characters` (space, `/`, `:`, non-ASCII, control bytes, NUL, `\x2f` and any escape except `\x2d`,
  an incomplete or upper-case-hex escape), `rejects_id_over_255_characters` (255 accepted, 256 rejected, by the
  validator directly so it is independent of the name bound), `rejects_empty_id`. Each yields `Undetermined`.
- Scope-name structure → `rejects_malformed_scope_names`: missing `.scope`, other suffix (`.service`, `.slice`),
  zero or two or more `-` after the prefix, empty or non-digit or 11-digit or u32-overflowing instance id, empty
  `<E>`, trailing garbage after `.scope`, `app-flatpak-` alone: all `Undetermined`. Boundary: instance id with 10
  digits that fit a u32 is read; `4294967295` read; `4294967296` rejected.
- Malformed and non-UTF-8 input → `non_utf8_and_binary_input_is_undetermined`: invalid UTF-8 after the prefix,
  a lone `0xff`, overlong encodings, NUL bytes; plus `non_utf8_without_the_prefix_is_none` (bytes that are not the
  prefix are `None` and never decoded).
- Oversized input → `oversized_name_is_undetermined`: 255 bytes accepted when valid, 256 and a megabyte of valid
  looking bytes `Undetermined` (a prefix-matching name), and the check does not allocate a copy of the input.
  The oversize bound constant equals the finding's 255.
- Absent / not flatpak → `absent_and_other_scopes_are_none`: no input, empty input, `app-gnome-gedit-99b.scope`,
  `init.scope`, `app-flatpak.scope` (no trailing dash, so no prefix): `None`; a name that merely contains the
  prefix elsewhere is `None`, not `Read`.
- Invalid text never escapes → `undetermined_carries_no_text`: `Undetermined` and `None` have no payload (checked
  by a compile-time shape: `matches!` on unit variants), the `Debug` output of the outcome for a hostile name that
  contains a marker string does not contain the marker, and `AppId` has no public constructor from a string
  (a `compile_fail` doctest).
- Pure, no I/O → a source check test `module_has_no_io` greps `app_id.rs` (excluding tests) for `std::fs`, `std::io`,
  `std::process`, `std::time`, `tokio`, `zbus`, `tracing`, `println` and fails on any; documents the claim.
- Joins `mutants` → `app_mutants_recipe_lists_the_module` (a test or `grep` in the `justfile` checks the path);
  and the real proof is `just mutants-diff F80` (verify): no missed mutant in `app_id.rs`.
- Negative control: one test is run against a deliberately weakened validator (for example `>= 255` instead of `> 255`,
  or no check of a leading digit) during step 3, shows red, and is reverted; the builder notes this in `PROGRESS.md`.
- If F67 had decided (d): not applicable; F67 decided (c), so the three outcomes above are defined and used by
  the scope parser.
