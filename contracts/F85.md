# F85 — PKCS#11 module on the documented API

## Scope
Today the module already goes through `custodio-client` (F64) and talks to the service with
`ListKeys` and `Sign` only (`crates/custodio-pkcs11/src/backend.rs`); F65 mapped the error names
for `Sign`. What this feature proves and, where it falls short, builds:
- The module's calls are exactly what `docs/api.md` describes: method names, argument and result
  signatures, bus name and path from the client crate. The module needs `ListKeys` and `Sign`
  and nothing else (api.md says so); it never calls `DeleteKey`, `ReplaceCertificate`, `ImportP12`.
- Every documented error name (all ten in the client crate) maps to a CKR code, for both calls
  (`ListKeys` too, not only `Sign`). CKR values per case stay as F65 left them (the existing
  table in `backend/tests.rs`); any name missing from the table or any changed value is a fix here.
- Visible behaviour with real uids: the module shows as tokens exactly the keys `ListKeys`
  returns for the calling uid; after `ReplaceCertificate` the next call (a fresh token query or
  `C_GetSlotList`/`C_FindObjects` in a new session) shows the new certificate and a signature
  verifies with it; after `DeleteKey` the key's token is gone and no object remains for it.
- The integration fixture (`crates/custodio-it/tests/cryptoki`) gets a replaceable credentials
  source so one service serves two uids (switchable per child process run), plus helpers to call
  `ReplaceCertificate` and `DeleteKey` on the bus as the "other client" (tests drive them through
  the service; the module itself never does).
- Any module code that still assumes pre-F72 behaviour (unfiltered list, a key type read from
  elsewhere, unknown-name handling) is fixed; if nothing is, the steps say so.

Not here: `src/ffi` is unchanged (the diff must not touch it; the FFI layer's tests are the
existing ones); the CLI (F86+); the service itself (F72, F76, F78: the scoping, delete and replace
semantics are proven there, here only through the module); `just e2e`, package gates and the real
packaged-module runs are proven at F90/F100. The M1/M2 guarantees (a connection per call, fork
safety, no leftover threads, no slots without the service) already have cryptoki tests
(`signing_leaves_no_helper_threads`, `fork_while_other_threads_use_the_module`,
`without_the_service_there_are_no_tokens`, `threads_can_sign_at_once`); they must keep passing with
the changed fixture and are re-run here, not rewritten.
Environment: the cryptoki tests need `dbus-daemon` and a built module; the existing
`custodio-it` cryptoki tests already run in this container under `just quick`.
Size: about five steps; no split.

## Steps
- [ ] Read the module and the existing cryptoki fixture; list in `PROGRESS.md` any place where
      the module's use of the API differs from `docs/api.md` (expected: none) and fix it test-first.
- [ ] Fixture: the service in `parent.rs` uses a switchable fake credentials source (uid per run),
      keys can be imported for any uid, and the monitor records the member of every call to the
      service; existing tests keep passing with the real-looking default uid.
- [ ] Error mapping: extend the `backend/tests.rs` table so all ten documented names are
      covered for both `ListKeys` and `Sign` paths, plus an unknown name and the two fdo names.
- [ ] Cryptoki tests: two uids; replaced certificate; deleted key; module's calls only
      `ListKeys`/`Sign`.
- [ ] Run `just quick`, then `just mutants-diff F85`; fix surviving mutants with tests.

## Evidence
- Module uses only the documented API → cryptoki test `module_calls_only_documented_methods`
  (monitor over a list, find-objects, sign scenario): every recorded member is `ListKeys` or
  `Sign`, with bus name and path equal to the client crate's constants (existing
  `bus_names_match_the_service`); would fail if the module called anything else.
  Module/CLI independence from `custodiod` → `just deps-check` inside `just quick` (F64), not
  repeated.
- Documented error names → CKR codes → unit test in `backend/tests.rs` over all ten
  `ERROR_*` constants of the client crate, the two fdo names and an unknown name, asserting the
  exact `BackendError`; plus one test through the real `Backend` against a fake bus service that
  returns each name from `ListKeys` and from `Sign`, asserting the resulting CKR code at the
  `Backend` caller. A mutant that swaps a mapping fails it.
- A process sees only its own uid's keys → cryptoki test `two_uids_see_only_their_own_keys`:
  service holds key `a` for uid A and `b` for uid B (and the same id `shared` for both with
  different certificates); the module run as A lists tokens/certificates for `a` and A's `shared`
  only; run as B the mirror; signing as A with B's id fails exactly as a missing id; a uid with
  no keys sees no token. Fails if the list is unfiltered or the wrong uid's certificate shows.
- Replaced certificate is what the module exposes next → cryptoki test
  `a_replaced_certificate_is_exposed_on_the_next_call`: module run before shows cert 1 for the
  id; `ReplaceCertificate` with cert 2 for the same key; a second run (and a second call in the
  same loaded module, no restart) shows cert 2 and its bytes differ from cert 1; a signature
  made then verifies with cert 2's public key. Fails if the module caches the certificate.
- Deleted key has no token → cryptoki test `a_deleted_key_has_no_token`: before, token exists;
  after `DeleteKey` the next call shows no token/objects for it, other keys remain, and signing
  with the old id fails; a re-imported id shows again.
- Every polkit-guarded signature still asks, a connection per call, fork safety, no thread left
  behind, no slots without the service → the existing cryptoki tests named in Scope pass
  unchanged in assertion, run by `just quick`.
- FFI layer unchanged → `git diff <base> -- crates/custodio-pkcs11/src/ffi*` is empty (checked by
  the evaluator; `mutants-diff` then has no `src/ffi` mutants).
- Tests can fail → negative control (reverted): make the fixture's uid filter ignore the caller
  (or have `ListKeys` fake return all keys) and `two_uids_see_only_their_own_keys` fails; make
  the backend cache the list and the replace test fails.
- `just mutants-diff F85` → no missed mutant in the changed module code.
