# F155 — The credential client keeps only the user-scoped Varlink route

## Scope
Design 5, service. Built here, all in `crates/custodiod`:
- `src/creds/systemd.rs`: the `systemd-creds` CLI route goes away with everything only it used: `run`, the launcher and `with_launcher`, `LAUNCHER`,
  `PROGRAM`, the close-descriptors script, `tpm_args`, `encrypt_cli`/`decrypt_cli`, `Failure`, the `program`/`launcher`/`tpm` fields, and the `tpm` parameter of
  `new`/`system`. What chooses between the routes goes too (the `match (&self.tpm, binding)` in `decrypt`, the `tpm` branch in `encrypt`). `encrypt` and `decrypt` call
  Varlink `Encrypt`/`Decrypt` (scope `user`, no `withKey`) and nothing else. Code left unused by this (base64 encode, `Binding` import, `secret`) is removed too, unless a remaining caller needs it.
  There is no version probe or setting today, and none is added. `main.rs` (already `SystemdCreds::system(None)`) and the module docs in `creds.rs`/`systemd.rs` follow.
- `src/creds/header.rs` and the guard in `seal` (`creds.rs`) are **not changed**: nonzero PCR mask, null key, `TooShort`, and the binding-versus-kind check in `import/protect.rs` / `store/record.rs`. Their existing
  unit tests stay as they are. `Binding::Tpm` stays: a TPM-bound credential (made by the user-scoped daemon when it finds a TPM) is still a valid stored form.
- No stored-credential migration, no new setting (nothing is in use before M6).
- Tests removed with the route: the CLI cases in `src/creds/systemd/tests.rs` (`the_tpm_command_line_names_no_pcr_and_no_data`, the launcher/`bad_names_never_reach_the_service` parts that start a program,
  `a_tpm_credential_is_not_sent_to_the_tpm_when_none_is_configured`), `tests/sign_kinds/descriptor.rs` (its subject, the child's inherited descriptors, no longer exists) and the CLI-bound cases of `tests/creds.rs`
  (`tpm_bound_round_trip`, `cleared_tpm_cannot_decrypt` as built on the CLI, the `swtpm` client). Removal is per test and each is named in the commit.
- Tests that must be **rebuilt**, not deleted, because they only used the CLI route to get a TPM-bound credential: the guard cases of `tests/creds.rs` (`credential_names_no_pcr`, `pcr_guard_refuses`,
  `seal_refuses_a_real_pcr_bound_credential`) and the rows of `tests/sign_kinds/{real,case,failures,kit}.rs`, `tests/tpm_lifecycle/world.rs`, `tests/kind_audit.rs`
  that bind a credential to the `swtpm` through `systemd-creds`.
  **Environment fact (F110, to be re-run by step 1):** the Varlink daemon cannot reach a `swtpm` (it opens the TPM itself, from its own command line; in a container it skips the TPM), so in this
  dev container Varlink `Encrypt` gives only a host-scoped credential. Therefore the rebuilt tests take their TPM-bound credential from `MemoryCreds::tpm()` (or a header built by the test from the F153 layout, read
  independently of `header::inspect`), and any PCR-bound or null credential from a header the test builds, or from the root CLI inside the test daemon's namespace (the existing wrapper) used only as a test tool to *make* a
  null or PCR-bound input, never by the service. A real TPM-bound credential from the user-scoped daemon is proven in the VM harness (M5 later features), not here: listed as proven at those features.
  The `swtpm` stays in suites that need it for TPM *keys* (`tpm_lifecycle`, `sign_kinds` TPM rows).
- Left for other features: VM cases, `docs/install.md` and SPEC wording, the `ubuntu2404` target, packaging (F154 did it). A step greps `crates/` and `docs/` (not `SPEC.md`, findings or `docs/milestones/`) for leftover
  `tpm2-device`, `with_launcher`, "255" credential-route text and fixes doc comments in the code touched.
- Size: about five steps; no split. The test rework in step 3 is the bulk; if it will not fit one session the builder records where it stopped in PROGRESS.md (the feature may take several sessions).

Environment (run in step 1, result recorded in PROGRESS.md): `systemd-creds --version` here is 257.13; a Varlink `Encrypt scope=user` against the test daemon returns a blob whose id is `55b9ed1d…` (host scoped);
`ls /sys/class/tpmrm` shows no usable device in the daemon's namespace. These are already what `tests/creds.rs::host_bound_round_trip` relies on; the step confirms the TPM line.

Cost (estimates; the loop measures against `budgets.tsv`):
- `tests/creds.rs` today starts one daemon per test (namespace + `systemd-socket-activate`, ~0.3–1 s) and, for TPM cases, an `swtpm`. Removing the CLI/`swtpm` cases makes the file faster; no new daemon-based test is added
  except the null-key and PCR-bound inputs made by the root CLI, at most two extra CLI calls (~0.2 s each) in already existing daemon tests. Tests stay parallel (each own daemon/dir).
- Unit tests added: milliseconds, parallel. `sign_kinds`/`tpm_lifecycle` rows that stop starting `systemd-creds` children get cheaper. No script test, no e2e case.
- Mutants: the changed lines are mostly deleted; `just mutants-diff F155` mutates the remaining constructor/`encrypt`/`decrypt`/`valid_name`/`request` lines. Cost is bounded by the few changed lines; a runtime over budget is reported in BLOCKED.md.

- The CLI route and its chooser are gone → `cargo build -p custodiod` plus `rg -n 'tpm2-device|with_launcher|Command::new' crates/custodiod/src/creds` finds nothing; the compiler is the proof for the removed
  fields (`SystemdCreds::new(socket)` is the only constructor shape used by every test). Not a grep on wording of a document.
- Seals only through Varlink `Encrypt`, scope `user`, no `withKey` → unit test in `systemd/tests.rs` over a fake Varlink socket (existing `serve`/`ask`) asserting the request line is `Encrypt` with `"scope":"user"` and no `withKey`, and that the
  blob is returned decoded; `host_bound_round_trip` (real daemon, real `systemd-creds` 257) → header id is the scoped host id and the key round-trips. Fails if the client used another method or scope.

  tests does not exist in the API. `decrypt_returns_secret` (real) → secret in `secrecy` memory, `ZeroizeOnDrop`. Fails if a TPM header took another route.
- Nothing in the client starts a process → `sign_kinds` rows that earlier used `Fail::MissingLauncher` are removed as their subject is; the descriptor test is removed; the unit suite has a case where the socket is unusable and the result is
