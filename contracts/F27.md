# F27 — Mutation testing and CRAP gate cover the M1 code

## Scope
`just mutants` already lists `audit.rs`, `audit/{wire,journal,memory}.rs`, `credentials.rs`,
`offload.rs`, `dbus.rs`, `polkit.rs` and `store.rs` for `custodiod`. What this feature does:

- Checks that the audit path really is covered: the audit sink (`audit.rs` and its three
  submodules), credential lookup (`credentials.rs`) and the Sign code that records the outcome
  (`dbus.rs`: `sign_call`, `attempt`, `audit_parts`). It runs the `custodiod` mutants and kills
  every survivor with a better test; it does not hide one with `#[mutants::skip]`, an exclude, or
  a weaker assertion. A skip is allowed only for a mutant that is provably equivalent, with a
  comment that justifies it (the same rule as `#[allow]`).
- Adds the module's code to the same recipe as a second `cargo mutants -p custodio-pkcs11`
  invocation with `--file` for `composed.rs` (mechanism mapping `from_ckm`/`ckm`/`raw`/`key_type`,
  `DigestHasher`, `digest_info`, `sign_input`) and `module/mechanism.rs` (`hash_message`,
  `mechanisms`, `mechanism_info`, `fits`, `params`). The second run honors the same extra
  arguments (`"$@"`), so `--in-diff` and `--shard` still work, and it writes to its own `--output` dir.
- Makes the CI side follow: `ci.yml`'s diff job and `mutants.yml`'s shards already call
  `just mutants`. Both are checked and changed only if the extra run needs it (sharding and
  `--in-diff` apply to both runs; artifact path covers both output dirs; job timeouts still
  suffice; the module's integration test needs `dbus-daemon`, which the runner has).
- Checks that `just coverage` and `just crap` (threshold 30) pass on the M1 code (audit,
  credentials, `composed.rs`, `module/*`, `ffi/login.rs`, `ffi/sign.rs`) and fixes any function
  over 30 by adding tests or splitting the function, not by raising the threshold or adding an
  `--exclude`. The two existing fuzzing excludes stay as they are.
- Runs `just check-slow` as a whole.

Left for other features: e2e (F28, F29, F31), new production behavior. Production code may change
only to make a mutant killable or a function simpler, without changing behavior.
Mutating `ffi.rs`, `unsupported.rs` and `module/signing.rs` is not asked for; if the run is cheap
enough they may be added, but they are not part of this contract.

If the new mutants are too many to kill in one session the work continues in the next one; the
steps below are ordered so each leaves the tree green.

## Steps
- [ ] Run `just mutants` as it is today; list the surviving or timed-out mutants in the audit path files and `dbus.rs` (a timeout counts as failing).
- [ ] Kill each of those survivors with a test that fails on the mutant (tests first); re-run until `just mutants` is clean for `custodiod`.
- [ ] Add the second `cargo mutants -p custodio-pkcs11` run to the `mutants` recipe (files above, own `--output`, same `"$@"`), and update the recipe comment. Run it and list the survivors.
- [ ] Kill each `custodio-pkcs11` survivor with a test; `just mutants` ends with exit 0 for both runs.
- [ ] Check `ci.yml` (diff job) and `mutants.yml` (shards, artifact upload and the issue report) with the second run; adapt them only if needed; `just lint` (actionlint, zizmor) passes.
- [ ] Run `just coverage crap`; fix any function above 30 without touching the threshold or the excludes. Run `just check-slow` and record the mutant counts in `PROGRESS.md`.

## Evidence
- Mutation testing covers the service's audit path → `just mutants` (exit 0), and `target/mutants/mutants.out/outcomes.json` (and `caught.txt`/`unviable.txt`) lists mutants for each of `audit.rs`, `audit/wire.rs`, `audit/journal.rs`, `audit/memory.rs`, `credentials.rs` and for `sign_call`, `attempt` and `audit_parts` in `dbus.rs` → `missed.txt` and `timeout.txt` are empty.
- The recipe really mutates those files → `cargo mutants -p custodiod --list --file <each file>` (the same list the recipe passes; the recipe text is grepped for each path) → non-empty list for every file; the check fails if a file is dropped from the recipe.
- The gate bites on the audit path → by hand once: in `dbus.rs` replace the audit-failure branch (e.g. flip the `Failed("audit unavailable")` return path or drop the `sink.submit` result) and in `audit/wire.rs` drop a field; `just mutants` / the test suite fails. Reverted; recorded in `PROGRESS.md`.
- Mutation testing covers mechanism mapping, hashing and DigestInfo construction → `cargo mutants -p custodio-pkcs11 --list --file crates/custodio-pkcs11/src/composed.rs --file crates/custodio-pkcs11/src/module/mechanism.rs` lists mutants in `from_ckm`, `ckm`, `raw`, `key_type`, `DigestHasher::update`/`finalize`, `digest_info`, `sign_input`, `hash_message`, `mechanisms`, `mechanism_info` → `just mutants` exits 0 with `missed.txt` and `timeout.txt` empty for that run.
- DigestInfo prefixes and hashing are pinned by exact bytes → the composed unit tests compare each of the six mechanisms' `sign_input` to known-answer vectors (the RFC 8017 prefix + digest, computed independently of the code) → they pass, and fail when a prefix byte is mutated (shown by the clean mutants run above).
- The second run is part of the same recipe and takes the same arguments → `grep -c 'cargo mutants' justfile` shows both invocations in the `mutants` recipe, and `just mutants --list` (extra arguments reach both runs) lists mutants from both packages → both appear.
- The CI mutants workflow runs it too → `mutants.yml` and the diff job in `ci.yml` call `just mutants` (grep), no step runs only the `custodiod` half; `just lint` (actionlint, zizmor) passes; the artifact path in both workflows contains the output of both runs.
- Coverage report and CRAP gate pass on the new code, threshold 30 → `just coverage-gate` → exit 0; `grep -n 'crap threshold' justfile` still shows `"30"`; the `--exclude` list in the `crap` recipe is unchanged (`git diff` of the recipe shows no threshold or exclude change); `target/coverage/coverage.json` contains the new files (`jq` / grep of `composed.rs`, `audit/journal.rs`, `ffi/login.rs`).
- No threshold lowered, no gate weakened → `git diff main -- justfile .github` shows no change to `crap`'s threshold, `security-score`'s threshold, `miri`/`asan` flags, and no `#[mutants::skip]`, `#[ignore]` or new `#[allow]` without a justifying comment (grep on the diff).
- `just check-slow` passes as a whole → `just check-slow` → exit 0 (this is the feature's `verify`).
